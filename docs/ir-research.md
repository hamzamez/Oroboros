# Research: the IR between the residual and everything that reads it

2026-09-25. **Research, not a decision.** It precedes a specification (ADR 0006's file format) and an
ADR (0032). It follows ADR 0007: candidates are named with the measurement that would kill each, and
a prototype decides what argument cannot. hamza's framing: "eat our own tail". Not a rewrite of the
compiler in Oroboros, but a refactor derived from what the language taught us, taking every win it
offers in correctness, soundness, expressiveness, simplicity, emitted speed and compile speed. The
emitted code no longer has to be readable. Only its speed against hand-written code matters.

---

## 0. Why now: what was measured

**The IR was promised and never written.** ADR 0006 (2026-08-13) decided that "the interface between
the compiler and a backend is a specified, serialized IR file format", "the most consequential
artifact in the project", which "should be written before the compiler". Every backend instead reads
the λ-term residual directly, so there has never been an IR.

**What its absence costs, measured on 2026-09-25:**

| symptom | measure |
|---|---|
| **allocation** | compiling `freq` (7 s wall, 13.6 s CPU): **46% of CPU is the garbage collector** |
| **recomputation** | **16% is `BufferRange`**: the backend reruns the interval analysis on a sub-term per `build` to choose an element width, because "`openFresh` REBUILDS a term … the build the backend holds is not the pointer the analysis saw … There is no key" (interval.go) |
| | the interval analysis is entered from **19 call sites** |
| | 115 `openFresh` calls reopen binders; 38 `snapshot`/`clone` sites copy fact maps |
| **duplication** | the four backends are 9,267 lines; **21 methods exist 3–4 times** (`emitLoop`, `emitLoopBody`, `emitAgain`, `emitIf`, `emitLet`, `emitInto`, `emitJoin`, `multiTail`, …). ADR 0031's join point was written four times |
| **fragility** | **28 functions** each recognise part of the residual's control structure (`soleExit`, `exitType`, `javaExitType`, `exitIsFloat`, `tailTypes`×2, `multiPrimCall`, `multiValue`, `tupleArity`, `isMultiApp`, `asLet`, `noValue`, `isJumpTerm`, …) |
| | **13 files** walk clause chains, each its own way; **31 side tables** are keyed by `*core.Term` |
| **the week's bugs** | were one species: *a shape a pass did not know*. The type checker and the interval pass skipped `((build …) K)` and checked nothing inside it (prodresult-2026-09-25). CLAUDE.md already has the lesson: "every walker of a clause chain walks four forms, and one that misses a form is unsound" |

Each row is a consequence of one fact: **the program's structure is implicit in λ-terms and is
rediscovered by each consumer.** The rest of this document derives what the structure is, so it can be
made explicit once.

## 1. What the residual is, algebraically

### 1.1 The theorem the design rests on

**Theorem A (the residual is a first-order, structured program).** After staging, the residual of a
definition is closed, monomorphic and first-order (types.md). Every λ in it sits in a structural
position: a `let`'s continuation, a `loop`'s step, a `build`'s scope, a host call's continuation, or a
tuple's eliminator (tables.md §14.1; closures are refused as values). Its control is generated by:

| construct | what it is |
|---|---|
| **sequencing** | `let`, and `seq` as a `let` whose binder is discarded |
| **branching** | `if`, the eliminator of `bool = 1 + 1` (ADR 0017) |
| **products** | `tuple`, eliminated by application to a continuation (binding.md §5) |
| **iteration** | `loop`/`again` (ADR 0015); no recursion (ADR 0014) |
| **scopes** | `build`/`build-map`, a scope introducing one linear value (ADR 0018) |
| **primitive calls** | including several results received by a continuation (ADR 0027) |

*Proof sketch.* Staging (β, δ, β-tab, case-of-case) terminates on closed terms without recursion, and
the reducer refuses to emit a λ in value position. What remains is built from the listed forms, by
inspection of the reducer's normal forms. The typing and effect side conditions are ADR 0010's and
types.md's. ∎

So **the residual is already a program in A-normal form with join points**. What it lacks is not
structure but *names*: its binders are de Bruijn-indexed λs, reopened by every walker.

### 1.2 The algebra: a distributive Freyd category with Elgot iteration

Take the objects to be the residual's types: integers of each representation, floats, bools,
strings, tables, buffers, maps, host types, and finite products of these. Take the morphisms to be
programs from inputs to outputs. Each construct is an operation of a well-studied algebra:

- **Composition** is `let`: `(let x e b)` is `b ∘ ⟨id, e⟩`.
- **Products.** A tuple is a product in the category, with `⟨f, g⟩`. Several results, ADR 0031's
  scope results and a host call's results are all products.
- **Coproducts, and distributivity.** `bool = 1 + 1`, and `(if c a b)` is `[a, b] ∘ dist ∘ ⟨id, c⟩`,
  using the isomorphism X × (1 + 1) ≅ X + X. That makes the category **distributive** (Cockett
  1993), and **case-of-case is the universal property of the coproduct**:
  `K ∘ [g, h] = [K ∘ g, K ∘ h]`. It is exactly the rule core/reduce.go applies.
- **Iteration.** A loop's clause chain is a morphism `f : X → Y + X`: the state X is the loop
  variables, `again` is the right injection, and an exit is the left one. The loop is its **Elgot
  iterate** `f† : X → Y`, the least morphism satisfying the **fixpoint identity**
  `f† = [id_Y, f†] ∘ f` (Elgot 1975). The equational laws of † are Bloom and Ésik's **iteration
  theories** (1993): the fixpoint, parameter, composition, double-dagger and commutative identities.
- **Effects.** ADR 0010 denies contraction, weakening and exchange to impure terms. In categorical
  terms the structure is **premonoidal, not monoidal** (Power and Robinson 1997). A pure term is a
  **central** morphism: it commutes with everything, and may be moved, shared or dropped. An impure
  one is not. The two together form a **Freyd category** (Levy, Power and Thielecke 2003). That is
  the precise reason a pure computation may float (code motion, common subexpressions) and an impure
  one may not.

**The laws already in use are laws of this algebra**, which is how the refactor can be checked:

| rule in the compiler | law |
|---|---|
| β | substitution / composition with an identity |
| case-of-case (`if`, `let`, host continuation) | coproduct universal property, plus distributivity |
| ADR 0031's projection Pⱼ, with ⟦Pⱼ⟧ = πⱼ⟦P⟧ | naturality of †: `((g + id) ∘ f)† = g ∘ f†` with g = πⱼ |
| ADR 0031's join point | the same law read left to right. `g ∘ f†` shares g, and `((g + id) ∘ f)†` copies g into every exit. They are equal in meaning and differ in size |
| `PostVars` (a uniformly updated variable moves to the `for` post clause) | a rewrite of f that preserves f† (the fixpoint identity) |
| linearity, ADR 0018 | a use discipline on buffer-typed morphisms: linear in consuming positions |

**Theorem B (models).** A backend, the concrete semantics, the type checker and every analysis is a
**model** of this algebra: an interpretation of each operation. ADR 0021 already speaks of "a target
is a model". So:

- **A backend is faithful** when its interpretation of each operation computes what the concrete one
  does. Faithfulness of the whole follows **by structural induction**, operation by operation.
- **An analysis is sound** when each abstract operation over-approximates the concrete one, the
  local soundness of abstract interpretation (Cousot and Cousot 1977). Global soundness follows by
  the same induction, with † interpreted as a post-fixpoint reached by widening.

This is why an explicit IR matters beyond tidiness. Every consumer then interprets the **same finite
set of operations**, a pass that forgets one fails to compile against the operation set, and a
planted fault can be stated per operation.

## 2. The candidates

| | candidate | literature | the tension with our constraints |
|---|---|---|---|
| **C0** | the λ-residual, as today | this repository | §0's table is its cost |
| **C1** | a **control-flow graph in SSA form with block parameters** | Cytron et al. 1991; Cranelift; MLIR's `cf` dialect; Go's own `cmd/compile/internal/ssa`; V8's Turboshaft | printing to JavaScript, Java and Go needs **re-structuring**, since they have no general `goto` (§3) |
| **C2** | **structured SSA**: regions (block, loop, if) with parameters and results, and exits to enclosing labels | WebAssembly (Haas et al. 2017); MLIR's `scf` dialect (Lattner et al. 2021) | it is the residual's own shape (Theorem A), with names made explicit |
| **C3** | **continuation-passing style**, or a higher-order graph | Appel 1992; Kennedy 2007; Thorin (Leißa, Köster and Hack 2015) | it reintroduces λs our residual has already removed; the benefit is for higher-order languages |
| **C4** | **sea of nodes** | Click and Paleczny 1995; V8 TurboFan | V8 left it after ten years: "Land ahoy: leaving the Sea of Nodes" (2025) reports compile time **halved**, simpler code, and ~3× fewer L1 data-cache misses on a CFG IR |
| **C5** | **an e-graph as the primary IR** | Tate et al. 2009; egg (Willsey et al. 2021); Cranelift's acyclic e-graphs | a strong optimiser *inside* a pure region, not a carrier of effects, control and linearity |

C3 is excluded by Theorem A: the residual is first-order, and CPS would reintroduce what staging
erased. C4 is excluded by V8's measurement and by its cost of scheduling. C5 is a candidate
*optimisation pass* over C1 or C2 (§8), not a primary IR. **The question is C1 against C2.**

## 3. Question 1: a graph or structure?

**What each can express.** Peterson, Kasami and Tokura (1973): loops with **multi-level exits**
express every **reducible** flowgraph without duplicating code, and single-level exits do not.
Ramsey ("Beyond Relooper", 2022) gives the translation: from a reducible CFG, using the dominator
tree and a reverse-postorder numbering, to WebAssembly's `block`/`loop`/`br`, in one recursive pass.

**Our graphs are reducible, and more.** Every edge but `again` is forward, and every `again` targets
its enclosing loop's head, which dominates it. So the graph of a residual is reducible, with one
natural loop per `loop` (ADR 0015's structured control, and CLAUDE.md's "never add unstructured
control flow").

So C1 and C2 **represent the same programs**, and they differ in which direction pays:

| | C1 (graph) | C2 (structure) |
|---|---|---|
| **built from the residual** | flatten, then build block parameters | rename binders, and that is all: the structure is the residual's |
| **printed to JS or Java** | needs Ramsey's algorithm (dominators, reverse postorder) | direct: `label: for (;;) { … break label; … continue label; }` |
| **printed to Go** | the same algorithm, plus Go's `goto` rules ("jump over a declaration", "into a block") | direct for loops. A multi-exit non-loop block needs a `for { … break }` or `switch` wrapper, or a forward `goto`, which is a printer question P2 measures |
| **printed to x86** | direct: blocks and jumps | flatten: trivial |
| **iteration order for an analysis** | a weak topological order must be computed (Bourdoncle 1993) | Bourdoncle's recursive strategy **is** the nesting, so widening happens at loop heads, which are syntax |
| **what C1 buys** | arbitrary edges: jump threading, tail duplication, block cloning | nothing in that column is anything the language asks for |

**Prediction: C2.** It keeps what the source has and three of four printers need, and removes a
structuring algorithm the language never needed. **What would kill it:** an optimisation measured to
matter against hand-written code that needs a non-structured edge, or a printer (Go's, P2) that needs
more code for C2's multi-exit blocks than Ramsey's algorithm would cost.

## 4. Question 2: names

**SSA's single-assignment property is α-normal form made global.** Kelsey (1995) showed that SSA and
CPS correspond, and Appel (1998) that SSA is functional programming: a block's parameters are a
λ's parameters, and a φ is an argument at a jump. In C2 a loop's parameters are exactly
ADR 0015's loop variables, and `again` passes its arguments.

**Construction without dominance frontiers.** Braun et al. (2013) construct SSA directly from a
structured source, with no dominator computation. In our case it is simpler still. The residual has
no mutable variables (ADR 0018: values are immutable, and a buffer is threaded as a value), so
**lowering is one α-renaming pass**. Every binder gets a unique id, and every occurrence is that id.

**What unique names buy, measured in §0:**
- no `openFresh` (115 calls), and so no rebuilt terms;
- no side table keyed by a term pointer (31), so "the key does not survive a rebuild" disappears as a
  class;
- facts become **dense vectors indexed by value id**, where today they are maps cloned per branch.

This is where the prediction of a large drop in compile time comes from. It has to be measured (P1).

### 4b. Path-sensitive facts without copying: π-parameters (found by P1)

P1 ([irp1-2026-09-25](../gauntlet/results/irp1-2026-09-25.md)) measured where `freq`'s 7.46 GB go.
**57.7% is the interval pass copying its environment** at every branch: `snapshot` and `restore`. That
cost exists because a fact is **path-sensitive**: `(if (< x n) A B)` narrows `x` in A only, so the
pass keeps a whole map per program point.

Unique names alone do not remove it: they move the per-point map from terms to values. What removes it
is a representation in which **each name has exactly one fact**:
- **e-SSA** (Bodík, Gupta and Sarkar, *ABCD*, PLDI 2000) and **SSI** (Ananian 1999) rename a tested
  variable on each side of a branch, `x₁ = π(x)`, and the narrowed fact belongs to `x₁`;
- an analysis over such a form is **sparse** (Tavares, Boissinot, Pereira and Rastello, CC 2014): the
  abstract state at a point is the product of the facts of the values in scope, each computed once at
  its definition. There is no environment per point, so there is nothing to copy.

**In C2 a π-node is a parameter of the branch's region**, the device a loop's parameters already are,
so the algebra gains no operation. **This is a requirement of the IR, whichever candidate wins.**

## 5. Question 3: the analyses as models, and their product

Each analysis in `emit/` is an abstract domain in Cousot and Cousot's sense: a lattice A, a
concretisation γ : A → 𝒫(Values), abstract operations, and a widening. Today each has its own walker:

| code (lines) | what it computes | the domain it is |
|---|---|---|
| `interval.go` (4,083), `bound.go` | integer ranges, exact to 2¹²⁶ | intervals with widening (Cousot and Cousot 1977) |
| `smash.go` | a table's element range | array smashing (Blanchet et al. 2003, Astrée) |
| `buflen.go` | `len x = e` | length equalities: a sub-domain of the linear one |
| `monotone.go` | a loop's value ≥ its start | a relational sign domain (octagon-like, Miné 2006) |
| `wordsel.go`, `bigrep.go`, `biglimb.go` | u64 against int, big, bit length | *functions of* the interval and bit-length domains (ADR 0026, 0029) |
| `refine.go`, `linear.go` (3,158 together) | linear facts, Fourier–Motzkin entailment, opaque atoms | conjunctions of linear inequalities: polyhedra computed lazily (Cousot and Halbwachs 1978), with uninterpreted atoms |
| `content.go`, `fact.go`, `component.go` | content facts, Houdini, strided components | array properties (Bradley, Manna and Sipma 2006), segmentation (Cousot, Cousot and Logozzo 2011), Houdini (Flanagan and Leino 2001) |
| `sct.go` | termination | size-change (Lee, Jones and Ben-Amram 2001) |
| `linearity.go` | buffer linearity | a use discipline: a dataflow over moves |

**Three observations the table makes plain:**

1. **Two fixpoint engines already do the same job.** The interval pass iterates loops with widening,
   and the refinement layer iterates them again with Houdini. They meet only through
   `DischargeRequires`, *sequentially*: literal, then interval, then refine.
2. **A reduced product proves at least as much as each factor** (Cousot and Cousot 1979), since the
   domains exchange facts at every step instead of once at the end. The interval domain's bounds
   become linear facts, and the linear domain's equalities narrow intervals. Today that exchange is
   done by hand where a program demanded it: `buflen`, the `lenFor` seeds, `seedFacts`. **The
   prediction:** proof counts go up (2,007 of 2,054; 343 of 381 today). It is measurable, and it can
   only be *prevented* from going down by keeping each factor's own transfer functions.
3. **Soundness becomes per-operation.** Each domain states, for each IR operation, that its abstract
   operation over-approximates the concrete one. That is what the planted-fault tests test today,
   scattered; on an IR they are a table with one row per (domain, operation).

**Obligations** (the indexings, the `where`s, the contract marks) are **verification conditions at
program points**. They are collected once from the IR and decided against the product's invariant at
their point, by the three routes of refinements.md §3a. That makes noprop-2026-09-25 structural rather
than vigilant.

**What this document cannot decide:** whether the product is one engine over all domains, or domains
run in a fixed order with reduction between them. The first is the theory; the second may be faster.
P3 measures one domain before the choice is made.

## 6. Question 4: effects, linearity and representation as types

- **Effects** (§1.2). An IR operation carries its purity. A pure operation is central: it may be
  moved or shared, and dropped when dead. An impure one keeps its order within its region. That
  replaces `pureTerm`'s judgement on terms with a bit on the operation, which ADR 0010 already
  declares per primitive.
- **Linearity** is a property of buffer-typed values: each is **consumed at most once on every
  path**, and read only before it is consumed. On SSA that is a forward dataflow over a two-point
  state per buffer (live or moved), which is today's `linearity.go` walk without the reopening.
  Rust's borrow checker runs on a CFG IR (MIR) for the same reason (RFC 2094, non-lexical lifetimes).
- **Representation is a type of an IR value, decided once.** An integer's representation (word, U,
  big), an element width, an index narrowed to the host's `int`: each is decided by the analyses
  *before printing* and recorded on the value. **A printer reads types and never recomputes a fact.**
  That removes `BufferRange`'s 16% and the backend's `typeOf`/`tailTypes`/`exitType` family.

## 7. Question 5: leaving the IR, and the measured decisions the printers must keep

**Out of SSA.** `again`'s arguments are a **parallel copy**. Sequentialising a parallel copy with the
fewest temporaries is the known problem Boissinot et al. (2009) solve. Our x86 `emitAgain` already
does it by hand ("parallel-copy sequentialisation, and it is worth the thirty lines exactly once"),
and the other three backends each do a version. On the IR it is one function.

**The printers inherit decisions that were measured**, each against hand-written code. These are
requirements, not heuristics to reconsider:

| decision | where today | evidence |
|---|---|---|
| a uniformly updated variable in the `for` post clause | `PostVars` | 1.4× on the sieve (loopshape-2026-08-25) |
| no result temporary when every exit yields one name | `soleExit` | the temporary defeated Go's escape analysis: 20,480 B/op against 0 |
| narrow the containers a counted loop indexes, before the loop | `countedGuard`, `emitNarrow` | the 1.96× that `fold-range` had (bce-2026-08-15) |
| a Java index in the host's `int` when the method fits | `NarrowIndex` | 1.04–1.45× (native-java-2026-08-25) |
| return from a tail loop instead of assigning and breaking | JavaScript `emitLoop` | 1.31× on V8 (native-js-2026-08-20) |
| several results as an object on JavaScript, native on Go, a record on Java | `multiFunc` | multiresult-2026-08-22 |
| a spare buffer alternated on a back edge | `LoopBufferReuse` | the 2.5–2.7× allocation price (native-gauntlet-2026-08-20) |
| element width by range; one width per loop variable | `elemTypeFixed`, `LoopOneJoin` | elemwidth-2026-08-27; on x86 a soundness question (wintables-2026-08-25) |
| packed JavaScript arrays (`fill(0)`) | JavaScript `build` | a sparse array is a dictionary on V8 |
| a negated condition is a swap | the reader | cond-2026-09-19 |

On the IR, each decision is one rewrite or one printer policy, stated once with its evidence. A policy
that exists for readability alone may go, now that readability is not a requirement. A policy that
exists for speed stays, and is re-measured when the IR changes what the host compiler sees.

**Printing structure per host.** JavaScript and Java have labelled blocks and labelled
`break`/`continue`. Go has labelled `break`/`continue` on loops only. x86 has jumps. C2's
region-exit maps to each directly except Go's non-loop block (§3). P2 measures that case.

## 8. Question 6: optimisation on the IR

Candidates, each already *seen* in a program, and none to be built without a measurement:

- **Common subexpressions of central operations.** u128-2026-09-23: "6 `Mul64` and 3 `Add64` where
  2 and 1 suffice", with Go's own merging *not measured*.
- **Loop-invariant hoisting.** `winmap.oro`: "a division per probe step, which the host hoists …; if
  that ever measures, `n` becomes a parameter".
- **Coalescing of block parameters** (§7, `soleExit`), which becomes a general rule rather than an
  exit pattern.
- **Equality saturation** (Tate et al. 2009; egg) inside pure regions. The Freyd structure (§1.2)
  says exactly which regions are pure. It is later, and only on measurement.

The host compilers are black boxes with measured behaviour (ADR 0008). Go's SSA, V8's Turboshaft and
the JVM's C2 already do much of this, so each IR optimisation must show a gain *after* the host's own
passes. That is the gauntlet's job, not this document's.

## 9. Question 7: the file format (ADR 0006)

**An s-expression text.** The reader already exists and is tested, and the format stays human-
checkable. The precedents are MLIR's generic textual form and WebAssembly's text format, each a
canonical printing of the IR, with a binary form optional. Versioning is a header and an operation
set: a backend declares the operations it prints, and **covering** (ADR 0002's capability graph)
decides whether a target can take a program, the way it does for primitives.

Not decided here: the binary form, and whether analysis facts are part of the format or only the
types they decide. The second is the likelier, since a backend needs representations and not the
reasons for them.

## 10. Question 8: is the lowering sound?

- **By construction.** Lowering is α-renaming plus making labels explicit (§4). It maps each
  operation of §1.2 to itself, so it is a homomorphism, and faithfulness is structural induction.
  CompCert (Leroy 2009) is the reference for layered IRs, each step proven semantics-preserving. This
  one step is small enough to argue in the specification.
- **By validation.** The differential suite runs every case on four targets against hand-computed
  answers. That is translation validation by testing (Pnueli, Siegel and Singerman 1998; Necula 2000
  for the static kind), and it stays the gate for every printer.

## 11. The prototype (ADR 0007): what decides C1 against C2

| | build | measure | kills |
|---|---|---|---|
| **P1** | lower `freq`'s residual (the largest program) to C2, and to C1 | wall time and allocation, against today's analyses and emission | C2 if its lowering is not cheaper than C1's; **the whole refactor** if neither removes a large share of the 46% GC |
| **P2** | a Go printer for C2 over the gauntlet's seven programs | ns/op against hand-written code, and printer lines against `golang.go`'s share | C2 if any gauntlet program loses parity, or if Go's multi-exit non-loop block costs more than Ramsey's structuring would |
| **P3** | the interval domain on C2, run on `freq` | compile time, and the per-program proof counts against `interval.go` | the one-engine plan if the counts differ or the time does not fall |

Each is a result document, and each is thrown away or kept by its numbers. The specification is
written from what survives.

**P1, done** ([irp1-2026-09-25](../gauntlet/results/irp1-2026-09-25.md)):
- Lowering costs 0.1–0.4 ms and at most 0.7 MB on four real programs, with nothing left opaque.
  Today's pipeline allocates 112 MB – 7.46 GB on the same residuals.
- C2 is cheaper than C1 by ~0.3 ms, which is immaterial, so C1 against C2 moves to P2 and P3.
- The refactor survives, but the largest cost it must remove is the path-sensitive environment
  (§4b). **P3 must therefore be the interval domain on C2 *with π-parameters*.**
- `SelectShifts` reruns the whole interval analysis on every program.

---

## 12. What this document does not decide

- **The exact operation set.** It will be §1.2's operations plus the primitive calls, and whether a
  `build` scope is an operation or a region is a specification question.
- **One analysis engine, or ordered domains with reduction** (§5).
- **The binary format** (§9).
- **Which optimisations** (§8).
- **The order of migration.** A sketch: the Go printer first, then JavaScript, Java and x86; then the
  analyses one domain at a time. The gates are the differential answers, the gauntlet against
  hand-written code, and proof counts that never fall. Byte-identical emission stops being a gate
  when a printer changes; it is re-baselined once per printer.
- **What stays on terms.** Staging does, and so do the passes that rewrite terms before lowering
  (`PromoteBig`, `SelectWords`, `FlattenProducts`). Whether they move onto the IR later is for later.
