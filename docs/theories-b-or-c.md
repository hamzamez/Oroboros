# B or C: parameters, views, and the surface

Research, **no decision, nothing built**. 2026-09-14, the follow-up to [theories.md](theories.md), on
hamza's *"let's explore B vs C, and remember this is oroboros, we eat our own tail: if the cost is a
rewrite, that is cheap. We have a bigger picture of everything now, so if the syntax needs to change
or improve, include that in the research as well."*

theories.md §7 set out five candidates and leaned toward **B**: theories, one declaration record, the
existing forms as sugar. **C** added what B leaves out — theories parameterised by theories, views as
things with names, and the structured-specification operations — and was set aside with modules.md
§9's reason: *"the target is already the parameter to reduction, and there should be only one."*

This document examines that reason, decomposes C into its separate features, prices each one against
this language's own constraints rather than against rewrite cost, and derives a surface syntax from
the result.

**The answer in four sentences.**

1. **The reason given against C is wrong**, because a build *already is* the instantiation of a
   parameterised theory: the program is parameterised by the target's theory, and the target is the
   argument (§2).
2. **Most of what C offers is already in B** once a model may contain definitions (§2.2).
3. **What is left of C splits cleanly.** First-order, applicative instantiation along named views is
   cheap and a conservative extension of B (§3–§5). Modular type checking, opaque sealing,
   higher-order functors and first-class modules each need a *typed static level* or a *runtime
   closure*, which this language refuses for independent reasons (§4, §6).
4. **So the foundation to specify is C restricted to its first two features, and the part to build
   first is B's.** The syntax is redesigned so that the rest of C is an addition, never a revision
   (§8).

## 0. The criteria, since cost is not one

Measured today, the rewrite would touch:

| what | count |
|---|---|
| `prim` declarations in `targets/` and `lib/` | 931, in 37 files |
| `.oro` files in `examples/` and `gauntlet/` | 119 |
| lines of `.oro` in `examples/`, `gauntlet/` and `lib/` | 6,015 |
| top-level forms in those programs | 485 `def`, 169 `use`, 95 `export`, 77 `sig`, 6 `provides`, 5 `module`, 2 `sum` |
| generated declarations (48,518) | regenerated by the surveys, not rewritten |

That is a mechanical translation plus two hand-written packages. hamza is right that it is cheap.
So the criteria are these, in order:

1. **Does it follow from the algebra**, or is it a list of cases?
2. **Is every check in an owned fragment** (theories.md §6.3), so nothing becomes a search?
3. **Does staging make it free**, or does it need a *typed static level* (the static level is untyped
   λ today, types.md) or a *runtime closure* (refused, callbacks.md tier 3)?
4. **Is there a live demand** in this repository, or only a plausible one?
5. **Does it remove forms**, or add them?

## 1. C is six features, not one

"Parameterised specification" names a bundle, and pricing the bundle hides which part costs what.

| | feature | literature | what it needs here |
|---|---|---|---|
| **C1** | a theory parameterised by a theory, instantiated along a view | Goguen, *Parameterized programming* (IEEE TSE 1984); Ehrig & Mahr (1985); Maude's parameterised modules | pushouts at resolution time (§3) |
| **C2** | views as named, checkable objects | OBJ, Maude, MMT views | a view check in fragments R1 and R3 (§5) |
| **C3** | sharing constraints (`with type t = …`) | MacQueen (1984); Harper & Lillibridge (1994) | amalgamation over a shared parameter; no demand yet |
| **C4** | higher-order functors | MacQueen & Tofte (1994); Dreyer, Crary & Harper (2003) | typing functor-valued parameters |
| **C5** | opaque sealing: abstract types defined *in the language* | Mitchell & Plotkin (1988); Reynolds's representation independence | **a typed static level** (§4.3) |
| **C6** | first-class modules at run time | Russo (2000); 1ML (Rossberg 2015) | **dictionaries, which are closures** — refused |

§3 to §6 take them in order.

## 2. The finding: a build is already an instantiation

### 2.1 The atom, re-read as parameter passing

[the-atom.md](the-atom.md) says the core is *lambda calculus in which the normal form is a
parameter*: a target supplies a partition of names into primitive and defined, and reduction runs
until only primitives remain. In theories.md's terms:

- the program `p` is a set of declarations whose free names lie in `lang ∪ Σ_T ∪ D`, where `Σ_T` is
  the **theory** a target realizes (`os`, `io`, `go/os`, …);
- the target `T` is a **model** of `Σ_T`: for each abstract declaration it gives a realization, and
  for some it also gives a definiens;
- **building** is (i) resolving `p`'s names along the view `Σ_T → T`, then (ii) normalising, which
  halts exactly at the declarations with a realization and no usable definiens.

Step (i) is **parameter passing** in Ehrig & Mahr's sense: a parameterised specification `Σ_T ⊆ p`
instantiated along a view. The four cells of modules.md are what happens at each name once the view
is fixed. **The target has been a functor argument since the first commit. It was never given the
name.**

`examples/tally/tally.oro` says the same thing about itself: its header calls the host interface *"an
ML functor applied at COMPILE time"*. `tally-go.oro` builds the argument by hand, as an untyped tuple
of six functions:

```lisp
(def host (values
  (fn (p) (re.MustCompile p))
  (fn (r s) (rx.MatchString r s))
  …))
(def main (fn () (tally.run host)))
```

So the language has **two** parameterisation mechanisms today. One is implicit, typed and checked: the
target. The other is explicit, untyped and unchecked: a static-level tuple. ADR 0011's *"a functor
would be a second, competing mechanism"* has it backwards. The second mechanism already exists, and
the way to have only one is to **name the first one generally enough that the second becomes an
instance of it**.

**One difference is real and does not break the identification.** An ML functor is *parametric*: its
body cannot inspect the argument. Target instantiation is not parametric, because native-wins makes
the normal form depend on which declarations the argument realizes. But the tuple is not parametric
either: β substitutes the functions and reduction inlines them. **Instantiation by reduction is never
parametric here**, and it does not need to be. Parametricity is what buys representation
independence under *separate* compilation, and this compiler compiles the whole program at once
(ADR 0011, "separate compilation": absent).

> **Correction owed.** ADR 0011's "Why not — Functors" argues from the wrong reason. When this
> research is decided, the superseding or amending ADR should record that the target is already an
> instantiation, and that functors are deferred **for lack of demand and for C4–C6's costs**, not for
> competing with the target.

### 2.2 Most of C is B plus one existing unbuilt item

`tally` needs its host interface to be *chosen by the target*. That is exactly what a portable theory
with per-target models already does for `os` and `io` (portableio-2026-09-09):

```lisp
(use os)          ; lib/os.oro declares the theory; lib/os/go.oro is (provides go os …)
```

The one thing `(provides go os …)` cannot hold today is a **definition**. Every cell is a `prim`, and
tally's `capture` is four lines of logic over `FindStringSubmatch`, not a template. That missing piece
is [target-system.md §6](spec/target-system.md)'s `D_T`, *"the target's own library"*, build-order
item 5, left waiting for a demand. **tally is the demand**, and it has been in the repository since
2026-09-11.

With definitions allowed inside `provides`:
- `tally.oro` writes `(use text/regex)` and calls `regex.compile`;
- `tally-go.oro` and `tally-java.oro` disappear as programs. Their bodies move into
  `lib/text/regex/go.oro` and `lib/text/regex/java.oro` as models, where they are checked against
  the theory in both directions, as portableio already checks `os`;
- there is **one** `main`, built with `-target=go` or `-target=java`.

That is B. It needs no explicit parameter, because the **ambient** view (the target's) is the only one
tally wants. **Explicit instantiation is needed only when a program wants a view other than the
ambient one**, and no program here does.

## 3. The algebra of instantiation (C1)

### 3.1 Parameter passing is a pushout

Let `P ⊆ B` be an inclusion of theories: `B` is parameterised by `P`. Let `v : P → A` be a view, a
morphism of theories (theories.md §2.5). **Instantiating `B` along `v`** is the pushout

```
          P ──────⊆──────▶ B
          │                │
        v │                │ v'
          ▼                ▼
          A ──────────▶  B[v]
```

`B[v]` is `A` together with `B`'s declarations translated along `v`: every occurrence of a `P`-name
is replaced by its image in `A`, and `B`'s own names are qualified into the instance. This is the
parameter passing of Ehrig & Mahr (*Fundamentals of Algebraic Specification 1*, 1985) and of Goguen's
OBJ (1984), and Maude implements the same construction.

The pushout **exists** because this system's names are qualified by path, so the translation is
injective on `B`'s own names. It is **well-formed** when `v` is a morphism:
- every type and term declaration of `P` has an image in `A`;
- classifiers translate to classifiers `A` agrees with (fragment R1);
- every prop-level declaration of `P` holds in `A`. For an assumed fact this is a conformance
  obligation, and for an R2 or R4 fact it is an entailment the compiler can try.

### 3.2 Theorems

**I1 — instantiation is resolution.** `B[v]` is computed from declarations alone, before reduction.
So modules.md's T1 (*reduction is target-independent except at the floor*) extends: *reduction is
independent of the argument except at the argument's realized declarations*. ADR 0011's decision,
that modules add nothing to the reducer, **stands**.

*Proof.* The pushout is renaming plus union of declaration lists, and neither is a reduction step. ∎

**I2 — instantiation is functorial.** For `v : P → A` and `w : A → A'`, `(B[v])[w] = B[w ∘ v]`, up to
the names of the instance.

*Proof.* The pasting lemma for pushouts: two adjacent pushout squares compose to a pushout. ∎

This is why layers compose (target-system.md §7.2), why `implements` is transitive
(coercion-2026-09-09 closes it at load), and why a library instantiated inside a library needs no
special case.

**I3 — instantiation is applicative.** Two instantiations of `B` along the same `v` produce the
same qualified names, so `B[v].t` and `B[v].t` are the **same type**.

*Proof.* A pushout is determined up to isomorphism by its diagram, and naming the instance by the
diagram makes that isomorphism the identity. ∎

Leroy's *applicative functors* (POPL 1995) is the literature's name for this. **Generative**
functors, where each application makes fresh abstract types, are needed only when instantiation
allocates state. Instantiation here happens at compile time and allocates nothing, so theories.md
§4.3's ν-calculus observation, that generativity is an effect, does not apply to it.

**I4 — a program is portable over every model of its parameter.** If `FV(B) ⊆ lang ∪ names(P) ∪
names(B)`, then for any two models `A₁` and `A₂` of `P` whose realizations cover `P`'s declarations,
`B[v₁]` builds exactly when `B[v₂]` builds.

*Proof.* Covering depends only on which names have a realization (target-system.md T4), and the free
name condition confines `B`'s demands to `P`. ∎

target-system.md T4 is the special case where `P = Σ_T` and the models are one target family's
members. I4 is ADR 0001's *portability is a program property* for **libraries**, not just for whole
programs.

**I5 — C is a conservative extension of B.** Every B program is a C program in which every
instantiation is along an ambient view, and its meaning is unchanged.

*Proof.* B resolves `(use M)` by taking `M`'s declarations and the ambient target's `provides` for
`M`, and that is `M[v_T]` for the ambient view `v_T`. The qualified names coincide, so the term
handed to the reducer is identical, and by I1 so is everything after. ∎

**I5 is the property hamza asked for.** Building B now, with a syntax that reserves C's instantiation
form, means that adding C later cannot change any program already written.

## 4. Checking a parameterised theory

### 4.1 Three disciplines

The question is *when* a parameterised body is checked against its parameter.

| discipline | checked | example | error appears |
|---|---|---|---|
| **modular** | once, at definition, against `P` | ML functors; Rust traits; C++20 concepts | where the body is written |
| **instantiation** | per instantiation, on the result | C++ templates; Zig `comptime` | inside the instance, possibly deep in it |
| **scope at definition, types at instantiation** | free names at definition; types on the residual | — | a missing or misspelled name at the definition; a type mismatch at the instance |

Garcia, Järvi, Lumsdaine, Siek & Willcock (*A comparative study of language support for generic
programming*, OOPSLA 2003) compare the first two across eight languages. The recurring cost of
instantiation checking is **diagnostics**: an error reported deep inside an instance, far from the
line that caused it.

### 4.2 The third row is what this compiler already does to targets

- **Scope at definition** is target-system.md §6.3's free-name condition,
  `FV(d) ⊆ lang ∪ P_T ∪ dom D_T ∪ dom D`. Covering is computed from exactly this, and it is linear
  and syntactic.
- **Types at instantiation** is [types.md](spec/types.md): the checker runs on the residual, which
  reduction has made monomorphic, first-order and closed.

So C1 needs no new checking discipline. **A parameterised theory is checked exactly as a program is
checked against a target**, because a program *is* a parameterised theory. The diagnostics cost of
§4.1 is not new either: every program already pays it, and sig's claim checked in two directions is
the mitigation that exists.

### 4.3 Where modular checking would cost, precisely

Checking a body's **types** against `P` once, before instantiation, means typing the body before
reduction. The body is written at the **static level**, which is untyped λ with fuel. Typing it
means a type system for the static level: at least Hindley–Milner for first-order uses, with rank
and polymorphism questions at every higher-order use (decidability-map.md cliff 3). **That is a real
language decision, and C1 does not need it.**

**Opaque sealing (C5) needs the same thing, and this is its exact price.** Hiding a user-defined
representation from clients means *rejecting a client that depends on it*. The client's dependence is
expressed at the static level, before reduction erases the abstraction. After reduction the residual
is monomorphic and the abstraction is already gone, so the residual checker cannot enforce it.
Representation independence (Reynolds 1983; Mitchell 1986) is a theorem *about a typed language*.

**Host abstract types do not need it.** `go/os.File` has a realization and no definiens, so there is
no representation to leak. The residual checker compares it nominally, which is what it already does
with `ptr-os-File`. That is abstraction *by absence of a definiens*: free. Abstraction *by hiding a
definiens* is what costs a typed static level.

> **Trigger for C5, and for typing the static level:** a portable library whose correctness depends
> on clients not constructing its representation directly — a map over tables with an invariant a
> client can break. No such library exists here.

## 5. Views (C2)

### 5.1 One form for three existing things

A **view** `v : P → A` assigns every declaration of `P` an image in `A`. Following MMT, an image may
be a **term**, not just a name. Three things in this repository are views written three different
ways:

| today | as a view | assignments |
|---|---|---|
| `(implements T I …)` | `I → companion(T)`, by name | identity on method names, checked by method-set inclusion |
| `(provides go os …)` | `os → go` | each name to a realization |
| tally's `(def host (values (fn …) …))` | `text/regex → go/regexp` | each name to a **term** |

With definitional assignments, one form covers all three, and the third stops being an untyped tuple.
It becomes a checked object: every declaration of `P` must be assigned, and each assigned term's
residual must agree with the translated classifier (R1).

### 5.2 Ambient and named

- An **ambient** view is the one a target supplies for a theory: `(provides T M …)`. Resolution uses
  it when a program writes `(use M)`. That is all of B.
- A **named** view is one a program chooses explicitly: `(use M with V)`. That is C1 plus C2, and it
  is reserved in the syntax and not built (§8.6).

### 5.3 Coherence

theories.md's T2 said views carry no run-time evidence, so orphans cannot be incoherent. With several
views possible, one question returns: **which view is ambient?** Two `provides` for the same theory
on the same target would make `(use M)` ambiguous.

The answer needs nothing new. **Ambient views are target fragments, and fragments within a layer glue
under `⊔`, which is partial.** Two disagreeing ambient views in one layer fail to glue and are
refused at load; between layers, `▷` decides. That is Haskell's global instance uniqueness, obtained
from an operation this system already has, and it applies **only to ambient views**. A named view is
chosen by the program, so it never competes.

## 6. What stays refused, and the candidate that tempts most

### 6.1 C3, C4, C6

- **C3, sharing constraints.** These are needed when two parameters must agree on an abstract type.
  Host types are named by path, so by I3 two uses of `go/io.Writer` are equal without any constraint.
  Sharing matters only for abstract types *in a parameter theory*, and no theory here takes two
  parameters. *Trigger:* the first such theory. The mechanism would be amalgamation over the shared
  sub-theory, the same partial pushout as §3.
- **C4, higher-order functors.** A theory parameterised by a parameterised theory. There is no
  demand, and typing it is where module systems have historically become research projects. Refused.
- **C6, first-class modules at run time.** A module chosen by run-time data is a record of functions
  selected dynamically: a dictionary, which is a closure. **Refused permanently**, for callbacks.md
  tier 3's reasons. This is not a matter of waiting for demand.

### 6.2 Candidate Z: modules as static values

The most tail-eating design deserves a full hearing. **1ML** (Rossberg, *1ML — core and modules
united*, ICFP 2015) and **Zig** both unify modules with the core language. In Zig an import *is* a
struct value computed at compile time, and a generic is a `comptime` function returning a type.
Here, the static level is already an untyped λ-calculus that terminates by fuel. So one could delete
the module language entirely: `(use os)` binds a static record, a functor is a static function, a
view is a static record, and tally's tuple is simply how everything is written.

**What it would buy:** zero declaration forms, C1, C2 and C4 for free (untyped), and the simplest
possible reader.

**Why it is refused**, with the reason stated as a principle, because it is the principle the rest of
this document relies on:

> **Declarations are data; definitions are terms.**

Everything this repository checks about a host is checked **without running a program**:
- `TestHandDeclarationsAgreeWithTheHost` compares declarations to the host's types;
- the surveys count them;
- the loader glues and overrides them, and refuses disagreement;
- covering reads which names are realized;
- R3 closes the subtype relation at load;
- R4 must know a rule's triggers before the refinement layer starts.

In Z, a declaration is a term, and knowing what a module declares means reducing it. Gluing becomes
an evaluation, disagreement becomes something discovered by fuel, and the target — ADR 0006's *file
format* — stops being inspectable data. That reverses ADR 0006 and ADR 0011 together, to gain
features that §2–§5 obtain without either.

target-system.md §6.3's stratification (*a target library may `def` and may never `prim`*) is this
same principle, seen once. theories.md §2.3's well-founded order is its type-level form. Z is
refused, and the principle is the thing to keep.

## 7. The verdict

| | B | C₁₂: C restricted to C1 and C2 | full C |
|---|---|---|---|
| algebra | theories, models, `⊔`, `▷`, reducts | + pushout instantiation, named views | + sharing, HO, sealing, first-class |
| fragments | R1–R5 | R1–R5 (a view is R1 plus R3) | + typing the static level |
| staging makes it free | yes | yes (I1) | no (C5); refused (C6) |
| live demand | `os`, `io`, types-in-modules, tally via `D_T` | tally's tuple (an explicit view today) | none |
| forms | unifies 14 into ~9 (§8) | + one clause (`with`) | + several |
| extends B conservatively | — | **yes (I5)** | no: C5 changes what a client may write |

**Specify C₁₂. Build B's part first.** The explicit `with` is specified and reserved, and its trigger
is named: the first program that needs a view other than the ambient one, such as two regex engines
on one target. C3 is deferred with its trigger, C5 waits on the static-level typing question, and
C4 and C6 are refused.

## 8. The surface

> **Revised 2026-09-15, and specified.** The rules are now [spec/theories.md](spec/theories.md) and
> [spec/data.md](spec/data.md), and those are authoritative where they differ from this section.
> Four changes came from the discussion that followed this section:
> - `data`/`codata` became **`variant`/`record`**, because `codata` means *infinite* in the
>   literature and this language has no recursive types;
> - `sum` became **`variant`**, the textbook pair of `record`;
> - `values` and the product type `(array A B)` became **`tuple`**;
> - record labels are **symbols**, `'x`.
>
> A host interface is **not** a record. It is an abstract type plus a companion module, and
> `include` derives its subtyping. The examples below are updated to match.

The syntax below follows from the algebra and changes **declarations only**. The term language — seven
term kinds, `fn`, `let`, `if`, `loop`, `again`, `match`, tables — is untouched. S-expressions stay.
The reader is one parser, a declaration is already a data structure, and a compiler that will one day
read its own source (*the name*) reads S-expressions trivially.

### 8.1 Principles

**S1 — one declaration, four parts, each with one spelling.** Name, classifier, definiens,
realization. Today's `prim` packs a classifier, a realization, purity and contracts into one
positional form, `(prim name args result kind "tmpl" pure (where …) (import …))`, so a portable
theory cannot state a classifier without also stating a host.

**S2 — a keyword names a level.** `type` for types, `sig` and `def` for terms, `fact` for
propositions, and `variant` and `record` for the two polarities (data.md §5.2 says why not `data`
and `codata`).

**S3 — the realization is a clause, `host`, and nothing else carries host text.** So a file with no
`host` clause makes no claim about any host, and a checker can test that property instead of
trusting a convention.

**S4 — a file is a module and its path is its name.** A library file must already declare exactly
the module its path names (modules.md, 2026-08-16), so writing the header is redundancy the loader
checks. Nesting is written `(module NAME decl…)`, a child relative to the enclosing module.

**S5 — every attribute is a clause.** `(where …)`, `(ensures …)`, `(import …)`. The exception is the
bare word `pure`, kept because it is one bit and reads well.

**S6 — a result list is a product, and says so.** `(tuple A B)`, not `(A B)`. Today `(int int)` in
a result position means two results, `(array int)` means one type, and only `TypeName` can tell them
apart (multiresult-2026-09-06). products.md recorded the cost: `(array int string)` in a result slot
is read as three results. A tuple is the one product, whether it is consumed, returned or stored,
and the compiler chooses its representation per position (data.md §3).

**S7 — the target comes from where a realization is, never from the realization itself.** A `host`
clause in `targets/go/…` realizes on `go`; inside `(provides java M …)` it realizes on `java`. Today
no prim in `targets/go/` names `go`, and that stays true.

### 8.2 The grammar

```
file     ::= decl*                                  ; module = the file's path
decl     ::= (use PATH [as NAME] [with VIEW])       ; `with` reserved (C₁₂), not built
           | (export NAME…)                         ; a reduct
           | (module NAME decl…)                    ; a child theory
           | (type NAME [τ] clause…)                ; abstract, or manifest with τ
           | (variant TNAME ctor…)                  ; positive; TNAME may be (NAME A…)
           | (include NAME…)                        ; inside a companion module
           | (sig NAME ((x τ)…) τ [pure] clause…)
           | (def NAME term)
           | (const NAME term clause…)              ; sugar, §8.3
           | (fact NAME ((x τ)…) φ (when φ…) (trigger t…))
           | (implements T I…)                      ; sugar for a view by name
           | (provides TARGET PATH assign…)         ; the ambient view
           | (view NAME PATH PATH assign…)          ; a named view; reserved (C₁₂)
           | (target NAME (backend B) clause…)      ; a target layer's header
           | (repr τ clause…)                       ; representation choice, §8.4
assign   ::= (host NAME clause…) | (def NAME term) | (type NAME τ)
clause   ::= (where φ) | (ensures φ) | (host [kind] "template" hclause…)
hclause  ::= (import "…") | (lib "…") | (checked NAME) | (data …)
kind     ::= expr | stmt | jump
ctor     ::= NAME | (NAME τ…)
τ        ::= … | (tuple τ τ…) | (record ('l τ)…) | (int e e) with endpoint expressions
```

`sig` and `def` stay separate: 485 `def`s against 77 `sig`s says most definitions are internal and
unannotated, so separating them costs nothing. `host` may be **attached** to a `sig`, `type` or
`const`, or **detached** inside `provides`. The detached form is the core, and the attached form is
sugar for a host-named module, where there is exactly one realization. That sugar is what keeps
the 931 host declarations from doubling in length.

### 8.3 Sugar, each expanded to the core

| sugar | expands to |
|---|---|
| `(const c v (host "h"))` | `(sig c (int v v) pure)` `(def c v)` plus host `h`: the conditional cell (theories.md §2.2) |
| `(implements T I)` | a view `I → companion(T)` assigning each destructor to its same-named image |
| `(module W (include R C))`, in `W`'s companion | the theory inclusion `R ∪ C ⊆ W` with `self` translated, so `W ≤ R` and `W ≤ C` are **derived**, not declared |
| attached `(host …)` on a declaration | the declaration plus a detached `host` in the enclosing layer |

The `include` row removes a hand-written declaration that exists today. `encoding-hex.oro` states
`(implements io-WriteCloser io-Writer)` because nothing knows `io.WriteCloser` is *defined* as
`interface { Writer; Closer }`. Written as an inclusion, the edge follows from I2, because an
inclusion is a view.

### 8.4 Every existing form and attribute, mapped

| today | new | why |
|---|---|---|
| `(prim n args r kind "t" …)` | `(sig n args r … (host kind "t" …))` | S1 |
| `pure` on a prim | `pure` on the `sig` | purity is Σ, R5 |
| `(where …)`, `(ensures …)` | unchanged, on the `sig` | Σ |
| `(import …)`, `(lib …)`, `(checked …)`, `(data …)`, `jump` | `host` clauses | I |
| `(length N)`, `(length-of N)` | `(ensures (= (len result) N))`, `(ensures (= (len result) (len a)))` | target-files.md §4 defines them as exactly these facts |
| `(type NAME "spelling")` | `(type NAME (host "spelling"))` in its module | theories.md §4 |
| `(implements T I)` | unchanged, or derived by `include` | §8.3 |
| `(provides T M prim…)` | `(provides T M assign…)`, now admitting `def` | §2.2 |
| `(sum S …)` | `(variant S …)` | data.md §5.2 |
| `(values a b)`, type `(array A B)`, result list `(A B)` | `(tuple …)` | data.md §3, §6 |
| `(module P)` header | removed for library files | S4 |
| `(target …)` wrapper | `(target NAME (backend B) (link …))` header | the model's header |
| `(backend B)`, `(link …)` | clauses of `target` | |
| `(int-repr LO HI "s")` | `(repr (int LO HI) (host "s"))` | a realization of a sub-lattice, chosen by containment |
| `(big-repr host\|limbs)`, `(shift-width N)` | `(repr big host\|limbs)`, `(repr shift N)` | realization choices |
| `(max-len N)` | `(fact max-len ((a (array A))) (<= (len a) N))` in the target layer | it is an R2 fact about this model |
| `(array-type "…")`, `(map-type "…")` | `(type (array A) (host "…"))`, `(type (map K V) (host "…"))` | realizations of `lang`'s constructors |
| `(boxed N "s")`, `(builtin-map)` | `repr` clauses | **undocumented until 2026-09-15**; specified in spec/theories.md §5.7–§5.8 |
| `(structural …)` | unchanged, retired layer only | not `lang`'s current set |

Two findings came out of building the table:
- **`boxed` and `builtin-map` are parsed by `emit/target.go` and specified nowhere**, which is the
  shape `split-words` had.
- **`length` is a postcondition under another name.** Moving it into `ensures` depends on
  postconditions.md's open limitation, that an `ensures` on a *pure* primitive is carried only as an
  opaque atom. The sieve's `c[i]` is proven through `length` today. So the move is gated on that
  limitation, and its acceptance test is the sieve's proof surviving unchanged.

### 8.5 Before and after

**A host-named module** — `targets/go/encoding/hex.oro`, which is module `go/encoding/hex`:

```lisp
; before
(target go
  (type io-Writer "io.Writer")
  (type hex-InvalidByteError "hex.InvalidByteError")
  (module go/encoding-hex
    (prim Encode ((dst (buffer (int 0 255))) (src (array (int 0 255))))
          ((buffer (int 0 255)) (int 0 9007199254740990))
          expr "func(dst, src []byte) ([]byte, int) { return dst, hex.Encode(dst, src) }(%s, %s)"
          (where (<= (* 2 (len src)) (len dst)))
          (import "encoding/hex"))
    (prim NewEncoder ((w io-Writer)) io-Writer expr "hex.NewEncoder(%s)" (import "encoding/hex")))
  (module go/encoding-hex/InvalidByteError
    (prim Error ((self hex-InvalidByteError)) string expr "%s.Error()" pure (import "encoding/hex"))))

; after
(use go/io)

(type InvalidByteError (host "hex.InvalidByteError"))
(module InvalidByteError
  (sig Error ((self InvalidByteError)) string pure (host "%s.Error()" (import "encoding/hex"))))

(sig Encode ((dst (buffer (int 0 255))) (src (array (int 0 255))))
            (tuple (buffer (int 0 255)) (int 0 (- (pow 2 53) 2)))
     (where (<= (* 2 (len src)) (len dst)))
     (host "func(dst, src []byte) ([]byte, int) { return dst, hex.Encode(dst, src) }(%s, %s)"
           (import "encoding/hex")))

(sig NewEncoder ((w io.Writer)) io.Writer (host "hex.NewEncoder(%s)" (import "encoding/hex")))
```

Gone: the hand prefixes, the re-declared `io` sorts, `9007199254740990` written as a bare literal,
the flattened path, and the need to guess whether `((buffer …) (int …))` is one type or two.

**Constants and a host alias** — the predeclared types in module `go`, then `unicode/utf8`:

```lisp
; targets/go/go.oro — module go, where go.+ already lives
(type int32 (int (- 0 (pow 2 31)) (- (pow 2 31) 1)))
(type rune int32)                         ; Go's spec: "rune is an alias for int32"

; targets/go/unicode/utf8.oro — module go/unicode/utf8
(const MaxRune 1114111 (host "utf8.MaxRune"))
(sig RuneLen ((r go.rune)) (int -1 4) pure (host "utf8.RuneLen(int32(%s))"))
```

`go.rune` is a **manifest** type, equal to its definiens, and **host-qualified**. It abbreviates a
storage fact and cannot be mistaken for "a Unicode scalar value", which declaration-surface.md §3.2
warned about. Because `MaxRune` has a definiens, `(int 0 utf8.MaxRune)` is a legal endpoint.

**A portable theory with a definitional model**, which removes tally's two binding files:

```lisp
; lib/text/regex.oro — module text/regex; no host clause anywhere
(type Re)
(sig compile ((p string)) Re)
(sig matches ((r Re) (s string)) bool pure)
(sig capture ((r Re) (s string)) string pure)

; lib/text/regex/go.oro
(provides go text/regex
  (use go/regexp as re)
  (type Re re.Regexp)
  (def compile (fn (p) (re.MustCompile p)))
  (def matches (fn (r s) (re.Regexp.MatchString r s)))
  (def capture (fn (r s)
    (let (re.Regexp.FindStringSubmatch r s) (fn (m)
      (if (>= (len m) 2) (m 1) (if (>= (len m) 1) (m 0) "")))))))

; examples/tally/tally.oro
(use text/regex as regex)
… (regex.compile p) …
```

One `main` builds on both hosts. The Java model sits beside the Go one and is checked the same way.
Nothing is lost: the six operations are relocated into two models, where they are **checked against
a theory**, instead of living as an untyped tuple in two programs.

**An interface, by inclusion:**

```lisp
; targets/go/io.oro — module go/io
(type Writer (host "io.Writer"))
(module Writer
  (sig Write ((self Writer) (p (array (int 0 255)))) (tuple int error) (host "%s.Write(%s)")))

(type Closer (host "io.Closer"))
(module Closer
  (sig Close ((self Closer)) error (host "%s.Close()")))

(type WriteCloser (host "io.WriteCloser"))
(module WriteCloser (include Writer Closer))
```

`WriteCloser ≤ Writer` is derived. `Close` becomes reachable on a `WriteCloser` through its companion,
which closes the gap hex-2026-09-14 §6 left open: `Close` on the dumper was unreachable.

### 8.6 What the syntax reserves

- **`(use M with V)`** — instantiation along a named view (C₁₂). The reader accepts the clause and
  the loader refuses it with *"named views are specified in theories-b-or-c.md and not built"*, so
  the word cannot be taken for something else in the meantime.
- **`(view NAME FROM TO …)`**, likewise.
- **`fact` with `trigger`** — R4 (theories.md §6.3). Its acceptance test is moving `seedDivAxioms`
  out of Go.
- **`variant` with type parameters**, `(variant (option A) …)` (data.md §5.3).

Nothing reserved has a meaning until it is built. The reader reserving it is what I5 needs: when it is
built, no program that used the word for something else can exist.

## 9. Build order, each step with a test that can fail

1. **Specify.** A `spec/theories.md` covering §3's pushout, §5's views and §8's grammar, and an ADR
   amending ADR 0011's reason (§2.1). *Test:* none. This is the spec-first rule.
2. **The reader and loader accept the new declaration forms and elaborate them to today's `Target`
   and `Module` structures.** Nothing downstream changes. *Test:* every target and program translated
   mechanically; **every emitted file byte-identical**; the differential and tooling suites green.
3. **Types in theories, nesting, companions and host paths.** *Test:* `encoding/hex` and
   `unicode/utf8` in the new form with no prefixes; `text/template.Template` and
   `html/template.Template` are distinct types; the hand-declaration checker still catches its
   planted mistakes.
4. **`const`, manifest types, and `tuple`/`record`/`variant`** (data.md, whose acceptance test is
   byte-identical emission after respelling). *Test:* `(int 0 utf8.MaxRune)` accepted; a
   wrongly written constant refused by a host check; the result-list ambiguity gone from `TypeName`.
5. **Definitions inside `provides` (`D_T`).** *Test:* tally is one program on two hosts, and its
   output is byte-identical to today's on the sample log and on the suite's `(a)?b` case.
6. **Companions with `include`; `implements` checked as a view.** *Test:* the hand-written
   `(implements io-WriteCloser io-Writer)` deleted and derived; a false edge refused from
   declarations alone.
7. **R4 facts.** *Test:* `seedDivAxioms` and the square bound moved into data, with byte-identical
   output and the containment harness failing when a moved rule is weakened.
8. **`length` into `ensures`**, gated on pure-call postconditions. *Test:* the sieve's `c[i]` still
   proven.

Named views, sharing and typing the static level wait for their triggers (§4.3, §6.1, §7).

## 10. What is not claimed

- **Nothing here is measured** except §0's counts. The theorems are proofs about the model. §9 is
  where the model meets the code.
- **§8's syntax is a proposal.** It is derived from S1–S7, and S1–S7 are choices. The one with the
  largest effect on how programs read is S4, removing the module header, and it deserves a look at
  real files before it is decided.
- **I4 assumes conformance.** A model that realizes a theory wrongly builds and gives a wrong answer.
  That is `split-words`, and a view check proves types, not meaning. The conformance suite remains
  the only evidence of meaning.
- **§2.1's identification rests on one claim that should be checked against the code**: that a
  program's resolution against a target, and a pushout along the ambient view, produce the same
  qualified names in every case, including layers, `provides` and the language's injected names. If a
  case differs, I5 fails there, and step 2's byte-identical test is where it would show.
