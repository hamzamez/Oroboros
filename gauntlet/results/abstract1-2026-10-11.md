# abstract1 — the reader builds trees of abstract Oroboros

2026-10-11. Step 1 of [spec/abstract.md](../../docs/spec/abstract.md) §13, decided by
[ADR 0050](../../docs/decisions/0050-the-abstract-syntax-fits-the-semantics.md), for the computation's
terms. hamza: *"go ahead for step 1"*.

## What was built

The reader is now **lex → datum → μ → D**. All of it is in `core/`:

| file | what it is |
|---|---|
| `abs.go` | Σ's trees as Go types: the sorts **Expr ⊆ Tail** and Pat. The primitive operators are `Var`, `Lit`, `Lam`, `Apply`, `Index`, `Let`, `Case`, `Loop`, `Local`, `BuildMap` and `The`. The derived ones are `If`, `And`, `Or`, `Not`, `Cond`, `Seq` and `Monad`. The tails that are not expressions are `Again`, `TLet`, `TSeq`, `TMonad` and `TRedex`. |
| `mu.go` | μ, today's notation read into trees. It is called by the reader on each list once its elements are read, so the tree is built bottom-up in exactly the order today's reader desugared, and every error is reported where it was. |
| `desugar.go` | D, trees into today's core Λ⁺. It is a homomorphism, with one clause per operator, memoized per node. |

**The tail rule (W3, ADR 0015) is a sort.** `again` builds an `*Again`, which is a Tail and not an
Expr, and so are the bindings whose body is one.
- **Demotion.** A constructor that needs an Expr where it receives a Tail *demotes* it: the `again`
  becomes the free name `again` applied, and the tree is marked stray.
- **Refusal.** A loop refuses a stray clause body. Anywhere else a stray `again` stays the unbound
  name it is, refused later, as today.
- **The walkers are gone.** `checkClauseBody` and `noAgain` enforced the rule on terms and are
  deleted. So are `readLet`, `readLoop`, `readMatch`, `readLocal`, `readScope`, `clauseChain` and the
  `#tuple-let` mark, which existed only so the walker could tell a tuple pattern from a higher-order
  call. In the tree they are different operators.

**μ checks on images.** Every check reads D of an element's tree, which is the term today's reader
inspected at that point. So every refusal and every message is unchanged, and μ is new only in what it
returns.

## What the build corrected in the specification

Four findings, recorded in abstract.md:

1. **μ cannot produce `index` from today's notation.** abstract.md §10 mapped `(f a)` "with f a table
   or map" to index. Whether `(t i)` indexes data is a fact about t's *value*, known after reduction;
   the notation does not mark it. So μ maps every `(f a)` to application. `Index` is a node only a
   rendering that marks data application builds, and D reads it as application.
2. **D carries claims; it is not defined after ε.** §6 had D: A_C → Λ⁺, after erasure. But `the` is
   read by the checker (`emit.KeepSortAscriptions`) and erased at emission. So D maps a claim to
   today's mark, and ε happens where the pipeline erases marks (ADR 0037's pattern). Theorem E is
   unchanged, since every mark is erased before a file is printed.
3. **W3 as written is stricter than today on one shape.** A λ of one parameter applied to one
   argument, written by hand, with a tail body: `((fn (x) (again x)) e)`. Today's walker accepted it,
   because it could not tell it from the redex a `let` reads as, and abstract.md's "no λ lies between
   them" refuses it. Step 1 keeps it accepted, as the node `TRedex`. Refusing it is a decision for
   hamza; no program in the corpus writes one.
4. **Lists in binder positions are read as lists.** Today's reader desugared every list as a term
   before its form inspected it. So a match's scrutinee list headed by a reserved word,
   `(match (not b) …)`, was rewritten first and gave four scrutinees, `if b false true`. μ validates
   on the image, so every refusal is unchanged, and it takes the elements as written. That is the one
   shape whose meaning changes, and nothing in the corpus or the 1,032 snippets writes it.

## What failed first

- **`again` was not dispatched.** The first run built no `*Again` at all, so the corpus matched (it has
  no refused program) and the snippet diff showed every W3 refusal missing. The snippet oracle caught
  it; the corpus alone would not have.
- **The inventory test** scans the reader's files for the words it dispatches on, and the dispatch moved
  to `mu.go`. The file was added to `inventorySources`.

## Not built

- **Declarations** (`def`, `sig`, `variant`, `use`, `export`, `provides`) are still read as terms by
  `toForm`. They are step 1b, with decision 3's merge of `sig` into `def` and target files' host
  declarations as definitions with a host body.
- **`assign`**: whether `(set c v)` writes a cell needs the scope above it, which a bottom-up μ does not
  have. It is classified today by the cell translation in `Load`.
- **A `case` pattern** and `try`'s and `expect`'s, which name constructors and are resolved in `Load`,
  are kept in the tree as written.
- **Claims beyond `the`, formulas, modes**: step 3 (ε and 𝒪) and the surface.
