# abstract1c — a host declaration is a definition with a host body

2026-10-11. Step 1c of [spec/abstract.md](../../docs/spec/abstract.md) §13, ADR 0051 D4. hamza: *"go
ahead with 1c"*. It follows [abstract1](abstract1-2026-10-11.md) and
[abstract1b](abstract1b-2026-10-11.md).

## What was built

`emit/hostdef.go` reads every declaration in a target file, a `sig` or a `const`, into a **definition
with a host body**: a `DefDecl` whose value is a λ carrying the claim, and whose `Host` is the
template's kind and text, the host clauses (`import`, `lib`, `checked`, `jump`) and the markers
(`pure`, `index`, `variadic`). `core.HostSig`, D for host definitions, writes today's `sig` back.

The target loader's `declare` now takes every primitive from that round trip:
1. `parseSig` reads the declaration as it always did, which reports any refusal where it was;
2. `hostDef` reads the declaration into its tree;
3. `parseSig` reads the primitive off the `sig` that D writes back.

**Usage is a mode, not a set** (ADR 0050, decision 2), now in the trees:

| written | tree |
|---|---|
| `(p (buffer V))` | `p ∈ Seq(V)`, mode `linear` |
| `(c (cell T))` | `c ∈ T`, mode `inout` (ADR 0048's value-result) |
| `(a (array (cell T)))` on a variadic declaration's list | `a ∈ Seq(T)`, mode `inout` on each trailing argument (ADR 0046) |
| `(buffer V)` as the result, or a component of a tuple result | the result binder's mode, per component (ADR 0051, D3: its pattern may be a tuple) |

`core.TermTree` reads a target file's set expressions, claims and host clauses as trees. A target file
is read by `core.ReadAll`, whose reader has already made `(tuple …)` a Church tuple, so `TermTree`
reads that λ back as Σ₀'s product former, and D's clause for `tuple` builds the same term.

All eight are caught.

## What failed first

- **`(tuple)` is a λ by the time a target file is read.** The first run refused `bufio.Err`'s unit
  result as "not a set expression": `core.ReadAll` desugars `(tuple)` into `(fn (#k) (#k))`.
  `TermTree` now reads a Church tuple back as the product former.
- **Thirteen tuple results lost their buffer's mode.** The mode was separated on the term, where a
  tuple is that λ, so `(tuple (buffer V) int (result …))` was not seen as a tuple. The round trip still
  held, since nothing was changed, and the test's count of a former left in a set caught it. The modes
  are now separated on trees, in both directions.
- **A nil dereference** in `resultModes` on a result that is not an application: the type assertion was
  read before it was checked.

## Not built

- **The trees are not kept on the `Target`.** Each one is built, checked by its round trip, and
  discarded, as the reader's are; a consumer (step 3's obligations, a rendering, the translator) will
  keep them. Keeping them on `Prim` would make two layers' identical declarations unequal by position.
- **Target files' other forms** (`type`, `repr`, `implements`, `fact`, `structural`, …), which are
  Σ_T, the model's data, unchanged by abstract.md.
- **The tooling step's Node pin** (abstract1), still to re-measure and re-pin.
