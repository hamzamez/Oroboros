# `alloc` of a buffer copies: every backend returned the buffer itself

2026-09-25. Found while lowering `alloc` to the IR (irstep1-2026-09-25 §4), fixed here in the term
backends (JavaScript, Java, x86, and the Go term backend behind `-printer terms`). The IR's Go
printer never had it.

## 1. The meaning

`(alloc t)` for a t that is not a rule is **the table of t's contents at that point**. By definition
(tables.md §2):

    (alloc t)  =  (alloc (table (len t) (fn (i) (t i))))

For an immutable t this equals t (η-tab, ir.md L12), so returning t is an optimisation. It holds
exactly when t is immutable. For a live buffer the copy is the meaning: a later store must not show
through. `emit/linearity.go` already said so ("alloc copies the contents, so it is an ordinary read
and must come first"). The backends did not: each returned the argument itself for anything that
was not a rule, and the Go backend's comment called that avoiding "a copy nobody asked for".

## 2. The witness, and what it showed

`gauntlet/differential/cases/alloc-copies.oro` stores 7, allocates, stores 9, and reads the
allocated table. The answer is 7:

| | answer |
|---|---|
| JavaScript, shipped backend | **9 9** |
| JavaScript, fixed | 7 7 |
| every target, fixed | 7 7 (the differential suite) |

Under the shipped code the runner stops at its first target, Go through `-printer terms`, which does
not compile this program at all ("declared and not used: b22": an unused product component). That
is a second defect of the retired Go term backend, recorded here and not fixed, since `gen` no longer
uses it.

## 3. The fix

- **The meaning, once:** `emit.allocMeaning` builds the definition's right side as a term, binding t
  by a `let` so it sits outside both new binders and needs no de Bruijn shift. JavaScript, x86 and the
  Go term backend emit it through the rule path they already had.
- **Java** spells it `t.clone()`, which is exactly the table of an array's contents and keeps its
  element type. A fill loop re-infers the type from its body and gave `long[]` for a `byte[]`, which
  javac refused.
- **A literal graph** keeps η, since it is a fresh immutable value and never a buffer.
- The term backends cannot tell a buffer from an immutable table reliably, so they copy every other
  non-rule `alloc`. **No program in the corpus writes one**, so emission is byte-identical except for
  the new case. The IR's printers know from the type and keep η where L12 holds.

The case needs `; checked: windows`: the elements of `(alloc t)` get no bound, so the value
`win/fmt.print-int` prints is unbounded. Element bounds through `alloc` are on the "deliberately not
next" list (bounds-2026-09-24).

## 4. Gates

- The differential suite: 45 cases (44 and the new one) agree on four targets.
- Emission: byte-identical for every existing program; the new case adds four outcomes.
- The `ir` step: 246 of 246 emitted programs lowered and verified.
