# Android: the Java backend on ART, and a class file with no frames

2026-10-05. The measurements behind [android-research.md](../../docs/android-research.md). hamza
named the primary targets: Go, Windows, Android and the browser ([ADR 0039](../../docs/decisions/0039-the-targets-are-go-windows-android-and-the-browser.md)).
Android raises the question of whether the language should still be compiled to Java source, or to
bytecode. Every Java figure in this repository was measured on HotSpot, and Android runs ART.

**The toolchain, all on this machine:**
- Android SDK build-tools 36.1.0, with `d8.jar` and `dexdump`;
- the platform `android-36` (`android.jar`);
- Android Studio's JDK 21 (`javac`, `java`);
- the emulator, with the AVD `Medium_Phone_API_36.0` (Android 16, x86-64), run headless.

Programs are run on ART with `dalvikvm64 -cp X.dex Main`, which needs no APK.

## 1. The Java backend's output runs on ART unchanged

| step | result |
|---|---|
| `javac --release 17` on the 25 generated Java files of the gauntlet (`gauntlet/java/gen`) | compiles; 1.2 s |
| `d8 --min-api 26` on the 26 class files | one `classes.dex`, 34.6 KB, **35 classes**; 1.4 s |
| `experiments/errors/chain.oro` through `build -target=java`, `d8`, `dalvikvm64` | `-1` with the file missing, `101` with it present: the same as Go, JavaScript and HotSpot |
| `examples/io/roundtrip.oro`, likewise | writes, reads back and prints, exit 0 |

Records are desugared by D8. `java.nio.file.Files` needs API 26, hence `--min-api 26`.

**The 9 extra classes are the Java source's detours.** The emitted corpus holds **50 lambdas applied
at once** (29 `BiFunction`, 18 `Consumer`, 3 `Function`), in 11 of 63 emitted Java files. They come
from host templates, which need a statement or a `throw` where Java source allows only an expression.
Two examples:
- `io.print`'s write, which is a statement;
- `big-fit`'s overflow check, which ends in a `throw`. Java has no throw expression.

D8 turns each into a synthetic class (`Main$$ExternalSyntheticLambda0`, …). In bytecode, a sequence
of statements and `athrow` are ordinary instructions, so none of this would exist.

## 2. The gauntlet on ART

`gauntlet/java/One.java` runs one case per process; the whole Java gauntlet was compiled, dexed
(`d8 --release`) and run under `dalvikvm64` in the emulator. Each figure is the best of 9 runs after
a 2-second warm-up, in ns per call; two passes, interleaved.

| case | hand-written | generated | generated / hand (pass 1, pass 2) |
|---|---:|---:|---|
| dot, n = 65536 | 36,171 / 36,712 | 34,821 / 36,071 | 0.96, 0.98 |
| dot, n = 1024 | 544 / 504 | 530 / 647 | 0.97, 1.28 |
| centroid | 36,048 / 33,344 | 32,722 / 32,287 | 0.91, 0.97 |
| search, late | 33,111 / 36,120 | 32,082 / 33,640 | 0.97, 0.93 |
| **stencil** | 211,374 / 216,300 | 247,961 / 258,403 | **1.17, 1.19** |
| word count | 7.65 M / 10.08 M | 7.95 M / 7.59 M | 1.04, 0.75 |
| sum | 41,065 / 31,547 | 49,535 / 31,856 | 1.21, 1.01 |
| into | 31,531 / 31,406 | 31,526 / 34,484 | 1.00, 1.10 |
| JSON tree | 18,584 / 18,957 | 8,898 / 9,009 | 0.48, 0.48 |
| JSON tokens | 16,056 / 15,304 | 11,879 / 10,123 | 0.74, 0.66 |

- **Parity holds on ART, with one exception, and the emulator is noisy.** Pairs whose passes
  disagree (`dot` at 1024, `sum`, word count) are within noise. The stencil is not: 1.17 and 1.19,
  both passes, above the 15% floor. HotSpot showed no stencil residue (gauntlet-2026-09-29), so this
  is ART's, and is named in research §6 (M6).
- **The JSON programs are about twice as fast generated.** The generated tree reads `short[]`, the
  element width its range gives, and the hand-written reference reads `long[]`. On HotSpot the tree
  was 0.78×.
- An emulator on a laptop is not a phone. These ratios say where to look, not what a device does.

## 3. A class file with no StackMapTable: D8 takes it, ART runs it

Since class-file version 50, the JVM verifies by **type checking** against a `StackMapTable` the
compiler supplies, and below 50 by **type inference** (JVM Specification §4.10). Computing stack map
frames is the hard part of emitting bytecode: it needs the least upper bound of classes, so the
emitter has to load the class hierarchy (ASM's `COMPUTE_FRAMES` does exactly that). DEX has no stack
maps; ART verifies DEX by inference.

`experiments/android/cw.go` (103 lines) writes a class file by hand: version 50, one method with a
loop and a call, **no `StackMapTable`**.

| | result |
|---|---|
| HotSpot (JDK 21) | runs, prints `45` (version 50 falls back to the inference verifier) |
| `d8 --min-api 26` | accepts it: 776-byte `classes.dex` |
| ART (`dalvikvm64`) | runs, prints `45` |

So a class-file printer for Android needs a constant pool, the instructions, `max_stack` and
`max_locals`, and **no frames**. The same file runs on a desktop JVM.
