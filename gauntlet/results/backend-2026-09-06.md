# The backend is the target's, and the emitter is a function

2026-09-06. [assessment-2026-09-06](../../docs/assessment-2026-09-06.md)'s item 1.

Two bugs, both silent, both found by building rather than reading. The first was
predicted by [target-system.md §1.1](../../docs/spec/target-system.md) and had
**two live instances**, one of which had been in the repository since August. The
second was found while verifying the fix for the first, and it is worse.

---

## 1. The backend was chosen by the flag string

```go
switch target {          // ← the -target FLAG, not the target's declared name
case "js":      …
case "java":    …
case "windows": …
default:        code, err = emit.Func(…)   // the GO backend
}
```

Three sites — one in `cmd/build`, two in `cmd/gen`. Any target whose *flag name*
was not one of four strings was compiled by the **Go** backend, silently.

**Instance 1, constructed.** A generated Windows target in a directory called
`wintest` loaded correctly, reported `tg.Name == "windows"`, and emitted Go
control flow with x86 templates spliced into it. The first sign of it was MASM
saying `invalid character in file`
([win32-2026-09-06 §6](win32-2026-09-06.md)).

**Instance 2, already in the tree.** `targets/portable-js.oro` — preserved since
the native targets replaced it, and the target the gauntlet's seven programs are
written against. Before the fix:

```
$ go run ./cmd/gen examples/dot.oro portable-js /tmp/out
// Code generated by oroboros. DO NOT EDIT.

package gauntlet

func GenDot(p /*vec-f64?*/, q /*vec-f64?*/) /*f64?*/ {
```

**Go source, from a JavaScript target, with unknown types**, and no diagnostic.
After the fix it emits JavaScript. `portable-java` was the same.

That second instance is why this became a test rather than a note: **nothing had
ever run `cmd/gen` against that target**, so a latent miscompilation sat in the
tree looking exactly like a working one. A path nothing runs is a path nothing
checks — the third time that sentence has been earned here, after the `-checked`
rebuild hid two bugs the same way.

### The fix: `(backend NAME)`, and no default

`T = (B, Δ)` made explicit. `Backends` is the closed set
`{go, js, java, x86-64}` — closed because a backend is compiler code, the same
reason `(structural …)` is closed. A target declares which one compiles it;
absent a declaration the target's own **name** is used *when the name is a
backend*, so `(target go …)` need not also write `(backend go)`; and when
neither resolves it is an **error**.

**There is no default, because a wrong default here is a silent
miscompilation.** The refusal names the fix and lists the set, since someone
seeing it is writing a target and has no other way to learn the set is closed.

**Declaring none stays legitimate**, and that turned out to matter. A target is a
capability set first, and one that only parameterises the *normal form*
(ADR 0002) has nothing to emit with: `targets/blas.oro` declares
`cblas_ddot(%s.n, %s, 1, %s, 1)` — which is **C** — and exists to show reduction
stopping at a different point under `cmd/oro`. Under the old switch,
`cmd/gen … blas out.go` would have written Go containing a C call. What is
refused now is emitting from such a target, not having one.

`(backend x86-64)` on `targets/windows/`, deliberately not `windows`: the
operating system and the instruction set are different things, and
target-system.md §5.2 wants them separable — the same Win32 API over an arm64
backend is one member of the same family.

## 2. AND THE EMITTER WAS NOT A FUNCTION OF ITS INPUT

Found while checking that the fix changed no emitted file. It changed two, in a
way that had nothing to do with the fix — so the sweep was run twice.

```
$ for i in 1..6; do gen examples/big/render.oro js; grep -c '.concat(' out; done
2 2 2 2 0 0
```

**Six identical runs of the same compiler over the same source produced two
different programs.** Five lookups in `emit/target.go` — `findBySpelling`,
`findOpBySpelling`, `findEq`, `findAlloc`, `ShiftNames` — searched `tg.Prims`,
which is a Go map, and returned the **first match**. Go randomises map iteration
order on purpose, so when a target declared one operation more than once the
winner was decided per run.

`targets/js/` declares `concat` at arity 2 **four** times: the language's
injected `concat`, `js.concat` (`%s + %s`), `js/String.concat` and
`js/Array.concat`.

> Every *"byte-identical across N programs × 4 targets"* claim in this directory
> assumes this cannot happen, and one of them was written while it was
> happening.

### The blast radius, measured rather than guessed

Every spelling every lookup searches for, across the four native targets:

| target | ties | genuinely divergent |
|---|---:|---|
| go | 11 | **0** |
| js | 11 | **1** — `concat` |
| java | 11 | **1** — `concat` |
| windows | 0 | 0 |

**Ten of the eleven ties on each host are harmless**, and the reason is
structural: they are the *injected* core name against the target's own —
`+` against `go.+` — and `addCore` injects a **copy**, so both entries carry the
same template and either winner emits the same text. The coin was flipped on
every arithmetic operator in every program and never landed differently.

The divergent case is `concat`, where `js.concat` is `%s + %s` and
`js/String.concat` is `%s.concat(%s)`. **The only program in the corpus that
uses `concat` is `examples/big/render.oro`**, so exactly one claim was taken on a
non-deterministic emitter: [render-2026-09-04](render-2026-09-04.md)'s. Its
conclusion is unaffected — both forms are correct JavaScript and the differential
suite ran both — but the sweep it cites should be read as covering the 60
pre-existing files, which it does.

### The fix is an ordering, and it is principled rather than merely stable

One helper, `spelled(want)`, returning candidates **least-qualified first, then
by name**. That is not just deterministic:

> A name in the target's **core module** is the operation. The same name in a
> **sub-module** is a host API binding that happens to share it.

which is [overloading.md §3](../../docs/overloading.md)'s distinction between a
concept name and a method, applied. `js.concat` beats `js/String.concat` for that
reason and not because `.` sorts before `/`.

A target declaring one operation twice is arguably ambiguous and could be
refused. It is not, because both spellings are correct and refusing would make
`targets/js/` illegal for binding the String method it binds.

## 3. Cost

| | |
|---|---|
| emitted files across 4 targets | **62 of 63 byte-identical** with `HEAD` |
| the one that changed | `render__js.mjs`, which `HEAD` produced at random |
| two consecutive full sweeps | **identical**, which they were not before |
| differential suite | 27 cases, four targets, green |
| unit tests, `go vet` | green |

Three tests, and each fails against its bug: the backend resolves per target and
`blas`/`tutorial` are refused with a message naming the fix; and the spelling
lookup puts the core module first and gives the same answer over twenty reloads.

## 4. What it leaves

`(backend NAME)` is `B` of `(B, Δ)` written down, which is the prerequisite
[target-system.md §7](../../docs/spec/target-system.md) needs for a target search
path and §5 needs for a family. Neither is built. What is closed is the specific
hazard that made both worse than they looked: **you can now name a target
whatever you like and be told, rather than miscompiled.**
