(wrapping is `mod 2ⁿ` on ℤ; `& | ⊕ ~ << >>` are ℤ's own) and
[ADR 0083](../../docs/decisions/0083-a-representation-is-an-abstraction-function-chosen-by-place.md) (a
representation is an abstraction function, chosen by place), built together, program first:
`examples/hash/fnv.oro` and `examples/hash/crc32.oro`, Go's `hash/fnv` and `hash/crc32` over a file.
hamza: "agree to all recommendations. Go ahead with the ADR and the build."

## 2. Measured

**Correctness**: on a 1 MB and a 128 MB file, every build prints what Go's `hash/fnv` and `hash/crc32`
print (`d719c8a0`, `ce39f5e253631a40`, `31ae53a8` on the first): Go, the JVM and JavaScript (CRC-32;
FNV-1a 64 is refused there, §4). The differential suite has seven new cases, each against Python:
`bits`, `bits-edges`, `fnv32`, `fnv64`, `fnv64-fold`, `bytes-table`, and all agree on every target that
runs them.

**Speed against hand-written code** (`experiments/hashbench/`): 128 MB of random bytes, each program end
to end (reading the file included), serial and interleaved, best of five. The references are what a
person writes: Go's and Java's loops as `hash/fnv` writes them and a table CRC as `crc32.simpleUpdate`
does, JavaScript's table CRC with `>>> 0` and an `Int32Array`.

| | generated | hand-written | ratio |
|---|---:|---:|---:|
| Go, FNV-1a 32 + 64 | 346.0 ms | 309.8 ms | 1.12 (1.08 in the first run) |
| Go, CRC-32 | 311.9 ms | 310.5 ms | 1.00 |
| JVM, FNV-1a 32 + 64 | 488.0 ms | 452.2 ms | 1.08 |
| JVM, CRC-32 | 454.5 ms | 451.1 ms | 1.01 |
| JavaScript, CRC-32 | 345.4 ms | 346.7 ms | 1.00 (2.72 before stage 5's fixes) |
| Go's library, all three hashes | 321.2 ms | | |

Everything is inside the ~15% noise floor. FNV is above 1 on both runs and both hosts, and the generated
Go shows why: FNV-1a 32 holds h in an `int` and masks each step with `& 4294967295`, where the hand-written
loop holds a `uint32`. A 32-bit scalar representation (ADR 0083 item 2's register rule) would remove it,
and is not built.

**JavaScript's CRC-32 was 2.72×**, for two reasons stage 5 fixed:

- `crc >> 8` printed `Math.floor(crc / 2 ** Math.min(8, 64))`, a float division per byte. With the
  operand proven in U₃₂ and the count below 32, `crc >>> 8` is exact. Realizations are now chosen by
  the operands' facts as well as the result's.
- The table was an `Array` of integers up to 2³², which V8 holds as doubles. JavaScript now declares
  typed arrays as its element representations, narrowest first (`Uint8Array` … `Int32Array`).

**Emission that moved, measured before it was accepted:**

- *The JVM's bytes* (stage 4): seven programs and two gauntlet files go from `short[]` to `byte[]`.
  JsonTree's generated parser runs 4.96–4.98 µs against 4.97–5.23. JsonTok's runs alone at 8.06 µs in its
  fast window, before and after, and 3.5% slower in its steady state (23.3 against 22.5 µs), the `& 0xFF`
  per read, under the noise floor. That steady state is the generated tokenizer degrading from 8 to
  22.5 µs mid-run, the same before this work: a task of its own.
- *JavaScript's typed arrays* (stage 5): JsonTok's generated tokenizer runs 7.99–8.11 µs against
  8.15–8.20, and JsonTree's 8.45–8.55 against 8.62–8.70, each case in its own process.

**Counts**: 2,607 of 2,664 integer operations and 388 of 411 loops proven, up from 2,103 of 2,148 and
353 of 376 with the new cases and programs. Every existing program's emission was byte-identical through
stages 1–3. Stage 4 changed the JVM's byte tables and stage 5 JavaScript's integer tables, each change
reviewed and timed.

## 3. What failed first

Each was found by a test or a differential case, and each is now a test.

- **The realization walk returned from the region** on its first match, so every later `⊕` in a block
  kept the S₃₂ realization; JavaScript's `bits` case was off by 2³².
- **`-${a}` printed `--5`** on a negative literal, a JavaScript decrement and a syntax error.
- **Java masks an `int`'s shift count by 31**: the language's `>>` widens its operand to `long` first.
- **`SelectShifts` found the language's own `>>` and `&`** by spelling and changed the emitted shift of
  limb programs on x86 and Java (correct, not byte-identical). The language's names are now skipped.
- **JavaScript's word is symmetric**: `~(2⁵³−1)` is −2⁵³, outside it. I had claimed the Boolean
  operations never leave the word; that holds for an asymmetric word only. Every new operation is now
  decided like `+`. `bits-edges` found it.
- **A target template naming its parameters out of order was filled in order.** The JVM's
  `(${b} >= 64 ? 0L : ${a} >>> ${b})` printed with a and b swapped. Such a template now gets indexed
  holes, `%[2]s`; every in-order template is unchanged.
- **An unsigned value boxed into a statement's argument** changed the statement's value, which is its
  first argument. Boxing moved to the printer, where ADR 0083 puts a move between representations.
- **`fnv32`'s data could not see a missing `& 0xFF`**: its table is a rule, which reduction inlines into
  the loop, so no `byte[]` existed. `bytes-table` stores its bytes and fails with the mask removed.
- **The refinement layer could bound neither `(h >> 4k) % 16` nor `(crc ⊕ b) & 255`**: a remainder of a
  non-linear dividend and the language's `&` were outside its fragment, so F6–F9's facts concluded
  nothing. Both are now atoms.
- **The program, not the compiler**: `table` is a language name; a unary `-` on a non-linear term is no
  primitive (`0 - x`); a `case` whose arms jump is no tail inside that block. Plan item 8, an `again`
  after a nested loop's join point, made CRC's table unroll its eight steps.
- **Before I measured, I asserted a fact about Theorem D**: widths-research.md said inferring a table's
  element set waited for a program, but ir.md §4.3 had built it. ADR 0083 item 5 was corrected before the
  build.

## 4. What is not built

- **JavaScript's unsigned word** (the split pair, u64repr-2026-09-22), so FNV-1a 64 is refused on
  JavaScript, and MASM's, so it is refused on windows (ir/llvm will realize it). These are 57 of the
  corpus's unproven operations.
- **The Boolean operations above the word**: a bignum operand or result is refused.
- **A 32-bit scalar representation** (§2's FNV mask) and **LLVM's widths**, with `ir/llvm`.
- **ADR 0083's re-declaration of the existing mechanisms** (word, unsigned word, limbs, bignum) as (H, d)
  data. The new representations are declared that way; the old ones are still separate code.
- **On windows**, `>>` takes a count proven at most 63, which x86 masks; and fusion above JavaScript's
  width of 32 bits.

## 5. Cost

Six commits. The compiler grew by about 1,430 lines (`core`, `emit`, `ir`, `cmd`, tests included), and
target files, libraries, programs and cases by about 300. The language's own code (`examples/hash`) is
about 120 lines. The balance this project measures ran the usual way: the compiler grew faster than the
code written in it.
