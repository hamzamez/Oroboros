# Bitwise semantics across four hosts, 2026-08-19

What the hosts actually do, measured rather than read off specifications — because
[ADR 0008](../../docs/decisions/0008-measurement-over-principle.md) exists and because the first
baseline run refuted four documentation-derived inferences at once.

The x86 column was produced **by our own compiler**: `targets/windows/x64.oro` already declares
`x64.shl`, so measuring it is a six-line Oroboros program.

## Three results

**1. AND, OR, XOR and NOT agree exactly on all four hosts, inside `[−2³¹, 2³¹−1]`.**

The boundary was measured rather than assumed. `2147483647 & 1` and `-2147483648 | -1` agree
everywhere; `2147483648 | 1` and `3000000000 | 0` do not. So the portable window is exactly
signed 32 bits, and it is JavaScript's `ToInt32` that sets it.

`~5 = −6` on all four confirms the 2-adic identity `not x = −x − 1`, which is what makes these
operations width-free in the first place ([bitwise.md §3.1](../../docs/spec/bitwise.md)).

**2. JavaScript truncates to 32 bits, silently.** `(1<<40) | 0` is `0`. There is no error and no
warning. `targets/js/builtin.oro` does note the coercion in a comment, so this is not undocumented
— but the comment carries no numbers, and nothing in the pipeline checks. The comment has been
given the measurement.

**3. Shift counts disagree three ways at four hosts.** `1 << 64` is:

- **0** on Go — the specification says a count at or above the width yields zero;
- **1** on Java — JLS §15.19 masks the count by 63;
- **1** on x86 — `shl` masks by 63 in hardware;
- **1** on JavaScript — for an unrelated reason: ECMAScript masks by 31, so it computed `1 << 0`.

Two hosts arrive at the same answer by different rules and a third disagrees outright. Any portable
shift has to constrain the count, and `0 ≤ n < 32` is a conjunction of linear inequalities —
**inside** the fragment `emit/linear.go` already decides.

## What was not measured

Cost. This run establishes *semantics*, not speed. The three measurements that would decide whether
to build anything are listed in [bitwise.md §6](../../docs/spec/bitwise.md): a bit-set sieve
against a byte sieve, FNV-1a and xorshift32 generated against hand-written, and whether `shl`'s
extra truncation on the 64-bit hosts is free.

## How to reproduce

Go, Java and JavaScript: the three programs in this result's commit message, or any equivalent —
the values are small enough to retype. x86:

```lisp
(use x64)
(use win/fmt)
(export main)
(def main (fn ()
  (seq (fmt.print-int (x64.shl 1 32))
       (seq (fmt.print-int (x64.shl 1 64))
            (fmt.print-int (x64.shl 1 65))))))
```

```bash
go run ./cmd/build -target=windows -o shift.exe shift.oro && ./shift.exe
```
