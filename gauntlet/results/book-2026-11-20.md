## What failed first, and was fixed (the book's findings 95–99)

Writing chapter 11 found that a claim on a record was not read as one:
1. **`p ∈ Point = record { … }` then `p.x` was refused**, the ascription hiding the record from the
   projection. And **`ink ∈ 0..255` given 300 compiled and printed 300**: a record's claim reached no
   part. A claim on a record is now split into its parts (`splitRecordClaim`, by e ∈ Π S_l iff
   e.l ∈ S_l), each range a decided obligation.
2. **The missing-label refusal printed the core's terms.** It is now X2 naming the label, X3 for an
   extra one, and a record set and its forms print as J writes them (`ShowSet`, `ShowTerm`).
3. **A record payload was refused as "a range"**; now as a payload of several parts, not built.
4. **`==` on records was refused in the lowering's words**; now as integer equality only.
5. **`set Node = record { next ∈ Node }` was accepted unused** and refused at its first use as
   "no set"; now refused where it is defined.

Writing chapter 18 found two more:
1. **A claim through an import, `box ∈ windef.RECT = …`, handed to PtInRect, was refused in the
   lowering, at HEAD too.** A body's claim spelled its set by the import's alias, which nothing
   resolved, so no rule read it as a record. Ascriptions in bodies are now resolved through the
   module's imports, as signatures were.
2. **A literal C string holding U+0000 was refused as "outside the decided fragment"**, though ν
   decides a literal exactly. Now: false at this call, and after how many bytes.

## What failed first in the work itself

- **I overwrote `docs/book/code/loop/digits.oro`**, chapter 12's §12.4 example, with a new one of
  the same name, without listing the directory first. The memory note says to. The book's check
  caught it; the file was restored from git, and mine renamed.
- **`git stash` held every uncommitted change**, the renumbering included, while I compared with
  HEAD. Everything came back, and the comparison was redone in a worktree, as CLAUDE.md's list of
  method errors says.
- **An example named `nul.oro` could not be committed**: `NUL` is a device name on Windows, so git
  could not index the file, and the check's book step, which reads git's list of chapters, did
  not see the two new chapters until they were staged. The file is `cstring.oro`.
- **The record claim's rule, written inside `normalizeStep`, overflowed Go's stack** on chapter 2's
  Y combinator. A larger frame times the recursion the fuel allows passed 1 GB before the fuel ran
  out. The rule moved into a function of its own, as `claimSet` had for the same reason, and its
  comment says so.
- **Chapter 13's finding 66 looked fixed and was not**: a table of tuples written as a list worked
  read at a constant index, which folds away, and fails at an unknown one.
- **A rule and a pin built, then withdrawn**: the record claim's case in the eraser
  (`recerase.go`) was never reached once the reducer split the claim, and `claimSet`'s record
  case was never reached at all. Both came out.
