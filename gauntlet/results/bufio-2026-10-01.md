# `bufio`, program first: a line tool, and what it demanded

2026-10-01. Plan item 2 of [assessment-2026-09-28](../../docs/assessment-2026-09-28.md), deferred
three times. The algebra first; then a tool written in the language,
[examples/lines/lines.oro](../../examples/lines/lines.oro), declaring only what it calls. The program
asked for four things of the compiler, and looking at the fourth found two faults that predate it,
one of them a wrong answer on every target.

## 1. The algebra

B = [0, 255], LF = 10, CR = 13.

**The lines of a stream.** B\* is free and LF is one letter, so every x ∈ B\* factors uniquely as

    x = u₀ LF u₁ LF … LF u_k,     no LF in any uᵢ,

with k the number of LFs. The line split is λ(x) = (c(u₀), …, c(u_{k−1})), followed by c(u_k) when
u_k ≠ ε, where c drops one trailing CR. So |λ(x)| = k + [u_k ≠ ε]: a final LF ends a line and does not
begin one. λ is not injective; it forgets a CR before an LF and whether the last line was ended.

**A Scanner is a cursor into λ(x)**, read once, forward. `Scan` advances it and answers whether a
token is there; `Text` is the token under it. `while Scan() { … Text() … }` is the fold of its body
over λ(x), driven by the host, in constant space. `Scan` is false exactly when the tokens ran out or
reading failed, and `Err` tells which.

**The bound.** A token is under `MaxScanTokenSize` = 65,536 bytes: a longer line fills the buffer
before its LF is seen, and the scan stops with `ErrTooLong`. That holds of every Scanner a program
can hold as long as `Scanner.Buffer` is not declared.

**A Writer is a monoid action made lazy**: writes w₁ … wₙ and then `Flush` put w₁·…·wₙ on the
underlying writer. Its error is sticky, so `Flush` reports the first failure.

**Nothing in the package is pure.** `Scan` moves the cursor; `Text` and `Err` read what it wrote.

## 2. The program

`lines [COLUMN] < FILE` numbers every line of standard input, as `nl` does, and prints one summary:
the count, and the sum of the integers in one whitespace-separated column. It is one fold over λ(x)
with state (n, sum, used) ∈ ℕ × ℤ × ℕ.

It builds for Go with **5 of 5 integer operations proven and its loop proven to terminate**, with no
`-checked`. It is 46 lines of code under its header, and it calls `bufio`, `os`, `strings`,
`strconv` and `fmt`. The emitted Go is a `for` over `Scan()` with the two accumulators as locals.

**Its limits are stated**: at most 2²⁴ lines, and values of magnitude at most 10¹¹, so
|sum| ≤ 2²⁴ · 10¹¹ ≈ 1.68 · 10¹⁸ < 2⁶³. **The first draft said 10¹² and claimed the same inequality
in its header. It is false**, 2²⁴ · 10¹² ≈ 1.68 · 10¹⁹ > 9.22 · 10¹⁸, and the compiler refused
`(+ sum v)` naming the interval [−16777216000000000000, 16777216000000000000]. The trip bound (the
line counter's guard) and the value's guard were both found by the IR.

**What is declared** ([targets/go/bufio.oro](../../targets/go/bufio.oro)): `NewScanner`, `NewWriter`,
`MaxScanTokenSize`, `Scanner.{Scan, Text, Err}` and `Writer.{Write, WriteString, Flush}`: 9 names of
the 63 functions, methods and constants Go's manifest lists for the package, checked against the host as a partial file with four planted
mistakes. `Writer.Write` is there because the view check demanded it: the `io.Writer` edge is false
without it. The header names the rest and what stops each: `Scanner.Bytes` is a borrow that the next
`Scan` ends, which an immutable table cannot be; `Split` takes a callback.

`cmd/build`'s `TestLinesFoldsTheLineSplit` builds the tool and compares it with λ written from §1,
not from `bufio`: twelve inputs (CR LF, a CR before the end of input, an unterminated last line,
bytes that are not UTF-8, the value limit at it and one past it, a token of 65,535 bytes and one of
65,536) and six argument cases. A wrong limit planted in the program fails it.

## 3. What the program demanded, in the order it was refused

1. **`strconv`'s parses take the host's string.** `ParseInt` declared `(s string)`, our Σ\*. A field
   of a line is a `go.bytestring`, and Go's function is total on B\*: bad bytes are a syntax error it
   returns. The five numeric parses take `bytestring` now, the host's domain. A caller passing our
   `string` still types, since string ≤ bytestring.
2. **A conditional joins comparable branches** ([types.md §3.2](../../docs/spec/types.md)).
   `(if (< (len fs) col) "" (fs (- col 1)))` has a literal on one side and a host string on the
   other, and the checker wanted the branches equal. A conditional is a join point, so its type is
   the larger, where the two are strictly comparable and of one representation. The IR needed the
   same rule: it typed a join by whichever branch unified first, and a function's result by its first
   yield. Both read one definition, `Target.JoinSameRepr`.
3. **A name is bounded by its value's tails** ([refinements.md §5a](../../docs/spec/refinements.md)).
   `os.Exit` requires 0 ≤ code ≤ 255. The status is a conditional over a loop whose exits are 0 or 1,
   some under a host call's continuation. The rule that bounds a `let`-bound value by its leaves
   walked `if` and `let` only; it walks all four forms of a clause chain now, and a loop's exits.
4. **The guard had to be written at each use.** `(let ok (and …) (again … (if ok (+ sum v) sum) …))`
   lost v's bound: the IR's facts do not pass through a boolean variable. The program states the
   condition through a small definition, `summed`, at both uses. Not built: a boolean's definition
   as a fact on its arms.

`again` under an `if` was refused too, as designed (ADR 0015): the program has one `again` with the
choice inside its arguments.

## 4. Found on the way: two faults that predate the program

**A loop variable inherited a parameter's facts, on every target.** Before extending rule 3 to walk
a loop's binders, a probe: does a loop variable that shadows an outer name get that name's facts?

```
(sig f ((n (int 0 5)) (a (array int))) int (where (= (len a) 6)))
(def f (n a)
  (let s (loop ((n 10)) (> n 100) n else (again (+ n 1)))
    (a s)))
```

The loop exits with 101. **The unmodified compiler accepted `(a s)`** and emitted `v1[v18]`, on Go,
JavaScript, Java and x86: a panic, `undefined`, an exception, and a read outside the table. Named
`m`, the loop was refused. The refinement layer's facts are keyed by name, and the residual's
hygiene pass renamed a binder only when its *body referred* to the outer variable, which keeps a
term from capturing. A context of facts is captured by the name alone. The invariant is now the
variable convention along the scope chain: no binder's hint equals an enclosing binder's
(`core/hygiene.go`, [ADR 0036](../../docs/decisions/0036-a-residuals-binders-are-named-apart.md),
[state.md](../../docs/spec/state.md)). A test had pinned the old behaviour by
name, `TestHygieneLeavesHarmlessShadowingAlone`.

The discard binder is covered by the same rule: nested `_`s become `_`, `_1`, …. A postcondition
attaches to its binder's name, so two `_`s would have pooled their facts.

**The product pass followed a buffer through a loop by its spelling.** Naming binders apart broke
two product tests, and the cause was not the renaming. The pass recognised a loop by a primitive
kind, `loop`, that nothing has: the language's `loop` is kind `iterate`. Its two loop branches were
dead code. It found a product buffer's stores only when the loop variable was spelled like the
buffer; on the unmodified compiler `(loop ((u t) …))` over a buffer `t` of pairs was refused as a
store into a frozen table. A path nothing runs is a path nothing checks.

**And the corpus's own proofs had rested on the same coincidence.** With binders named apart, the
gate refused programs it had accepted: `freq` on three targets, the JSON tokeniser and
tree, both sieves, `tally`, and four differential cases. Every refusal was one shape, an index into a
loop variable that threads a buffer:

```
(c1 i) is an indexing, and (< i (len c1)) does not follow
```

`(loop ((c c) …))` is the idiom ADR 0018 gives for filling a buffer, and the loop variable was
spelled like its buffer. So `len c = n`, a fact about the buffer, was read as a fact about the loop
variable, which is a different value at every iteration. The conclusion was true in those programs,
and nothing had established it. In the probe above the same reading was false.

**The invariant that replaces it** (`threadLengths`, [refinements.md §5b](../../docs/spec/refinements.md)).
`set` preserves length, len (set c i x) = len c, which is its declared postcondition. So for a loop
variable v with initial value z: if every back edge passes at v's position a term of length len v,
then len v = len z at every iteration, by induction. The refiner had this rule, and it could not fire
on the idiom, for three reasons the names had covered:
- **an initial value that is a plain name had no length.** It has: the quantity len(z);
- **it was all or nothing** across a loop's variables. It is now the greatest inductive subset: each
  variable's equation is tried, and one a back edge does not preserve is dropped, the rest re-checked
  (Houdini; Flanagan & Leino, 2001);
- **two lengths were compared as text.** A merge sort swaps two buffers on its back edge, so the edge
  passes length len b where len a is wanted; they are compared under the facts at the loop's entry,
  which say both are n. And a back edge that passes a name bound by a `let` in the body is followed.

Every program is proven again, with the counts it had (§7).

**Three import sets were process-wide and never cleared.** A second build in one process emitted the
first's imports, and Go refuses an unused one. `build` clears them per program (`emit.ResetImports`).
It showed when a test built two programs.

## 6. What failed first

- **The `where` as a box.** The first answer to rule 3 was to split a primitive's `where` into its
  interval conjuncts, a box, and the rest, and send the box down the route a declared range takes,
  to the IR's intervals. ⟦W⟧ = (∏ₚ Iₚ) ∩ ⟦R⟧ is exact, and the program compiled. Thirteen tests then
  accepted programs they must refuse, `(os.Exit 256)` among them. Reduction places a range mark only
  when a driver installs the contract tables, so every pipeline that does not (the tests', and any
  future one) would have had the box checked by nothing. Closing that means marking in every
  reduction, which changes every printed residual. It was reverted for the local rule of §3.3, and
  the hazard it met is named in §8.
- **The tails rule cost a quarter of a small compile.** Paired and serial against the commit before,
  `tree` compiled in 1.24× and `jsonfmt` in 1.32×. The profile put it in the extended walk, which
  entered every `let`-bound scanner loop and cloned the facts at each conditional, to bound a tail
  that is a loop variable and that it cannot bound. The walk now looks at the tails first, without
  the facts, and stops unless every one is linear and none names a variable of a loop it is in
  (refinements.md §5a). A plant removing that restriction survives, as it should: it is a limit,
  not a soundness rule.
- **One witness was vacuous three times, and its plant showed it each time.** The first test of a
  loop variable's initial value used an exit of 3i, which the rule refuses with or without the
  fault. Its replacement bound a pure loop used once, which reduction substitutes, so there was no `let` for
  the rule to see; then its second exit was guarded by `=`, which adds no fact a contradiction
  needs. It took a value used twice and an order guard before the planted fault accepted an index
  of −m.
- **The join pass hung** the test suite. Two names of one host type subsume each other, and a fixed
  point that picked either swapped them forever. The join is strict now, so types only move up.
- **A first join rule accepted a concrete type with its interface**, and W5 then refused the program
  from inside the IR. The rule is restricted to one representation, and the checker refuses the
  rest itself.

## 8. Not built

- **`Scanner.Bytes`, `Reader.ReadSlice`, `ReadLine`, `Peek`**: a borrow that a later call ends. The
  language has write-borrows and consumes (host-buffers.md), and no borrow with that lifetime.
- **`Scanner.Split`**: a callback, tiers 1 and 2.
- **A boolean's definition as a fact on its arms** (§3.4).
- **A join across two representations**, a concrete type with its interface (types.md §3.2).
- **A `where`'s interval part on the IR's intervals** (§6). The refinement layer decides a
  primitive's `where` alone, and it does not know what the IR knows about a value.
- **Range marks outside a driver.** A declared parameter range is an obligation only where
  `InstallRequires` ran: `build`, `gen` and `intervals` run it, and a pipeline that does not places
  no mark. That predates this step, and it is why the box was reverted.
  **Closed the next day**: [hazard-2026-10-02](hazard-2026-10-02.md).
- **The 2²⁴-line limit is not in the test suite**: its input is 32 MB and its output 174 MB. Run by
  hand on this commit: 16,777,216 lines of `3` give status 0 and *"16777216 lines; column 1:
  16777216 values, sum 50331648"* in 3.1 s; one line more gives status 1 and *"lines: more than
  16777216 lines"*, after the 16,777,216 it numbered.
