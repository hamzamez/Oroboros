# A buffer keeps its length

2026-09-24. The cheapest of the four limits [bounds-2026-09-24](bounds-2026-09-24.md) named:
`emit/winmap.oro`'s slot count was not known to be at least 1. Asked for as a derived fact, not a
clamp.

## 1. The law

`(set b i v)` hands back b with one cell changed, so `len (set b i v) = len b`: a store acts on a
table's cells and never on its domain [0, len). So along any chain of stores the length is an
invariant. That includes a loop that threads the buffer through its back edges, and a nested loop
that hands its own buffer variable back at every exit, which is what every `wm-put` probe is.

The interval pass knew the first half: `exactLen` follows a `set` chain to the `build` that made it.
It did not know the second. A loop-carried buffer had no length, and neither did a `build`'s own
buffer inside its lambda. In `winmap`, `n = len(m)/3` could then be 0, the mask `n − 1` could be −1,
and `k & −1` is k. Every probe index was unbounded, for a map whose buffer has exactly 48 cells.

## 2. What is built (`emit/buflen.go`)

- **The relation `keepsLen(t, xs)`**: t's value is a table as long as the names in xs. It holds for:
  - a name in xs;
  - a `set` whose buffer keeps it;
  - a `let`, whose binder joins xs when its value keeps it;
  - both branches of an `if`;
  - a host call's continuation, whose results never join xs;
  - a nested loop whose buffer variables keep it. That is Houdini: a variable joins when its
    initialiser keeps the length, and is dropped when some back edge does not, until nothing
    changes. Then every exit must keep it.

  It walks the four forms of a clause chain (ADR 0027), and anything it does not recognise is not the
  same length.
- **Two seeds.**
  - Inside `(build n (fn (b) …))`, len(b) is n's interval.
  - A loop variable whose initialiser's length is known, and which keeps it on every back edge, has
    that length for the loop's duration.
- **Shadowing.** `openFresh` renames a binder only against names it handed out itself, and the lambda
  case, which opens a `build`, hands out none. So a loop variable, a `let` binder or a continuation
  parameter can share the buffer's spelling while holding another table. Each one now sets its own
  length or removes it, and never inherits.
- **The mask and the shift are strict in ⊥.** In a dead branch the buffer's length is ⊥, and
  `and(⊥, ⊥)` came out ⊤, because F9's clauses are for a non-negative operand and ⊥ is neither. Found
  by bisecting `map-len`: `run(0)` alone had 22 of 52 unproven, all in the insert loop that
  `(>= i 0)` makes dead.

## 3. What failed first

- **Strictness for every transfer function** proved the map cases and cost three others: `sum-case`,
  `negative-zero` and `len-bounded` on windows took traps in `print-int`'s digit loop. The
  differential suite caught it, which is what item 2 was built for. Bisected to the strictness rule.
  The additive transfers already gave an empty interval on ⊥ with crossed endpoints, and the loop
  analysis reads those endpoints. So only the mask and the shift are strict.
- **Two tests were vacuous.** The shadowing tests first bound the table with a `let`, which runs the
  element analysis over the `build` first. That opens the loop once and takes the spelling `b`, so
  the counted walk saw `b2` and no collision. Both passed with the shadowing removed. They now take
  the build's length directly, and fail when it is removed.

## 4. Checked, and how each check fails

`emit/buflen_test.go` has six tests, each hanging one proof on a length: `(+ (len b) K)` with
K = 2⁶³ − 1 − L is in the word exactly when len b ≤ L.

| rule removed | caught by |
|---|---|
| the loop seed | `TestALoopCarriedBufferKeepsItsLength` and one more |
| the `build` seed | the same |
| a store keeps the length | the same |
| a nested loop keeps the length | the same (the nested case) |
| back edges are checked | `TestATableReplacedOnABackEdgeHasNoLength` (3 cells, then 8) |
| an unseeded loop variable is shadowed | `TestALoopVariableDoesNotInheritAShadowedLength` and one more |
| a continuation parameter is shadowed | `TestAContinuationParameterDoesNotInheritAShadowedLength` |
| a `let` binder is shadowed | `TestALetBinderDoesNotInheritAShadowedLength` |
| the mask is strict | `TestAnUnreachableMaskIsUnreachable` |
| **a lambda parameter is shadowed** | **nothing** |

The last is unreachable today. After a `build`'s own lambda, which is seeded, the lambda case opens
only host callbacks, and no declared callback takes a table. The rule can only remove a fact, the
safe direction, so it stays, and it is recorded here as unchecked.

## 5. What it changed

| case | before | after |
|---|---|---|
| `map-dynamic`, windows | 208 of 260 | **260 of 260**, declaration removed |
| `map-static`, windows | 200 of 256 | **256 of 256**, declaration removed |
| `len-bounded`, go js windows | unproven | **proven**, declaration removed |
| `map-len`, windows | 119 of 156 | 155 of 156, still declared |
| `map-keys`, windows | 138 of 210 | 180 of 210, still declared |

**`len-bounded` corrects bounds-2026-09-24.** Its elements are `i + 1` with `i < len b`, so the
missing fact was the loop-carried buffer's length, not an element bound.

What is left:
- `map-len`'s one operation is `wm-len`'s count of `used` cells. They are 0 or 1, but the elements
  of the table the map is stored in get no bound.
- `map-keys` has that too, plus the geometric accumulator.

Both declarations say so.

- **Emission** is byte-identical, and the corpus's proof counts are unchanged at 2,387 of 2,434 and
  349 of 387. The sweep compiles each source on its own, and no standalone program has this shape;
  the gain is in the differential builds. **Compile time:** 1.07× median, within the rule.

## 6. Not built

- **`winmap`'s clamps (`wm-c`) stay.** They answer the refinement layer's index obligation, which
  reads linear arithmetic and not `&`. That is a different layer from the interval proof this
  closes.
- The other three limits in bounds-2026-09-24 stand: element bounds for `alloc (table …)`,
  geometric accumulation, and narrowing through a conjunctive guard.
