# Win32 by header: the type names in their headers, TinyRetroPad's calls declared and checked

2026-11-17. Item 3 of [assessment-2026-11-17](../../docs/assessment-2026-11-17.md) §5, its half
D1 by header (W1), after 6c ([tinyretropad-2026-11-17](tinyretropad-2026-11-17.md)).
[ADR 0126](../../docs/decisions/0126-win32-is-by-header-and-a-c-type-name-is-its-whole-value-set.md).

**Win32 is by header, and its type names are sets its headers define.** A data model interprets
exactly the four names of basetsd.h's `#if defined(_WIN64)` branch. The 47 TinyRetroPad functions
a program can call are declared by hand, and kernel32's 20 moved to their headers: 61 declarations
in 14 header modules. 57 are checked against the SDK's prototype, and the other 4 are exempt with
their reasons. One program makes 17 of their calls on both triples and prints what C prints.

## 1. The algebra

- **A typedef is a definition**, and the SDK's typedefs are a definitional extension of C's base
  types. A data model interprets the base types and so, uniquely, every name.
- **Two models differ exactly where a definition reaches pointer width.** In the SDK's text that
  is basetsd.h's `#if defined(_WIN64)` branch, four names (read off shared/basetsd.h, 10.0.26100.0):
  `INT_PTR`, `UINT_PTR`, `LONG_PTR` and `ULONG_PTR`.
- **So the fibre is four lines per member.** SIZE_T, SSIZE_T, DWORD_PTR, WPARAM, LPARAM and
  LRESULT are defined once in the base, through the four.
- **A C integer type's set is its whole value set.** A name is one set, so a 64-bit unsigned type
  is 0..2⁶⁴−1 at both positions, the unsigned word. ADR 0094's two readings (0..2⁶³−1 in, the word
  out) cannot both be one name, and its result reading was a claim no C function makes: HeapSize's
  (SIZE_T)−1.

## 2. What was built

- **Headers** (`targets/win32/`):
  - the type names: `minwindef`, `winnt`, `windef`, and `basetsd`, with the four in each member's
    `model.oro`;
  - kernel32's 20 declarations, moved to `fileapi`, `handleapi`, `processenv`, `errhandlingapi`,
    `memoryapi`, `heapapi`, `winbase`, `processthreadsapi` and `winnt`;
  - TinyRetroPad's 47 reachable functions. Six were kernel32's already; the 41 new are 26 in
    `winuser`, 7 in `wingdi`, 2 each in `datetimeapi`, `libloaderapi` and `winbase`, `shellapi`'s
    one, and `fileapi`'s GetFileSize;
  - every declaration carries its `lib`, `kernel32`, `user32`, `gdi32` or `shell32`;
  - `windows/kernel32` is retired.
- **A set's name through a `use`** (`emit/alias.go`): `basetsd.SIZE_T` inside a module that uses
  `windows/basetsd`, resolved as a term name is. Before this only a module's own names and its
  enclosing modules' resolved.
- **0..2⁶⁴−1 is a C type** where the target realizes the unsigned word, and 0..2⁶³−1 no longer is
  (`emit/target.go`, with `PlantNaturalsCType`).
- **The unsigned word on ι's image** (`ir/words.go`, `ir/pipeline.go`): `SelectWordsOnImage` after
  each round of realizations, with `PlantNoWordsOnImage`.
- **The survey** (`gauntlet/stdlib/win32.go`):
  - a 64-bit unsigned type is 0..2⁶⁴−1;
  - a handle is `ptr`;
  - the module is `win/<header case-folded>`.
- **The check**, `TestWin32DeclarationsAreTheirPrototypes`: all 57 hand declarations agree, 4 are
  exempt with their reasons, and twelve planted mistakes plus a name the SDK lacks are each caught.
- **The program**, `acceptance/trp-surface.oro`: a hidden STATIC window, a popup menu, the global
  heap, a date's length, a brush, a library and a registered message.
  - Its 17 lines are what the same calls print from C on x86-64 and on i686. The C reference was
    run before the program was written.
  - It runs as `trp-surface` on `windows` and `trp-surface-i686` on `windows32`.

## 3. What failed first

- **The survey's handles were the word.** A handle is a pointer, and the check's first run found
  it on every function taking an `HWND`, `HMENU` or `HDC`.
  - On x86-64 an `i64` and a `ptr` pass alike, so nothing had shown it. On i686 the word is eight
    bytes and a handle four.
  - The verdicts are unchanged: a program can pass a handle it holds.
- **HeapSize's result on windows32 was declared `i64`**, a wrong ABI on i686 whose return is EAX
  alone. Written by hand as the word because 0..2⁶³−1 would have been a false claim. Latent: no
  program called it. Now `r ∈ basetsd.SIZE_T`: `i32` on i686, `i64` on x86-64, and the unsigned
  word, so −1 is `icmp eq … 2^64-1` and its order is `icmp uge`.
- **SIZE_T as 0..2⁶⁴−1 was refused by the C ABI's check**: the list of C types had no U₆₄.
  Admitted, it then failed W5, because `region`'s HeapAlloc is substituted after the unsigned word
  is chosen.
  - Choosing it again from the facts refused the factorial loop: an existing `u64-of` was read as
    a declared position, its argument's fact recomputed less tightly.
  - The selection on the image keeps the types, and converts only at a declared position.
- **The acceptance layer collided with the hand modules.** Generated files at the project's
  `windows/fileapi.oro` shadowed the target's `windows/fileapi` for `lib/win/print`. This is the
  same collision the Go programs met; they moved to `tg/`, and so do these now.
- **The first full check failed**: four tests still named `windows/kernel32` (the realization
  interpreter's stubs, the C ABI's printing test, two `cmd/build` programs), and the class
  witness's `heapsize` declared `(Int)` over HeapSize's result, which is now the unsigned word.
  Its result is now its own.
- **The checker on the first pass**, five of my errors:
  - a write-borrow's result read as the C result;
  - three exemptions that the survey could in fact declare (stale, so refused);
  - TextOutA's count written 0..2³¹−1, refused as no C type and moved to a `where`.

## 4. Measured

- **Emission**: 35 windows files change, by the conversions alone. 1,721 sites print `or i64 %x,
  0`: a word value crossing into SIZE_T, VirtualFree's literal 0 included.
  - Compiled with clang -O2, all 35 give the same machine code as the baseline (`llvm-objdump -d`
    compared).
  - The gauntlet's three windows files that changed (`gen_jsontok`, `gen_jsontree`,
    `gen_smooth_native`) also compile to the same machine code, so their harnesses' times
    cannot move. They were not re-timed.
  - Go, JavaScript and Java are byte-identical. Proofs are unchanged: 8,852 of 8,906 integer
    operations, 924 of 962 loops.
- **windows32**: the differential suite gives 72 of 74, as before; the two left are Go-only
  (`u128-fact`, `u128-ops`). The acceptance program prints the same 17 lines on both triples.
- **The survey's figures** are unchanged: the verdicts did not move, only the generated sets did.

## Paid and bought

- **Compile time**: 1.05× the baseline by the check's gate (the median of 63 compiles over 300
  ms), run alone, under its rule. The image selection is one more pass over a function per round
  of realizations that changed something. The IR grew from 140,670 to 142,365 operations, the
  conversions.
- **Run time**: x86-64 unchanged (identical machine code). i686 not compared instruction by
  instruction; its suite passes as before. Owed: windows32's emission against a baseline.
- **Code size**: unchanged on x86-64.
- **Proofs and refusals**: unchanged counts. 0..2⁶³−1 is now refused as a C type at a parameter
  and at a result. No declaration used it; the generator wrote it, and now writes U₆₄.
- **Compiler lines**: +97 −8:
  - `emit/alias.go` +34 −1;
  - `emit/target.go` +21 −4;
  - `ir/words.go` +27 −3;
  - `ir/pipeline.go` +15.
- **Tests**: `win32hand_test.go` +303, `imagewords_test.go` +70, `cabi_test.go` +19 −6, and
  `tooling_test.go` +29 −22 (the layer moved to `tg/`, the new programs, windows32's artifact).
- **Target lines**: 18 header files, +371, against `kernel32.oro`'s 101 retired; `os.oro` +13 −7;
  each `model.oro` now four names.
- **Language lines**: `lib/os/windows.oro` +28 −22, `lib/io/windows.oro` and `lib/win/print.oro`
  +4 −2 each, and the acceptance programs' renames. `trp-surface.oro` is new, 59 lines.
- **Emitted text changed**: windows 35 files, the identity conversion; the others none.
- **Rules made less general**: 0..2⁶³−1 is no longer a C type, so a declaration that used the
  word's naturals for an unsigned 64-bit argument must now write 0..2⁶⁴−1. None did.
