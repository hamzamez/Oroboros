# cabi-2026-11-05: a C function is its prototype, and the C ABI derives its call

6b′ step 2 (hamza, 2026-11-05: "go ahead, with step 2. always mathematical and algebraic"),
ADR 0094.

## The algebra

A C function's type is τ₁ × … × τₙ → τ over C types. On a triple t, the C ABI maps each type to an
LLVM type and gives two maps between a language value and an LLVM value:

- **in**: `trunc` for an integer narrower than the word, exact on its set; s ↦ s + 8 for a C string;
  the identity otherwise;
- **out**: `sext` or `zext`, the embedding back; the identity otherwise.

The call is out ∘ F ∘ (in × … × in).

**The set is the C type, on full ranges.** The range of a w-bit integer determines w and the sign,
so the map from type to range is injective. A subset does not determine the width: 0..9 is a `char`
or an `int`, and the width is the ABI. So a narrow C integer's set is its type's full range, and a
narrower domain is a `where`. Win32's own constants are then integers of the type: STD_OUTPUT_HANDLE
is ((DWORD)-11) = 4294967285.

**What the prototype does not say, the triple does:**
- `dllimport` on a Windows triple;
- `stdcall` is x86_stdcallcc on i686 and the C convention on x86-64.

## What was built

- **`host expr call "SYMBOL" [stdcall | cdecl]`** (`host stmt call` for `void`), read into the clause
  `(call "F" conv)`. It goes through D's tree like any declaration (`hostDef`: the call is a clause,
  not a template), and lowering takes it as a host call.
- **`emit.CType`**, the set → C type map, and **`cPrototypes`** at load:
  - every set must be a C type;
  - a C string's parameter must carry `where nulfree(p)`;
  - a C function is refused off an LLVM target.
- **`ir/llvm`'s `cCall`** derives the instructions and the `declare` from the prototype and
  `tg.Triple`.
- **kernel32**: six of its seven hand declarations are prototypes, with `GetStdHandle`'s DWORD at its
  full range. `WriteFile` stays a template: its buffer is a table's segment, and it writes the
  target's `@__written` cell.
- **The survey** writes 10,479 prototypes, its conventions read from the headers' macros (`WINAPIV`
  is `cdecl`, the rest `stdcall`), and writes no template. A 64-bit unsigned parameter is now
  0..2⁶³−1, where it was the word, whose negative values the callee would have read as large ones.

## Witnesses

- **`TestACFunctionIsItsPrototype`**:
  - loaded: an int, a DWORD, a pointer and a SIZE_T; a C string with its obligation; a `void`
    function; an obligation among others;
  - refused, each naming its reason: a narrow domain, a Boolean, a result no C type, a C string
    without `nulfree`;
  - **planted fault**: with the obligation not required, the C string loads.
- **`TestACCallIsDerivedFromItsPrototype`**:
  - on x86-64: `declare dllimport`, `zext` for a DWORD result, `sext` for an int's, `trunc i64 7 to
    i32`, and no x86_stdcallcc;
  - on i686: `call x86_stdcallcc i32 @GetLastError()`.
- **All 10,485 C functions load as one layer of windows**, the survey's and kernel32's: every
  prototype is a C type, and every C string carries its obligation.

## What failed first

- **D's tree read the host body's third element as the template string** (`hostDef`), dropping the
  call clause. The loader then refused the declaration as an `expr` with no template.
- **Lowering refused a declaration with no template** unless a term realized it. A C function is a
  host call whose instructions the printer derives.
- **kernel32 stated domains, not types.** `ExitProcess`'s UINT was declared 0..2³¹−1 and
  `GetStdHandle`'s DWORD −2³¹..2³¹−1, so that a caller could write −11. Under the full-range rule
  each is its type's range, and the callers pass Win32's integer.
