# A C call's arguments as a linear term: kernel32's last templates derived

2026-11-16. [ADR 0118](../../docs/decisions/0118-a-c-calls-arguments-are-a-linear-term-over-its-parameters.md),
amending ADR 0094. hamza, after the audit of what was still written as text: "Go ahead, always
mathematical and algebraic".

**No template in the LLVM or windows layers is longer than one instruction now.** The audit
(`strings-2026-11-16`'s successor) found four pieces of text: kernel32's `ReadFile`, its two
`WriteFile`s, and `llvm.store8`. The three file calls are now `host expr call "ReadFile"(h,
elem(b, lo), n, got, null) stdcall`, derived by the C ABI on the triple. `store8` is two single
instructions composed in the language. The one template left that is no LLVM instruction is
`divq`, the triple's 2-by-1 division (ADR 0104), one line.

## 1. The algebra

- ADR 0094's call was out ∘ F ∘ (in₁ × … × inₙ), a product of conversions, one per parameter.
  A segment is a function of two parameters, b and lo, and `NULL` corresponds to no parameter, so
  neither is in that product's image. The conversion **in becomes a term** ⟨t₁, …, t_k⟩ in the
  signature {x, elem : Table(B) × ℕ ⇀ ptr, null : 1 → ptr}. elem(b, lo) is &b[lo], the action of
  (ℕ, +) on the region's addresses (ADR 0084).
- **The term is linear.** Every parameter appears exactly once, so ⟨t⟩ is a permutation of the
  parameters, with pairs of them under elem and constants beside them.
  - Dropping a parameter would leave a claim, its set and `where`, about an input the host never
    sees.
  - Duplicating one would pass two addresses into one linear view (ADR 0084's separation).
  - Linear terms are exactly those that carry each view to one argument.
- **elem is partial**: it is defined on 0 ≤ lo ≤ len b, one past the end included (C11 §6.5.6¶8,
  LLVM's `inbounds`). So the declaration's `where` must state lo ≤ len(b), or lo + m ≤ len(b)
  with m a natural, and each call decides it (ADR 0028). The printed `getelementptr inbounds` is
  then a fact.
- **One host function, one declaration.** The Boolean `WriteFile` with its global `@__written`,
  and `WriteFileC` with a cell, were two claims about one symbol. They are now one, with the count
  through the caller's cell.
- **`store8` was a composite**: `getelementptr`, `trunc`, `store`, and an `icmp eq i64 0, 0` that
  existed only to give it a result. Now it is `store_zero(offset(p, o))`. `offset` is
  `getelementptr inbounds i8` and pure; `store_zero` is `store i8 0`, a statement whose value is p.

## 2. What failed first

1. **The inventory test**: the reader's `args` and the terms `elem` and `null` are words the
   compiler now knows. The words are listed in inventory.md §2 (specified, 141 → 144). An
   internal kind written as a string (`"param"`) was read as a word too. It is a typed constant
   now, since it is no word of the language.
2. **The realizations' interpreter had no cells**: `cell-fresh` and `cell-get` were unsupported, so
   every windows term that writes to standard error (each `trap-if`) failed its agreement check. A
   cell is now modelled as a one-slot reference (ADR 0048). WriteFile's meaning is stated: n
   through the cell and a nonzero BOOL.
3. **My Python edits wrote CRLF** on thirteen files. `TestTheRepairsGuardCatchesAWrongRepair`'s
   planted fragment is a two-line source match, and it stopped matching. The witness itself said
   so ("no longer writes U+FFFD as the test plants it") rather than passing vacuously. The files
   are LF again.
4. **`lo + n <= len(b)` under `&&`**: D writes `a && b` as `if a { b } else { false }`, and
   `boundsElem` first walked only `and`. A declaration whose bound was the second conjunct was
   refused. It now walks D's form as `hasConjunct` does.

## 3. The witnesses

`TestACCallsArgumentsAreTermsOverItsParameters` (emit/cabi_test.go):
- **Loaded**: a segment's address, the count and null; the same arguments reordered; lo bounded
  by itself under `&&`.
- **Refused, each for its reason**:
  - a parameter left out ("appears 0 times");
  - a parameter twice ("appears 2 times");
  - a name that is no parameter;
  - elem of a pointer;
  - elem of a table of words;
  - a signed offset;
  - a `where` that does not bound lo;
  - lo bounded through a signed m.
- **Planted faults**: `PlantCArgDropped` loads the dropped parameter, and `PlantElemUnbounded`
  loads the unbounded elem. Each refusal above is reached by its rule.

The derived calls agree with the templates they replace. The differential runs every windows case
that writes to standard output; `os`'s `read-loop` and `text-of` read files through ReadFile; the
file programs' outputs agree with C and Go before they are timed; the gauntlet's 22 cases agree
with Go. Each emitted call is now `call i32 @ReadFile(ptr %h, ptr %c, i32 %n, ptr %cell, ptr
null)`.

## 4. Measured

- **The gauntlet's three changed files** (`gen_jsontok`, `gen_jsontree`, `gen_smooth_native`), old
  against new, 10 alternating rounds:
  - tokenizer 1.002;
  - tree 1.001;
  - the allocating stencil 1.014.
- **The file programs**, old (HEAD's build) against new, measured twice, 41 and 101 rounds, with
  the machine loaded throughout (q3 near twice the median):
  - median ratios, first run then second: roundtrip 1.09 then 0.98, wc 1.02 then 1.05, count 1.05
    then 0.98, freq 1.07 then 1.01, jsonfmt 0.95 then 1.06;
  - no ratio keeps its sign across the two runs, and every one is inside the ~15% floor.
- **What changed in the code**: a write's count is a stack slot (an alloca) where it was a global,
  so the call is reentrant. `win/print.write` is now kept as a function (P8's rule, |f| ·
  max(π − 1, 1) ≥ 64, now that the call has a cell). A finer reading on a quiet machine is owed.

## Paid and bought

- **Compile time**: the median 1.01× the baseline. Five suspects were each cleared paired against
  `a3c224e`'s `gen` (0.93–1.12×).
- **Run time**: §4. Inside the noise on both suites; a quiet machine's reading is owed.
- **Code size**: jsonfmt's executable 16,384 → 16,896 bytes, roundtrip's 18,432 → 19,456 (the
  kept `write` and its cell); wc, count and freq unchanged.
- **Proofs**: unchanged, 8,857 of 8,911 operations and 924 of 962 loops.
- **Refusals changed**: none in the corpus. The target loader refuses five more malformed C
  declarations (§3).
- **Emitted text changed**: 37 windows files, the calls and the allocator's NUL; the gauntlet's
  three windows files. Go, JavaScript and the JVM are byte-identical.
- **Compiler lines**: non-test +248 / −6 (`emit/target.go` +184, the term's resolution and checks;
  `core/jreadtarget.go` +35, the reader; `ir/llvm/llvm.go` +29 / −3, the printer). Tests +66 / −1.
- **Target and library lines**: +40 / −34. kernel32 loses its three templates and its global.
- **Rules made more general**: a C call takes any linear term of parameters, segments and null.
  **Less general**: none. A segment through `elem` must have its bound in the `where`, which the
  templates had stated too.

## What was not built

- **Affine terms**, a ghost parameter used only in the `where`: nothing needs one.
- **A computed byte stored through a pointer**: `store_zero` writes 0 only. A byte v needs `trunc`
  to i8 and an i8 sort the language lacks.
- **elem over a table of wider elements** (&t[i] for a table of words, offset i·w): no host call
  needs it yet. Win32's struct arrays will (TinyRetroPad, 6d).
