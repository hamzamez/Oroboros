# A map's capacity is a claim on its len: the book's finding 71, the second half

2026-11-16. [ADR 0121](../../docs/decisions/0121-a-maps-capacity-is-a-claim-on-its-len.md), on
[ADR 0120](../../docs/decisions/0120-a-map-on-the-llvm-layer-is-realized-after-the-decision.md).
hamza, of four options shown in the surface: "Go ahead with B′, always mathematical and algebraic".

**A map of capacity c is in {m ∈ Map(K, V) : len(m) ≤ c}, and an insert past it is refused on every
target.** Before, Go, JavaScript and the JVM grew the map and windows dropped the key, so one program
had four behaviours beyond 2c keys. Every map program in the corpus is proven within its capacity,
except one differential case, which had inserted nine keys into a `map(8)` since it was written and
now declares 16. Emission is byte-identical, since the claim is decided and erased, and compile time
is 1.00×.

## 1. The algebra

- **Map_c = {m : |dom m| ≤ c}**, len(m) = |dom m|. `map(c)` ∈ Map_c, and a binder may state it as a
  separation (ADR 0061), so capacity is a declared set's claim (ADR 0079) with no new parameter.
- **insert is partial on Map_c**: m[k ↦ v] ∈ Map_c iff k ∈ dom m ∨ |dom m| < c. The state
  translation marks each insert into a map place with the sufficient half, len(m) < c, ADR 0028's
  mark, decided as a store's domain is (ADR 0119).
- **Three laws decide it**:
  - |dom| = 0 at `build-map`'s binder;
  - dom(m[k ↦ v]) = dom m ∪ {k}, so len(m) ≤ len(m′) ≤ len(m) + 1;
  - Houdini's |dom t| ≤ v for a loop threading a map, which holds at entry and is kept by a back
    edge that inserts once.
- **A length is an atom of its subject**, lengthVar. Splitting inside `len`'s argument rewrites the
  subject, so a fact keyed by it no longer matches. Only a conditional subject is split,
  len(if c a b) = if c len(a) len(b).
- **A mark's condition is logic, never run** (ADR 0049). Linearity and `lengthSubject` read a mark
  as its body. S remains the state-passing translation after erasure ε (ADR 0050).

## 2. What failed first

1. **S never saw the capacity.** I first recorded it at `build-map` in S, but S reaches a map place's
   scope by a path that never visits that branch. The capacity now travels in the scope form,
   `(#mapplace m (fn (m) body) #cap-m)`.
2. **A capacity term copied into each mark could be captured** by an inner binder: `map(n)` with an
   inner loop variable `n`, the class finding 53 belonged to. D binds it once, to `#cap-m`, which is
   apart along the scope chain because `noShadow` refuses a nested `var m`.
3. **The insert's law as a fact of lang's was refused by its own admission**: `insert` inside `len`
   is not flat (F-B, condition 2). It is instantiated on each present insert term instead, a ground
   instance of a local extension, and is `insert`'s postcondition at a binder (Lemma 2).
4. **A postcondition at a binder misses the back edge**: S passes an insert straight to `again`,
   which is no β-redex, so it is never let-bound there. The ground instances cover it.
5. **The decision of marks seeds its own facts** (`emit/requires.go`), separately from the
   refinement walk. It seeds the insert law too.
6. **Houdini proposed |dom #vm| ≤ i and dropped it at a back edge** whose goal followed linearly from
   the facts present. `firstAlien` had descended into `len`'s argument, found the `if` in the
   insert's value, and split on it.
7. **Linearity read the marked insert as a frozen map**, because the mark is no store; the legal
   map's second insert was refused. Linearity reads a mark as its body now.
8. **Two tests pinned the old form**:
   - S's program-order theorem test now compares after erasing marks, and asserts the map's mark is
     there before;
   - the inventory met the structural kind `map-insert` in `fact.go`, so the instantiation moved to
     `refine.go`, where the walk is.
9. **My witness's over-capacity case built**, because `fill(3)` was inlined with n = 3 and was
   proven, which is correct. Calling it with r ∈ 0..19 gives the refusal.

## 3. The witness

`TestAMapsCapacityIsAClaimOnLen` (cmd/build, Go and windows):
- **built, with their outputs**: the book's tally (`7 3`) and three inserts with one key written
  twice (`2`);
- **refused for the map's capacity**: nine keys into a `map(8)`, and a count up to 19 into a
  `map(8)`;
- **planted faults**: `PlantMapNotEmpty`, `PlantInsertUnbounded`, `PlantNoMapTemplate` and
  `PlantSplitInsideLen` each refuse the tally; `PlantCapacityUnmarked` builds the nine keys again.

`TestAStoreIntoAFrozenValueIsRefused` gains `PlantMarkOpaqueToLinearity`, which refuses the legal map
again.

## Paid and bought

- **Compile time**: 1.00× the baseline, no compile confirmed slower.
- **Run time, code size**: the emitted text is byte-identical on every target, since the marks are
  decided and erased; nothing to time.
- **Proofs**: unchanged, 8,852 of 8,906 operations and 924 of 962 loops.
- **Refusals changed**: an insert past a map's capacity is refused on every target. `map-dynamic`
  declares 16 and `run(n ∈ 0..16)`.
- **Compiler lines**: non-test +222 / −7:
  - `emit/refine.go` +137: the map binder, the template, the ground instances, the length atom;
  - `core/cell.go` +38: the mark;
  - `emit/target.go` +22: insert's postcondition;
  - `emit/linearity.go` +11, `core/desugar.go` +9 / −2, `core/scope.go` +4, `emit/requires.go` +1.

  Tests +34, and `cmd/build/capacity_test.go` 75.
- **Rules made less general**: a map filled exactly to its capacity and then updated is refused,
  since presence is not a fact yet. No program in the corpus does this.

## What was not built

- **Presence**, the k ∈ dom m half of the domain, from a read's `'some` arm.
- **A borrowed map parameter stating its capacity** (`m ∈ set { m ∈ Map(Int, Int) : len(m) <= 16 }
  linear`). Specified (maps.md §6), and no program has one yet.
- **A count cell on windows** for an O(1) `len`, for a program that must guard an insert. None does.
