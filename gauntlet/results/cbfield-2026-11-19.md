# A callback at a struct's field: a function of ours at C's convention (ADR 0133 step 1)

2026-11-19. hamza, 2026-11-18: "build until you run out of things to build", on the tier 2 decisions
of [callbacks-sketches.md](../../docs/callbacks-sketches.md) (ADR 0133).

## 1. What was built

- **The claim as a set** (ADR 0053, built for the first time): a header writes
  `set WNDPROC = fn(h ∈ HWND, m ∈ UINT, w ∈ WPARAM, l ∈ LPARAM) (r ∈ LRESULT)` and its C signature
  `repr WNDPROC c(h, m, w, l) stdcall`. The reader's forms are `callback-set` and `conv`. The set is
  `callback Q`, opaque to the alias machinery and a `ptr` at a C boundary, and the loader keeps the
  claim in `Target.Callbacks`.
- **WNDCLASSA's `lpfnWndProc ∈ WNDPROC`**, a field of the record, where it was a pointer determined
  0 (Theorem F).
- **The lifting** (`core/record.go`, `liftCallback`): at the `#ref` boundary, a leaf of a callback
  type must be a closed λ of the claim's arity, or the name of a definition or a host function,
  whose η-expansion it is. It is recorded in `Env.Lifted` and replaced by its address primitive.
- **The build** (`ir/callback.go`): each lifted λ is built once as a kept definition is. Its
  parameters are assumed in the claim's sets, its result is a claim in the claim's result set, and
  it is lowered and decided by `ir.Entry`. `cmd/build` and `cmd/gen` call it between reduction and
  lowering.
- **The text** (ADR 0038): a lifted function's IR_P carries `(callback "Q")` after its results.
  The printer derives the wrapper from the target and that name, and `RegisterProgram` registers
  the address from the text, so `cmd/check` reprints a callback from IR_P alone.
- **The wrapper** (`ir/llvm`, `CallbackWrapper`): the function the host calls, at the claim's
  convention (`x86_stdcallcc` on i686 only, as for C calls). Its parameters are C's types in C's
  order, each widened to the IR's, `zext` unsigned and `sext` signed, and its result truncated.
  Names use `~`, an IR identifier character no J name holds: `F~cb`, `F~cb~c`, `F~cb~addr`.

## 2. Measured

- A definition by name, a λ written at the field, and a host function by name
  (`lpfnWndProc : winuser.DefWindowProcA`) each register a class, take `CreateWindowExA`'s
  `WM_NCCREATE` and `WM_CREATE`, and answer `SendMessageA`'s WM_USER with `42 + w`. Each prints 49
  on windows and windows32.
- **The cdecl fault does not crash.** callbacks-research §5 predicted that a wrapper printed cdecl on
  i686 would unbalance the stack after the first message. Measured, user32 restores its stack
  pointer itself, and the program still prints 49. The convention's witness is therefore the
  wrapper's text, `x86_stdcallcc i32` on i686 and no convention on x86-64, which `PlantCallbackCdecl`
  removes.

## 3. What failed first

- **`$` is no IR identifier character.** Names `F$cb` were written by `gen -ir` and refused by the
  reader, which `cmd/check`'s IR step would have found. They are spelled with `~` instead.
- **A result attribute broke the wrapper's parse.** `define internal range(i64 …) i64 @f(` was cut
  at the first parenthesis, so the wrapper read five parameters. It is now cut at the function's
  name.
- **An alias read outside its module** (older than this step): a program's header naming
  `minwindef.WPARAM` was refused, `basetsd.UINT_PTR is no set`. Both `unboundSet` and
  `UnfoldType` substituted an alias's definition as written, then read it in the program's module.
  They now resolve it in the alias's own module. No program had named WPARAM in a header before.

## 4. The tests

- `cmd/build` `TestACallbackIsAFunctionOfOurs`: the procedure by name and at the field, on both
  triples. Its refusals: a λ that captures, a λ of three parameters, and a value that is no function,
  each naming its reason. Its faults: `ir.PlantCallbackCdecl`, seen in the wrapper's text, and
  `core.PlantCallbackOpen`, a capturing λ lifted, which must then fail by another refusal or a panic,
  never build.
- `ir/llvm` `TestACallbackIsPrintedFromItsText`: print ∘ read is the identity on a callback's text,
  and its wrapper and address print from the text on both triples.
- `TestACStringFieldIsLent` gives its class `winuser.DefWindowProcA` by name.
