# A C call as C writes it: out-results and segments (ADR 0131, 0132)

2026-11-18. hamza: "go ahead, build 0131 and 0132 first, spec first".

## 1. What the two ADRs said

A C declaration's host clause states how C receives the arguments, which is representation; its
header states what a program sees, which is meaning (ADR 0130's test). Two things were in the
wrong place:
- **an `_Out_` parameter was a cell in the header**, `rc ∈ cell(windef.RECT)`, so every caller
  wrote `out windef.RECT`, restating the declaration's own type. A value the host writes and the
  program only reads is a result: f : X × T* → R with T written only is observably X → T × R
  (local.md §5, mutscope decision 4's order). The header says so, `(rc ∈ RECT, r ∈ BOOL)`, and
  the call writes `&rc`;
- **a (pointer, count) pair was three parameters**, `b, lo, n` with `where lo + n <= len(b)`, the
  segment's formation restated in every declaration. A segment is a table (ADR 0074), and its
  address and length are a table's two projections, so the declaration takes one table `s` and
  the call writes `s, len(s)`.

Both are written in C's notation, `call F(x, &x, &r, &b[lo], len(s), NULL)`, each argument read as
ADR 0118's linear term.

## 2. What was built

- **The specs first**: llvm.md §6a (the table of written forms, the linearity, the segment rule, the
  refusals, the reader's forms); local.md §5 and §6 (`_Out_` a result, `out τ` written only where
  the program chooses τ); j.md §2.5's grammar (`c_call`, `c_arg`) and §1.4 (`NULL` contextual,
  `elem`, `ref` and `null` read and refused).
- **The reader** (`core/jreadtarget.go`): the C call parsed as C writes it, the callee an
  identifier; `cOutsAhead` finds each `&r` naming a result before the result is read, and each such
  result leads the result tuple and becomes a trailing `cell(T)` parameter, listed in `(outs i…)`.
  The old spellings are refused naming the new ones.
- **Out-results filled** (`core/outcell.go`): the loader's `cells` form carries `Outs`, their sets
  and the arity, and `CellDecl.fillOuts` writes `out T` at each position a caller omits, in a
  plain call and beside a borrow (`core/place.go`).
- **The segment variant** (`emit/target.go`, `segmentVariants`): a declaration with `len(s)` gains
  `F#seg(…, s, s#lo, s#hi, …)`, its C arguments `&s[lo]` (`CElem`) and hi − lo (`CDiff`, truncated
  to the width the `where` states), its `where` 0 ≤ lo ≤ hi ≤ len(s) conjoined with the original's,
  len(s) read as hi − lo. `len(s)` is `CLen`: the length at s, truncated.
- **The rewrite, in two places** (`core/reduce.go`): the loader's `(segments i "F#seg")` form
  rewrites a call whose argument i is `b[lo:hi]` before the state translation, so a lent table's
  segment is the table lent and threaded (`segmentCalls`); a segment that reaches the call only by
  β, a definition's table parameter, is rewritten by the reducer.
- **The declarations**: WriteFile and ReadFile over one table with the count a result; TextOutA over
  one table; GetFileSizeEx, GetFileSize, GetLocalTime, GlobalMemoryStatusEx, GetClientRect and
  GetDlgItemInt with their `_Out_` results; SetFilePointer, whose `_Inout_` LONG stays a cell; every
  other C call respelled. Their callers in `lib/io`, `lib/os` and `lib/win/print`.
- **jdecl** writes `call F`, the argument list omitted where the call is derived.

## 3. What failed first

- **A borrowed table's segment was not threaded.** The variant was first chosen by the reducer,
  after the state translation, so `ReadFile(h, b[lo:lo + n])`'s lent b was not seen as lent: eight
  `cmd/build` tests refused `lib/os`'s read. Moving the rewrite into the loader, before the state
  translation, fixed it, and the borrow path then had to fill the omitted out-results as the call
  path did (`fillOuts`, one function for both).
- **The `(outs …)` clause was lost** through the declaration's round trip (hostdef, `HostDecl`,
  decl.go), so `Prim.Outs` was empty and a call of the declared parameters was a call of too few.
- **The reducer's hook deepened its recursion.** Written inline in `normalizeStep`, the rewrite's
  slices enlarged the frame every reduction step stacks, and Ω under a binder overflowed the stack
  before it exhausted its fuel (`TestDiagnosticsUnderABinderKeepTheirNames`). It is now a function
  of its own, kept out of line.
- **A segment's end computed twice was unproven.** `win/print.write` guarded `lo + n > len(b)` and
  then passed `b[lo:lo + n]`: the IR has no CSE, so the arm's `lo + n` had no bound from the guard,
  the variant's end was outside the signed word, and `write` was no longer kept (ADR 0113). The
  program now names the end once, after lo and n are known natural, and guards that name; `write`
  is kept again, its one operation proven.
- **A planted fault looped.** Under `PlantOutsUnfilled` the translation still judged the call as
  written and translated it again, forever; `asWritten` now asks `fillOuts` itself.
- **Two consumers of the C arguments**: the Win32 prototype check read `len(s)`'s C type as
  unsigned, and TextOutA's count is an `int` (the `where`'s `2^31-1`), so a length's term now
  carries its sign; and it counted the derived variants as hand declarations without prototypes,
  so they leave its list. The interpreter's meaning of WriteFile (`ir/realize_test.go`) is stated
  for both the declaration and its variant.
- **A wall found by the test program, older than this step**: a local buffer lent to a host call in
  a scope that ends in further host statements is refused as a function term (R1), at HEAD too in
  the old spelling. In a scope whose value is a value, `(got, b)`, it builds. Owed, not touched here.

## 4. The tests

- `emit`: `TestAnOutParameterIsAResult` (Outs, the results' order, the four old spellings, `&n` of
  a scalar parameter) and `TestASegmentIsACArgument` (the variant's arguments and `where`, a length
  without its address, twice, or without a width; `PlantNoSegmentVariant`); the C-argument tests
  respelled.
- `cmd/build`: `TestASegmentIsPassed` writes three of five bytes through a definition (the
  reducer's rewrite), seeks back, and reads them into a segment of a local buffer (the loader's),
  printing `3 0 3 0 105 33 10` on windows and windows32. Its three faults each refuse the program
  for their own reason: `PlantOutsUnfilled`, `PlantSegmentsLate`, `PlantNoSegmentVariant`.
  `TestAScalarCellIsTheHostsCell` runs SetFilePointer's cell; `TestACellAfterAnOutCallIsACell`
  now puts PRINTDLGA's cell after GetLocalTime's out-result, its two faults unchanged.

## Paid and bought

- **Compile time**: 1.01× the baseline (median of 67 compiles over 300 ms), no suspect confirmed.
- **Run time**: the gauntlet's 34 generated files are byte-identical, so no benchmarked program
  changed. A segment read or written by `os` on windows computes `lo + n` and the printer `hi − lo`
  where it passed n; LLVM folds the pair, not measured beyond that.
- **Code size**: windows only. 36 emitted files changed: a whole table's length is read at s
  (`load`, `trunc`) where the call passed a parameter, and a segment's length is a `sub`; one
  `alloca` per out-result as before.
- **Proofs**: 8,862 of 8,916 integer operations proven, against 8,852 of 8,906: the ten new ones
  are `os/host.readinto`'s (8 programs) and `writeall`'s (2) `lo + n`, all proven; 924 of 962
  loops, unchanged.
- **Refusals changed**: none, 215 refused as before. New refusals for a declaration: the four old
  spellings, `&x` of a scalar parameter, `len(s)` without its address, twice or without a width, and
  `&r` results not leading the tuple.
- **Compiler lines**: +556 −46 (`core/jreadtarget.go` the reader, `core/outcell.go` and `place.go`
  the filled outs, `core/reduce.go` the two rewrites, `emit/target.go` the variant, `CLen`, `CDiff`
  and the sign, `ir/llvm` their printing, jdecl's spelling). Tests +288 −83.
- **Language lines**: targets and `lib` +119 −103; the declarations are shorter by the parameters
  they no longer take (WriteFile 5 parameters to 2, ReadFile 5 to 2, TextOutA 6 to 4), and each
  caller writes no `out T` and no `lo, n` pair.
- **Emitted text changed per target**: windows and windows32 only; Go, JavaScript and the JVM
  unchanged.
- **A rule made less general**: none. `_Inout_` stays a cell; a program that chose `out τ` itself
  still writes it.
- **Owed**: the R1 wall above; a segment at a C declaration whose variant was not derived is refused
  only by the borrow's arity, not by a message naming the segment.
