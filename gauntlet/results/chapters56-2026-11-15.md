**The two rules already decided now hold in the code, the two correct programs build, and the three
refusals give their true reason.** A value held above the word comes back into it where its fact is
inside the word (28); an export's result is the word its declared set names, on JavaScript's pair as on
every other target (27); a claim is an atom in its set (23); an unstated result is the body's (24); an
empty range is said to be empty, in J (25); JavaScript's quotient and midpoint are refused for the
declared `Int` they break (26); a statement whose value is a function is refused (22, ADR 0116).
Finding 29, `1_000_000` and `0b101`, is deferred as recommended: j.md promises neither and no program
needs one. Every rule has a witness whose planted fault restores the old behaviour. The corpus's
emission is byte-identical on all four targets, refusal texts included.

## What failed first

1. **K(ℕ\*) had no `word`.** On windows the retraction reached the numeral library, which had none. It
   is `dig(a, 0) & dm` with the sign applied. The mask is needed because the interval domain does not
   know a digit is in [0, 2⁶⁴), so `% 2^63` of an unbounded value was refused. The negative case is
   nested `if`s, because a disjunction's π did not narrow `0 - d`.
2. **`claimBounds` stopped at the first non-application.** The claim sits under the redex that β left
   for the inlined call, so it walks into `fn` bodies, and `asLinearIn` reads through a one-parameter
   redex and a `let`.
3. **The unstated result broke a harness.** The fnv64 differential's `main` states no result, and
   JavaScript's new refusal at a declared set refused it. An unstated result declares no set, so the
   rule applies only to a stated one (`stated`).
4. **An explicit `(Any)` and an unstated result were one string**, `any`.
   `TestWithoutAMultiResultSigItIsStillAClosure` writes `(Any)` and expects one result. D now spells
   the unstated result apart.
5. **Two tests pinned the old texts**: the empty range's `(int 100 0)` and the inventory, which now
   lists `big-word`.

  against `fe38917`'s `gen` and none confirmed (`freq` 1.01×, `big-negmid` 1.09×, `big-subdiv` 1.05×,

  host call where a refusal was (`int(v.Int64())` on Go).

  `quotient-corner` on JavaScript took finding 27's reason. Its `run` states no result, so it now
  keeps its own reason, a quotient of a pair by a non-constant. Two correct programs that were

- **Rules made more general**: a value above the word reaches a word position where its fact allows;

- **The book**: chapters 1, 5 and 6 updated where an output changed; every written chapter passes
  `go run docs/book/check.go`.
