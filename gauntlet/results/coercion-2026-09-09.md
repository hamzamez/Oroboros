# The coercion is built, and the host is the oracle

2026-09-09. `emit/target.go`, `emit/check.go`, `gauntlet/stdlib/survey.go`,
`gauntlet/stdlib/acceptance/io-reader.oro`,
[target-files.md §2a](../../docs/spec/target-files.md). The one thing
[interfaces.md](../../docs/interfaces.md) recommended, built — and it says the
research was right about the size and wrong about nothing.

> **`io.ReadAll(f)` with an `*os.File` builds and runs**, printing
> `wc -c < go.mod`. The emitted Go is `b, e2 := io.ReadAll(f)` — **no conversion
> syntax at all**, because `⟦coerce⟧ = id` and the host inserts what it needs.
>
> **ONE DECLARATION, ONE LOOKUP, NO BACKEND.** `(implements T I …)` is a target
> fragment; `Subsumes` is a map lookup in the type checker; nothing downstream
> learns that a coercion happened. **178 of 178 emitted files byte-identical.**
>
> **AND THE HOST IS THE ORACLE, which is the finding.** The api manifest lists
> the EXPORTED API, so an interface sealed by an unexported method —
> `ast.Decl` has `declNode()` — looks satisfied by everything, and the
> structural computation cheerfully claimed `*ast.ArrayType` is an `ast.Decl`.
> **182 of 1,651 candidate edges were false**, and `go build` on a generated file
> of `var _ io.Reader = *new(*os.File)` named every one. The generator now
> **candidate-generates and host-filters**, and emits nothing if the toolchain
> cannot run.
>
> **The prediction was 47 names and the delivery is 41**, usable **44.5% →
> 45.4%**. `net/http` 68 → **77**, `regexp` 42 → **46**. The interface residue
> falls from 47 to **6**.

---

## 1. What was built

```lisp
(implements ptr-os-File io-Reader io-Writer io-Closer …)
```

A target-level declaration beside `(type …)`, and three small things:

| | |
|---|---|
| `Target.Implements` | `T → the interfaces it satisfies`, closed transitively at load |
| `Target.Subsumes` | a map lookup — no variance, no inference, no fixed point |
| `checker.agree` | one call, at **the only site with a direction** |

`agree(what, got, want)` is where `got` flows into `want`, and `compatible` is
symmetric. **Subsumption is not**: a `*os.File` goes where an `io.Reader` is
wanted and an `io.Reader` does not go where an `*os.File` is wanted, because the
coercion FORGETS every method but the interface's own and forgetting has a
direction. So `agree` is the only place that could ask, and it is the only place
that does.

**Glue and override are the same operation here**, which no other field can say:
a relation is a set, so two layers both knowing that `*os.File` reads is not a
collision — there is no disagreement expressible, so there is nothing to detect.

**Transitivity is closed at load** rather than spelled: `(implements T ReadCloser)`
plus `(implements ReadCloser Reader)` gives `T ≤ Reader`. A target file that had
to write out every consequence would be stating a closure by hand and getting it
wrong.

## 2. The host is the oracle, and that is what the build taught

The research proposed generating the relation structurally — Go's own rule, a
type satisfies an interface when it has every method at the same signature — and
that is what was written. The first assertion file did not compile:

```
implements_check.go:95:19: *ast.ArrayType does not implement ast.Decl
                           (missing method declNode)
```

**The manifest is the EXPORTED API.** `ast.Decl` is `{ Pos, End, declNode }` and
the third is unexported, so the manifest shows two methods, every AST node has
them, and the rule concludes that every AST node is a `Decl`. It is not a bug in
the rule — the fact is not in the manifest, and no amount of care with the
manifest recovers it.

So the generator is **candidate-generate, host-filter**:

1. compute the candidates structurally — **1,651**;
2. write them as `var _ I = *new(T)`, one line per edge;
3. `go build -gcflags=-e`, map each error line back to its edge, drop it;
4. repeat until the file compiles — **one pass**, 182 dropped;
5. emit the **1,466 survivors** as `(implements …)`.

`*new(T)` rather than `(T)(nil)` because it is well typed for every `T` — a
pointer, an interface, and `os.FileMode`, which is an integer.

> **Every edge this language relies on has been accepted by the Go compiler.**
> That is a stronger guarantee than any `prim` template carries: a template is
> checked only when some program happens to call it.

**And if the toolchain cannot run, no edge is emitted.** An unverified edge is a
claim, and a claim that makes our type checker accept a program the host refuses
is precisely the failure this avoids. The refusal is loud and the number is zero.

One bug on the way, and it is the shape to remember: the line-number map was
computed from a *guess* at the header length, so no error ever matched an edge
and the refinement dropped nothing while reporting the same 182 errors twenty
times in a row. **A loop that reports identical progress is not converging
slowly, it is not moving** — the fix is to count the newlines actually written.

## 3. Measured

`gauntlet/stdlib/acceptance/io-reader.oro`, every declaration generated:

```lisp
((gos.Open "go.mod") (fn (f e1)
  (if (gos.err-nil e1)
      ((gio.ReadAll f) (fn (b e2) … (io.print-int (len b)) …))
      (io.print-int 0))))
```

emits `b, e2 := io.ReadAll(f)` and prints **72**, which is `wc -c < go.mod`.

**The control is exact.** Strip the `(implements …)` lines and the same program is
refused:

```
build: main: in go/io.ReadAll's argument 1: f is ptr-os-File,
       but io-Reader is required here
```

### 3.1 What it buys, against what was predicted

| | before | after |
|---|---:|---:|
| **usable** | 44.5% | **45.4%** |
| func usable | 66.5% | **68.2%** |
| method usable | 31.5% | **31.8%** |
| cannot build the argument | 46.2% | **45.1%** |
| `net/http` usable | 68 | **77** |
| `regexp` | 42 | **46** |
| `encoding/json` | 26 | 26 |
| blocked ONLY by a suppliable interface | 47 | **6** |

**41 names**, against a prediction of 47 — the difference being the 182 false
candidates the host removed. interfaces.md said *build it because it is nearly
free, not because it moves the number*, and 0.9 points is what that looks like.

The six that remain are blocked by an interface we can supply **and** something
else; the 87 blocked by an interface we hold nothing for are unchanged, and they
are tier 3.

## 4. Cost

| | |
|---|---|
| emitted files | **178 of 178 byte-identical** |
| differential suite | 30 cases, four targets, green |
| unit tests, `go vet` | green |
| compiler code | `Implements` field, `closeImplements`, `Subsumes`, one call in `agree` |
| new term kinds, reduction rules, backends | **none** |

One test, with the control that makes it mean anything: the same program is
accepted with the edges and **refused without them**, and the refusal must name
both types. It also pins transitivity (`file → rc → reader`) and antisymmetry
(`reader` does not go where `file` is wanted).

## 5. What it leaves

**The residue is not interfaces and never was.** 1,867 declarable-and-unusable
names are blocked by something that is not an interface: **struct arguments built
by literal**, and types no declarable function returns. That is products.md §7's
deferred layout arriving from one side and Win32's struct-by-value 13.9% arriving
from the other — two independent questions converging on one missing thing, which
is the best evidence this repository uses.

**A naming hazard, recorded rather than worked around.** A generated target file
called `go/os.oro` beside a program is found by `(use go/os)` as a LIBRARY module
and read with the wrong grammar, because layers made a target directory and a
library directory the same kind of thing. The acceptance recipe puts generated
files in `tg/go/` under a different basename; whether the two searches should be
distinguishable is a target-system question, not a bug in either.

**And `interface{}` is still nothing special.** It is the top of the lattice, so
every type is below it — but `any` already means *demands nothing* in the checker,
so it needed no edge and got none.
