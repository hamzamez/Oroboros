# `cond`, and the rule that makes it free

2026-09-19, following [letflat](letflat-2026-09-19.md) the same day. `core/read.go`,
`core/sugar_test.go`, thirteen sites in the corpus, `README.md`,
[booleans.md §4.2a](../../docs/spec/booleans.md).

[binding-surface.md §5](../../docs/binding-surface.md) measured `cond` against the nested `if` and
concluded it was free. Adopting it showed that was **half right**, and the other half is a rule.

## 1. What the research got wrong

`wc.oro`'s three outcomes as three clauses, emitted to Go:

```go
-  if (err == nil) {                       // the staircase
+  if (!(err == nil)) {                    // the clause chain
+      fmt.Println("wc: cannot read that file")
```

Same proof counts, same program — but **not the same code**. The `not` a flat chain needs to put the
failure case first survived into the condition, so the emitted branches came out in the opposite
order with a `!` in front. The research's second bullet claimed otherwise and is corrected in place.

That is a real cost, twice over. `!(err == nil)` is not what a Go programmer writes, which is this
project's standard for emitted code; and the refinement layer reads its facts off **comparisons**, so
a comparison wrapped in a negation stops being one — the same hazard `wc.oro`'s own comment records
about writing two conditions as one `and`.

## 2. The rule

```
(if (not c) a b)  ⟶  (if c b a)          a, b not boolean literals
```

**Not a new rule**, which is the point. `(not c)` reads as `(if c false true)`, and the language
already has case-of-case and `(if true a b) → a`:

```
(if (if c false true) a b)
  ⟶ (if c (if false a b) (if true a b))     case-of-case
  ⟶ (if c b a)                              evaluation
```

so the identity is a theorem of rules already written down. What is new is *when* it is applied: the
reader performs both eagerly, at the one place it builds an `if` (`core/read.go`'s `mkIf`, used by
the `(if …)` form and by `clauseChain`, which `cond`, `loop` and `match` share).

**The side condition keeps a connective a connective.** `(and a b)` is `(if a b false)` and
`(or a b)` is `(if a true b)`, so a boolean literal in either branch means the term is an operator
every backend emits as one (`emit/connective.go`). Swapping there would turn `!p && q` into a
conditional — lowering further than the target requires, which is the objection ADR 0012 raised
against booleans in the first place.

Witnesses in `core/sugar_test.go`, both shown to fail against a planted bug:

| test | pins | fails when |
|---|---|---|
| the swap | `(if (not p) a b)` = `(if p b a)`; double negation collapses; a `cond` chain and a `loop` clause both get it | the swap is removed |
| the control | `(and (not p) q)`, `(or (not p) q)`, `(not (not p))` and `(if (not p) true b)` are **unchanged** | the literal side condition is dropped |

## 3. Adopted, and where it was not

Thirteen sites, chosen from the thirty if-staircases a scan found:

| kept | |
|---|---|
| `wc.oro` | the README's line counter — three outcomes, three clauses |
| `jsonfmt.oro` `tok-end` | string / number / bare word |
| `tree.oro`, `json-tree.oro` | the scalar clause's `tg` and `ni`, two three-way choices inside one `let` |
| four `run` entry points | `(= k 0) … (= k 1) … (= k 2) … else`, in both JSON programs and their differential twins |
| `sum/parse.oro` `step` | divide by zero / not divisible / ok |
| `tally/host-go.oro` `capture` | two groups / one group / none |
| `negative-zero.oro` `run` | three arms of a differential case |

**Not adopted, and the reason is a shape rather than a rule.** Seventeen staircases are *clamps* —
`(if (< i 0) 0 (if (>= i (len t)) 0 (t i)))` — where two of the three outcomes are the same value.
As a clause chain they take four lines to say what one line says, and the flatness buys nothing
because there is no third outcome to read. Two more sit inside an argument to `again`, where a
`cond` block reads worse than the expression it replaces. Both were converted first, read, and
reverted: the rule adopted here is *three outcomes, three clauses*, and a clamp has two.

## 4. Acceptance

`go run ./cmd/check`: **456 runs, byte-identical to the baseline**, 2,361 of 2,413 operations bounded
and 345 of 382 loops proven — unchanged — with the differential suite green on four targets and the
tooling suite green. So the adoption is a change to what the programs look like and to nothing else,
which is only true because of §2.

The README's line counter was rebuilt and run: 471 lines of `CLAUDE.md`, agreeing with `wc -l`. Its
stated output was corrected from 455, which had gone stale as the file grew.

## 5. Not built

- **n-ary `+`/`*`**, and the reader owning arity for `(+ 1 2 3)` — recommendation 4 of the research,
  which rests on the monoid law and a measurement of its own.
- **A `cond` in `emit/bignum.oro`, `emit/winmap.oro` and the big-integer cases**: all clamps, §3.
- **Any change to `match`**, whose clause chain already shares `clauseChain` and therefore already
  gets the swap.
