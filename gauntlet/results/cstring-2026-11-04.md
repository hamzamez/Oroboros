# cstring-2026-11-04: C strings, the code page, and the allocator as a term

hamza's decision on mastretire-2026-11-03's wall ("go ahead with your recommendation"), and his
question why `lang.alloc` was still LLVM IR in a string. Three things built, ADR 0091 and 0092; three
put on the plan with their triggers.

## The algebra

- **C strings** (ADR 0091). ν : Σ* → (𝔹, ∨, false) is the monoid homomorphism true exactly on
  U+0000. The C strings are its kernel, the free submonoid on Σ ∖ {0}. Since ν is a homomorphism,
  its abstraction is complete for `++` (abstract ∨), so membership is decided exactly by evaluating ν
  on the argument's term:
  - a literal by its scalars;
  - `string_of(c)` by c ≠ 0;
  - `a ++ b` and a conditional by both sides;
  - anything else by an identical assumption, the guard `if nulfree(s)`, which is the checked
    conversion.
- **The code page.** The `A` functions read bytes in the process's code page. With UTF-8 declared,
  the identity s ↦ s + 8 is their encoding on the whole kernel.
- **The allocator** (ADR 0092). alloc : ℕ × {1, 8} → Region is a term over kernel32 and Σ_LLVM,
  total: a request past ⌊(2⁶³ − 9)/8⌋ elements is exhaustion, the trap a null region already is. The
  allocation is an operation of the IR, so ι reaches it and the decision proves n·w + 8 (`mul nsw`).
  Bounding by the widest element makes that linear; n ≤ ⌊K/w⌋ ⇒ n·w ≤ K is not.

## What failed first

- **A host's `where` is decided apart from a definition's.** `refine.go`'s `discharge` decides it, so
  the first build refused `lstrlenA("hello")`. Both routes now call `nulFree`.
- **The guard's first form, n > ⌊K/w⌋.** n·w ≤ K is nonlinear in w, so the instance, decided once over
  w ∈ 1..8, was refused. Bounding by the widest element made it linear.
- **Under `-checked`, `json-tokenize`'s table length came from a trapped operation, unbounded below.**
  The term's n·w was then unproven at the site. The guard now states its whole domain, 0 ≤ n.
- **A crash's newline, `array { 10 }`**, is made by a term ι substitutes after the storage pass, so it
  had no storage. Storage and ι now iterate to a fixed point.
- **ι changed what the program proved.** With storage, `json-tokenize` lost 12 proofs (148 of 164
  against 160 of 160). The cause was the intervals' widening thresholds: the term's n·8 and its guard
  joined the set, so a loop counter climbed past where it stopped within the 16 threshold rounds.
  Bisected by table kind, and fixed at the principle: legality is decided before ι (ADR 0090), so a
  term's statements are not the program's thresholds. Any set is sound.

## What was measured

- **The Windows sieve**, 21 interleaved process runs each, twice: the allocator as a term ran at 0.70
  and 0.68 of hand-written MASM, the template at 0.70 and 0.67. No difference.
- **Counts**: 4,999 of 5,059 operations and 492 of 516 loops, the 60 and 24 left unchanged: the new case is proven, and so is every allocation. **Emission**: each windows program that makes a table, its allocator inlined; the gauntlet byte-identical; compile time 0.98×.

## Not built, on the plan with their triggers

- A C string from Win32 into ours (`strlen` and a copy, total, into the kernel): a call returning or
  filling one, TinyRetroPad's `GetWindowTextA`.
- The list of C strings, (B*₀)* → bytes: TinyRetroPad's open-dialog filter.
- The `W` functions' UTF-16: a `W` function.
- `string_of` and `++` on windows as terms over the bytes: they need V, the valid-UTF-8 refinement,
  by the same argument as ν. Trigger: the next change to `strings.oro`, or V's first use.
