# defects-2026-10-26: three defects the documents' audit found, each a rule

The 10-24 plan's item 3 (hamza, 2026-10-25), from docs-2026-10-25 §3. Each was a message or a missing
check; each is now a rule stated, built, and shown to fail on a planted fault. Emission is byte-identical:
no corpus program met any of them.

## 1. No module defines a language name

**The set.** Σ_L, the language's signature, is the names J's reader and `Load`'s expansions emit bare:
`if c { a } else { b }` is `if`, `a + b` is `+`, `t[i]`'s length `len`, `expect`'s failure `abandon`.
A module of a program is a theory extending the language's, and a **definition introduces a fresh
symbol** (a definitional extension, Shoenfield 1967 §4.6). A definition of a symbol of Σ_L is no
definition: it redefines the symbol J's syntax is read as.

**What it did, measured before the fix:**

| | result |
|---|---|
| `fn \`+\`(a, b) { 7 }` in the root, `x + 1` | compiled, the target's `+` used (ADR 0002's ▷), the definition ignored with a note |
| `module m { fn if(c, a, b) { 7 }; pub fn f(x) { if x > 3 { 1 } else { 2 } } }` | **compiled to `return 7`**: resolution qualified the module's `if`, so the construct called the definition, and `m.f` answered 7 whatever `x` was |

The audit had seen only the first, a note where state.md said "an error". The second is a wrong answer.

**Built**: `core.LanguageSignature`, checked in `Load` before any resolution, in every module; the refusal
names the reason. The target side's lists (`emit`'s `coreNames`, `langOps`) are held inside it by
`TestATargetsForbiddenNamesAreTheLanguages`, so the two sides of one rule cannot drift.

## 2. The recursion refusal names the construct the language has

It said "iteration is fold-range (ADR 0014)", a construct that left with the portable layer
(portable-2026-09-29). It now gives the reason and the construct: "recursion is not in the language,
since δ unfolds a definition and a cycle has no normal form (ADR 0014). Iteration is `loop` with `again`
(ADR 0015)". **A test had pinned the stale text**: `TestScopeCheck` required "fold-range", so the
message could not have been corrected without the test failing. It now requires `loop` with `again`, and
`TestRecursionIsRejected` refuses "fold-range".

## 3. A set has no representation

**The algebra.** A set denotes an element of 𝒫(V), a static value of the logic (ADR 0063), which never
prints (ADR 0049). A set position reads one: a binder's set, a binder's claim, a former, a `set`
declaration. A computation's position needs ρ, and no set has one. Membership in a computation would be
the characteristic function χ_S : V → Bool, which is not built; for a range it is the derived
lo ≤ e ∧ e ≤ hi.

**What it did, measured before the fix:**

| | result |
|---|---|
| `b = x ∈ 0..9`, `b = 0..9` | refused as "`` is not imported: add `use `": the range `..` reached resolution as a name containing `.`, read as a path with an empty alias |
| `b = Int ∪ Bool`, `x ⊆ y` | refused as "`∪` is not bound" |
| `export fn f(x ∈ 0..20) where x ∈ 0..9 { x }` | **compiled**: an entry point's `where` is assumed, here an atom over the unbound names `∈` and `..` |
| the same `where` on a definition, called as `g(5)` | refused, "does not follow", though 5 ∈ 0..9: the obligation could never be decided |

So the audit's garbled message was one face of a gap: a set operator in a term had no rule, and in a
header it was assumed or undecidable.

**Built**: `setInTerm` in resolution (a computation) and in the reader of a header (`where`, `ensure`):
each set operator is refused saying what it is, with the derived range test for `∈` and `∉`.
