## 2. The answer to "do we still have `def` and `sig`?"

Yes, as **the core's forms**, and no source file writes either. J writes one declaration, the header and
its body, `fn f(x ∈ S) (R) where φ ensure ψ { e }` (ADR 0051, 0062, 0064). D makes two core forms of it:
`def`, the named λ, def(f; λ), and `sig`, its claim, which the type checker and the contracts read. They
are as much J's as `let` (a block) or `tuple` (a pair): words of the term below the surface.

## 3. What the probes found

- **j.md §1.4's reservation is not built.** "Reserved, never an identifier", and `fn f(set) { set }`,
  `spec`, `map`, `export`, `axiom` and others read as names: J's reader takes a word as a keyword only
  where its grammar meets one. Recorded in j.md's status, not changed (a language change, and no program
  has been harmed by it).
- **Three of the core's refused spellings are reachable from J** (`int_repr`, `big_repr`, `max_len`, as
  model forms of a target file), and their messages already name J's replacements. The inventory's rows
  now give J's spellings.
- **A program may define a language name.** `fn if(x) { x }` compiles, with a note that the target's
  `if` is used; state.md §2 said declaring one is an error, which holds for a target file only. Recorded
  as a gap in state.md §2.
- **Two messages are wrong.** The recursion refusal says "iteration is fold-range", a construct deleted
  long ago (`core/reduce.go` `checkRecursion`). `x ∈ 0..9` as a value is refused with
  "`` is not imported: add `use `", a quoted empty name. Neither changed here: a refusal's text is
  pinned by the emission baseline where a corpus program meets it, and both are outside this item.
- **`x'` in a program's `ensure`** is read and then refused as outside what the compiler decides; it
  was listed as built.
