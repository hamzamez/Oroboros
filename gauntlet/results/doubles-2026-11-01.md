# doubles-2026-11-01: doubles, each rounding its target's call (ADR 0086, numbers.md §9 part 4)

Part 4 of step 1 of [ADR 0086](../../docs/decisions/0086-a-number-is-an-element-of-z-tenth-and-a-rounding-is-its-one-lossy-operation.md):
F64 as a set of N held as a double, and the gauntlet's six float programs in the language's numbers.
Program first: dot, centroid and search are now one source each for Go, JavaScript and Java, where
each target had its own copy because the arithmetic was the host's.

## What was built

**F64 is a set, the double its representation** (numbers.md §2, §6.2):
- The abstraction function d(x) is the real a finite double denotes: onto F64, with d(−0) = d(+0). So
  N's order and equality on two doubles are the host's comparisons, exact (IEEE 754 §5.11), and
  negation is the host's, F64 being closed under it. W5 admits these and no other operation on doubles.
- **A separation of F64 by constant bounds is F64 ∩ [lo, hi]**, canonically `f64 LO HI`
  (`core.F64Grid`): the set whose characteristic function is χ_F64 ∧ lo ≤ x ∧ x ≤ hi. The reader gives
  it that form wherever a set may stand, a table's element included, which no other separation may
  be yet. An omitted end is ±MAX, and both forms are the same set.
- A negative numeral is one literal, `-0.5`, as a negative integer is.

**A rounding onto F64 is a rewrite by the target's equations** (`ir/doubles.go`):
- A declaration `fn fadd(a ∈ F64, b ∈ F64) (r ∈ F64) pure ensure r == round(F64, a + b) { … }` is the
  equation round(F64, a + b) = fadd(a, b), read right to left. Go, the JVM and JavaScript each declare
  `fadd`, `fsub`, `fmul`, `fdiv` and `fint`, the conversion of an integer in ±2⁵³.
- The match is modulo the commutativity of + and ·, and a pattern variable binds only a leaf: a value
  no operation of N defines. So an inner rounding is a leaf, and two roundings are two calls.
- Go's `fmul` is `float64(${a} * ${b})`: Go's specification lets `x*y + z` fuse "possibly across
  statements" unless a conversion rounds the product.
- A rounding of constants folds when compiling, by rational arithmetic, to the nearest double, ties to
  the even one. `round(F64, 0.1 + 0.2)` is 0.3's nearest double, since the sum is exact, and IEEE's
  0.30000000000000004 is `round(F64) { 0.1 + 0.2 }`, three roundings.
- **A double compared with a constant is compared exactly, by a Galois connection**: ι : F64 ↪ ℚ has
  both adjoints, so x < q is x ≤ ⌊q⌋ when q ∉ F64, and x = q is false there. `x < 0.1` prints as
  `x <= 0.09999999999999999`, and `0.1 <= x` as `x >= 0.1`, the double just above one tenth.

**The scope `round(F64) { … }`** (numbers.md §3): D rewrites each `+ − · ÷` and numeral of its body
to a rounding the scope wrote. One whose operand has sort ℤ is the identity, decided on the IR's least
sorts and, conservatively, on the residual (`emit.Unscope`), so `i + 1` still indexes. A rounding
written inside is the program's own. This is IEEE's reading, where an integer operation is not a
floating one, and round(S, t) has sort N exactly when t has, so no operation's sort changes.

**The obligations, decided on an interval domain over the reals with double ends**, each operation
rounded outward (Moore 1966):
- each rounding's term within ±MAX, which makes the nearest rounding finite;
- each ÷'s divisor away from 0, and each conversion's integer in ±2⁵³;
- F64 ∩ [lo, hi] onto which a rounding goes, at a declared result, and at an internal function's
  parameter (ADR 0028), the last a mark the require route decides on the doubles' facts;
- an accumulator, by **Theorem A**. Its lemma: for q ∈ F64 and the nearest rounding r,
  |r(q ± y) − q| ≤ 2|y|, because r(q ± y) is an element of F64 nearest q ± y and q is one; and
  |r(q·y)| ≤ |q| for |y| ≤ 1. So an accumulator moves by at most twice its increment per step, and
  |p| ≤ |p₀| + T·β over T back edges, at any magnitude, subnormals included.

**A host's double is refused where the language's numbers read it** (numbers.md §6.3): a double a
call computed that no realization made, and what the dataflow carries one to, may not be a rounding's
operand or stand in N's order. `round(F64, go.f/(a, b) * 0.5)` is refused, saying that a host's double
may be NaN or ±∞. It may stand where the host's own operations read it.

**The ports:**
- `examples/native/dot.oro`, `centroid.oro`, `search.oro`: one source each for three targets. Each
  keeps what it tested, dot its delayed vector and centroid its Church-encoded point. Their entries
  are in `set { x ∈ F64 : -1e100 <= x && x <= 1e100 }`, which makes every rounding finite over any
  length the word counts (Theorem A), with no check at run time.
- `generic-*`, `report-*`, `smooth-*`: the arithmetic is the language's, and the maps, printing and
  buffers stay the host's, one source per target.
- Java's harness calls `centroid` where it called `centroid_x`, the name the other two had.

## What was measured

- **Agreement**: every harness's check passes, Go's `go test`, JavaScript's `native.mjs`, and Java's
  `NativeBench` ("agreement: ok").
- **Parity**, against the hand-written code, serial runs, medians:

  | program | Go | JavaScript | Java |
  |---|---|---|---|
  | dot | 0.97 (434 / 445 ns, n = 1,024) | 1.05 | 1.00 (n = 65,536 and 1,024) |
  | centroid | 1.00 | 0.97 | 1.02 |
  | generic sum | byte-identical emission | 0.94 | byte-identical emission |
  | search late | byte-identical emission | 1.00 | 1.02 |
  | smooth, allocating / reusing | byte-identical emission | 1.03 / 0.95 | byte-identical emission |

  All inside the 15% noise floor. Where the emission is byte-identical to the Tier 2 version's, the
  language's numbers reached the instructions the host's names did. Go's product conversion costs
  nothing on amd64.
- **The roundings on every target** (`gauntlet/differential/cases/f64-round.oro`): seven roundings at
  a tie or next to one, each compared exactly with its double, answer 1 on Go, JavaScript and Java.
  Planted: Go's `fadd` printed as a difference answers `0 0 1 1 1 0 0` there.
- **Tests**, each rule with its fault planted and seen (`ir/doubles_test.go`, `ir/golang`): the
  realization on three targets; two roundings never fused, with a fused multiply-add declared by the
  test; comparisons with constants exact on each constant's neighbouring doubles; constants folded to
  the nearest even; an accumulator bounded by its trip count, a doubling and an untripped sum refused;
  a host's double refused; the scope's identity on ℤ; F64 ∩ [lo, hi] at a call.
- **The corpus** (`cmd/check`, accepted): 4,801 of 4,853 integer operations proven and 502 of 525
  loops, against 4,773 of 4,825 and 497 of 520; every change is the ported programs' and the new
  case's, and every other program's emission is byte-identical. The emission sweep's compile time is
  1.15× the baseline, under the gate. All 26 gauntlet files are regenerated, and every printer
  reproduces its file from the IR's text.

## What failed first, what it cost

- **`where len(a) < 2^16` never reached the loop**, at HEAD with integers too. The assumption narrowed
  the length of a π of the table, not the table the loop measures, because `narrowAssumed` followed a
  value's π to its source and not a table's. dot-go's `i + 1` had been proven by the word's bound on a
  length alone. Repaired: a table's π is followed as a value's is.
- **The first accumulator rule needed T·m ≤ 2⁵¹**, from a relative error (1 + 2⁻⁵²)^m per step, which
  fails at the word's bound on a length: the harnesses' 65,536 elements are past the old programs'
  `len(a) < 2^16`. The lemma above needs no relative error, and spec §5's magnitude rule,
  e(x) = max(e(x₀), e_y + t) + 1, was false for a rounded accumulator in any case. The spec now gives
  the lemma and Theorem A.
- **The IR's typing decided an operation's sort in the order it met its operands.** In
  `loop s = 0 { … again(round(F64, s + i)) }`, `s + i` was met before the continue made `s` a double,
  and `s`, sharing the literal 0's class, was made N. Repaired by two least fixed points over the
  dataflow, the values of sort N and those held as doubles (`numSorts`), through tables, builds,
  stores and rules.
- **The refinement layer read a double's `x > 9` over ℤ**: `NumNames` counted N's names and not the
  doubles', which until now only reached host calls. Doubles are names of N there now.
- **The checker's loops and conditionals had no join of ℤ with F64**, and an exit before the `again`
  that widened its variable was refused in that round. Each round that widens is walked again, both
  arms of a clause before either's refusal, with `numJoin`: ℤ ∨ F64 = F64, anything ∨ N = N.
- **`SelectNumbers` did not renumber the values it made**, so the printer did not reproduce its file
  from the IR's text, nine programs, ADR 0038's invariant. It ends with `Canonicalize` now, as every
  other pass that makes values does. Part 3's decimals had passed only because a later pass renumbered.
- **A negative numeral was a host call**, `(- 0.333…)`, typed as an integer, so a comparison with it
  converted it. The reader folds it now.
- **The differential case's first two forms did not test the targets.** Its driver calls `run(1)` with
  literals, which fold, and a table's elements are one interval, so a divisor read from one may be its
  zero fill. Its operands come from a buffer, each read taken mod 2⁵³ − 1, and its divisors are literals.
- **A heredoc ate backslashes three times**, CLAUDE.md's lesson; the Edit tool repaired each.

## What was not built

- **The host's double as its own type, and the decode** (numbers.md §6.3). The taint closes the
  soundness hole; the type would move every target's float declarations and the surveys' map of
  `float64` to F64, and the decode needs an option of a double on Java and JavaScript. Until then a
  Tier 2 declaration types its result F64, and a program returning one at an export claims the host's
  value, as before.
- **`sqrt`, a fused multiply-add**: no target declares either as a realization yet; floats-research
  §19.2's `math.FMA` and `math.Sqrt` are the next declarations, and JavaScript has no fma.
- **The directed modes onto F64**, F32, a rounding onto F64 of a decimal, `-checked` for a rounding,
  and the windows target's realizations, which wait for `ir/llvm`.
- **JavaScript's table of doubles is `new Array(n).fill(0)`**, where `report-js` had a `Float64Array`;
  a `repr` of F64's tables as `Float64Array` waits for a program measured by its speed.
