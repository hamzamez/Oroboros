# A target may define: `D_T`, and tally is one program

2026-09-16. `core/reduce.go`, `core/read.go`, `emit/target.go`, `cmd/{build,gen,oro,intervals}`,
`examples/tally/`, `gauntlet/stdlib/tooling_test.go`, `core/targetdefs_test.go`,
`emit/declforms_test.go`.

Step 5 of the build order in [theories-b-or-c.md §9](../../docs/theories-b-or-c.md): *"tally is one
program on two hosts, and its output is byte-identical to today's on the sample log and on the suite's
`(a)?b` case."*

## 1. What it is

A target has always been able to say how a host **spells** a name — `P_T`, the primitives. `D_T` lets it
say that the host **defines** one, in Oroboros. [target-system.md §6.2](../../docs/spec/target-system.md)
put it as one more use of the operator every layer already composes by:

```
impl  =  P_T  ▷  D_T  ▷  D
```

Five cells instead of modules.md's four, and **nothing in the reducer changes**: a name in `D_T` is more
entries in the definition environment, and δ unfolds it exactly as it unfolds a library's. The one genuine
restriction is a stratification — a target library may `def` and never `sig`/`type`/`structural`, because
`P_T` is reduction's parameter and may not depend on reduction — and it holds by construction: `D_T` goes to
the program loader, never to the primitive table.

theories.md §5.4 spells it as an assignment inside `provides`:

```lisp
(provides go tally/host
  (use go/regexp as re)
  (def compile (fn (p) (re.MustCompile p)))
  …)
```

## 2. Where it enters, and why there

Target files are read by the target loader and programs by `core.LoadWith`; `D_T` crosses from one to the
other as `core.Form`s. **It is injected AFTER the import fixpoint**, and that is not a detail: declaring the
module up front puts its path in `seen`, and the library file that really defines it would never be read.

Composition is the usual per-name rule, tested both ways: a `def` repeated within a layer is refused, and
between layers the nearer wins. Against a **library's** own definition the target's wins too — `D_T ▷ D` —
and the build says so in a note, as it already does for a primitive shadowing a definition.

## 3. Demand-driven, which the first build was not

The first build injected every target definition into every program, creating the module where no file
declared it. **`hello.oro` was refused** — *"in tally/host.capture: go/regexp/Regexp.FindStringSubmatch is
not bound"* — because the emission sweep's search path reached `examples/tally/host-go.oro`, and
`CheckProgram` reads **every** definition, not only what reduction reaches.

The rule is the one covering already follows: **a module the program does not import contributes
nothing**. A target-provided module is exactly a `use` that found no file (modules.md §4), so `D_T` creates
a module only for a path in the program's unresolved set, and adds to one only if a library declared it.
`TestATargetsDefinitionsForAnUnusedModuleAreNotInTheProgram` fails with the guard removed.

## 4. tally

`tally-go.oro` and `tally-java.oro` are gone. Each was an entry program that built a six-closure `(tuple …)`
and passed it to `tally.run` — an ML functor applied at compile time, written by hand, which is what
theories-b-or-c.md §2.1 said a build already is. Now:

- `examples/tally/tally.oro` exports `main` and writes `(use tally/host as h)`;
- `examples/tally/host-go.oro` and `host-java.oro` are `(provides go tally/host …)` and
  `(provides java tally/host …)`, library fragments beside the program, found by the loader's existing
  `provides` walk.

**The emitted Go is byte-identical to the old entry's** — 16,291 bytes, no diff — and the program prints the
same on the sample log. The tooling suite builds both hosts from `tally.oro` and checks both inputs (the
sample log, and `(a)?b`, where the JVM's group is `null`) against hand-written Go calling `regexp`. **Lines of
Oroboros: 15 + 19 + 98 = 132 → 12 + 16 + 101 = 129.**

## 5. One finding: the six are bound once, and the comparator is why

The natural rewrite writes `h.cmp` at each use. **It is refused**:

```
tally.main: (cs u) is an indexing, and (< u (len cs)) does not follow
```

Bisected over the six operations, one substitution at a time: **only the use inside the sort comparator
loses the proof** — `(fn (u v) (< (h.cmp (cs u) (cs v)) 0))`. The same comparator with `cmp` a λ-bound
parameter proves. Both reduce to the same function; what differs is **when**: β substitutes a parameter
before the comparator is handed to `msort`, and δ reaches a global inside a lambda at a different point in
normalisation, after which the refinement layer no longer carries `len cs = n` to the index. So `tally.oro`
binds the six once, destructuring `(tuple h.compile … h.show)` at the top of `tally`, and says why beside
it.

**Recorded, not fixed.** A meaning-preserving edit changing what can be proved is the shape
frozen-2026-08-28 once withdrew as a soundness bug in disguise; here no answer is wrong, a proof is lost, and
the witness is one line to reproduce.

## 6. A fragment is not a program

A file holding only `(provides …)` used to be read as a program whose top-level term applied an unbound
`provides` — *"provides is not bound"* for `lib/io/go.oro` on windows, *"re is not imported"* for the new
files. `(provides …)` is now a form the program reader skips, and `cmd/gen` and `cmd/build` refuse a file
that says nothing else **by what it is**: *"a target fragment — it declares (provides …) and nothing else, so
there is no program here to build"*. Six existing refusal messages changed to it, accepted.

## 8. Not built

- **"A `provides` may not declare a new name."** A target-provided module has no theory file to check the
  assignment against — which is tally's case exactly. The check needs `sig`s written in a theory module, and
  none is.
- **The three `//go:embed` libraries** (`bignum.oro`, `bignum-host.oro`, `winmap.oro`) still ship through Go
  passes; `D_T` is now the mechanism they could move to.
- **The comparator** of §5.
