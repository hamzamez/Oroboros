# du-2026-10-14 — a directory walk, program first, and three faults it found

The gauntlet program of surface-design installment 6 (assessment-2026-10-14 §5.2: each installment
tested on a real program). `examples/os/du.oro`: how many bytes the regular files under a directory
hold, how many there are, and how many directories, symbolic links not followed. Written in today's
notation first, so the D and J renderings in installment 6 are translations of a program known to
work.

## 1. What it is

A fold of a finite rooted tree (ReadDir lists a node's children; a symbolic link is a leaf) into
(ℕ_C, ⊕)³, x ⊕ y = min(x + y, C), C = 2⁶² − 1: commutative and associative, so the order of the walk
does not matter, and saturating, so the program says what happens past C. C is chosen so that two
members sum inside the word: x + y is computed exactly and compared with a constant, which an interval
sees. No recursion (ADR 0014): one loop over a cursor (the current listing and an index into it) with a
stack of directories in a buffer of 4,096 paths; a directory found with the stack full is counted and
reported, not entered. A directory it cannot read is counted; ReadDir is a partial success
(ADR 0044), so its partial listing is still walked.

**Proven**: 19 of 19 integer operations, 1 of 2 loops (the walk's termination depends on the file
system). **Checked**: the acceptance harness builds it, runs it on a tree of five files at four
depths, and compares with the totals from du's definition (`duReference`); by hand against Go's
`filepath.WalkDir` on `examples/` and `docs/`, the same totals.

## 2. The declarations it needed, checked against the host

- `targets/go/io/fs.oro` (new): `DirEntry` and `FileInfo`, interfaces checked against Go's manifest;
  `FileMode`'s `IsDir` and `IsRegular`, checked against the survey, with three planted mistakes.
- `targets/go/path/filepath.oro` (new): `Join`, variadic over one type, one declaration (ADR 0046).
- `os.ReadDir`, a partial success, in `targets/go/os.oro`.

## 3. What failed first, in order

1. **`again` inside a hand-applied λ** (a host call's continuation written as `((os.ReadDir d) (fn …))`)
   is refused by the reader: a λ's body is never a tail (ADR 0051). Rewritten with a tuple pattern.
2. **An `again` inside a join point**, the body of a tuple pattern over a loop, is not built
   (tables.md §2.5): one loop per directory handing totals back. Rewritten as one loop over a cursor.
3. **A counter's bound across iterations**: `sat`'s declared result says nothing where it is inlined,
   and x + y ≤ M held only under the guard y ≤ M − x, a relation intervals cannot keep. Saturating at
   C = 2⁶² − 1 makes every bound visible to an interval.
4. **A program's `(the S e)` did not lower** (a fault, §4.1), found while ascribing `sat`'s result.
5. **Law S refused a set in a claim position** (a fault, §4.2).
6. **The stack's element**: filled with `""`, our string, it could not hold `Join`'s host string;
   filled with the root by a rule, `(fn (k) root)` (a fill by a name is a copy, thaw).
7. **sp ≥ 1 in the IR**: the refinement layer proved the pop's index from ¬(k ≥ len ∧ sp = 0) and
   k ≥ len (unit resolution, refinements.md §5d), and sp ≠ 0 beside sp ≥ 0 (§3c); the IR's intervals
   have neither rule, so `(- sp 1)` was not proven in the word. Reordered: the entries first, then
   `(< sp 1)` as the exit, a bound both analyses read, and the clearer program.
8. **The IR typing's order** (a fault, §4.3).
9. **An unused import**: the survey gives `FileMode`'s methods `(import "io/fs")` though their template
   names no package; Go refuses an import nothing uses (§4.4).

## 4. The faults, each with a witness that fails without its fix

1. **A program's ascription did not lower** (`core/desugar.go`). D wrote `(the S e)`'s set as a term,
   and every consumer reads a canonical type string; `int` was lowered as a value. The interval route,
   which lowers the residual to decide a range obligation, failed silently and left every mark to the
   route for ranges above the word, which refused in-word ranges as unproven. No corpus program wrote
   `the` in code (claims.go counted 0), so the path never ran. Witness:
   `TestAnAscriptionInAProgramLowers`.
2. **Law S reached claim positions** (`core/reduce.go`, `staged`): ADR 0063's staging check refused
   `int` inside `(the (int 0 9) e)`, a set erasure drops. Witness: in `TestNoSetSurvivesStaging`.
3. **The IR's typing kept the wrong side of a clash** (`ir/typing.go`). Regions were typed outermost
   first, so a loop's results nested in a scope were first met at a later use, a variadic list of boxes
   whose strings fixed them, and the loop's own ints clashed in the verifier (W5, "IR_P does not
   verify"). Typed in program order, each statement's sub-regions after it, a value is typed where it is
   defined. No emitted byte moved in the corpus. Witness: `TestALoopsResultsAreTypedBeforeTheirUses`,
   which fails with the old order, after the first draft passed vacuously because it stopped short of
   the step to IR_P.
4. **The checker's import rule, and its interface reader** (`gauntlet/stdlib/tooling_test.go`). An
   import is needed only by a template that names the package, so a hand method may import nothing where
   the survey imports a package it does not name; planted mistakes show the rule still catches a
   template naming `fs` unimported and an import of the wrong package. The interface reader now reads a
   type the manifest writes unqualified in its own package (`FileInfo` inside `io/fs`), and its planted
   "one result fewer" no longer panics on a method of one result.

**Named, not fixed.** `ir.DischargeRanges` swallows a lowering failure and leaves every mark, so a
residual that does not lower reads as unproven ranges (fault 1's symptom). A read whose table is a
loop's value, `((bn-fact 64 200) k)`, is refused by lowering.
