# Effects — gauntlet program 5, and the ordering discipline

Specified in [docs/spec/effects.md](../../docs/spec/effects.md) **before** the code, which is the
first time this project has done it in that order.

**Result: the discipline costs nothing measurable, program 5 reaches parity on all three targets,
and the core still has not changed shape** — six term kinds, two reduction rules, one parameter.
β gained a side condition; nothing was added to the language except one reader sugar.

---

## 1. What was predicted, and what happened

[g5 §5](../../docs/derivations/g5-bindings.md) predicted that effects would be the first
*correctness* defect where all earlier ones were performance defects. That was right. It also
said effects would **arrive** with program 5, and that was wrong: `dict-inc` has mutated a
dictionary in place since word count, and `dict-empty` has had a fresh identity for just as long.
Program 5 does not introduce effects, it makes them **observable**.

g5 listed two hazards, duplication and context change. There are **three**, and the missing one is
the one that matters most:

| Hazard | Structural rule | In g5? |
|---|---|---|
| the argument is copied | contraction | yes |
| the argument moves into a loop or an arm | exchange | yes |
| **the argument is dropped at zero occurrences** | **weakening** | **no** |

The third is what makes sequencing expressible at all — `(seq a b)` desugars to a β-redex whose
binder is used zero times, so it survives *only* because an impure argument is kept anyway. A
discipline written from g5's two hazards would have had no way to write program 5.

## 2. Cost to the six existing programs: zero

All 28 core tests and 3 emit tests pass unchanged. Every example still reduces to the same normal
form, and five of the six emit byte-identical source.

The sixth changed by two lines. `generated_generic.go` gained a binding, because `dict-empty` is
now impure and is no longer substituted:

```go
-	acc := (make(map[string]int))
+	init := (make(map[string]int))
+	acc := init
```

**Machine code is byte-identical**, checked by `go tool compile -S` before and after. So the
conservative rule — *never substitute an impure term, even at one occurrence* — costs nothing
here, and the precise rule g5 §5 described (compare execution-context depth on both sides) was not
needed. Recorded because the precise rule is delicate and the conservative one is four lines.

This is the project's own standard applied to itself: the clock and the source both suggested a
regression, and [the machine code said otherwise](duplicate-read-2026-08-14.md), for the second
time.

## 3. Program 5, three targets

One source, `examples/report.oro`, reduced against three primitive sets. The normal form:

```lisp
(fn (label xs)
  (let (print-line label) (fn (_)
  (let (print-line (alen xs)) (fn (_)
    (print-line (fold-range 0.0 (alen xs)
      (fn (acc i) (add acc (mul (aindex xs i) (aindex xs i)))))))))))
```

Three effects, in order, once each — and `dot` **still fused into one loop** with no intermediate
vector, exactly as in [g1](../../docs/derivations/g1-dot-product.md). The effect did not block
fusion in the pure part, and fusion did not move the effect. That was the point of the program.

```go
func GenReport(label any, xs []float64) float64 {
	fmt.Println(label)
	fmt.Println((len(xs)))
	acc := 0.0
	n1 := (len(xs))
	for i := 0; i < n1; i++ {
		acc = (acc + ((xs[i]) * (xs[i])))
	}
	fmt.Println(acc)
	return acc
}
```

JS and Java are the same shape. All three compile and run; **the Go output is byte-identical to
the hand-written `Report`**, asserted by `TestGeneratedReportMatchesHandWritten`.

### Parity

Go, `vecA`, 2s × 3, on the usual noisy laptop:

| | ns/op | B/op | allocs/op |
|---|---|---|---|
| hand-written `Report` | 32,676 | 32 | 3 |
| `ReportFast` (bypasses `fmt`) | 32,559 | 64 | 1 |
| **`GenReport`** | **33,565** | **16** | **2** |

+2.7%, well inside the ~15% noise floor — and the generated form writes to a real file descriptor
where the hand-written one writes to `io.Discard`, so the comparison is unfair *against* us.

It also allocates **less**: 2 boxes instead of 3, because `label` is already `any` at the boundary
and needs no boxing on the way into `fmt`. Escape analysis confirms the loop is clean:

```
./generated_report.go:7:27: xs does not escape
./generated_report.go:9:14: len(xs) escapes to heap
./generated_report.go:15:14: acc escapes to heap
```

The only escapes are `fmt`'s own `...any` boxing, which hand-written Go pays identically.

## 4. §6 confirmed, in our own output

`(print-line (dot xs xs))` with `xs = [1, 0, 0, 0]`, so the value is exactly `1.0`:

| | Go | JS | Java |
|---|---|---|---|
| printed | `1` | `1` | `1.0` |

Three targets, two answers, on the simplest possible float. This is the measurement behind
`print-line` being **Tier 2** and carrying no portability claim — previously taken from a
hand-written probe, now reproduced by the compiler's own output.

## 5. Two latent bugs that only a second `stmt` primitive could find

Both had been in the code since word count, and both were invisible while `dict-inc` was the only
statement primitive in existence.

**The result type was never implemented.** Every target file says *"stmt — the value of the term is
argument 0"*. No backend did that; all three returned the *declared* result type. `dict-inc` hid it
by declaring `dict` for both its argument and its result, so the wrong answer and the right answer
coincided. `print-line` is the first primitive where they differ, and Java emitted `Object
genReport` instead of `double`.

**Operand filling was dict-shaped.** JS and Java both did `append(vals, vals...)` with the comment
*"dict-inc names both operands twice"*. That is a fact about one primitive promoted to a rule about
a kind. `fmt.Println(%s)` names one operand once, and produced `console.log(label)%!(EXTRA
string=label)`. Now the template's `%s` count decides.

> **One instance of a kind is not enough to specify the kind.** Both bugs are the same mistake:
> generalising from `dict-inc` to `stmt`. Worth naming because `loop2` and `cond` still have
> exactly one instance each.

## 6. What the `any` type cost

`print-line` is polymorphic on all three hosts — `fmt.Println` takes `...any`, `System.out.println`
is overloaded, `console.log` is dynamic — and a target file cannot declare an overload, because
primitive names are unique.

So `any` became a real entry in the type table (`any` on Go, `Object` on Java, absent on JS, which
has no types at all). It is treated as the **absence** of a constraint rather than as a type: it is
remembered weakly and used for a parameter only when nothing else ever constrains it. Otherwise
`(print-line n)` followed by `(alen n)` would type `n` as `Object`.

This is [g5 §7](../../docs/derivations/g5-bindings.md)'s boundary marshalling, arriving smaller
than predicted: the boxing is the *host's own*, at the host's own boundary, and the interior is
untouched.

## 7. What is still not fixed

The aliasing hazard in [effects.md §1](../../docs/spec/effects.md). `dict-inc` mutates in place and
its correctness depends on the pre-mutation dictionary being dead — which nothing checks. Ordering
is now preserved; destructive update is still unchecked.

It stays unobservable because **no primitive reads a dictionary**, which is the same accident that
made strings cheap. It becomes real the moment one does. That is
[g7](../../docs/derivations/g7-aliasing.md)'s question, and this document does not answer it.
