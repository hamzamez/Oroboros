# Errors as they are: a product that leaks, and a sum that would cost nothing

2026-10-04. The measurements behind [errors-research.md](../../docs/errors-research.md) §0. The
language has been handling host failures for six weeks without a specification: Go's `(T, error)`,
spelled `(let (tuple v err) …)` and tested with `err-nil` (ADR 0027 made its continuation a tail;
nothing made it an error model). `sums-research.md` §3 chose "Result + explicit propagation" on
2026-08-22, and it was never built.

## 1. What there is

**Declarations.** A fallible host call is declared returning `(tuple T error)` or `error`, where
`error` is the host's opaque error type and `err-nil` its discriminant:

| host | `sig`s | declared fallible | how the host fails | totalised by |
|---|---:|---:|---|---|
| Go | 381 | 77 | a second result | nothing: the pair is Go's |
| JavaScript | 189 | 2 (`os`) | `throw` | a `try`/`catch` template assigning `%r0`, `%r1` |
| Java | 184 | 2 (`os`) | `throw` | the same |
| Windows | 87 | **0** | a sentinel (`BOOL`, `NULL`) and `GetLastError` | **nothing: `ReadFile` and `WriteFile` are declared total** |

The other JavaScript and Java declarations that can throw are declared total, and some of them
**`pure`**:
- `java/Integer.parseInt`, `parseLong` and `parseDouble` are `(sig parseInt (string) jint pure …)`,
  and each throws `NumberFormatException`;
- `String.charAt` and `substring` throw `IndexOutOfBoundsException`, and declare no `where`.

A throw from one ends the program, and nothing in the language says so. Worse, a `pure` call may be
dropped when its result is unused, duplicated, or moved (ADR 0010 orders only impure calls). So
whether the failure happens at all can depend on what reduction did, which is ADR 0009's rule ("staging
must not change an answer") broken through a declaration. Measured on Java
(`experiments/errors/vanishing.oro`):

| program | output |
|---|---|
| `(let n (Long.parseLong "abc") (seq (io.print-int 7) 0))` | `7`: the call was dropped |
| `(let n (Long.parseLong "abc") (seq (io.print-int n) 0))` | `NumberFormatException: For input string: "abc"` |

**The corpus.** 16 fallible call sites in 7 programs (12 tuple bindings, 4 single error results):

- **every one tests only `err-nil`.** No program reads an error's content: not its kind, not its
  message;
- **5 errors are discarded silently, all in `lines.oro`.** Three are writes to a `bufio.Writer`,
  whose errors are sticky and reported by `Flush`, so discarding them is right by the host's
  algebra (bufio.oro's header says so; the language does not). One is a message to standard error
  that has nowhere to report its own failure. One is a `Flush` before exiting with failure anyway.
  All five are defensible, and nothing distinguishes them from a forgotten check.

## 2. The product leaks: one program, three behaviours

`experiments/errors/ignored.oro` reads a file that does not exist and uses the value without testing
the error:

```lisp
(let (tuple src err) (os.ReadFile "no-such-file.txt")
  (seq (io.print-int (len src)) 0))
```

The compiler accepts it on all three hosts that have the portable `os`:

| host | `src` on failure | output | exit |
|---|---|---|---:|
| Go | `nil`, a slice of length 0 | `0` | 0 |
| JavaScript | `null` | `TypeError: Cannot read properties of null (reading 'length')` | 1 |
| Java | `null` | `NullPointerException: Cannot read the array length because "<local0>" is null` | 1 |

ADR 0026 says every target that accepts a program computes the same answer. This program breaks it,
and the type checker passed it, because `src` is typed `(array (int 0 255))` on both arms. Algebraically
the call is a sum A + E (§2.1 of the research), encoded as a product A_⊥ × E_⊥ under the invariant
"exactly one side is meaningful". Nothing checks the invariant, so the meaningless side is read, and
each host gives its own meaning to meaninglessness.

## 3. A sum costs nothing once inlined

`experiments/errors/chain.oro` wraps the same read in `(variant (result T) (ok T) (err int))` and
propagates it through three levels, each a `case` whose error arm rebuilds the error (`try`, written
out). Reduced for Go (`cmd/oro`), `main` is:

```lisp
((os.ReadFile "case.oro") (fn (#nl5 #nl6)
  (if (os.err-nil #nl6)
      (if (> (len #nl5) 0)
          (let (#nl5 0) (fn (#c) (let (+ #c 1) (fn (#p) (let (io.print-int #p) (fn (_) 0))))))
          (let (io.print-int -2) (fn (_) 2)))
      (let (io.print-int -1) (fn (_) 1)))))
```

**No tag, constructor or tuple survives, and each error path is one branch to the handler, its code
folded to a constant.** That is the commuting conversion (case-of-case, sums.md §5) applied at each
level, and it is the code a hand-written nested `if` gives. Built and run on Go, JavaScript and Java,
it prints `-1` for a missing file and `60` for a present one, on all three.

Propagation by explicit `case` is therefore free inside a program. It is the argument exceptions were
invented to answer (Goodenough 1975: threading status codes is costly and unreadable). Inlining
removes the cost, and `try` as reader sugar would remove the noise. Only a result crossing an
export's boundary carries a tag, as `examples/sum/parse.oro` does.

## 4. Not measured

- The cost of a host's throw when failures are frequent: Java's `NumberFormatException` in a loop
  that parses mostly invalid numbers, against Go's error value (research §7, M5).
- A sum carried as a loop variable, `(again (err 3))`, which sums-research §5 names as the one place
  a sum is split into variables.
