# `expect`, and a crash is a value in 0

2026-10-06. Step 3 of [errors.md §12](../../docs/spec/errors.md): `expect`, the one way to give up
(ADR 0040), and `abandon`, the crash it expands into, on all four targets. `try` was built in
[sumofsums-2026-10-06](sumofsums-2026-10-06.md)'s commit. Writing `expect` found four places where the
compiler gave the crash a value it does not have. Each was closed by one fact: **`abandon` is
crash : E → 0, and 0 is the initial object**. There is exactly one arrow 0 → Y for every Y, so any two
arrows out of 0 are equal.

## 1. What was built

```lisp
(expect (s x) e why body)  ⟶  (case e  (s x) body  (c y) (abandon why)  …)
```

`expect` shares `try`'s expansion (`core/sum.go`, `monadForm`): the pattern names the variant's marked
success constructor and is checked to be it, and every other constructor's arm is `(abandon why)`.
`abandon` is declared by each target and found by spelling, as `+` and `big+` are, injected unqualified
and impure (`emit/target.go`):

| target | `(abandon why)` | exit status |
|---|---|---|
| Go | `panic(why)` | 2 |
| JavaScript | `throw new Error(why)` | 1 |
| Java | `throw new IllegalStateException(why)` | 1 |
| Windows | the reason's bytes and a newline to standard error, then `ExitProcess(1)` | 1 |

What is emitted for `examples/errors/expect.oro`'s `quarter`, two `expect`s over `lib/result`, is
what a person would write:

```go
func GenQuarter(v0 int) int {
	v10 := (v0 & 1)
	v12 := (v10 == 0)
	if v12 {
		v14 := (v0 >> 1)
		v16 := (v14 & 1)
		v18 := (v16 == 0)
		if v18 {
			v20 := (v14 >> 1)
			return v20
		}
		panic("a multiple of four is expected")
	}
	panic("an even number is expected")
}
```

No tag and no constructor survive: the case meets `half`'s constructor and fuses, as `try`'s does.

## 2. What failed first, and the law that closed each

**The checker typed the crash as its reason.** A statement's value is its argument 0
(target-files.md §3), so `(abandon why)` was a `string`, and `(if c body (abandon why))` was refused:
*the branches of a conditional are int and string*. The crash has no value, so it now has no type of
its own (`emit/check.go`). It agrees with every demand, and a conditional takes its other branch's
type: that is the arrow 0 → Y.

**A function whose every path crashes was refused.** `always-crashes` gave *declares 1 result(s) and
does not produce them: the body yields 0*. A body with no `yield` ends every path in `unreachable`.
Its value is in 0, and 0 → int exists, so it takes its declared results (`ir/lower.go`). Each printer
then emits the crash as the whole body: `panic`, `throw`, `ExitProcess`.

**A crash in a value position leaked its "value".** The differential driver inlines `run` at each
literal input, so `run 3` became `(fmt.Println (abandon "…"))`: a crash as an argument. javac refused
the statement after the throw as unreachable, and on Windows the IR's verifier caught the reason's
string flowing into `eq`, `lt` and `sub` (W5). Go and JavaScript emitted dead code and passed. That is
"a path nothing checks" for the third time, and two of the four hosts caught it.

The rule is **the commuting conversion at arity 0**. `abandon w` is a term of the empty coproduct,
whose eliminator is the empty copairing []. Case-of-case, K ∘ [g₁, …, gₙ] = [K ∘ g₁, …, K ∘ gₙ], at
n = 0 is K ∘ [] = []. In the residual (`core/reduce.go`, `absorb`):

```
(f a₁ … aₖ₋₁ (abandon w) …)  ⟶  (let aᵢ (fn (_) … (abandon w)))   for each impure aᵢ, i < k
```

A strict position is an argument that is not a λ, or an `if`'s condition. The effects evaluated before
the crash stay in order (ADR 0010), and a pure term before it is dropped as β drops one.
`(let (abandon w) k)` is an instance, because `let`'s value is its strict argument, and so is `seq`.
A crash in an `if`'s branch, or under a λ, is not evaluated there and stays where it is. So reduction
is still the four rules state.md lists, with the fourth read at one more arity.

**The IR's terminator table was sized four.** `Program.Ops` kept `var terms [4]bool` indexed by
terminator, and the fifth terminator, `unreachable`, panicked it the first time a printed program held
one. It is now sized by the name table, `[len(termNames)]bool`.

## 3. The IR: `unreachable`

A region that ends in the crash has no exit (spec/ir.md §1.3). Its terminator is `unreachable`, which
passes nothing and so may end any arm of any tree, whatever the others pass. W3 refuses one whose
region does not end in a `call` of `abandon`, so control cannot fall out of it. Every consumer of a
terminator was read. The collectors of "the exits of kind K" find none in it, which is right, because
the one arrow out of 0 constrains nothing. The `switch`es fall through to the conservative arm: no
yield in the interval analysis, no fused boolean leaf on x86. The printers print nothing after the
crash: Go, Java and JavaScript accept `panic` and `throw` as a function's last statement, and on x86
`ExitProcess` does not return.

## 4. Windows writes the reason, and an import names several externs

The first Windows template only exited. To make a crash the same observable outcome on all four hosts,
it now writes the reason to standard error. It measures the NUL-terminated string with a MASM local
label loop, then calls `WriteFile(GetStdHandle(-12), …)` and `ExitProcess(1)`. Because the crash never
returns, the template may use any register.

That template calls three functions, and a template could import one. One import per template is a Go
rule: a Go template names one package. A Win32 template calls functions, and each is its own extern.
So `(import …)` takes several names in one clause, and only on x86-64 (target-files.md §6). Elsewhere
the extra names are refused, not dropped, by `Target.checkExterns`. A second clause is still refused
everywhere.

## 5. The differential suite: a crash is an outcome

`gauntlet/differential/cases/expect.oro` holds the property that matters: every target prints the same
answers and then crashes at the same point with the same reason. A case names the reason,
`; abandons: REASON`. A run that stops with it on standard error answers what it printed, then
`abandon`, as a declared bound's `trap` already did:

```
ok   expect                 0 1 2 abandon  [go js java windows]
```

## 6. A wall, named and not built: `again` under `try`

A read loop is the first program of step 5: read, `try`, go round. `(try (ok x) e (again …))` is
refused by the reader, because `again` may not sit inside an expression (ADR 0015). The success arm is
a binding in ADR 0015's sense: it binds the payload and runs once, now, as a host call's continuation
does (ADR 0027). So I measured the relaxation before proposing it. With the reader allowing it, the
next refusal is deeper and does not involve `try` at all:

```lisp
(loop ((i 0) (acc 0))
  (>= i 10)      (result.ok acc)
  (= (% i 2) 1)  (result.err i)
  else           (again (+ i 1) (+ acc i)))
```

*a tuple pattern of 2 names takes apart a `build` or a `loop`, so every exit must give 2 values.* **A
loop cannot yield a sum.** Its exits are constructors, Church-encoded functions, and the case on the
loop is read as a product pattern. So both are needed together, and the experiment was reverted:
- a sum as a loop's result, its tag and payload as the loop's two results (data.md §5.5's boundary
  lowering, applied at a loop exit);
- `again` in a `try`/`expect` success arm, an amendment to ADR 0015's surface rule.

They are decided when step 5's read loop meets them (errors.md §8).

## 8. Cost

- **Emission:** every existing source × target is byte-identical. The changes are two new sources,
  `examples/errors/expect.oro` and the case, on four targets each. Integer operations and loops are
  unchanged at 1,970 of 2,015 and 347 of 365.
- **Compile time:** 1.05× the baseline (median of seven compiles over 300 ms).
- **Balance**, counted as assessment-2026-10-03 §3.1: +380 −33 lines of compiler (`core`, `emit`, `ir`,
  tests included) against +14 lines of code in `examples/`, 25 : 1.
