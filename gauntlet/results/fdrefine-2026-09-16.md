# F-D₁ derived, the refinement half: a table's contents are proven by induction on its store chain

2026-09-16. `emit/content.go` (new), `emit/refine.go`, `emit/linear.go`, `emit/content_test.go`.

array-facts.md §8.3's third step, the refinement layer only. The interval layer's consumer (array smashing) is not
built, so no clamp in the corpus can be deleted yet, and the acceptance in array-facts.md §8.2 is **not** claimed here.

## 1. What is built

An F-D₁ fact about table `t` is `∀s. 0 ≤ s < len t → φ(t[s], x̄)`, kept as φ over the placeholder `#e`.

- **Theorem D (use).** At a read `(t i)` whose two domain bounds are PROVEN, `φ[#e := (t i)]` holds. A propagated
  bound gives nothing: an undefined read has no value to state a fact of. A content read is an alien to
  `provedBySplit` and to guard naming, so its instances reach the goal under a fresh name.
- **Theorem S (base and step).** One judgement, `holds(t, F, C)`, decides which φ ∈ C hold of every slot of the table
  term `t`, by structure:
  - a `build` binder is the zero fill: φ(0) under `len ≥ 1`, since an empty table satisfies every φ vacuously;
  - a `set` is McCarthy's axioms: φ of the base, and φ(v) for the stored value;
  - `if` intersects its branches under their guards; `let` walks under its binding;
  - a loop gives what every exit holds, under the content invariants its walk cached.
- **Theorem S′ (loops).** Candidates are `0 ≤ #e`, `#e < s` and `#e ≤ s` for every guard side `s` naming no loop
  variable, plus every content fact in scope. Houdini keeps the greatest subset that holds on entry and that every
  back edge preserves, **jointly over all table-valued loop variables**, so two buffers swapped on the back edge are
  one induction. Back edges are checked after the dry walk, because an argument that is a nested loop threading the
  same buffer is known only once walked.

## 2. Witnesses, each failing against a planted bug

`TestAStoredBoundHoldsOfEveryRead` and `TestSwappedBuffersKeepTheirContentJointly`:

| case | expected | planted bug that fails it |
|---|---|---|
| stores `i` under `i < n ≤ len a`, then `(a (t k))` | proven | `contentInvariants` disabled |
| stores `i + 1` | propagated | `set` not checked against the stored value |
| stores `m − 1` only when `m ≥ 1`; zero fill violates `#e < m` | propagated | zero fill accepting every candidate |
| two buffers swapped, stores `i` | proven | `contentInvariants` disabled |
| two buffers swapped, stores `n` | propagated | `set` not checked |

The first zero-fill control tested `1 ≤ #e`, which is not a template, so it could not fail. It was replaced by one
that can.

## 3. Cost, and the compile time it first cost

**Emission byte-identical, proof counts identical, no refusal changed**; compiler and differential steps pass.

The first version made the emission sweep 24 s → 37 s. Profiling freq, the largest program, showed `entails` at half
its compile time. The time went into re-substituting every fact on every query, and into walking all O(n²) fact
pairs through map iteration. Two exact rewrites fixed it:

1. **The substituted facts are cached on the fact set.** A new equation invalidates the cache; a new inequality
   extends it. `substitute` also returns at once when no equation names a variable of its argument.
2. **A pair is rejected before any sum is built.** A sum of two facts can equal the goal's variable part only if every
   variable one of them has and the goal lacks occurs in the other, to be cancelled. That is a slice-against-map check.
   The combination itself is then checked without allocation.
   - This is exact because no constructor stores a zero coefficient.

Measured sequentially on freq, which sets the sweep's wall time:

| | HEAD | first version | now |
|---|---|---|---|
| Go | 10.7 s | 16.0 s | **9.6 s** |
| Java | 21.4 s | 26.7 s | **20.8 s** |

The whole sweep, back to back on one machine: **27–29 s now, 30–32 s at HEAD**. So the change is no slower, and the
decision procedure's speed-up more than pays for the content analysis. Java's remaining time is the interval pass's
buffer ranges, which predates this work.

## 5. Next

The interval layer's consumer: array smashing (Blanchet et al., PLDI 2003). A buffer's element cell becomes an
abstract variable in the loop's Kleene iteration, with weak updates, the zero fill as `[0, 0]`, and exit element
records. Only with it can the 15 value clamps be deleted with 100% of operations still bounded, since those
operations are counted by the interval layer, not the refinement layer. Then tree's walk, which needs a relational
consumer, and the benchmark.
