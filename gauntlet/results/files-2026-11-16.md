## 1. What was measured

The five programs of `examples/io`, as processes ([gauntlet/files/](../files/README.md)), on fixed
inputs, each under its program's cap:
- `wc` and `count`: 8 MiB of words in lines (cap 2²⁴);
- `freq`: 60 KiB of mixed-case words (cap 2¹⁶);
- `jsonfmt`: 60 KiB of minified JSON (cap 2¹⁶);
- `roundtrip`: its own file.

**The variants** of each program:
- `windows`, the program on windows;
- `winold`, the compiler at `8b8a643`, before this step (`wc`, `count`, `roundtrip`; the other two
  crashed);
- `c`, hand-written C with the C runtime's stdio, built by the same clang at `-O2`;
- `gohand`, hand-written idiomatic Go;
- `go`, the program on the Go target.

Each toolchain's do-nothing process is its **floor**, and a program's **work** is its median less
its own floor. Every variant's output was checked equal to the windows build's before any timing.
Then 101 rounds, each running every (program, variant) once, in an order rotated each round, each
a fresh process timed alone. The runs and the analysis are in
[files-2026-11-16/](files-2026-11-16/), with a log of every other compiler process.

Each reference was written from the program's meaning, so equal output is a check, not a
formality:
- `freq`'s order is count descending, then the folded word, each word spelled as its first
  occurrence. The program's two stable merge sorts give that; the C sorts with an explicit
  tiebreak, the Go with a map and one sort.
- `jsonfmt`'s layout is written as one streaming pass;
- the C runtime's stdout is put in binary mode, or it would write CRLF.

## 2. The crash: a table released by a width it was not allocated with

**Found** when the inputs were made. `freq` and `jsonfmt` faulted on windows from 8,191 bytes of
input on, and ran at 8,190. So did a three-line program, `io.print(os.text_of(src))` after
`os.ReadFile`. The compiler at `e07ffc9` crashes alike, so it predates this round.

**Under the debugger** (`cdb`, the module rebuilt with `-g`), it was `RtlFreeHeap` called from `main`
on a page-aligned pointer, which only `VirtualAlloc` answers. Σ_OS's `region` and `release` choose
their allocator by the byte count, `VirtualAlloc` from 2¹⁶. Now 8,191 · 8 + 8 = 2¹⁶ exactly, and
8,190 · 8 + 8 is below it. So a table of the input's length was allocated with 8-byte elements and
released with 1-byte elements.

**Why.** `os.ReadFile` on windows is `readfile`, kept as a function (ADR 0113). Storage (ADR 0092)
sized its buffer by the type the table had *before* Theorem D′'s classes (`ir/final.go`), `array
int`, 8 bytes. `Finalize` later gave the class its representation, bytes, since the buffer reaches
`kernel32.ReadFile`'s byte table and the function's byte result. The printer then indexed it as
bytes, and the caller, holding the result by its declared type, released it as bytes. Inside one
function the two widths only over-allocated (an 8-MiB file took a 64-MiB region). Across the
boundary they named two allocators.

**The rule.** ADR 0092 states it: w is "the one layout the printer indexes by, so the allocation and
every access agree". The width read was a different one. Release's soundness needs release(p, b) and
region(b′) to choose one allocator, which holds when b is the size region was asked for.
- **The fix**: the layout is the class's representation. Storage computes Theorem D′ on a copy of
  the function and writes each table's final type back before sizing anything, so the allocation,
  every release (W11), every token (W12) and the printer read one width.
- **Parameters are excepted.** A parameter's type is its declaration, the callers' contract.
  Narrowing a kept definition's buffer parameter made its callers owe the narrower set, and P4
  inlined them (`freq` was refused, and `roundtrip` passed the step limit). The first form of the
  fix did exactly that.

**The witnesses.**
- `TestAFileReadIsReleasedByItsOwnLayout` (`cmd/build`) builds the three-line reader on windows and
  runs it on 8,191 bytes, which must come back. `PlantStorageWidthIRA`, the width taken before the
  classes, faults again.
- `TestATablesStorageIsItsLayout` pinned the old width: its "integer table" held n ∈ 1..100 and
  expected 8 bytes, which the printer never used. It now pins the final layout, bytes for a table of
  bytes and 8 for one past the byte, and the second planted fault restores 8 for the table of bytes.

**What it changed.** 28 windows files: every table proven to hold bytes is now allocated in bytes.
Measured no slower where a benchmark covers them:
- the sieve 0.999 (identical output);
- the gauntlet's windows tokenizer 0.925 and tree 0.994, the hand-written references 0.99 beside
  them;
- `wc` 0.96 and `count` 0.96 against `8b8a643` (clamps included, §4).

## 3. The residues, each made to explain itself

**`wc`, work 1.43× C: the counter's width.** Both scans are vectorized by clang. The generated code
counts in 64-bit lanes (`paddq`, 4 bytes an iteration) and the C in 32-bit ones (`paddd`, 8 bytes),
because C's `long` is 32 bits on Windows. The control is the C with a `long long` counter, which
does 5.80 ms of work against the program's 5.67. So the whole gap is the width, and lines ≤ len(src)
< 2²⁴ is proven, so the word is wider than the value.

That is the trigger CLAUDE.md lists under "waiting on a trigger": **a 32-bit scalar representation**
(ADR 0083 item 2's register rule), "a loop whose mask is measured above the noise floor". It is met
here, at 1.43×. It is a representation choice ρ makes by place, with conversions at the boundaries
between widths, and an ADR's step of its own. The second triple, `i686`, needs i32 scalars anyway.

**`freq`, work 3.47× Go by hand, 0.79× C: the algorithm.** The program sorts its words (two merge
sorts), and Go hashes them (a map, one sort of the distinct words). Against the same algorithm in C
it is faster. A program that hashes strings needs a dictionary keyed by strings, which is
gauntlet-2026-11-16's wall, met here from the program's side.

**`jsonfmt`, work 1.66× C, 0.22 ms: passes.** The program computes the output's length (one pass),
renders it (a second), then `os.text_of` validates it as UTF-8 (a third) and copies it into a
string, the NUL after it (a fourth). The C streams once. Over 127 KB of output that is the 0.22 ms,
which is inside the medians' own spread. It is recorded, not built: the copy is ADR 0091's C-string
invariant, and a pass is the price of proving the output's length.

## 4. Two clamps were proofs no longer missing

`wc`'s loop clamped its count, `if lines < cap_in`, and `count`'s both of its counters. Each
program's comment said the guard "cannot fire" and was there "because the ANALYSIS needs it": a
counter incremented under a condition had no bound from its loop's guard. The IR's trip bounds now
give it one, lines ≤ i < len(src), and without the clamps **all four targets prove both programs**,
every operation and every loop. So the clamps went, and the comments now say why.

## What failed first

1. **The first inputs read "cannot read that file" on both targets.** That was my composed path;
   with a relative one both read. An agreement on a failure is no agreement.
2. **The first form of the fix narrowed parameters** (§2), refusing `freq` and sending `roundtrip`
   past the step limit.
3. **A program would not build from the scratch directory**, "io.print-line is defined twice". A
   source's own directory is its nearest module layer, and that directory held a worktree with its
   own `lib/`. The floor program lives in the repository instead.
4. **The runner's agreement check caught a stray variant**, the old crashing `jsonfmt`, before
   anything was timed.

## Paid and bought

- **Compile time**: 1.04× the baseline by the median of 50 compiles; five suspects paired against
  `8b8a643`'s `gen`, none confirmed. Storage now finalizes a copy of each function once more, inside
  that figure.
- **Run time**: the tables above. The fix and the clamps: the tokenizer 0.925, `wc` and `count`
  0.94–0.98 on four targets, and the rest within 0.99–1.00.
- **Memory**: a byte table on windows takes 1 byte an element, where it took 8; `wc`'s 8-MiB file
  takes an 8-MiB region, where it took 64.
- **Proofs**: 8,857 of 8,911 operations and 886 of 924 loops, against 8,881 of 8,935. The 24 gone are
  the clamps' comparisons, and the unproven are unchanged.
- **Refusals changed**: none. Two programs that crashed now run.
- **Emitted text changed**: 28 windows files (byte tables in bytes); `wc` and `count` on all four
  targets (the clamps). Accepted with the measurements above.
- **Compiler lines**: `ir/storage.go` +43 (the final layout, the parameter exception, the plant).
  Tests +69 / −3 (`cmd/build/files_test.go` new, 56; `ir/storage_test.go` +13).
- **Language lines**: `wc.oro` and `count.oro`, the clamps gone and their comments rewritten
  (+14 / −21, most of it comment).
- **The harness**: `gauntlet/files/` (inputs, runner, six C programs, `nop.oro`) and
  `gauntlet/go/files/` (six Go programs).
- **Rules made more general**: none. **A soundness rule restored**: the allocation's width is the
  printed layout's.

## What was not built

- **The 32-bit scalar representation** (§3), `wc`'s 1.43×: an ADR's step, beside the second triple,
  which needs it.
- **A dictionary keyed by strings**, `freq` against Go: the wall named in gauntlet-2026-11-16.
- **`jsonfmt`'s passes**, 0.22 ms: recorded.
- **`readinto`'s n ≤ len(b)**, owed since p8step3: `readfile`'s clamp of m stays. It is one
  comparison a file read, which none of these measurements can see.
