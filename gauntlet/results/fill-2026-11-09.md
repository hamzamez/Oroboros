# fill-2026-11-09: a table born full takes a region with no zero fill

6b′ step 3, in R1c's place (hamza, 2026-11-09: "Fill elision instead", after the measurement below).
ADR 0097.

## What was measured first

R1c's plan was a frame slot for every table of static length, to remove its allocation. After R1b,
the leak loop's steady state allocates nothing, so the measurement asked what was left. On 10⁷ limb
additions, best of five runs:

| | time |
|---|---|
| reuse (R1b) | 183 ms |
| reuse with no zeroing (unsound, measurement only) | 145 ms |

So zeroing was 21% of the loop, about 1.3 ns a table, and a frame slot would still owe it.

## The algebra

**region = zero ∘ region_raw.** When every element of a table is written before any is read, the
zero is never observed, so it is a dead store (ADR 0084's U3: a table is born full).
- **A rule and an array literal** write every element by construction.
- **A build, by the written prefix** (`ir/fill.go`). Its loop carries the buffer and a counter i from 0
  by +1, writes b[i] on every continuing path without reading b, and leaves only by a branch on i ≥ n,
  the build's own length. Then:
  - at the first iteration's start, [0, 0) = ∅ is written;
  - an iteration that starts with [0, i) writes i and passes i + 1, so [0, i + 1);
  - the exit has i ≥ n, so [0, n) is written, and every read comes after.

  The descending counter, from n − 1 by −1 leaving on i < 0, is the same theorem on the suffix (i, n).
  In the limb loop, three of the four builds an iteration have one of the two shapes. `mul`, which it
  does not use, accumulates into its output, so it reads before every element is written and keeps its
  fill.

## What was built

- **Σ_OS's sixth header**, `region_raw(b)`, which windows defines by `region`'s size rule:
  `VirtualAlloc` from 64 KiB (its pages are zero anyway), and `HeapAlloc` without `HEAP_ZERO_MEMORY`
  below.
- **`alloc-raw` and `reuse-raw`**, with `lang.allocate_raw` and `lang.reuse_raw`. `ir.Storage`
  chooses the raw form for a rule, an array literal, and a build the theorem proves. `ir.Reuse`
  keeps the kind: a raw allocation's token is taken unzeroed. W12 checks both reuses alike.

## Witnesses

- **`TestTheWrittenPrefixTheorem`**:
  - proven: an ascending write loop (`add`'s shape) and a descending one (`div_small`'s);
  - refused: a loop that reads its buffer before every element is written, and a build whose fill is
    read where nothing wrote it (the sieve's shape).
- **`TestAZeroFillIsKeptWhereItIsRead`**, run on windows: each iteration makes a table of 10 with one
  element set and sums it. Its region is the last iteration's, reused, so the sum is 1000 only if
  that region is zeroed. **The planted fault**, every build taken as born full, makes the sum wrong.

## What was measured

10⁷ limb additions, best of five runs, two rounds:

| | round 1 | round 2 |
|---|---|---|
| reuse, zeroing every token (R1b) | 178.0 ms | 182.4 ms |
| **fill elision** | **135.6 ms** | **143.4 ms** |
| no zeroing at all (unsound) | 137.2 ms | 141.9 ms |

Three of the iteration's four zeroings are gone, and the time is that of no zeroing (0.76× R1b). The
output is the same. Against the original leak (1,672 ms) the loop is now at 0.08×.

**The check**: see below.

## What failed first

- **The layout test looked for allocations by the name `alloc`**, and an array literal now asks for
  `alloc-raw`. The test is about each element's width, which both kinds carry, so it accepts both.
- **The run-time witness's sum had no proven bound**: a property of the test program. A modulus
  keeps it in range with the same expected answer.
