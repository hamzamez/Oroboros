# The written prefix with a tail: `mul_small`'s result is born full

2026-11-17. The first of the two fixes [alloc-2026-11-17](alloc-2026-11-17.md) measured, built at
hamza's word ("Build both fixes first"). An extension of ADR 0097's proof. No new surface, and no
ADR, since it proves more of what ADR 0097 states and changes nothing it decides.

**`nat.mul_small`'s result now takes a region with no zero fill.** windows32's 20000! product drops
to 0.82 of its time, x86_64's to 0.90. The emission changes in one file, and its answers are
unchanged.

## 1. The algebra

ADR 0097: region = zero ∘ region_raw, and the zero is a dead store when every element is written
before any is read. The written-prefix theorem proved it for a loop that writes b[i] at a counter
from 0 by +1 and leaves exactly on i ≥ n, n the build's count: by induction [0, i) is written at
each iteration's start, so [0, n) is written at the exit.

`mul_small`'s loop leaves on i ≥ k, k = mᵢ, while the build's count is n = k + 2. Its exit arm writes
b[k] (the last carry) and b[k + 1] (the header). The extension is **an interval cover**. If the loop
leaves on i ≥ k with n = k + c, c a constant, and the exit arm stores b[k + j] for every j < c, with
values not read from b, before any read of b, then

  W = [0, k) ∪ {k + j : j < c} = [0, k + c) = [0, n).

For k ≥ 0 the prefix and the tail meet. For k < 0 the loop writes nothing, and the tail alone covers
[k, n) ⊇ [0, n). Counts and indices are compared as affine forms, a base and a constant offset (`ma
+ 1 + 1` is (ma, 2)), with bases equal by congruence as before. A read of b in the exit arm before
the tail is complete is refused. That is conservative, a cost and never an error.

## 2. The witnesses

`TestTheWrittenPrefixTheorem` (ir), four new cases:
- the tail in `mul_small`'s shape is born full;
- a tail missing a slot is not;
- a tail slot read before it is written is not;
- a tail store whose value reads the buffer first is not.

**The planted fault** (`PlantFillTailOne`) checks only the tail's first store, and the tail missing
a slot is then taken as born full.

On the 20000! program, instrumented as in alloc §2: zeroed `HeapAlloc` calls went from 20,000 to 1,
and the allocator's time from 86 to 20.6 ms. That is the emulation's count exactly.

## What was not built

- **A tail after a descending loop**, from n − 1 down, with stores below 0. No program has the
  shape.
- **A tail store whose value reads written elements** (the fourth case): proving it needs the
  read's index inside W at the read's point, and nothing asks for it.
- **The second fix**, reuse across the call, which is next.
