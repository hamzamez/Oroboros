# A dead region serves a request it fits (R1d, ADR 0100); where K(ℕ*)'s time goes

Date: 2026-11-10. R1d of the plan, its trigger claimed met by natdiv-2026-11-10's measurement.
Decision: [ADR 0100](../../docs/decisions/0100-a-dead-region-serves-a-request-it-fits.md), amending
ADR 0096 item 6. hamza's standing measure, set with this step: **the windows implementation is to be
faster than the Go one. As long as it is slower, the gap is work owed, whether or not it is done now.**

## What it is

R1b's law, release(p, b) ; region(b) ≡ zero(p, b), handed a dead region only to a request of equal,
static size. A region answered for b bytes is a block of at least b bytes, so the law holds for any
b′ ≤ b of the same size class:

    release(p, b) ; q ← region(b′)   ≡   q ← zero(p, b′)     b′ ≤ b, class(b′) = class(b)

The class is the rule `region` and `release` choose their allocator by (VirtualAlloc from 64 KiB, the
process heap below), so the reused table's own later release gives the block back by the rule that
made it. A reuse keeps the class, so by induction it is the region's. The token carries its table's
element count k, and the fit is a comparison at run time where R1b's was an equality the facts proved.

ADR 0096 gave run-time sizes a data stack. The loops that make them are not LIFO: fib's
(a, b) → (b, a + b) carries b out of its iteration while a + b is born.

## What was built

- **Σ_OS's seventh operation symbol**, `class(b)` (`targets/llvm/os.oro`), defined by windows at
  65,536 (`targets/windows/os.oro`).
- **`reuse_fit` and `reuse_fit_raw`**, terms of the LLVM layer (`targets/llvm/lang.oro`):
  - a null token, allocate;
  - n ≤ k and the classes equal, take the region (zeroed, or raw for a table born full);
  - otherwise give it back and allocate.
- **`ir.Reuse`**: a release and an allocation where either size is the run's, with one constant
  width, become a reuse by fit:
  - locally, the release's count beside it;
  - across a back edge, a pair of body parameters, the token and its count: null and 0 on entry,
    the dead table's storage and `len` at each continue, a discard by the same count on an arm that
    makes nothing.

  Static pairs keep R1b's form, and their emission is unchanged.
- **W12** re-derives every token by fit:
  - null, or a table's storage not used after it is handed on and not released elsewhere;
  - its count that table's own `len`;
  - its width the table's;
  - consumed once on every path;
  - a discard giving it back by the same count;
  - no token of a run-time size taken by `reuse` unchecked.

## Witnesses

- **`TestADeadRegionServesARequestItFits`** (`ir`): a loop carries a table whose length is a
  parameter's, each successor one shorter on odd rounds, so a strict fit b′ < b is exercised. Its
  region is taken by fit and zeroed, and W12 accepts it.
- **`TestAFitW12RefusesIsAFault`** (`ir`), each fault refused by W12 for its stated reason:
  - `PlantFitCount`, the request's count handed as the token's;
  - `PlantFitUnchecked`, a run-time size taken by `reuse`.

  The first version of the witness could not fail: the successor's length was the dead table's, so
  the request's count *was* the token's. The successor's length now differs on odd rounds.
- `big-fib`, `big-nat-ops`, `big-nat-div` and the M3 programs print what Go prints.

## What was measured

Tokens by fit after `ir.Reuse` (IR dumped before realization):

| program | by fit | static reuse | fresh allocations in the text |
|---|---|---|---|
| fib(10⁵) | 1 | 0 | 9 |
| fact(20,000) | 1 | 0 | 8 |
| 2,000 quotients (D) | 683 | 4 | 17 |
| 10⁷ bounded additions, K(ℕ\*) | 2 | 0 | 9 |

Time, best of five, two rounds; "before" is R3c's build and "after" this one:

| program | before | after | Go, `math/big` |
|---|---|---|---|
| fact(20,000) | 410.6 / 392.4 ms | 411.1 / 408.3 | 39.8 / 42.3 |
| 2,000 quotients | 272.1 / 283.8 | 280.4 / 280.3 | 106.3 / 97.4 |
| fib(10⁵) | 258.1 / 264.4 | **245.7 / 244.2** | 33.2 / 34.2 |
| 10⁷ bounded additions, K(ℕ\*) | 624.0 / 616.6 | 608.3 / 628.5 | (V₉: 143.5 / 143.2) |

**The allocation was not the cost.** fib gained about 6%, inside the 4% arithmetic predicted
(10⁵ allocations of about 100 ns against 252 ms), and the rest nothing beyond the noise. In the
bounded loop two of the three allocations per iteration are now by fit, and its time did not move.
So natdiv-2026-11-10's reading of its 4.4× as R1d's trigger was wrong; that loop's cost is
computation (below). R1d stays, being sound and the allocation's removal: it is ADR 0096's design
completed for run-time sizes, and it removes the VirtualAlloc system calls past 64 KiB.

## Where K(ℕ*)'s time goes

The addition's inner loop in fib, read in the `-O2` assembly of the emitted LLVM IR, is about 45
instructions and 8 branches per 32-bit digit. `math/big`'s `addVV` is a few instructions per 64-bit
limb. What the 45 are, and the work each names, by expected gain:

1. **Every operand's length is reloaded each digit** (`movq (%rbp), %r10; decq; cmpq`). LLVM cannot
   tell the output table from the inputs, so nothing is hoisted, but the facts can: a fresh region is
   disjoint from every live table (ADR 0084's views). **`noalias` on `alloc`'s result** and on
   borrowed parameters, the LLVM attributes ADR 0084 left for `ir/llvm`.
2. **Every digit read is masked** (`dig`'s compares and `cmov`): the representation's invariant
   d ∈ [0, B) stated as a mask. Owed: the invariant as a fact, an inductive property of a table's
   contents, the fixed limbs' `at` debt too.
3. **The operand swap and σ are selected per digit**: loop-invariant, not unswitched. Owed: unswitched
   in the library, now that a region taken by fit makes a branch's allocation cheap, or by
   `loop-unswitch` on the emitted IR.
4. **The carry is normalized by comparisons**. Owed: **M4**, 64-bit digits with
   `llvm.uadd.with.overflow` (one `adc`) and `i128` products: half the digits and a quarter of the
   products. It needs ADR 0083's native iN on LLVM.
5. **The size is tracked per digit.** A sum's size is m or m + 1 by the final carry; only a difference
   needs a scan, once, from the top.

Until these are done, windows is slower than Go on every K(ℕ\*) program (fact 9.6×, D 2.8×,
fib 7.2×, from the table above), and the gap is owed.

## What failed first

- **The hypothesis.** The bounded loop's 4.4× was read as allocation. Removing the allocations
  falsified it.
- **A witness that could not fail** (above).

## What was not built

- The data stack: replaced (ADR 0100).
- A token across a branch: nothing in the corpus allocates differently on two arms after R3a.
- A static allocation taking a run-time release's region (the bounded loop's constant table): it
  would remove the last allocation there, which the measurement says costs nothing worth having.
- Items 1–5 above.
