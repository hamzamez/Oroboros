# A frozen buffer carries what was put in it — 2026-08-28

Two measurements and one build. The measurements came first, and they changed what got built.

---

## 1. Clause-order sensitivity is gone, and it was the fixpoint bug

[json-2026-08-26 §4](json-2026-08-26.md) recorded that moving one clause in `examples/json/tokenize.oro`
took it from 80 of 124 integer operations bounded and 12 of 16 loops proven to **36 and 0** — same
guards, same answers. It called the cause **not isolated**: four hand-written reductions of the shape
all proved at 1 of 1, so nothing smaller than the real program reproduced it.

Moved back today:

| depth-limit clause | with the `where` | without it |
|---|---|---|
| **above** end-of-input | 165/165 ops, 20/20 loops | 143/165, 16/20 |
| **below** it (as committed) | 165/165, 20/20 | 143/165, 16/20 |

Identical in both positions, at both precision levels.

**The cause was almost certainly the fixpoint bug**, found the next day
([fixpoint-2026-08-27](fixpoint-2026-08-27.md)). `restore` installed its snapshot **by reference**, so
the environment leaving an `if` carried `¬c` — a fact true on one path only. *Which* guard's negation
leaked into *which* later clause is decided by the order of the clauses. That is an order-sensitive
defect by construction, and it explains why four reductions failed to find it: they were searching for
a precision bug in a soundness bug's shadow.

So **"a meaning-preserving edit can lose a termination proof" is withdrawn**, and with it one of the
three standing arguments for octagons.

## 2. The tree's residue was named, and it was not relational

`cmd/intervals -v` lists every unproven operation. All 50 in `examples/json/tree.oro` traced to one
root:

```
run: go.- [-inf, +inf] in (go.- (nodes 0) 1)
run: go.* [-inf, +inf] in (go.* (nodes (go.+ (go.* 4 (if (go.< n 0) 0 …
```

`(nodes k)` — a read out of the **frozen** node table — was ⊤, and every arithmetic above it inherited
it. An octagon relates variables; it cannot say what a table holds. So the fact that was missing was
**non-relational**, and building an O(n³) domain would have bought none of it.

---

## 3. The rule

> **Theorem (read containment).** Let `b = (build n λx.e)` and let `E = ElemType(b)`. Then every value
> read out of `b` is in `γ(E)`.
>
> **Proof.** A slot holds either the zero fill or the value of the most recent `set` into it. There is
> no third source: `build` is the only allocator, `set` the only store, and ADR 0018's linearity means
> no other reference can have written it. `E` joins the zero fill explicitly and contains every stored
> value. ∎

This is the same theorem the containment harness tests
([containment-2026-08-27](containment-2026-08-27.md) §2). There it was *checked*; here it is *used*.

**Why it is not circular**, which is the objection this had to answer. Stratify the reads of `b`:

- **stratum 0** — a read inside `λx.e` itself, where the buffer is still being filled. Nothing binds
  `x`'s element range: the only binder is `let`, and a build term is never in scope inside itself. So
  such a read stays ⊤.
- **stratum 1** — a read of `b` from **outside** `λx.e`, after the freeze, where the value no longer
  changes.

`E(b)` is computed by analysing `λx.e`, in which every read of `b` sits at stratum 0. So computing
`E(b)` never consults `E(b)`. Induction on build-nesting depth extends it: an outer build may learn
what a completed inner one holds, and the inner analysis cannot mention the outer.

`walk` takes the node table as a **parameter** — frozen on the way out and read back as an ordinary
array — so its reads are stratum 1, and they were the missing fact.

## 4. What it needed that the argument had not

**The sub-analysis loses the input length, and that is what decides a buffer's contents.**
`BufferRange` runs on the `build` lambda in isolation, where everything the enclosing program bound is
free and therefore ⊤. In `measure` the declared `(where (go.< (len src) 1024))` covers it — that is
what `intervalsAssuming` was built for. In **`run` there is no signature at all**, and `run` is where
reduction has substituted four literal documents, so every `(len src)` is an array literal's length:
exact at the binding, invisible one lambda in.

Measured: the *identical* shape succeeded in `measure` and failed four times in `run`.

So the sub-analysis is now **seeded** with the enclosing pass's facts — and deliberately only with the
**exactly-known lengths**. That restriction is a soundness argument, not tidiness: a length fact comes
either from `exactLen` on a literal table or from `assumeWhere` on a signature, so it is syntactic or a
premise. Neither is a fixpoint iterate. Seeding an iterate would seed a claim that is not yet a
post-fixpoint, and the sub-analysis would believe it. A fact is dropped when the lambda binds the table
name itself, because the inner table is a different one.

## 5. Result

**`tree.oro` 91.3% → 92.7%**, `go.-` from 70 of 74 to **74 of 74**, `go.*` 200 → 204. Loops stay 25 of
25 and the tokeniser stays 100% and 20 of 20.

**Every emitted file on all four targets is byte-identical**, across the whole corpus — `examples/`,
`examples/native/`, `examples/int/`, `examples/json/`, 41 programs × 4 targets. Compile time is unmoved
(679 ms against 715 on `tree.oro`, three runs each, inside the noise). So this is a **pure provability
gain and not a speed one**, which is the honest way to record it: it buys a fact, and on this corpus
nothing was waiting on that fact to emit different code.

## 6. And the honest limit is now a DIFFERENT one, with a witness

The 42 operations still unproven in `tree.oro` all chain off **one variable**:

```
(go.+ acc (go.* (nodes (nslc n 0)) d))     ; acc accumulates tag × depth
(go.+ d 1)
```

`d` is a depth **read back out of the worklist that stores it** — a genuine self-reference, stratum 0,
correctly refused. `wl` stores `d` and `d+1`, so its element range is the least solution of
`E ⊇ {0,1} ∪ E ∪ (E+1)`, which widens to ⊤. What actually bounds `d` is that it grows at most once per
iteration and the loop carries a trip bound of 1024, i.e.

```
d ≤ steps
```

**That is relational, and an interval cannot express it.** So the octagon argument survives — but it
now has a concrete witness in a real program instead of an unexplained order-sensitivity, which is a
better reason than the one it replaced.

## 7. Tested

`TestFrozenBufferReadContainment` in `emit/containment_test.go`: 1,000 generated programs that build a
buffer, freeze it, hand it to a reader, and accumulate every element. **634 get a bounded `MaxOp`** —
the anti-vacuity guard, because refusing to bound the reader is always sound and a test passing on
refusals proves nothing. It fails when the frozen range is narrowed by one:

```
seed 44: the analysis claims every operation is in 0..9, and one produced 10
```

The interpreter gained `let`, which is what the residual actually uses to bind a frozen buffer.
