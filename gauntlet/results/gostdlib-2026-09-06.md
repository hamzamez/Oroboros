# Can we declare the whole Go standard library?

2026-09-06. `gauntlet/stdlib/survey.go`, run against `$GOROOT/api/go1*.txt` on
go1.26.5.

[ADR 0001](../../docs/decisions/0001-parasite-model.md) says a target is an
**ecosystem** and that reaching it costs a line of data per name. This is that
claim measured against the largest ecosystem we target, symbol by symbol, instead
of asserted.

> **70.0% of the callable surface can be DECLARED. 19.0% is USABLE by a program.**
>
> And the gap is not where it was expected. It is not multiple returns, not
> generics, and not concurrency. **It is that a host object has to come from
> somewhere**, and the language can name a type it cannot construct.

---

## 0. Method

The universe is the Go team's own API manifest — the file that *defines* the
compatibility promise, so it is the library's account of itself rather than ours.
Union across every `go1*.txt`, deduplicated by identity because the manifest
records history (`os.Chmod` appears twice, taking a `FileMode` and later an
`fs.FileMode`, one alias and two lines).

**141,680 platform-qualified lines are counted separately** — `pkg syscall
(windows-386)` is one platform's surface, a different question from the portable
library. What remains is **167 packages and 9,282 portable symbols**, of which
**4,765 are callable** (1,752 functions and 3,013 methods).

Three levels, kept apart on purpose, because reporting one number hides which
layer would have to change:

| level | question | whose problem |
|---|---|---|
| **declarable** | can a `(prim …)` line be written? | the target **format** |
| **obtainable** | can the program get hold of the host types involved? | the **language** |
| **usable** | can the program call it and do something with the answer? | both |

**Obtainable is a least fixed point** and had to be, because "a method takes a
receiver the program cannot build" is a *claim* and it is false whenever a
constructor exists. A host type is obtainable when some declarable function
returns it and every argument that function needs is a scalar or already
obtainable; iterate to stability. `strings.NewReader` returns a `*Reader` from a
`string`, so every `*Reader` method is reachable. `os.Open` returns
`(*File, error)`, which the format cannot declare at all, so no `*File` method is.

**The first version of this survey scored methods at 0% usable**, by defining an
opaque receiver as unusable rather than computing it. That was a definition
masquerading as a finding; the fixpoint moved methods to 13.7% and the total from
9.2% to 19.0%.

## 1. The result

```
CALLABLE SURFACE (func + method): 4765
  declarable as a (prim …):   3336   70.0%
  usable by a program:         907   19.0%
    func     1752 total   1049 declarable (59.9%)    495 usable (28.3%)
    method   3013 total   2287 declarable (75.9%)    412 usable (13.7%)

HOST TYPES A PROGRAM CAN OBTAIN: 108
```

**And it emits.** The declarable subset is generated as target files
(`-emit DIR`): **952 primitives across 148 packages**, which load as one target,
and a program calling `math/bits`, `unicode` and `sort` through them compiles and
runs. That is what makes 70.0% a measurement rather than a classification — the
number is what survived being written out and loaded.

## 2. Why the other 30% cannot be declared

| reason | count | share | whose |
|---|---:|---:|---|
| **several results** | 942 | 19.8% | format |
| variadic | 117 | 2.5% | format |
| interface value | 89 | 1.9% | language |
| function argument | 87 | 1.8% | language |
| type parameters | 74 | 1.6% | format |
| unsafe / uintptr | 31 | 0.7% | language |
| complex number | 30 | 0.6% | language |
| generic instantiation | 26 | 0.5% | format |
| table of opaque | 25 | 0.5% | language |
| channel | 4 | 0.1% | language |
| map key is not int | 4 | 0.1% | language |

**Several results is 19.8% on its own — two-thirds of everything refused — and it
is the FORMAT, not the language.** `Prim.Result` is one string. Meanwhile
[values.md](../../docs/spec/values.md) gives the language several results,
`(values a b)` is reader sugar for `(fn (#k) (#k a b))` so the reducer needed
nothing, and it measured **0.99x on Go with 0 allocations**. So the single
largest obstacle to the whole Go ecosystem is a slot in a data format that the
language behind it already has.

It is also self-compounding: `(T, error)` is Go's constructor idiom, so every
name it blocks also blocks every method on the type that name would have
returned. **Fixing one field in `parsePrim` is the highest-value change this
survey found.**

**Concurrency is 4 symbols.** Channels barely appear in the portable API surface —
they are how you *use* the library, not how you *call* it. The absence of
concurrency from the language costs almost nothing at this boundary, which is the
opposite of what the list of missing features suggests.

**`slices` is 0 of 40** and `maps` likewise: they are entirely generic. A whole
modern package can be unreachable while the reason accounts for 1.6% overall.

## 3. Why a declarable name is still not usable

| reason | count | share of declarable |
|---|---:|---:|
| cannot build the argument | 1,828 | 54.8% |
| cannot read the result | 494 | 14.8% |
| result is an error | 107 | 3.2% |

> **The parasite model reaches an ecosystem's FUNCTIONS. It reaches its OBJECTS
> only as far as some constructor happens to be declarable.**

108 host types are obtainable. Those 108 carry 412 usable methods. Everything
hanging off a type whose only constructor returns `(T, error)` is unreachable —
declarable, loadable, and impossible to call.

`io` is **10 declarable and 0 usable**, and that is the shape in one package: it
is interfaces all the way down, and an interface is a value we can hold and never
ask anything. `fmt` is **1 of 23**, because `fmt` is variadic `...any`. `context`
is 4 and 0.

Against that, the packages that are all values come out well: **`math` 63 of 67,
`math/bits` 37 of 49, `strconv` 24 of 36, `bytes` 51 of 95, `regexp` 31 of 48,
`unicode/utf8` 11 of 15.** A numeric or text kernel gets most of what it wants.

## 4. Roadblocks, ordered by what they would cost

These are the deliverable. Each names the mechanism, not just the symptom.

### 4a. A `prim` has exactly one result — FORMAT, and the language is ahead of it

`parsePrim` reads `p.Result` as a single string. `(sig f (…) (int int))` is
already legal in the *signature* language and measured at parity. Cost: a slot in
the format plus the multi-result path the backends already have (`multiTail`).
**Worth 942 symbols directly and an unknown multiple of that indirectly**, since
it is Go's constructor idiom.

### 4b. There is no way to declare what a host call RETURNS, as a range

Found by building it. A generated `bits.OnesCount64` is declarable, loads, emits
and compiles — and any program doing *arithmetic* on the result is **refused**,
because `emit/interval.go` returns `top` for an application of any primitive it
does not structurally recognise. The declared result type is never consulted.

Three spellings were tried and none works: `(ensures (and (<= 0 result) (<= result 64)))`
on a pure prim, the same on an impure one, and a range in the result position
`(prim ones (…) (int 0 64) …)`. `ensures` feeds the **refinement** layer;
in-window proof is the **interval** layer; the two do not meet here.

**So ADR 0019's bounded-by-default refuses arithmetic on every host result in the
standard library**, and `-checked` is currently the only way through. That is a
much larger consequence than it looks, and the fix is small and structurally
obvious: mirror `paramIval`, which already reads a declared range off a
signature's parameter.

This is the *fourth* independent demand for a postcondition naming a result —
after precision-integers.md, indexnarrow-2026-08-27 and general-purpose.md's
Win32/SAL `_Out_range_`.

### 4c. One `int` collapses Go's twelve integer types — and the fix already exists

The first generated program failed to compile:

```
cannot use n (variable of type int) as uint64 value in argument to bits.OnesCount64
```

`int8 … uint64`, `byte` and `rune` all map to our `int`, and the host rejects the
call. **The target format can already say the right thing** — the template
carries the conversion and the argument carries the range that makes it sound:

```lisp
(prim ones ((x (int 0 4294967295))) int expr "bits.OnesCount64(uint64(%s))" pure)
```

Verified: the range on the argument is read and discharged. So this is a
**generator** limitation rather than a language one, and it is exactly ADR 0003
at the call boundary — *a range says what a value IS, the target says how it is
stored* — with the missing half being a **conversion at a boundary**, which
[ADR 0019](../../docs/decisions/0019-precision-by-declaration.md) explicitly
left open.

### 4d. Variadic — FORMAT, 117 symbols

Arity is fixed and checked. `fmt.Printf` is why `targets/go/fmt.oro` declares
`Printf`, `Printf2`, `Printf3` by hand, which
[overloading.md §3](../../docs/overloading.md) already names as the one live
instance of arity overloading and as a target-file wart. Keying primitives by
`(name, arity)` is the small version; a genuine variadic template is the large
one.

### 4e. Interfaces — LANGUAGE, 89 refused and the cause of `io` scoring zero

An interface is a value with no constructor and no eliminator on our side. Note
what it is *not*: it is not dispatch we lack — `case` on a sum is dispatch — it is
that the host's interface is an **existential** (`∃T. T × (T → …)`), and
[callbacks.md](../../docs/spec/callbacks.md) tier 3 is exactly the thing refused.
Reaching `io.Reader` means letting a manufactured closure escape, which ADR 0018
depends on not happening.

### 4f. Generics — FORMAT, 100 symbols across two shapes

Two distinct things, worth separating. **Type parameters on a function** (74) need
instantiation, and the residual is monomorphic, so the natural home is the
declaration: a target file would say which instantiations it provides.
**A generic instantiation as a type** (26) — `iter.Seq[[]uint8]` — is worse: our
type language has one constructor per concept and **no way to apply a host type
constructor**. The generated file failed to load on exactly this, which is how it
was found.

### 4g. Structs — LANGUAGE, and mostly invisible here

Only counted where a bare `struct{…}` appears, because a *named* struct is opaque
and therefore declarable. That is precisely the trap: `time.Time` is declarable,
obtainable, and its fields are unreachable. The 34 usable `time` methods are the
ones returning scalars. A product with named fields is what
[type-algebra.md](../../docs/type-algebra.md) says we have at the static level and
refuse at the dynamic one.

### 4h. Void functions have no value

The generator skips them: a `stmt`'s value is argument 0 (§3 of the format), and a
Go function returning nothing has no argument 0 to be. Small, and it removes a
long tail of `Reset`/`Grow`/`Close`-shaped methods.

## 5. What this says about the parasite thesis

**It holds for functions over values and it is the honest bar.** 495 of 1,752
functions are usable today with no language change at all, and the packages a
numeric or text program reaches are 60–95% covered. One line of data per name is
true, and the generator demonstrates it at 952 lines produced mechanically.

**It does not yet hold for objects.** 3,013 of 4,765 callable names are methods,
and reaching them is gated on a constructor being declarable — which is gated on
§4a, one field in a data format.

**And the ordering is the useful part.** Two format changes — several results, and
a declared result range — sit in front of most of the gap, and neither touches the
core, the reducer, or ADR 0018. The language-level refusals (interfaces,
closures, structs) are the ones this project has argued for on other grounds, and
this survey neither strengthens nor weakens those arguments: it prices them.

## 6. Reproducing

```bash
go run gauntlet/stdlib/survey.go            # the table above
go run gauntlet/stdlib/survey.go -emit DIR  # the declarable subset, as target files
```

The numbers move with the Go release, which is the point of reading the manifest
rather than a snapshot.
