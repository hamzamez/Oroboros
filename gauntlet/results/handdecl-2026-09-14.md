# A buffer is linear wherever it is bound, and the first package declared by hand

2026-09-14. `emit/linearity.go`, `emit/linear_host_test.go`, `targets/go/unicode-utf8.oro`,
`gauntlet/stdlib/acceptance/unicode-utf8.oro`, `gauntlet/stdlib/tooling_test.go`. The two things
decided after [host-buffers.md](../../docs/host-buffers.md): **R1**, seed linearity by type, and
**host declarations written by hand, with the generator kept as their checker** — hamza's
*"shouldn't we do it by hand, all of it?"*.

> **TWO SOUNDNESS HOLES CLOSED, NOT ONE.** The research found a buffer a primitive *returns* was
> never linearity-checked. Building the fix found the second: **an immutable array could be handed
> to a primitive declared to take a buffer**, because the type checker gives `build` no result
> type — a frozen array passed to a write-borrow type-checked, built and ran. Both are the
> hypotheses of host-buffers.md §4's theorem, and each now has a test that fails against HEAD.
>
> **WALKING EVERY BUFFER REFUSED THREE CORRECT PROGRAMS FIRST, and each refusal was a rule the
> checker had never had to state.** `again`'s arguments are simultaneous; `len` observes and never
> hands a buffer on; and a length **cannot observe a write**, so it is legal even through a dead
> name. The corpus found all three — the JSON tokeniser, the limb library, the Windows map.
>
> **`unicode/utf8` IS DECLARED BY HAND and prints the host's answer, 63 lines**, now including the
> bytes `EncodeRune` writes and an accumulator `AppendRune` cannot alias. Its declared result
> ranges take the program from **3 of 9 integer operations proven to 8 of 9**; the one left is a
> loop invariant, not a host fact.
>
> **The generator checks the hand**: every declaration must spell the host's own types, allowing
> only three justified refinements, and must cover every exported name — and six planted mistakes
> are each caught.

## 1. R1: the checker was seeded by syntax and the property is a type

`CheckLinear` walked a buffer's scope from exactly two binders: `build`'s parameter and a signature
parameter declared `(buffer V)`. host-buffers.md §2 showed a third producer — a host call that hands
a buffer back — reaches the program unchecked. The walk now opens **every** binder and asks whether
the value it binds is a buffer:

| binder | holds a buffer when its value is |
|---|---|
| `build`'s parameter | always |
| a declared parameter | declared `(buffer V)` |
| a `let` | a store, a buffer-typed primitive result, a buffer name, or a conditional/`let`/loop whose value is one |
| a loop variable | an initial value that is a buffer |
| a host call's continuation parameter | declared `(buffer V)` in the result list |

Binders are opened against one shared set of taken names, so no check can count a sibling's or a
shadowing binder's occurrences as its own.

**The second hole was found by writing the first fix's witness.** Witness G hands `(build 1 …)`'s
frozen result to `AppendInto`, declared on buffers:

```lisp
(let (build 1 (fn (b) (set b 0 104))) (fn (h) (fmt.Println (u.AppendInto h 233))))
```

It built. The type checker has no case for the structural `build`, so `h` has no type and agrees
with a parameter of any type. **Now every argument to a parameter declared a buffer must itself be a
buffer**, refused otherwise with the value named:

```
argument 1 of go/utf8b.AppendInto, h, is not a buffer, and go/utf8b.AppendInto declares it
`(buffer int 0 255)`.
```

**Four tests, each failing against HEAD** (7e495b2, run in a worktree with only the test file added):
`TestABufferAHostCallHandsBackIsLinear` (witness E), `TestABufferALetBindsIsLinear` (witness B),
`TestALoopVariableHoldingABufferIsLinear`, `TestAnArrayIsNotABuffer` (witness G) — each with a control
that must still be accepted.

## 2. What walking every buffer refused, and the three rules it made the checker state

The first version of the fix refused three programs in the corpus. None was wrong.

**`again` is simultaneous.** `examples/json/tokenize.oro` passes its stack through unchanged in one
`again` argument and reads its top in another. A bare occurrence was a move, so the read after it was
refused. ADR 0015's arguments are all evaluated before the jump rebinds, so a buffer passed through is
handed on **at the jump**. A store among the arguments is still evaluated where it stands, so
`(again (set stk sp x) … (stk sp))` is still a read after a move.

**`len` observes.** The limb library's `guard` (`emit/bignum.oro`) reads a buffer's length and then a
limb of it. `(len b)` was a move.

**A length cannot observe a write, so it is legal even through a dead name.** The Windows map library
(`emit/winmap.oro`) stores into its buffer and computes the next index from `(len m)` in one
expression. `set` passes its buffer's length through, and a call that grows a buffer hands on a new
one and leaves the old name's extent as it was — so a length sees no store, which is the only thing
linearity forbids. `alloc`, which copies the contents, stays an ordinary read.

**The emission sweep did not show the third, and the differential suite did**: the sweep emits with
`cmd/gen` without `-checked`, and all four map cases emitted unchanged there; the suite builds with
`-checked`, and refused all four on Windows. Why the two paths differ was not isolated — what matters
is that a check which only one of them runs is a check the other cannot vouch for. *A path nothing
runs is a path nothing checks*, again.

Each rule is pinned by `TestAPassThroughAndALengthAreNotMoves`, with a control: a pass-through beside
a store into the same buffer is still two moves.

## 3. Cost

**178 of 178 emitted files byte-identical** to HEAD across examples, `lib/` and the differential cases
on four targets. Compiler tests green; the differential suite agrees on every case and every target, the four map
cases included once §2's third rule was stated.

## 4. `unicode/utf8`, by hand

`targets/go/unicode-utf8.oro`: nineteen names, every claim read off the package's documentation and
source in the Go 1.27 toolchain.

| claim | names | why a person and not the generator |
|---|---|---|
| `pure` | 17 — the four constants and every function but two | purity is a promise that the call writes nothing, read off the source; the generator stopped claiming it for exactly that reason (gomethods-2026-09-09) |
| a **buffer** | `EncodeRune`, `AppendRune` | the host writes: a write-borrow `B ⊸ B ⊗ int` and a consume-and-return `B ⊸ B` |
| a result **range** | `RuneLen` `(int -1 4)`, `EncodeRune` `(int 1 4)`, the four decoders `(int 0 1114111)` and `(int 0 4)`, the counts non-negative | the manifest says `int` and `rune`; the documentation says what comes back |
| a `where` | `EncodeRune`: `(<= 4 (len p))` | "which must be large enough" — conservative, since the exact need is a disjunction the linear fragment cannot state. **Corrected the same day** (hex-2026-09-14 §3): this was NOT checked at any call site — a primitive with several results is applied to a continuation, and the refinement walk returned at that shape — so the same program with a three-byte buffer built. It is checked now, and refused. |
| an `ensures` | `RuneCount`: `(<= result (len p))` | every rune, valid or not, is at least one byte |

**The acceptance program says what the generated declarations could not.** It prints what
`EncodeRune` wrote as well as the count — `3` and `[230 151 165 0]` for `日` — because the call hands
its buffer back; and its accumulator is a buffer threaded through the loop, so two appends to one
value are refused rather than aliased. **63 lines, identical to hand-written Go calling the real
package.**

**And the ranges pay in the analysis, measured**: **3 of 9 integer operations proven** by the
previous version of this program over the generated declarations (gostd-utf8-2026-09-13), **8 of 9**
by hand. The two programs differ in how they thread the accumulator, so the comparison is between
versions rather than a controlled one; what moved is the operations on host results, which is what a
declared range is for. The one left is `(+ c 1)`, a count of rune starts bounded
by the loop invariant `c ≤ j` — a relational fact about the program, not a fact about the host, and
the program is built with `-checked` for it.

## 5. The generator as checker

`TestHandDeclarationsAgreeWithTheHost` loads the survey's generated declarations and the hand file
and requires, for every name, that the hand declaration spells the host's types, differing only in
three ways a person can justify and the generator cannot:

1. a parameter or result the host spells as a slice may be a **buffer**, because the host writes it;
2. a write-borrow's result list may **begin with the buffer it hands back**;
3. an integer result may be a **narrower range** inside the host's type.

It also requires the template to call the host's own function, the import to match, and **coverage
in both directions** — no exported name undeclared, no declared name the host lacks.

**A checker that cannot fail proves nothing**, so the test plants six mistakes and requires each to be
caught: a mistyped argument, a template calling the wrong host function, a result range wider than
the host's type, a buffer where the host takes a string, a missing name, and an invented one. All
nineteen hand declarations agree with the host, all six mistakes are caught, and the tooling suite is
green with twelve acceptance programs in 148 s. **The new target file changes no emitted file**: the
sweep taken with it installed is again 178 of 178 byte-identical.

## 6. What it leaves

- **The census default** is no longer the generator's question: a person decides whether a call writes.
  The generator's classification from host-buffers.md §6 becomes a *hint* for the person, not a claim.
- **Maps are not seeded.** A map buffer from `build-map` is still checked only from its own binder;
  nothing declares a map buffer on a host call yet, so the hole has no producer. Named, not closed.
- **One package of the standard library is by hand; the rest is not.** The next package is chosen the
  same way, and the survey's coverage report says how many names each one is.
