## 1. A skip is a claim, checked

A skip said a case does not run on a target, and nothing checked it. It is a proposition, P(c, t):
the case fails on t. Like any claim it is checked by evaluating it. The skipped target is built and
run with the others, and P holds when there is:
- a build error;
- an output other than the one the running targets agree on;
- or a trap the case does not declare (the harness builds `-checked`).

A true P can still be true for a reason no longer the written one, so the skip states its reason:
`// skip: T because "TEXT"`, with TEXT a substring of the failure. Then:
- **stale**: the target builds and agrees, and the case fails;
- **wrong reason**: it fails some other way, and the case fails, quoting what it did;
- **no reason**: refused.

**What evaluating them found** (with a placeholder reason, so each failure printed itself):

| case | target | it actually fails because |
|---|---|---|
| `word-wide-native` | js | **it does not: it builds, runs and agrees** (a stale skip, removed) |
| `mersenne-hash` | go, java | under `-checked` the product above the word is a trap, which fires at the fourth input: `panic: int overflow`, `long overflow` |
| `mersenne-hash` | js | a remainder of a pair by p, not a power of two, is not built |
| `quotient-corner` | js | a quotient of a pair by a divisor not a constant is not built |
| `u128-fact`, `u128-ops` | js, java, windows | `go/math/bits` is unbound |
| `u64-digits` | js | a comparison of pairs is not built |
| `u64-mulhi` | go, java | `>>` in the unsigned word is not built (ADR 0082) |
| `u64-mulhi` | js | an operand of `>>` above JavaScript's word |
| `u64-square`, `u64-values` | js | a division or remainder of a pair by a non-power of two |

Two skips said one thing and did another:
- `mersenne-hash`'s comment said Go and the JVM refuse the product. Under the harness's `-checked`
  they trap instead, so the comment now says both.
- `quotient-corner`'s said JavaScript has no corner. That is true, but the build refuses the pair's
  quotient first.

**The witness**, `TestASkipIsACheckedClaim`, runs four cases. `u64-digits`, refused on JavaScript
for a comparison of pairs, is the control and passes. The planted faults are:
- a skip of the JVM on a case that agrees everywhere, failing as stale;
- the control's skip with a reason it does not have;
- a skip with none.

## 3. A compared file holding K(ℕ\*)'s text, and the defect behind its absence

None of the windows files the emission step compared held a K(ℕ\*) function. The programs that
would, examples/big's fib, pair, fact and power, were refused by `gen` at W5:
*%548 is array int and flows into nat.add's argument 2, which is array int 0 18446744073709551615*.
`cmd/build` never met it, since it builds only programs with a `main`. Inside a `main` the same loop
passes (the differential's `big-fib`), so the difference is the entry point.

**The cause is Theorem D′** (`ir/final.go`). The tables a function's values flow between form
classes, and a class takes the representation a declaration fixes. Here one class held two fixed
members:
- the export's result, declared `array int` by the rung;
- `nat.add`'s parameters and result, each a numeral's table, `array int 0 2⁶⁴ − 1`.

The theorem reports such a class instead of resolving it, which is what W5 did. The wrong input is
the first declaration. On K(ℕ\*) a natural held exactly is a numeral, its digits in [0, 2⁶⁴), the
type every instance already has (ADR 0101, 0106). So the rung declares it so, on K(ℕ\*) only (the
fixed limbs keep `array int`). It is a claim, proven after the rung's decision by the body's own
stores (`proveResultElems`, ADR 0072 on a table), as each instance's result is.

The four programs now emit. Their files hold `nat.add` with the full adder
(`llvm.x86.addcarry.64`, `subborrow.64`, ADR 0108), the product and D, and the emission step
compares them. The book's finding 23, `square(square(10^20))`, owed on windows by
[chapters56-2026-11-15](chapters56-2026-11-15.md), is the same defect and now builds there.

**The witness**, `TestAnExportsNumeralIsANumeralsTable`, requires fib's file to hold `nat.add` and
the full adder. `PlantNumeralResultInt` declares the result `array int` again, and W5 refuses.

## 4. The interval route's error is carried, not swallowed

The interval route is a partial function, residual → residual ⊎ error. When the residual does not
lower, it decides no range, which is sound, since the refinement route still sees every mark. But
it returned nothing, so if the refinement layer then refused, the refusal named an obligation the
IR might have proven, and the cause was lost. That misled oswin-2026-11-15's diagnosis twice.

Now the route returns its error with the residual, `DischargeRanges(…) (*core.Term, error)`, and
`DischargeRequires` joins it to any refusal that follows:

> the IR's intervals decided none of the ranges here, so the refinement layer was asked alone: the
> residual does not lower: a table rule that was never allocated … That is the error to fix first.

A lowering error that no refusal follows changes nothing, as before.

**The witness**, `TestARefusalCarriesTheIntervalRoutesError`, combines ADR 0115's planted fault (a
rule at an export's boundary left unallocated) with a call `g(i * i)`. The intervals bound i · i,
and the refinement layer's linear fragment cannot. The refusal must name the rule never allocated.
With `PlantRangeRouteSilent` the error is swallowed again, and the refusal is `g`'s parameter alone,
which the test also requires: the premise, computed.
