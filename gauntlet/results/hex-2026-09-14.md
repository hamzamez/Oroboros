# encoding/hex by hand, and the refinement layer had never looked inside a host call

2026-09-14. `targets/go/encoding-hex.oro`, `gauntlet/stdlib/acceptance/encoding-hex.oro`,
`emit/refine.go`, `emit/linear.go`, `emit/monotone.go`, `emit/target.go`,
`emit/multiwhere_test.go`, `examples/io/jsonfmt.oro`, `examples/io/freq.oro`. The second standard
library package declared by hand, on hamza's *"pick a new package and let's do the same. always be
mathematical and algebraic."*

> **THE PACKAGE IS AN ALGEBRA AND THE DECLARATIONS SAY AS MUCH OF IT AS THE LANGUAGE CAN CHECK.**
> The encoding is a monoid homomorphism that doubles length, decoding is its left inverse,
> encode-after-decode is a projection, and off its domain decoding returns a prefix. Two
> preconditions are LINEAR in two lengths and are stated exactly. The acceptance program is those
> laws in order, and prints what the real package prints, 31 lines.
>
> **AND WRITING A SHORT BUFFER UNDER `hex.Encode` BUILT.** It panicked inside the host. The refinement
> walk returned at any application whose operator is not a name — which is how every host call with
> several results is used — so such a call's `where`, its arguments and its whole continuation had
> never been checked. **unicode/utf8's `EncodeRune` precondition, recorded this morning as checked at
> every call site, was checked at none.** A second silent drop sat beside it: a repeated `(where …)`
> replaced the first.
>
> **Closing it refused two corpus programs, and one of the two refusals was a real out-of-range read.**
> `jsonfmt` on a document ending in a backslash inside a string printed a NUL on Go and JavaScript and
> threw on the JVM. The other, `freq`, needed four facts the analysis now derives and five statements
> saying what the program assumes; its output is identical to before on five files and three hosts.

## 1. The algebra

Let `B = [0, 255]`, `D` the sixteen bytes of `"0123456789abcdef"`, and `A = D ∪ "ABCDEF"`.

**The encoding** is the monoid homomorphism `H : B* → D*` generated by `h(b) = d(⌊b/16⌋) · d(b mod 16)`,
so `H(xy) = H(x)H(y)`, `H(ε) = ε`, and `|H(x)| = 2|x|`: length is a homomorphism into `(ℕ, +)` and H
doubles it. H is injective, since h is.

**The decoding** is a partial map `G : A* ⇀ B*`, defined exactly on words of even length over A. Two
laws:

- `G ∘ H = id` — G is a LEFT inverse of H;
- `H ∘ G ≠ id` but `(H ∘ G)² = H ∘ G` — encode-after-decode is a PROJECTION, onto lowercase.

**Off its domain** the host totalises G by returning the longest prefix of whole pairs before the first
byte outside A, with `n ≤ ⌊|src|/2⌋` bytes, and an error saying why (`hex.go`: a bad byte is reported
before an odd length, because it is the earlier problem).

**The lengths**: `EncodedLen` is the ℤ-linear map `n ↦ 2n` and `DecodedLen` is `x ↦ x/2`, truncating.
The language's window (ADR 0012) is closed under the second and **not** under the first.

**The streams** — `NewEncoder`, `NewDecoder`, `Dumper` — allocate an object with mutable state, so two
calls are two objects and substituting one for the other is observable. Generativity is an effect
exactly when the generated thing can be told apart (Pitts & Stark's ν-calculus, 1993). `DecodeString`'s
fresh slice cannot be told apart — the program only reads it — so it is pure and the streams are not.

## 2. The declarations

Thirteen names in two modules, each claim read off `src/encoding/hex/hex.go` in Go 1.27.

| claim | names | from the algebra |
|---|---|---|
| `pure` | `EncodedLen`, `DecodedLen`, `EncodeToString`, `DecodeString`, `Dump`, `InvalidByteError.Error` | a function of its arguments that writes nothing it was handed |
| impure | the three streams; `Encode`, `Decode`, `AppendEncode`, `AppendDecode` | generativity; a write |
| a **write-borrow** `B ⊸ B ⊗ R` | `Encode` (R = the count), `Decode` (R = the count and the error) | the host writes `dst` and returns a count; the template hands `dst` back |
| **consume and return** `B ⊸ B` | `AppendEncode`, `AppendDecode` (with its error) | `slices.Grow` may or may not reuse `dst`, so `dst` is dead either way |
| a **linear precondition** | `Encode`: `2·len src ≤ len dst`; `Decode`: `len src ≤ 2·len dst + 1` | the host indexes `dst[0 .. 2|src|)` and `dst[0 .. ⌊|src|/2⌋)` and checks nothing; `⌊s/2⌋ ≤ d` over ℤ is `s ≤ 2d + 1` |
| a precondition from ADR 0012 | `EncodedLen`: `|n| ≤ 2⁵² − 1` | the preimage of the window under `n ↦ 2n`; the host needs none |
| a result range | `Encode` count `0 … 2⁵³ − 2`, `Decode` count `0 … 2⁵² − 1` | always `2|src|`, and at most `⌊|src|/2⌋` |
| an **interface edge** | `io.WriteCloser ≤ io.Writer` | method-set inclusion, which `io.go` states by embedding |

**Both preconditions are EXACT rather than conservative**, unlike utf8's `EncodeRune`, whose exact need
is a disjunction. That is the first time a hand declaration could say precisely what the host requires.

**The interface edge is the one declaration this package needed that is not about the package.** The
generated relation has only concrete subjects — `*os.File ≤ io.Writer` — and `Dumper` returns an
`io.WriteCloser`, which nothing could be written to until `io.WriteCloser ≤ io.Writer` was stated.
Method-set inclusion is a preorder on interfaces as well (Cardelli's record subtyping); the edge emits
nothing, and Go's compiler would refuse the file if it were false.

**The checker covers both modules.** `TestHandDeclarationsAgreeWithTheHost` now takes a list of modules
per package and a table of planted mistakes per package; for hex: a mistyped argument, `Encode` calling
`hex.AppendEncode(`, a count range past the window, a buffer where the host takes a string, a missing
name and an invented one. All six are caught; both modules agree with the host.

## 3. The refinement layer had never looked inside a host call with several results

**The acceptance program built, and so did every mutant of it.** A buffer one byte short under
`Encode` built and panicked in `hex.Encode`; the same under `Decode`, and under the prefix case, built.
**The same mutant of this morning's utf8 program — a three-byte buffer under `EncodeRune` — built too.**

`refine.go`'s walk began `if op.Kind != core.KName { return nil }`, and a host call with several results
is used by applying it to its continuation, `((p a…) (fn (x y) body))`, whose operator is an
application. So three things were never walked: the call's `where`, its arguments, and **the entire
continuation** — which, for every program that opens a file, is the program. It is the shape of
jsonfmt-2026-09-07's first bug (the interval pass returning ⊤ at the same operator) in the other
analysis, and it survived that fix because each layer had its own walk.

**The fix walks the operator and the argument.** Walking more can only find more obligations, so it is
sound in the direction that matters. One operator is excluded, and by algebra rather than by a list:
`((m k) (fn (tag v) …))` is a MAP read being eliminated, whose domain condition is a VALUE — the option —
not a proof (maps.md F2). It is recognised without types: an array element is never a function, since a
closure does not survive staging.

**And a repeated clause dropped a precondition.** `(where a) (where b)` assigned a field twice. It is
refused now, naming the clause, with the conjunction spelled `(where (and a b))`.

### What walking the bodies needed, and each is a theorem

Walking the continuations refused `freq.oro` and `jsonfmt.oro`. Five of the facts those refusals wanted
hold and were not derived; each is now derived, with a witness that fails against HEAD and a control that
must stay refused.

**(a) A loop is at least its lower bound — rule 6 of `e ⊒ S`.** monotone.go's corollary gives `⟦L⟧ ≥ ⟦z⟧`
for a loop whose every step and exit is at least its variable. Used inside the relation it was derived
from: `L ⊒ S` if `LoopLowerBound(L) = z` and `z ⊒ S`. The induction is well-founded because z is a proper
subterm. An index assigned a scanner's result, `(let (scan src i) (fn (ni) … (again ni)))`, is then
non-decreasing, and **the refinement layer now asks the relation** where it had asked only whether every
`again` adds a literal.

**(b) A loop's start need not be a literal.** The theorem gives `v ≥ z` for z's value on entry, and every
name z mentions is immutable, so `0 ≤ z` entailed on entry is `0 ≤ v` throughout.

**(c) Euclidean division has two halves.** For `x ≥ 0` and `k > 0`,
`k·⌊x/k⌋ ≤ x ≤ k·⌊x/k⌋ + (k−1)`. Only the first was assumed. The guard that makes both sound is the one
already there — x is a length. Without the second, a buffer of `⌊len enc / 2⌋` could not be shown to hold
the decoding of `enc`, which is exactly `Decode`'s precondition.

**(d) Facts and goals are rewritten by the same equations.** A fact was substituted when ASSUMED and a
goal when ASKED, and the division axioms are seeded before any `let`, so under `let enc = build (2·len a)`
the axiom kept `len(enc)` while the goal said `2·len(a)`. Equality is a congruence: rewriting both sides
by one set of equations at query time changes no meaning.

**(e) A value bound to a conditional keeps what all its branches satisfy.** For `x = (if c₁ … ℓ₁ … ℓₘ)`
with linear leaves reached under path facts Pⱼ, if `Pⱼ ⊢ φ(ℓⱼ)` for every j then `φ(x)`, since exactly
one leaf is evaluated on a path whose facts hold. The φ tried are the template inequalities comparing x
with each linear side of each guard and with 0 — the join of template constraint domains (Sankaranarayanan,
Sipma & Manna, VMCAI 2005), exact over the templates and never needing a convex hull. It walks through a
`let`, because a clamp of a table read binds the read first, and refuses any template naming that inner
binder. **This closes a limitation CLAUDE.md recorded with the product**: *a clamped value used twice is
let-bound, and the refinement layer loses the clamp's bounds across that binding.*

**Nine witnesses in `emit/multiwhere_test.go`, all failing against HEAD** (8e35acb, run in a worktree with
only the test file copied in) and all passing now.

## 4. What the corpus had been hiding

### jsonfmt read one byte past its input

`scan-string` skips two bytes at a backslash, so a document ending inside a string on a backslash took
`j` to `len + 1`; the copy loop then read `src[len]`. Built from 8e35acb on `{"a": "x\`:

| host | output |
|---|---|
| Go | `{` `"a": "x\` then a **NUL** |
| JavaScript | the same, a **NUL** |
| the JVM | `ArrayIndexOutOfBoundsException: Index 9` |

**One source, two answers, and a crash** — invisible because nothing checked the body and every test
document was well formed. The scanner now ends a token at a backslash on the last byte, which keeps every
exit at least `j` and so keeps (a)'s derivation; the copy loop gains a guard the analysis needs and no
input reaches. **All three hosts now print `"x\` and a newline**, and a well-formed document formats
byte-identically to 8e35acb's binaries on each host. 103 of 103 integer operations bounded, 13 of 13
loops.

### freq assumed what a permutation holds

Once (a)–(e) were derived, `freq` still needed facts no analysis here has: that the entries of the sort's
own permutation are word indices, and that a distinct-word count is at least one when a word exists —
invariants over a table's slots and across two functions (frozen-2026-08-28). **The program says them
instead, in five places**: a guard on the comparator's two indices; `(< nd 1)` in `dists`; the report's
two loops bounded by `nd` and by `topn` separately rather than through `mmin`, whose comparison against a
conditional the fragment cannot read; `(< (len sp) 1)` beside those; and `dword` clamped into the span
table it indexes as well as below the arithmetic cap. **Every one is never taken on real input, and the
output is identical to 8e35acb's on five files on Go, JavaScript and the JVM.** 324 of 324 integer
operations bounded and 27 of 31 loops, as before; **80 index obligations are now reported propagated,
not proven** — an index written as an inline clamp is outside the fragment — where before nothing was
reported because nothing was checked.

### tally, which is freq's shape on two hosts

`examples/tally`'s core copies freq's `dists`, and it failed the tooling suite on Go and the JVM with the
same refusal — the group read `(dt s)` with no fact that `nd >= 1`. The emission sweep had not shown it,
because it skips `examples/tally`, whose core does not emit alone. **The same one clause, `(< nd 1) dt`,
fixes it**; the rest of its reads clamp into the table they index and the join (e) covers them. All four
tally acceptance programs print the host's answer — the sample log and the optional group, on Go and on
the JVM.

## 6. What it leaves

- **`Close` on an `io.WriteCloser` is unreachable.** No declaration, generated or by hand, gives an
  interface its methods, so the dumper is written to and never closed; the acceptance program shows the
  dump missing exactly what `Close` would write. Interface method sets are the next thing `io` needs.
- **A comparison against a conditional is opaque to the refinement layer**, and so is an index written
  as an inline clamp — 80 notes in `freq`. (e) gives a NAME the join; a comparison or an index operand is
  not a name.
- **`hex.InvalidByteError`'s `Error` is declared and cannot be called**: a program holds an `error` and
  cannot narrow it to the named type. `fmt.Println` of the error prints its message, which is what the
  program uses.
- **`os.text-of` on bytes that are not UTF-8 is a cross-host divergence**, found while checking jsonfmt
  and present at 8e35acb: Go keeps the byte, V8 and the JVM substitute U+FFFD. Named, not fixed.
  **Closed by [ADR 0030](../../docs/decisions/0030-a-hosts-string-is-the-hosts.md)** ([hoststring-2026-09-24](hoststring-2026-09-24.md)):
  `text-of` is d, the standard's maximal-subpart substitution, on all three.
- **The surface questions** — `go/unicode-utf8` or `go/unicode/utf8`, sugar for a constant, a name for a
  range — are written up in [declaration-surface.md](../../docs/declaration-surface.md) for decision.
