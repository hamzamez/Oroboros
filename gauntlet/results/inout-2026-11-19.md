# inout — a cell parameter is the mode, built (ADR 0135), 2026-11-19

## What was built

A binder is `x ∈ S mode` (ADR 0135 item 1): S ranges over values, the mode says what the program
observes of the caller's place. D maps `x ∈ T inout` to the core's `(x (cell ⌜T⌝))` and
`b ∈ Array(V) linear` to `(b (buffer ⌜V⌝))`, so the core's formers are D's image and J writes the
mode.

- **The refusal** (`core/jparse.go`'s `coreFormer`, called from J's program reader at a parameter and
  from the target reader at a host declaration's parameter and result): `cell(T)` at a binder is
  refused, "a cell is a place, not a set: write the value's set and the mode, `x ∈ T inout`, not
  `cell(T)` (ADR 0135)", and `buffer(V)` likewise naming `b ∈ Array(V) linear`. A host result's
  handed-back buffer is `b' ∈ Array(V) linear`, read to the core's `(buffer V)` as before.
- **W7** (abstract.md): `inout` stands on a program definition's parameter as on a host's.
- **The respelling**, 31 sites in code and tests, every one the same core term: `targets/go/strconv.oro` (10),
  `encoding/binary.oro` (2), `encoding/hex.oro` (2), `fmt.oro` (3), `unicode/utf8.oro` (1),
  `targets/win32/commdlg.oro`'s `pd ∈ PRINTDLGA inout`, `fileapi.oro`'s `hi ∈ winnt.LONG inout`,
  `examples/native/wndproc-win.oro`'s `s ∈ S inout`, `gauntlet/differential/cases/cell-param.oro`, the
  tests in `cmd/build/callback_test.go`, `emit/hostdef_test.go`, `core/slot.go`'s message, and
  callbacks.md, local.md, llvm.md, target-files.md, inventory.md, README.md, CLAUDE.md.
- **The test** `TestACellIsAModeNotASet` (`core/record_test.go`): each former at a binder refused for
  its reason, the same declaration with the mode read (so the premise of each refusal is the former
  alone), and the fault `PlantCoreFormerAccepted` reading the formers again, which makes the refusal
  cases fail.

## What failed first

The respelling script also rewrote two **program results**, `smooth_into(…) (buffer(F64))` in
`examples/native/smooth-go.oro` and `workspace(…) (buffer(0..65535))` in `examples/kara/workspace.oro`,
to `(Array(F64) linear)`. The emission step refused both on all four targets: "a definition whose
result is linear moves out a region it owns … this one returns #1.0, which it does not own
(ADR 0084)". The two spellings are not one term at a result. `(r ∈ Array(V) linear)` is ADR 0084's
moved-out region (the definition made it, the caller now holds it). `(buffer(V))` is ADR 0070's lent
buffer handed back (the caller lent it, the definition returns it written). At a parameter the mode
names one relation. At a result there are two, and J has a word for only the first. The two results
are restored, and the program reader does not refuse `buffer(V)` at a result. Its spelling is set
aside for hamza (below).

## Not built, and set aside for hamza

(Item 1 decided by hamza on 2026-11-19, option (a), ADR 0140, and built.)

1. **A lent buffer handed back as a program's result**, `(buffer(V))` today. Its parameter is
   `dst ∈ Array(V) linear`. Its result is the same place returned, which ADR 0070 reads as the borrow
   ending. The candidates, each one core term:
   - (a) the host's spelling, a primed name `(dst' ∈ Array(V) linear)`, the prime naming the parameter
     it returns, so `linear` at a result means "moved" unprimed and "handed back" primed;
   - (b) no result at all: a definition whose parameter is `linear` returns `()` and the caller keeps
     its buffer, the borrow ending at the call as at a host call (ADR 0070). This changes the two
     programs;
   - (c) keep `(buffer(V))` at a result only.

   (a) is what the target files already write for the host's consume-and-return.
2. **The variadic of cells**, `fmt.Scan(a ∈ Array(cell(go.Value)))`: a table each of whose elements
   is a place. The mode applies to the binder, not to an element, so `Array(go.Value) inout` would say
   the wrong thing (the table written back, not each element). abstract.md's D reads it as "each
   trailing argument `x ∈ T inout`". Left as written, nested, until a program calls `Scan`.
