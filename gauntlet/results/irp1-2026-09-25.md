# P1: what lowering to an IR costs, against what the pipeline costs today

2026-09-25. The first prototype of [docs/ir-research.md](../../docs/ir-research.md) §11. Code:
`experiments/irproto/`, run as `go run ./experiments/irproto SRC.oro`. It runs cmd/gen's pipeline
stage by stage on every export, recording each stage's time and bytes allocated
(`runtime.MemStats.TotalAlloc`). It then lowers the residual the emitter received:
- to **C2**, structured SSA: regions whose terminators are yield, break, continue and branch;
- to **C1**, a control-flow graph of blocks with parameters, by flattening C2;
- and it computes on C1 what Ramsey's structuring needs before a JS or Java printer can use it:
  reverse postorder and dominators (Cooper, Harvey and Kennedy 2001).

## 1. The lowering is nearly free, for both candidates

| program | residual (term nodes) | residual → C2 | C2 → C1 | C1: RPO + dominators | C2 size |
|---|---:|---:|---:|---:|---|
| `io/freq` | 2,948 | 0.40 ms, 0.44 MB | 0.25 ms, 0.39 MB | 0.05 ms | 1,536 values, 1,464 ops, 625 regions |
| `json/tree` | 4,589 | 0.41 ms, 0.71 MB | 0.35 ms, 0.69 MB | 0.07 ms | two exports, 2,648 values |
| `json/tokenize` | 2,329 | 0.17 ms, 0.32 MB | 0.10 ms, 0.29 MB | 0.05 ms | two exports, 1,191 values |
| `io/jsonfmt` | 1,234 | 0.10 ms, 0.17 MB | 0.10 ms, 0.16 MB | <0.01 ms | 654 values |

- **Nothing was left opaque.** Every shape of four real residuals lowered to C2's operations
  (constant, global, primitive, index, map read, if, loop, build).
- **The lowering reopens no binder.** It resolves de Bruijn indices against a stack of frames, one
  pushed per λ crossed. That is research §4's claim, measured: the names cost 0.1–0.4 ms.
- **C1 costs C2's traversal plus a flattening plus dominators**, before a structured host can print
  it. So by P1's criterion C2 is the cheaper, and it survives. The difference is about 0.3 ms, though,
  so **lowering cost does not decide C1 against C2.** Printing (P2) and analysis (P3) decide it.

`examples/tally` is excluded: `gen` refuses it too, and it is built with `cmd/build` and a host layer.

## 2. The pipeline costs 100 to 2,500 times the program

| program | today, total | refinement | intervals (legality) | `SelectShifts` | emission (Go) |
|---|---|---:|---:|---:|---:|
| `io/freq` | 9.9 s, **7,460 MB** | 1,054 MB | 1,803 MB | **1,801 MB** | 2,771 MB |
| `json/tree` | 1.5 s, 1,260 MB | 132 MB | 408 MB | **408 MB** | 277 MB |
| `json/tokenize` | 0.40 s, 241 MB | 148 MB | 40 MB | **40 MB** | 4 MB |
| `io/jsonfmt` | 0.20 s, 112 MB | 43 MB | 30 MB | **29 MB** | 3 MB |

`freq` allocates **7.46 GB for a residual of 2,948 term nodes**, about 2.5 MB per node, where the
whole program as C2 is 0.44 MB.

**`SelectShifts` reruns the interval analysis in full.** It costs, on every program, what the legality
pass costs (`interval.go:4029`). Emission's share on `freq` is mostly `BufferRange` rerunning the
analysis per `build` (research §0). So the same analysis runs at least three times over one residual.

## 3. Where the bytes go (`freq`, allocation profile)

| class | MB | share | removed by |
|---|---:|---:|---|
| the interval pass copying its environment: `restore` 2,744, `snapshot` 1,361 | 4,105 | **57.7%** | facts that do not depend on the path (§4) |
| rebuilding terms: `openWith` 526, `closeTerm` 363, `shift` 298, `App` 134, `openTerm` 123, `Name` 109, `Bound` 71, … | ≈1,565 | **≈22%** | unique names: the IR itself |
| refinement copying its facts: `facts.clone` 150, `linear.clone` 103 | 252 | 3.5% | the same |
| Fourier–Motzkin, rows and the rest | ≈1,200 | ≈17% | not addressed by an IR |

The interval pass is **85%** of all allocation (`app`, 6,054 MB cumulative).

## 4. What P1 found that the research had not said

The largest class is not rebuilding terms. It is **copying the environment at every branch**, and it
exists because facts are **path-sensitive**: a guard narrows a variable on its own side only, so the
fact about `x` depends on the program point, and the pass keeps a whole map per point.

**An IR with unique names alone does not remove it**, because it moves the per-point map from terms
to values. What removes it is a representation in which **each name has exactly one fact**:
- **e-SSA / SSI** (Bodík, Gupta and Sarkar, *ABCD*, PLDI 2000; Ananian, *The Static Single
  Information Form*, 1999): after a branch on `x < n`, each side renames `x` by a π-node, `x₁ = π(x)`,
  and the narrowed fact belongs to `x₁`;
- **then the analysis is sparse** (Tavares, Boissinot, Pereira and Rastello, CC 2014): one fact per
  value, computed once, with no per-point environment and nothing to copy.

**In C2 a π-node is a parameter of the branch's region.** It is the same device as a loop's
parameters, so it adds no operation to the algebra. This becomes a **requirement** of the IR (research
§4b).

## 5. Verdict against P1's criteria

- **C2 against C1:** C2's lowering is cheaper, so it is not killed. But the margin (~0.3 ms) is
  immaterial, and the choice moves to P2 and P3.
- **The refactor as a whole** was to be killed if neither IR could remove a large share of the
  allocation. It is not killed:
  - **≈22%** (rebuilding terms) is removed by construction;
  - the **repeated runs** of the interval analysis are removed by computing facts once, on values;
  - **57.7%** (environment copying) is removable only with π-parameters.

  The last two are predictions until **P3** measures an interval domain on C2 with π-parameters,
  against `interval.go` on the same programs, with proof counts that must not fall.

## 6. Not measured, and why

- **An analysis on the IR:** that is P3.
- **A direct residual → C1 lowering,** rather than through C2: it would cost about C2's traversal
  plus building blocks, and C1 would still need dominators to print. The measured sum is an upper
  bound.
- **Removing `SelectShifts`' second run on today's code,** a win independent of the refactor. Its
  flags differ from the legality run's (it asks for shifts and representations), so whether one run
  can serve both is to be checked, not assumed.
