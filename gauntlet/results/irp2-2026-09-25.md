# P2: a Go printer for C2, at parity on the gauntlet

2026-09-25. The second prototype of [docs/ir-research.md](../../docs/ir-research.md) §11, after P1
([irp1-2026-09-25](irp1-2026-09-25.md)) and P3 ([irp3-2026-09-25](irp3-2026-09-25.md)). P2 decides
the printing side of C1 against C2. Its kill criteria:
- C2 dies if any gauntlet program loses parity with hand-written Go;
- C2 dies if Go's multi-exit non-loop block costs more than Ramsey's structuring would.

Code:
- `experiments/irproto/gogen.go`: **the printer**, C2 → Go.
  - **Types by unification.** A union-find over values unifies a loop parameter with its initial value
    and every `again` argument, an `if`'s or a `build`'s result with its yields, and a store with its
    buffer. Constants, signatures and declared results seed the classes. LoopOneJoin's rule, that
    every table flowing into one variable has one host type, is this unification, not a special case.
  - **Table widths once per class**, from the sparse analysis's element ranges (P3), through
    `HostType("array int LO HI")`.
  - **Liveness as a least fixpoint.** An operation is live if it has an effect, owns a region, or has
    a result that is read. A yield's or break's argument j is read only if its owner's result j is.
  - **The measured emission decisions as rules on the IR:**
    - soleExit: a loop result that every break yields as the same parameter *is* that parameter;
    - PostVars: a parameter that every back edge advances by the same literal moves to the `for` post
      clause;
    - bounds-check re-slicing (bce-2026-08-15): an invariant table the loop reads only at the
      parameter guarded by `len X` is re-sliced to `len X` before the loop;
    - connectives: `(if c true E)` prints as `c || E` and `(if c E false)` as `c && E` when E is an
      expression tree (booleans.md, cond-2026-09-19).
- `experiments/irproto/main.go`: `-print PREFIX -o FILE -pkg PKG` prints a Go file instead of
  measuring.
- `emit/classify.go`: `HostType` and `IsLengthName`, thin exports of the emitter's own tables, so the
  prototype spells types and recognises lengths exactly as `golang.go` does.

## 1. Method

- Two scratch copies of the `gauntlet/go` module: one with **today's `gen` output, regenerated**, and
  one with the prototype's output under the same file and function names.
  - The committed `gen_*.go` files are stale: dot, centroid, generic, smooth and jsontok differ from
    what `gen` emits today.
  - `wordcount` is regenerated with `-checked`, which today's legal compile of `NativeTally` needs.
- Each benchmark ran in **its own process**, the three variants interleaved over 7 rounds at
  `-benchtime=1s`. The table gives medians.
- `hand` is the gauntlet's own hand-written reference for each program.

## 3. What made a suspicious result explain itself

The first run, without the connective rule, gave two results outside the rest:
- **json tokeniser 0.95 of `gen`**;
- **json tree 1.04 of `gen`**.

Both sets of seven runs were disjoint from `gen`'s. Go's bounds-check report was identical for both
variants (70 checks in tree, 10 in the tokeniser), so the difference was not bounds checking. The
visible difference was the connectives:
- `gen` prints 170 and 100 `||`/`&&` operators;
- the prototype printed 70 and 50 boolean joins (`var v bool; if a { v = true } else { v = … }`).

Second run, 9 interleaved rounds, adding the prototype *with* the connective rule:

| | hand | gen | proto, joins | proto, operators |
|---|---:|---:|---:|---:|
| json tokeniser | 9,608 | 9,198 | **8,782** | 9,274 |
| json tree | 4,367 | 4,796 | **4,974** | 4,789 |

The rule accounts for both deviations exactly. With it, the prototype equals `gen` (1.01, 1.00).
**The join and the operator are each worth about 5%, in opposite directions on two programs.** That
is Go's block layout, and it is below the noise floor, so no decision can rest on it. The printer
keeps the operator, which is what the reader preserves the connective for and what today's backend
emits. The rule is a measured decision and belongs in the table of research §7.

## 4. Correctness

- **The gauntlet's agreement tests pass** on the prototype's output. Every benchmarked function is
  called by one (`GenRun` and `TreeRun`, the `main`s, are not).
- **The tests can fail.** Two planted faults:
  - `v4 + v14` turned into `v4 - v14` in `NativeDot` fails the dot agreement test;
  - `v549 * 1000` turned into `v549 * 999` in `TreeMeasure` fails `TestTreeAgree`.

  A third, `+ 1` turned into `+ 2` on tree's whitespace skip, passed: the test documents never reach
  two consecutive whitespace bytes there. That is a gap in the test's inputs, not in the printer.
- **Beyond the gauntlet**, a differential run links the prototype's and `gen`'s output into one binary
  and compares the answers:

  | program | printed lines | inputs | agree |
  |---|---:|---|---|
  | `io/freq` | 2,054 | README.md, CLAUDE.md, docs/ir-research.md | all |
  | `io/jsonfmt` | 583 | conformance/cases.json, a small document, a malformed one | all |
  | `io/wc` | 59 | stdin | yes |
  | `table/sieve` | 54 | `count-primes n`, n < 3,000 | all 3,000 |
  | `big/limbs` | 78 | `limb n`, −5 ≤ n < 5,000 | all 5,005 |

  `tally` was not printed: it needs its own host layer, which the harness does not load.

## 5. The second criterion does not arise

In C2 as lowered, a non-loop region (an `if`'s arm or a `build`'s body) is lowered in value position,
so every leaf is a yield. Only a loop body's leaves are `break` or `continue`, and those target the
innermost loop, which is exactly Go's `break` and `continue`. **No printed file contains a label or a
`goto`.**

Go's multi-exit non-loop block therefore costs nothing, because there is no such block: a yield is an
assignment and a fall-through. C1 would have to recover this structure (P1 measured the RPO and
dominators that Ramsey's structuring starts from). C2 carries it.

This is the printing half of what P3 found on the analysis side: **C2's structure is its syntax**, and
both consumers read it by recursion over regions.

## 6. Size and cost

**The printer.** `gogen.go` has 1,104 lines of code (comments and blanks excluded), against 1,706 for
`golang.go` and `golang_join.go`:

| concern | lines | belongs in |
|---|---:|---|
| types by unification | 275 | the IR: research §6 has types in the IR, and a printer reads them |
| table widths | 27 | the IR, as a representation decision |
| liveness | 81 | the IR, and shared by every printer |
| bounds-check re-slicing | 110 | the Go printer, or the IR as a fact (`len Y ≥ len X` on the guard) |
| connectives | 95 | every printer with `\|\|`, which is all four |
| everything else | 516 | the Go printer |

The comparison is not like for like in either direction:
- `golang.go` leans on shared machinery in `emit/` (`typeOf`, `elemTypeFixed`, `openFresh`, the loop
  shape and buffer-reuse passes), which it does not count;
- it also covers what the prototype does not print (§7).

What the comparison can say: once types, widths and liveness live in the IR, a printer is **about
700 lines** for what the gauntlet exercises. None of those lines renames a binder or rebuilds a term.

**Printing time.** Timed once each, lowering + sparse analysis + printing against today's emission
stage on the same residual:

| program | C2, lower + analyse + print | emission today |
|---|---:|---:|
| `io/freq` | 74–84 ms | 2.78–2.91 s |
| `json/tree` | 8–10 ms | 258–265 ms |

These are three single runs each, not a benchmark, so they give a scale and not a ratio to quote. The
smaller programs are below the timer's resolution on this machine.

**Output size.** The printed files are about twice as long: one line per value, 3,151 lines against
1,453 for tree. The Go compiler's time on them was not measured.

## 7. Found on the way

- **`go.len` is not a primitive of kind `len`.** The emitter recognises it as `isOp(n, "alen")`, so
  P3's lowering created no π for a guard on `(go.len X)` and P3's analysis gave it no length fact.
  `IsLengthName` exports the emitter's own test, and the lowering, the analysis and the printer all use
  it now. **P3's counts did not move**, on the seven programs or on the five meant to be refused, so
  none of those reaches a counted operation through `go.len`. The bounds-check rule could not fire
  without the fix.
- **The committed `gen_*.go` files are stale** (§1). The gauntlet's benchmarks have been timing
  whatever `gen` emitted when each file was last written. That is a harness gap of the kind
  CLAUDE.md's first lesson names, and it is fixable by making `cmd/check` compare them.
- **Indexing reaches the printer in two shapes**, `OpIndex` and a primitive with `Index` set
  (`go.at-float64`). The IR should have one.

## 8. Not built

- Legality: the prototype prints whatever it is given (§2's `NativeTally`).
- The u64 and bignum representations, `-checked` traps, `keys`, host callbacks, multi-result
  `values`, strings beyond what the gauntlet and `freq` use, and back-edge buffer reuse
  (LoopBufferReuse, 2.5–2.7×, which no gauntlet program exercises).
- Printers for JavaScript, Java and x86.

## 9. Verdict

**C2 survives P2.**
- Every gauntlet program is at parity with hand-written Go, and within ±2% of today's backend.
- The multi-exit criterion does not arise: C2's exits are Go's `break`, `continue` and fall-through.
- The measured emission decisions are small rules on regions. One decision that had never been
  written down as a rule, the connective, showed up under measurement and is now recorded as one.

With P1 and P3, the three prototypes agree:
- lowering is nearly free;
- the analysis is 12–115× cheaper on C2 with π-parameters;
- a printer from C2 loses nothing.

What remains is the specification: ADR 0006's format as C2, and ADR 0032.
