# IR step 3, first part: a shared plan, and the JavaScript backend is the IR's printer

2026-09-25. ADR 0032's third step, for JavaScript. Java and x86 remain on terms.

## 1. What was built

| file | lines | what it is |
|---|---:|---|
| `ir/plan/plan.go` | ~900 | the decisions every printer shares |
| `ir/js/js.go` | ~620 | JavaScript's spelling of Σ |
| `ir/golang/golang.go` | 668 | Go's, refactored onto the plan (from ~1,200), **byte-identical** |

**The division of a printer.** A printer is a model of Σ, and its work divides into two parts.
**Decisions** are facts about the IR justified by a law of spec §1.4, and they live in `ir/plan`,
once:
- aliases (L9);
- liveness (L7);
- soleExit, PostVars (L4) and buffer reuse (Rule R);
- connectives and conditional expressions (L10, L2);
- β-inlining (L1, L6);
- the target's spellings;
- the parallel move.

**Spelling** is the host's: declarations, operator forms, maps, several results. The four term
backends wrote the decisions four times; this is the one copy.

## 2. Algebra found on the way

- **The parallel move is over read sets.** `plan.Moves` is Rideau, Serpette and Leroy's algorithm
  (JAR 2008, CompCert's): one temporary per cycle. It is tested exhaustively over every move on up to
  four variables, including the temporary-per-cycle bound. Once a printer inlines, a source is an
  expression, and the dependency is on the identifiers it mentions. With name-equality,
  `a ← (a+1), c ← (a+1)` gave c the new a. A second exhaustive test over expressions catches that
  fault when it is planted.
- **Division is ℤ's only where the target says so.** The shared alias table maps `/` to `div`, so
  JavaScript's float `/` was classified like `idiv`. They are different operations: division in the
  reals against ℤ's truncating division. `ir.IntegerDivision` holds that a primitive is ℤ's `div` or
  `rem` only if its declaration fixes integer operands (Go's `/`) or it is named integer division.
  `TestDivisionIsTheTargetsIntegerDivision` runs both under node: `intDiv(7, 2)` is 3 and
  `realDiv(7, 2)` is 3.5.
- **"Every type final" is a property of the backend.** JavaScript declares types as documentation
  (`int` is `number`) and its backend spells none. So W9's "no `any`", and the refusal of an untyped
  parameter, apply where the backend is typed (Go, Java: `ir.Typed`).

## 3. The measurement that had to explain itself

The first JavaScript printer was at parity everywhere except the JSON tokeniser: **1.22× the term
backend** (1.06× hand-written; the term backend beats hand-written there, 0.86×). The disjoint
distributions made it real. What it was not, and what it was:

| step | tokeniser, IR / terms | what changed |
|---|---:|---|
| first version | 1.22 | every value bound to a `const` |
| β-inlining of single-use values | 1.21 | **hypothesis refuted**: the temporaries were not it |
| buffer reads inlined when quiet; nested conditionals as expressions | 1.21 | still not it |
| pure `if`s inlined; a branch terminator as a conditional expression | **1.01** | the closer arm and every guard are one expression each |

So V8 compiled the nested *conditional expressions* better than the equivalent statement `if`s
assigning a declared result. No single rule was the cause, and only measurement could say which
combination was. Each rule is an algebraic identity with its premise stated (spec §9.4):
- β-inlining is L1 and L6, for a value read once in its own region;
- a buffer read moves only when no effect lies between it and its use;
- a conditional expression is the coproduct as a value.

Go's `Speller.Cond` returns "none", so Go's output is unchanged.
