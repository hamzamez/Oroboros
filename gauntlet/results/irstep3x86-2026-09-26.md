## 2. The algebra: a place is a colour

x86 is the one host with no variables, so the printer decides where each value lives: a callee-saved
register, an immediate, or a frame slot. The other three hosts' compilers make that decision. Here
the IR makes it, and spec §9.6 makes it a theorem.
- **Live sets are exact.** A read inside one arm of a branch covers that arm's path, not its
  sibling's. A loop not holding the definition is covered whole, because its back edge returns to
  every point.
- **The colouring is optimal.** Colouring in order of definition, which is dominance order in
  structured SSA, uses exactly ω registers, the most values live at one point. For strict SSA the
  interference graph is chordal (Hack, Grund and Goos 2006). The aliases the printer merges (π,
  a store's buffer, a build's frozen buffer) keep the program strict SSA.
- **A template's `%r` is an early clobber**, so a result interferes with its operands. The exception
  is the term backend's textual proof: `mov %r, %1` with `%1` named nowhere else may share `%1`'s
  register, when the two live sets meet only at that statement.

**The first version used intervals, and measurement refused them.** With intervals, the sieve's
counter stayed live through the sibling arm of its guard. That blocked the in-place `add` on the
back edge, which printed `mov r12, rdi` / `add r12, 1` / `mov rdi, r12`. With exact live sets the
sieve's loops are the term backend's, instruction for instruction, and `count-primes` uses one
register fewer.

**Loop results are not coalesced with parameters here**, unlike Go's soleExit. Coalescing keeps a
counter live across the whole loop, which on this host costs a move on every iteration to save one
at the exit.

## 3. What failed first

The differential suite, run with the x86 printer on, found five things. Each was fixed, and each case
is the fault's witness.

| case | fault | the rule it taught |
|---|---|---|
| `array-literal` (and every `print-str`) | `len` of a string read a table header: a qword of string bytes became a length, and `WriteFile` ran on into the next literal | lowering classifies `x64.strlen` as the IR's `len` (the alias `slen`), which is right. `len` has two spellings on x86: a table's header, and a string's target template |
| `alloc-copies` | `tabulate` was not printed | a counted fill loop, whose table, count and index are live across it |
| `big-limbs`, `big-divmod`, `render` | Rule R's swap missed, so the spare pointed at the live buffer and the next iteration's clear zeroed it | the swap is Rule R's parameter j, whatever class the `continue` argument has |
| `big-limbs` again | the swap reads the old buffer at the `continue`, which liveness did not count, so its register went to the new buffer | **the printer's own reads count** |
| `map-keys`, `map-len` | a build's size and its buffer shared `rbx`: the header store after the allocator call wrote the pointer as the length | the same rule: the header store reads the size where the buffer is defined |

The last two are one lesson, the recurring one about shapes an analysis does not know, turned on the
printer itself. An instruction the printer adds reads what it reads, and the numbering must say so.
`TestThePrintersOwnReadsCount` pins both. Planting either fault (removing the size's read, or the
swap's) fails it, and planting a colouring that ignores interference fails
`TestTheAllocationIsAColouring` too.
