# IR step 4a: the term backends are retired, and their tests found five gaps in the IR path

2026-09-26. ADR 0032's fourth step begins by deleting what step 3 replaced. The four term backends
(`emit/golang.go`, `js.go`, `java.go`, `asm.go`) and their join files are gone, 8,609 lines, with the
production code only they reached. `-printer` is gone: each backend has one printer, the IR's.

## 1. What was deleted, and how its tests moved

| | lines |
|---|---:|
| the four printers and their joins | −8,609 |
| helpers only they reached (`NarrowIndex`, `LoopBufferReuse`, `soleExit`, `needTemps`, `elemTypeFixed`, …, 47 declarations) | the rest of `emit`'s −9,173 |
| **production code, net** | **−8,858** |
| tests, net | −67 |

**What the printers shared survives in `emit/host.go`**: the mangles, the keyword sets, the file
wrappers, the assembly templates, literals and peephole. A dead-code finder (reachability from
production code, over `go/ast`, iterated to a fixpoint) found the 47. A function whose only callers
were its own tests counts as dead, since a path nothing runs is a path nothing checks. The one kept is
`ResetAsm`, a test utility for the literal pool.

**Fifty-one test sites called a term printer.** An internal `emit` test cannot import `ir/*` (a cycle),
so they moved to external test files (`package emit_test`, `*_ir_test.go`) beside what they test. A
tool moved them by source position, keeping every comment, rewrote each printer call to the IR's
`FromResidual` (the same signature), and qualified `emit`'s names. Then every failing assertion was
read one at a time.
- **Most checked a spelling**, a name like `src` where the IR prints `v0`. Each was restated as the
  property it stood for: a shape over value numbers, or Go's own compiler as judge (`goBuilds`,
  shown to fail on a declared-and-unused variable).
- **Some checked properties that are true by construction on the IR**, and were retired with the
  reason written where they stood. Binders cannot shadow once every value is numbered, and a
  statement's value is computed once because it is an alias (L9).
- **The retired portable layer's `fold-range` tests went with it.** No live target declares
  `fold-range`, and all eight programs that call it are refused on all four targets. **No callback
  capability is lost**: tiers 1 and 2 of callbacks.md were never built on any backend, which makes
  CLAUDE.md's wording ("only tier 3 is refused") an overstatement, corrected there.

## 2. What the tests found in the IR path

Five things the term backends did, or refused, that the IR's printers did not. **Two were wrong
answers, one was an unkept obligation, and two were lost shapes.**

1. **Theorem D′'s premise was assumed, not discharged.** A class that takes a declared representation
   must hold only values in the declared set: "the analyses proved it, or the program was refused",
   says the theorem. Finalize never checked it. `(x.take (array 104 300 33))`, where `x.take` declares
   `(array (int 0 255))`, printed `[]byte{104, 300, 33}` on Go, which only Go's compiler caught, a
   `short[]` holding 300 on Java, and a plain array on JavaScript. **Now discharged in `ir/final.go`.**
   The class's proven range (the reduced product both branches now share) must lie inside the declared
   element, or the program is refused, naming the literal when one is at fault
   (literal-elements.md, refinements.md §3a).
2. **The declared arity was dropped.** A signature declaring `(tuple int int int)` over a body yielding
   two values printed `func Three(a int) (int, int)`. A single declared `any` over a product printed two
   results. A caller compiled against the signature disagrees with either. **Now refused in lowering**,
   where the signature is in hand: "declares 3 result(s) and does not produce them".
3. **Go's string literals were not ASCII-only.** string-literals.md §6.1 makes the emitted literal ASCII
   on every host, and `emit/strlit_test.go` checks it over all 1,112,064 scalars. The IR's Go printer
   used `strconv.Quote`, which passes printable non-ASCII through raw. It was legal Go, and invisible
   because the corpus has no non-ASCII literal, but the stated obligation was unkept from step 2. **The
   printer uses `GoStringLit` again**, and the whole-range test with it.
4. **x86 lost its ordered back edges** (windows-target.md §5 item 3). `(again (+ i 1) (+ acc i))`
   computed `i + 1` while `acc + i` still needed `i`, so neither could be in place: two extra moves per
   iteration. **The printer now schedules**: an in-place candidate `v = p ⊕ k` whose value is the
   `continue`'s argument for `p` moves after the last statement reading `p`, when none reads `v` (L6,
   pure arithmetic commutes with everything it passes). The back edge is `add rdi, rsi` / `add rsi, 1`.
5. **x86 jumping code went through trampolines, and Go and Java lost the tail connective.** `and` in a
   guard jumped to a label whose only instruction was `jmp Lelse`. A new pass threads jumps through
   such labels and drops code no path reaches (`ir/x86/thread.go`, tested on a trampoline chain, dead
   code and a template's own loop). On Go and Java, `(and a b)` at a function's tail is a `branch`
   *terminator*, since case-of-case copied the continuation, so the `if`-statement connective rule
   never saw it. `ir/plan.BranchConnective` applies L10 there, and `(if c false true)` is `!c` wherever
   a printer implements `Negator`.

Each has its test, and each soundness one its planted fault. `TestALiteralOutsideTheDeclaredElementIsRefused`
and the byte-buffer control cover (1). `TestResultArityMustMatch` and
`TestWithoutAMultiResultSigItIsStillAClosure` cover (2). `TestEveryScalarRendersAndRoundTrips` covers (3).
`TestAsmLoopIsInPlace` and `TestAsmAndIsJumpingCode` cover (4) and (5). The borrow rule, ported from the
term backend's own test to `ir/x86`, fails when a register this instruction uses is left unmarked.

## 3. What the tests showed is different by design

- **A declared `(array int)` result is the word.** A signature's result is a boundary host code is
  compiled against (Theorem D′). The term backend narrowed a returned table to `[]byte` with its
  contents, which changed the host-visible type with the data. The tests that relied on that now
  consume the table inside the function, where narrowing still happens.
- **PostVars takes only a literal step.** The term backend also hoisted `i = i + n` for a
  loop-invariant `n`. Go measured at parity without it (irstep2), the sieve's `j += i` included.
  `TestThePostClauseRules` states the IR's rule over five programs.
- **Typing is unification**: a parameter reaching a typed primitive is typed without a signature. Only
  a parameter nothing reaches is refused.

## 4. Gates

| gate | result |
|---|---|
| the module's tests | pass, the acceptance programs included |

1.01× hand-written and 1.03× the step-3 printer on medians, with the same minimum: at parity.

## 5. Not built, and noticed

- **The analysis port**, the rest of step 4: the interval, refinement and termination analyses still
  run on terms. The next measurement is the IR's interval domain as a legality checker, run in shadow
  beside the term analysis on the corpus. The gap to 2,007 proven operations is what each slice must
  close.
- **JavaScript fills a boolean table with 0.** `build`'s zero for a boolean is `false`, and both
  JavaScript backends wrote `fill(0)`. Inside a program it cannot be observed, since `=` is integer
  equality and every boolean reader treats 0 as false. It shows only at a host boundary, where an
  exported boolean table hands `0` to JavaScript. `fill(false)` changes V8's element kind, so it is a
  measurement before a change.
- **An option's tag is materialised on Go.** A map read prints `v, ok := m[k]` and then builds the tag
  from `ok` before testing it, a case-of-case the IR leaves to Go's SSA. Go's tally programs are at
  parity (irstep2), so no measurement asks for it.
