# IR step 4h: the rung above the word is chosen on the IR

2026-09-27. [ADR 0034](../../docs/decisions/0034-the-rung-above-the-word-is-a-least-fixed-point-on-the-ir.md),
written first. On a target holding arbitrary precision in the host's bignum (Go, JavaScript, Java), the
values held exactly are chosen on the IR, from the decision's facts, and `PromoteBig` runs only for the
fixed-limb rung. The term checker's integer sort now includes the rung above the word, closing ADR
0033's parenthesis.

## 1. The system

B, the values held exactly, is the least set closed under two rules (`ir/big.go`).
- **Supply.** v ∈ B when v is:
  - a parameter declared above the word, or a `big` result;
  - a language + − · / with an operand in B;
  - a remainder by a divisor in B;
  - a join with an incoming value in B;
  - a closed constant term outside S.
- **Demand.** These positions demand an exact value:
  - a result declared above the word;
  - a `big` argument;
  - an ascription above the word;
  - the incoming values of a join in B;
  - the operands of an operation in B;
  - both operands of a comparison with one in B.

  A demanded value is in B **iff its fact is not inside S**. Otherwise it is computed in the word and
  widened by `big-of` where it is used, which is the inclusion S ↪ ℤ.

Both rules are monotone in B over a finite lattice, so the iteration reaches the least fixed point.

The term pass had three rules. Its PRESSURE rule (promote a name a big operation reads when its
interval leaves the word) is demand at an operand position. Its distinction between a NAME, which
demand promoted, and an EXPRESSION, which demand widened, has no meaning on SSA. The fact replaces
it: a value proven in S is a word, and one that is not has no other way to be computed.

The rewrite:
- an operation of B becomes `big+ − · / %`, under `big-fit` or `big-fit-signed` when the program
  declares a finite set (ADR 0029);
- a remainder by a word is `big%-small`, a word;
- a comparison with an operand in B becomes `big< … big=`, and its π-parameters are dropped, since it
  is no longer an IR comparison;
- a value of B at a position declared in the word is refused, with the checker's old message;
- ascriptions are erased, and the function is decided again.

A widening of a value's only use sits right after the value, where the term's `(big-of e)` put it: it
is pure, so the placement is free, and it keeps the emitted order.

## 2. The destination, restated as ownership and liveness

Go's `math/big` writes into its receiver. `emit/bigreuse.go`'s rule R let `acc.Mul(acc, i)` happen
when acc occurs only in its own update in the `again` and its initialiser allocates. That is liveness
read off the syntax. `ir/bigreuse.go` states the two conditions it stands for:
- **ownership**: every value bound to the parameter, at the initialiser and at each continue, is a
  fresh allocation read exactly once (allocated in this iteration, on a continue) or another owned
  parameter's object, and no continue binds one object twice. Owned is the greatest such set;
- **liveness**: the call reads the parameter's object, and nothing that may hold the object is read
  after the call in the iteration. The holders are the parameter, its π's, a `big-fit` or a
  destination of one, and a join one reaches.

By induction on iterations, an owned object is held by nothing else live.

**What measuring found.**
- **Rule R missed an aliasing.** Its condition (4) checked the initialiser only. A continue that hands
  a loop variable an object from outside the loop makes the next iteration write into it. That shape is
  not owned here. No source program builds it today, since a pure binding read once is substituted
  into the loop, so it is witnessed on hand-built IR.
- **SSA sees more writes.** `power`'s squaring reads x in the accumulator's product *before* its own
  square, so x is dead after it. `pair`'s b + a is computed after a's last read. Rule R declined both,
  because x and a occur twice in the `again`.
- **A printer's inlining had an unstated premise.** β-inlining moves a pure call past effects (L6),
  which assumes a pure value observes no store. A bignum on Go is an object a destination form writes,
  so `new(big.Int).Mul(a, b)` written at its use after `a.Add(b, a)` would read the new a. It is now
  guarded as a buffer's read is (`ir/plan`). Today only JavaScript inlines, and it has no destination
  forms, so the guard fires nowhere yet. It is witnessed on hand-built IR.

## 3. What else changed

- **The checker's integer sort includes big**, except where the target has no bignum and the range is
  ℤ, whose refusal is a capability and stays the checker's. `CheckSignatures` still checks a claim
  after `PromoteBig`, where a sort is a representation, so a bignum under a declared `int` result is
  refused there by name.
- **W5 is strict between a word and `big`**, as it became between S and U in 4g. The first plant of the
  remainder rule survived because W5 read the checker's relation, which had just been told they agree.
- **A declared result of ℤ is ascribed**, as a finite range above the word was (`core.Env`, and the
  term pass's `ascribedBig`). A program whose helper declares `(int 0 +inf)` and whose export is a word
  was refused for want of a demand, and is now accepted.

- **The limb rung's fallback runs, on the IR.** A program on the fixed-limb rung that needs an
  operation the limb library lacks (bignum ÷ bignum) takes the host's bignum. On HEAD that fallback
  never produced code for a program with a signature. `CheckSignatures` checked the host-promoted term
  against the LIMB form of the signature, and refused it with *"big-fit is big, but array int is
  required here"*. The claim is now checked on the rung the promotion took. The drivers take the
  fallback through `ir.SelectBig` (`emit.PromoteLimbs` returns `ErrLimbsFallBack`), so no emitted
  program uses the term pass's destination rule any longer.
  `TestTheLimbFallBackIsCheckedOnTheHostsRung` fails against the old check.

## 4. Soundness

`TestTheBigSelectionKeepsEveryAnswer` generates 220 programs over 14 shapes and runs each one's IR
before and after the selection. The shapes:
- the corpus's factorial, Fibonacci, squaring, pair and digits;
- the premises' own shapes: one object bound to two parameters, a join holding a parameter's object
  read after the write, an initialiser read elsewhere, supply with no demand;
- a finite bound, and a signed set.

The interpreter computes ℤ on both sides, and runs a destination form by writing into its receiver's
`*big.Int`, as math/big does. So an unsound destination changes the answer. Each selected function
must also be decided with every word operation proven, and verify at IR_P.

| rule | planted fault | caught by |
|---|---|---|
| ownership: a continue's binding | not checked (rule R's gap) | the outside-object shape, and `TestAnObjectFromBeforeTheLoopIsNotOwned` for one read once |
| ownership: the initialiser | not checked | the shared-initialiser shape |
| ownership: no object twice | not checked | the `(again b b)` shape |
| liveness | not checked | the read-after shape |
| holders through joins | ignored | the join shape (t bound before the write, read after) |
| fresh: read once | not required | the generator |
| supply: a remainder by a bignum | dropped | W5, at IR_P |
| supply: a join | dropped | refused by the word rule |
| supply: a constant past the word | dropped | the decision: the spine left unproven |
| demand | dropped | the decision |
| the widening | not inserted | W5 |
| a word position refuses a bignum | not refused | `TestABigValueIsRefusedWhereAWordIsDeclared` |
| the bound on a sum | not fitted | `TestTheDeclaredBoundTrapsOnTheHostsBignum` |
| the printer's L6 premise | not checked | `TestABignumReadIsNotMovedPastAWriteIntoIt` |

Several first plants survived, each for a reason worth recording:
- **Demand masked supply.** Every value the supply plants touched was also demanded with a fact
  outside S. The fix was a shape where the values are only compared.
- **The test's constants fit the word.** Nineteen digits is often below 2⁶³.
- **A shape made `b` a word.** Its fact was bounded, so `(again b b)` widened it into a fresh object.
- **A `let` read once was substituted.** The join was then computed after the write, not before it.

Two conditions turned out to be unreachable, and they are now stated as what they reduce to:
- **`obj` through fits and destinations:** a continue's parameter argument is never wrapped.
- **`inIteration`'s `tabulate` case:** a continue argument's definition dominates the continue, so it
  lies on the continue's branch path.

- `word-wide`, a differential case: `(big-str 0)` has nothing in B, only demanded values, and an early

## 7. Not built

- **The fixed-limb rung** still runs on terms (`PromoteBig`, `LowerLimbs`), and with it the term
  interval analysis. On the IR it means inlining the limb library, a module of IR.
- **A bignum operation's transfer is its declared type**, so the second decision knows nothing about
  a value held exactly. That is no loss today: the first decision's facts choose the representation,
  and nothing counted reads a bignum.
- `CheckSignatures` still promotes on terms to check a claim.
