# IR step 4i: the fixed-limb rung is chosen on the IR, and the limb library is a theory

2026-09-28. [ADR 0035](../../docs/decisions/0035-a-compiler-library-is-a-theory-checked-once.md),
written first. The last emitting use of the term promotion is gone: on the fixed-limb rung, as on the
host's bignum since 4h, the values held exactly are chosen on the IR. Each bignum operation is then an
instance of the limb library, inlined.

## 1. The library as a theory

`emit/bignum.oro` computes in Vₙ = [0, Bⁿ), B = 2²⁴, presented by ι(o) = Σ oᵢ·Bⁱ. Each definition f
is a lemma: under its precondition P, ι(f(ā)) is the operation on ι(ā) when the result lies in the
program's set [0, 2ᵇⁱᵗˢ), and f traps otherwise, through `guard`.

**What a use needs of the lemma does not depend on the use.** The lemma's typing, its linearity and its
refinement obligations are properties of the definition under P:
- every index sits under `at`'s guards;
- every store index is below the build's length by the loop's exit;
- every divisor is a literal or k, with k ≠ 0.

So `emit.LimbFunc` checks each definition once per specialisation (n, lim). It η-expands the
definition at the literals, normalises it, and runs the type checker, the signature check, linearity
and the refinement layer, under `where k ≠ 0` for short division and remainder. At a use, that
precondition is the program's own division obligation, which the refinement layer discharged on the
residual before the rung was chosen.

The term path proved the same lemmas again at every site, because it spliced the library into the
residual first. It also needed the term promotion to know where to splice.

## 2. Instances, inlined

`ir.LowerLimbs` replaces each call `SelectBig` wrote in the host's shape by its instance. The instance
is lowered to IR once, and each use copies it with fresh values, binding its parameters to the
arguments. A body ending in a yield hands over its values by renaming. One ending in a branch becomes
an `if` with the branch's arms. No instance ends in a branch today, so that path has a hand-built
witness (`TestAnInlinedBranchIsAnIf`).

Two shapes are chosen by facts where the term pass used a marker (`big-of-small`) written during its
promotion:
- **One pass.** A product or quotient by a widened word k with k ∈ [0, 2²⁸) is `mul-small` or
  `div-small`: limb·k + carry < 2²⁴·2²⁸ + 2²⁸ stays inside every word. A widening only such an
  instance reads is dead. The first version kept it as an `of` instance, which gave fact-limbs one
  limb table more per iteration.
- **A magnitude.** `big-of v` is `of`, whose limbs are v's digits in base B. That represents v iff
  v ≥ 0, so a widened value that may be negative is refused, naming its interval (ADR 0029: limbs hold
  a magnitude). The term path split such a value into limbs anyway.

`SelectBig` on this rung writes no `big-fit`, since `guard` enforces the set, and no destination,
since a limb table is built, not written into.

An operation with no instance (a quotient or remainder by a bignum) raises `ErrNoLimbForm`.
`ir.SelectRung` then takes the host's bignum for the program where the target has one, and refuses by
name where it has none. The drivers and the IR tests share `SelectRung`.

## 3. Soundness

`TestTheLimbRungKeepsEveryAnswer` generates 84 programs over seven shapes, on Go (`-big-repr limbs`)
and windows, with the set 2⁴⁰⁰ (17 limbs). The shapes are:
- `mul-small` and `mul`, including a product by a word past 2²⁸, whose widening stays limbs;
- `add`;
- `sub` keeping a magnitude;
- the comparisons, of two bignums and of a bignum with a word;
- `div-small` and `rem-small` with a word result.

Each program runs unselected, where every operation is ℤ's, and on the limb rung. ι of the limb result
must equal the integer on every input. The lowered function must also be decided with every word
operation proven, verify at IR_P, and contain no bignum operation.

| rule | planted fault | caught by |
|---|---|---|
| the theory's index obligations | `at` without its upper guard | `TestTheLimbLibraryChecksAsATheory`: *"(a i) is an indexing, and (< i (len a)) does not follow"*, for `add`, `sub` and `mul` |
| the theory's precondition | `div-small` without k ≠ 0 | `TestALimbDivisorNeedsItsPrecondition` |
| the one-pass ceiling | any widened word | the decision: `limb·k` unproven |
| the one-pass word | the wrong operand as k (divide, multiply) | the decision |
| limbs hold a magnitude | not checked | `TestANegativeWideningIsRefusedOnLimbs` |
| the set, enforced | (the guard) | `TestTheDeclaredBoundTrapsOnLimbs`: 4·10²¹ under 2⁷⁰ traps |
| a branch body is an `if` | its arms swapped | `TestAnInlinedBranchIsAnIf` |

One plant survived and is not a gap: handing every result the first yielded value. Every instance has
exactly one result, so the plant is the code.

**What failed first.**
- **The instances' signatures spelled `(array int)`.** Lowering keeps a declared parameter's spelling,
  so the printer wrote `((array int))` and the reader refused it. The IR step's round trip and the
  differential suite caught it. The limb tests did not, because they never print and read.
- **`LowerLimbs` retyped exact values to the same non-canonical spelling**, and IR_P's representation
  check refused the flows.

## 4. Gates

| gate | result |
|---|---|
| the module's tests | pass, the acceptance programs included |
| the differential suite | pass, on four targets, and in the `limbs` variant on Go, JavaScript and Java for its seven cases |
| the IR step | 250 of 250 programs lowered and verified |
| proof counts | 1,994 of 2,041 operations, 357 of 375 loops (was 2,010 of 2,057 and 362 of 381): render on windows, whose factorial counter is now a word, so its limb loops are gone; its 13 remaining loops are all proven, where one of 19 was not |
| emission | **3 changes**, accepted; fact-limbs, render (examples) and big-limbs are byte-identical on windows |
| compile time | 0.99× the baseline's median; render on windows compiles in 0.49× (578 → 281 ms) |

The three changes:
- **big-divmod on windows**: `add rbx, 7` (n + 7, the accumulator's initial value) moves earlier in the
  prologue. The term splice computed it inside the `of` instance's setup; the IR computes the word
  before the instance. It runs once either way.
- **render on windows**: the factorial counter is a word. Per iteration, a 17-limb addition and a
  17-limb comparison become a word addition and comparison: 1,322 lines become 830.
- **render's notes on windows**, for the same reason.

## 5. Not built

- `CheckSignatures` still promotes on terms (`PromoteBig`, `LowerLimbs`) to check a definition's
  claim. It is the term promotion's last caller.
- An instance is always inlined. Emitting it once as a host function would trade the specialisation
  for code size: a measurement of its own (ADR 0008, ADR 0035's "Why not").
