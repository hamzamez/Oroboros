# IR step 4j: the term interval analysis is deleted

2026-09-28. The last step of ADR 0032's migration. The term interval analysis
(`emit/interval.go`, 3,913 lines, and seven files around it) had no emitting caller after 4i. This step
moves its last readers onto the IR and deletes it, with everything only it reached.

## 1. The last readers

- **`CheckSignatures`' claim check.** It promoted each signed definition on terms (`PromoteBig`) and
  checked the body's type against the claim. With the checker's integer sort ℤ (ADR 0033), the typing
  needs no promotion. What the promotion bought was one check of representation: a bignum where the
  claim declares a word. That is a membership claim, and `ir.CheckClaim` decides it by lowering the
  definition and choosing its values held exactly (`SelectBig`). A value of B at the word result is
  refused, with the old message.

  **Measured first**: the first version took the whole rung, and refused `u64-values`' helper `one`
  on windows. Windows has no limb form for a quotient by 2³², but `one` is never compiled there: the
  program has no exports, and the harness runs it on Go. A missing limb form is the program's refusal
  wherever the definition is used, not a violation of its claim, so the claim check stops at the
  selection.
- **`cmd/intervals`** reports the IR's decision per export, through the drivers' pipeline. `-assume`,
  a knob of the 2026-08 experiment the term analysis ran, has no equivalent and is gone.
- **`gen -irproof`**, the shadow that compared the two analyses, is gone. `cmd/intervals -v` lists
  what the IR leaves unproven.
- **`requires.go`'s set decision**, which the IR's range obligations go through, converted the IR's
  exact ends into the term analysis's interval type. A range obligation is set membership,
  [lo, hi] ⊆ ⟦τ⟧, over ℤ̄ with exact ends, and it is now stated on `*big.Int` ends, with nil for an
  infinite end. That removed the last use of `ival` and of `bound.go`'s 128-bit ends.

## 2. What was deleted, and how it was found

**Reachability, not guesses.** An analyzer type-checked `emit` with `go/types`, took as roots every
exported name used outside the package (read from the ASTs, comments excluded) plus `init`, and
computed the closure over resolved uses: a method is its receiver's, not a name. Two false starts
were corrected:
- the first run counted names in comments, which kept dead code alive;
- the second counted emit's own tests as outside users, through a path filter missing a leading
  slash.

**Deleted:**
- the files `interval.go`, `sct.go`, `smash.go`, `buflen.go`, `prodfacts.go`, `wordsel.go`,
  `bigreuse.go` and `bound.go`;
- in `bigrep.go` and `biglimb.go`, the term promotion and the term limb splice (`PromoteBig`,
  `LowerLimbs`, `LimbSig`, `LimbSupported`, …);
- `fact.go`'s induced interval transfer;
- in `target.go`, an element-width path (`fitsIndexSource`, `storedRange`, …) that nothing had called
  since the term backends went (irstep4a);
- two dead helpers in `host.go`;
- `experiments/irproto`, the prototypes that decided ADR 0032 against the term analysis. Their results
  are irp1–irp3, and the code is in git.

**Kept and moved** to `emit/opnames.go`: which operation a name is (`arithOp`, `uncheckedName`), the
unsigned word's operation names, and `HasBigDest`. `monotone.go` stays: its syntactic rules are the
refinement layer's.

After the deletion, the analyzer finds no unreachable declaration in `emit`.

## 3. The tests

Each test that reached the deleted code was one of two things.
- **A test of the engine itself** is deleted with it. These were the ones about its interval
  arithmetic, containment, smashing, its term rebuilding, its size-change graphs, its induced
  transfers, `BufferRange`, the term promotion's rules and the term destination rule R. The IR has its
  own witnesses for each law (`ir/*_test.go`, irstep4b–4i), each shown to fail against a planted
  fault.
- **A test of a claim the compiler makes** moved to the IR's decision (`decideOn` in
  `helpers_ir_test.go`; the file `decision_ir_test.go`, and `matchguard`, `mapvalue`, `maxlen` and
  `jsonfmt` as external tests). These are claims about what is proven of a shape: a guard's
  connectives narrow, a trip count holds on every edge, a length is bounded, a scalar range is a
  premise, a declared result range is read, a back edge in a host continuation is seen, a shadowing
  loop gives the parameter back, each component of a tuple has its own facts, and a map read carries
  its inserted range.

  Their `FitsIndex` and `MaxOpRange` clauses are dropped. They checked the term backends'
  whole-method narrowing to Java `int`, which is now ρ of each value's range in the Java printer.

**The last claim failed on the IR**, and the IR was missing a law. The term analysis bounded a map
read by the hull of the values inserted, and the IR's `read` gave its payload no fact. The law is the
frozen-buffer theorem over another index set:
- `build-map` is the only allocator and starts empty;
- `insert` is the only store, and the buffer is linear;
- so every value a read returns was inserted;
- an absent key's payload is one the program cannot observe (spec §5.3).

The domain now carries a map's cells as an element fact: ⊥ at `build-map`, joined at `insert`, and
read as the payload. The test's control failed too, for the opposite reason. It inserted `(* i 10)`
and expected nothing proven, because the term analysis refused every computed insert. The IR proves
it in [0, 80], soundly, so the control now inserts an unbounded parameter.

**The ascription is typed.** 4h ascribed a declared result of ℤ, and the checker typed `(the T e)` as
unknown. So windows accepted a program needing ℤ, which it cannot hold. `(the T e)` now checks e
against T and has type T. A conditional of two integer branches has the wider type, in ℤ.

## 4. One pipeline

`gen`, `build`, `cmd/intervals` and the tests each rebuilt the steps from an entry point's residual to
its decided IR. `ir.Entry` is those steps once:
1. products;
2. the rung's plan;
3. the checks on terms;
4. lowering and the decision;
5. the rung;
6. the unsigned word;
7. the postcondition.

A note callback keeps each driver's phrasing and its order, so outcomes are byte-identical.

**What failed first.** The differential suite failed on Java's `map-dynamic`. The newly narrowed
payload was printed as `(int) (b2)` of a `Long`, which is not Java. A narrowing of a boxed value
unboxes first: `(int) ((long) b2)`.
