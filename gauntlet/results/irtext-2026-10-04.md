# The IR's text: what every printer reads, and what a writer could claim

2026-10-04. The first question of the 10-03 round: is the IR's text a format others should read and
write? Decided in [ADR 0038](../../docs/decisions/0038-the-irs-text-is-read-not-written.md); specified
in [spec/ir.md §10.4](../../docs/spec/ir.md).

## 1. The question, as algebra

Let p : IRₜ → Σ* be the canonical printer, r : Σ* ⇀ IRₜ the reader, and e_T : IRₜ → Host a printer.
`cmd/check` already pinned r ∘ p = id, so p is a section of r and the text is canonical. That says the
text is faithful to the IR. It does not say the IR in the text is what the printers read. The
printers took the decided function in memory, which carries the interval facts, the range marks and
provenance, none of them printed (`ir.Func`'s `facts`, `marks`, `Stmt.Src`).

**The text is the printers' whole input iff e_T factors through p**: e_T = e_T ∘ r ∘ p, which holds
iff ker p ⊆ ker e_T. That is a claim about e_T's behaviour on every input, so it is measured on every
program, not argued.

The second half of the question, writing, is a question about trust. A file someone else writes is an
input. Whatever the printers assume of it, something must check.

## 2. Reading: the measurement

For each of the 253 programs the sweep emits, the experiment read its `.ir` text and printed it with
the target's backend, wrapped as `gen` wraps it, and compared the result with the emitted file.

| run | identical | different |
|---|---:|---:|
| decided IR_A text → `FromFunc` (the step to P, then the printer) | 160 | 93 |
| … with every process-wide sink reset between programs | 251 | 2 |
| IR_P text (take the step, print P, read it back) → `Func`, the printer alone | 251 | 2 |
| … with only `targets/` and `lib/` as declarations, not the source's directory | 251 | 2 |
| … with `gen` printing in the text's order | **253** | **0** |

What each row found:

- **The 93 were the harness, and then a bug.** Every Java and every Windows file differed, by a
  record, an extern or a string literal from an earlier program. `emit.ResetImports` cleared the
  three import sets and not `JavaRecords` or the assembly's data, externs and libraries. It is the
  same process-wide state bufio-2026-10-01 found for the imports. It was latent: each `gen` process
  builds one program, and in a test process an unused Java record or MASM extern still compiles. But
  it made a file depend on what the process had printed before. `ResetImports` now empties every
  sink.
- **The 2 were an order.** `gen` printed functions in export order, and the text lists them by name.
  x86 numbers its labels and literals with one counter across the file, so `lib/win/fmt` and
  `kara/workspace`, the two Windows programs with more than one function in a non-sorted export
  list, renumbered (`Ltop10` against `Ltop4`). A program is a set of functions, and the text is
  canonical on the set, so `gen` now prints them in name order. The two files change only in their
  labels' numbers, checked by normalising labels and comparing.
- **IR_P suffices.** The printers' own step (`Finalize`: the interval domain rerun, L13's re-slicing)
  needs nothing the text lacks either. But a printer reading A would have to run that step, which is
  an analysis. So the published file is IR_P: `gen -ir` and `build -ir` now write the program the
  printer read.
- **The declarations a printer reads are the target's**: `Prims`, `HostType`, `ValueType`,
  `BoxedType`, `ReprBytes`, `IsLengthName`, `FindAlloc` and `Name`, read off the four printers and
  `ir/plan`. With the standard target files and `lib/` alone, every program prints the same, so none
  of the 253 needs anything its own directory declares. `examples/tally` would, and is not swept.

## 3. Writing: the planted claims

Hand-written files, each making one false claim, taken through `Read`, `Verify`, then the printer
(P), or the decision and then the printer (A):

| file | claim | stage P | stage A |
|---|---|---|---|
| `(add exact %0 %1)` on two `int` parameters, Go | the sum is in the word | **printed**: `v2 := (v0 + v1)` | refused by the decision: `add [-inf, +inf]` |
| `(val (%2 (int 0 10)) (add exact %0 %1))`, parameters in [0, 2⁵³), JavaScript | the sum is in [0, 10] | **printed**: `return (v0 + v1);` | refused: `add [0, 18014398509481982]`, bounded but not by the word |
| `(index %0 %1)` with `%1` the constant 5 and nothing on `len %0`, JavaScript | the index is in range | **printed**: `return v0[5];` | **printed** |

- **At P every claim is trusted.** That is spec §9.1's contract: a printer may assume every index is
  in range, every operation exact or trapping, every type final. W1–W10 check structure, scope,
  types by sort, linearity and the stage, not the decision's conclusions. Nothing is wrong with
  that for our own files, which the decision wrote. For a file anyone wrote, it would make the format
  a channel for undefined behaviour.
- **At A the decision re-derives arithmetic**: it ignores a written range on an operation's result
  and computes the operation's interval.
- **At A an index is still trusted.** Index obligations are proven on terms, by the refinement layer
  (`emit.Refine`), before lowering. The IR has no prover for them. On JavaScript the third file
  returns `undefined` for an `int` function, the failure noprop-2026-09-25 removed from the
  language's own path.

So writing waits on the IR proving index obligations, which is the round's fifth question ("one
prover or two?"). When it does, the entry point is A, through the decision. P is never an input: its
claims are a function of A that `Decide` derives in milliseconds (irp3), and its types are not a
complete certificate, since the facts behind them are not in the file (spec §12). Checking them would
cost a derivation.

## 4. The gate, and its witnesses

`cmd/check`'s `ir` step now checks, on every emitted program, that printing what the reader makes of
the IR_P file writes the emitted file byte for byte. Targets are loaded as `gen` loads them, once per
layer set. Each witness was planted with the step's check in place:

| planted fault | caught |
|---|---|
| `ResetImports` clears the import sets only (the shipped bug) | 93 programs, every Java and Windows file after the first |
| `gen` prints functions in export order (the shipped order) | `lib/win/fmt` and `kara/workspace` on windows |
| the Go printer appends a comment for any statement with provenance (`Stmt.Src`), which is in memory only | 44 Go programs |

The third row was planted first on `index` statements and passed. Lowering sets provenance only on
arithmetic, so that plant read nothing that was there. It was rewritten until it read what exists,
and then it failed.

## 6. Not built

- **A written file as input.** No tool takes one, until the IR proves index obligations (ADR 0038).
- **A self-contained file.** It names `(target T)`, and a printer needs T's declarations beside it.
  A program's own `provides` fragments are not carried; no swept program has one.
- **A binary form**, and a version bump. Nothing changed the meaning of an operation or the syntax, so
  `(ir 1 …)` stands.
