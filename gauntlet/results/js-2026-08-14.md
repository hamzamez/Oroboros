# The JavaScript backend — 2026-08-14

[ADR 0004](../../docs/decisions/0004-first-targets.md) has said since the first draft that the JS
backend must be built **before any front-end features**, because JS is the most hostile host in
the set — no integers, no structs, no int64 — and it surfaces core flaws while they are still
cheap to fix.

**Result: parity on both programs, and the core required no changes at all.** Not one line of
`core/` was touched to make JavaScript work.

---

## Parity

n=1024, medians of nine runs after warm-up, Node 26.7:

| | hand-written | **generated** |
|---|---|---|
| `dot` | 472.7 ns | **469.1 ns** |
| `filter-sum` — binds once | 534.1 ns | **500.3 ns** |
| `filter-sum` — reads twice | 522.6 ns | |
| `filter-sum` — ternary (the emitted shape) | 576.5 ns | |

Correctness asserted first: generated agrees with hand-written on both.

The four filter variants span 500–576 ns, which after
[the alignment finding](duplicate-read-2026-08-14.md) should be read as **indistinguishable**
rather than as generated-is-fastest. The honest claim is parity, not a win.

## What the second backend found

This is the point of building it, so the findings matter more than the numbers.

### 1. ANF is target-dependent, not a property of the language

[g3 §6](../../docs/derivations/g3-generics.md) and [g5 §4](../../docs/derivations/g5-bindings.md)
each derived, independently, that a statement/expression split was required. The Go emitter
confirmed it a third time. It looked like a fact about the design.

**It is a fact about Go.** Go has no conditional expression, so `(if c a b)` in value position
must become a temporary plus a statement. JavaScript has `?:`, so when both branches are pure the
emitter produces:

```js
acc = ((a[i]) > 0) ? (acc + (a[i])) : acc;
```

The JS backend emits ANF only when a branch actually needs statements. Three independent
derivations agreed on something that turned out to be one target's constraint — a useful
correction to how much weight "it arrived three times" should carry.

### 2. The type lattice is entirely Go's

`emit/golang.go` carries a four-point type lattice, an inference walk, and an error for
*"cannot determine a Go type for parameter"*. **`emit/js.go` has none of it** — no types, no
inference, no way for a parameter to fail.

Everything the Go backend does with types exists to satisfy Go. This is direct evidence for the
decision recorded in [parity-2026-08-14 §3](parity-2026-08-14.md): **types belong in the backend,
not in the language.** Had they been pushed into the core to serve Go, JS would now be carrying
machinery it has no use for.

### 3. Name mangling belongs to the language

The transformation is *identical* in both: hyphen to camelCase, `?` to `P`, `!` to `B`, other
characters to an escape. Only two things differ — the keyword set, and JS permitting `$`.

That split suggests mangling is a **language-level** notion (what an Oroboros name *is*) with a
small per-target table (what the target forbids), rather than a backend concern.

### 4. The primitive table shape held

| | Go | JS |
|---|---|---|
| Template with holes | ✓ | ✓ |
| Arity | via `Args` | explicit |
| Statement-or-expression | `Loop`, `Cond` | `Loop`, `Cond` |
| **Types** | **required** | **absent** |

The shape survived contact with a second target. Types are the only field that is target-optional,
which is a sharper answer to *"what must a binding format carry"* than
[parity-2026-08-14 §"What a binding format has to carry"](parity-2026-08-14.md) could give from
one target.

### 5. The duplication is real and is the walker

| | lines |
|---|---|
| `emit/golang.go` | 313 |
| `emit/js.go` | 235 |

Six structures appear in both: `emit`, `emitIf`, `emitFoldRange`, `line`, `fresh`, `File`. Only
`inferFrom`, `typeOf`, `export` and the `Ty` lattice are Go-only.

So roughly **the whole term walk is duplicated**, and the genuinely target-specific parts are the
primitive table, the mangling keyword set, and — for Go alone — types.

That is the concrete shape of the backend interface
[ADR 0006](../../docs/decisions/0006-ir-file-format.md) asks for, discovered rather than designed.
It should not be factored yet: two points define a line, and a third target (Java) is what would
show whether the line is straight.

## What did *not* happen

**The core did not change.** `core/` is byte-identical to what it was before the JS backend
existed. ADR 0004 said the second backend exists to surface core flaws while they are cheap.

It surfaced none. That is the strongest single piece of evidence the design has produced — and it
is a *negative* result, which is why it is worth stating explicitly rather than leaving implicit
in a passing test suite.

## Still not measured

- **Four of six gauntlet programs.** Structs, generics, word count, and formatted output have
  never been emitted to anything. Structs are the interesting one — neither backend has a struct
  primitive, and [g2](../../docs/derivations/g2-structs.md) says JS needs a different
  representation from Go.
- **Java.** One of three targets untouched by the emitter.
- **Escaping closures.** Both backends refuse them. JS could emit one directly, which makes it
  the cheaper place to find out what g6's cost model looks like in practice.
- **Bindings.** No program calls a host function yet, so [g5](../../docs/derivations/g5-bindings.md)'s
  Tier 2 story is still entirely on paper.
