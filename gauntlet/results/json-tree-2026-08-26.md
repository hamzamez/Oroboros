# A JSON tree without recursion — the value half — 2026-08-26

[`examples/json/tree.oro`](../../examples/json/tree.oro),
[`gauntlet/differential/cases/json-tree.oro`](../differential/cases/json-tree.oro).

[This morning](json-2026-08-26.md) settled the **control** half of the standing claim that
*recursive data is a flat table plus indices*: a JSON tokeniser nests to an input-decided depth
with no recursion, only a stack in a table. It produced counts, not a tree, and said so.

This is the **value** half. A document parsed into a flat node table, linked parent-to-child and
sibling-to-sibling by index, and then **walked** — because building a tree and never traversing it
would prove nothing, and the walk is where a tree normally recurses.

```
ok   json-tree              3030081 3030111 4040171 7070331  [go js java windows]
```

Four documents, four targets, byte-identical, and **every answer was computed by hand before the
program was run**:

| document | nodes | seen | Σ tag×depth | packed |
|---|---|---|---|---|
| `[1,2]` | 3 | 3 | 8 | 3030081 |
| `{"a":1}` | 3 | 3 | 11 | 3030111 |
| `[[1],2]` | 4 | 4 | 17 | 4040171 |
| `{"a":[1,2],"b":true}` | 7 | 7 | 33 | 7070331 |

`seen == nodes` on every one, which is the check that matters: every node is reachable exactly once
through the links. A linking bug a parse-only test cannot see shows up here as a wrong count.

107 lines of code. No new term kind, no new reduction rule, no new primitive, and no target declares
anything.

---

## 1. The shape

Node `k` occupies four slots, stride 4 — `tag`, `val`, `kid`, `sib` — and **node 0 is the `none`
sentinel**, so its own four slots are free and hold the header: the node count and `ok`. That is why
`none` can be `0` rather than `-1`, and why every index in the program is non-negative, which the
refinement layer cares about a great deal.

The parse stack is a second buffer, stride 2: the open container's node index, and **its last child
so far**.

**That second slot is the whole difference from recursive descent.** A recursive parser *returns*
its subtree and the caller appends it. Here nothing returns, so the parser has to remember where to
point next. It costs one machine word per level of depth — and note which direction that goes: the
explicit version is *smaller* per level than a stack frame.

---

## 2. `build` zero-fills, and that had never been said

A leaf writes neither `kid` nor `sib`, and reads `0` for both. So the sentinel is free **only**
because a fresh buffer is zero.

That was true on all four targets from the day `build` was written, by four unrelated mechanisms —
Go's `make`, the JVM's `new long[n]`, `new Array(n).fill(0)`, and `VirtualAlloc` handing back
committed pages — and **nothing specified it**. Agreement across four targets with no specification
and no test is exactly the shape of `split-words`, which passed every check for two months while
returning a different answer per target.

It is now [tables.md §14.3](../../docs/spec/tables.md) and
[`cases/build-zero.oro`](../differential/cases/build-zero.oro), which reads every slot of a buffer
with exactly one element written. It found nothing — but it was a guarantee this program leans on
for correctness, held up by luck, and now it is neither.

---

## 3. The same emitted code was a Java compile error and a JavaScript silent wrong answer

The bug of the day, and it is the argument for the differential suite compressed into one line.

A uniformly-updated loop variable is hoisted into the `for` statement's post clause — worth 1.4× on
the sieve. Both the Java and JavaScript emitters had Go's shape verbatim:

```
for (;; a, b = x, y)
```

| host | `a, b = x, y` means | result |
|---|---|---|
| **Go** | simultaneous tuple assignment | correct |
| **Java** | a comma-separated list of *statements* | **syntax error** — `not a statement` |
| **JavaScript** | the **comma operator**: evaluate `a`, assign `b = x`, discard `y` | **silent wrong answer** |

JavaScript compiled it, ran it, and returned `3000081` where every other target returned `3030081`
— the first hoisted variable never updated at all, and the second took the wrong value. Nothing
threw.

**It was latent for months because one hoisted variable emits `a = x`, which is correct on all
three hosts.** No program had two until this walk's `seen` and `steps`.

The fix is one assignment per variable on both hosts. Sequential assignment would be wrong if one
update read another hoisted variable, and it cannot: `PostVars` already refuses any update that
reads a loop variable other than its own — **a condition written to make the Go hoist correct, which
turns out to be exactly what makes the sequential form correct too.**

## 4. Two limits the compiler makes the parser state, and one it cannot

The tokeniser had to say what happens when nesting exceeds the stack. This program has to say it
twice: `(set nodes …)` carries an obligation on `nn`, and `(set stk …)` one on `sp`, and neither can
be discharged because both grow with the input.

```lisp
(go.>= nn (nmax))  (set (set nodes 0 nn) 1 0)
(go.>= sp (dmax))  (set (set nodes 0 nn) 1 0)
```

A recursive-descent parser has both limits too — the heap and the C stack — and is never asked about
either.

**The walk is the case where nothing can be proven, and that is the honest result.** Termination
depends on links read out of a table, and no analysis here can know a table is acyclic. So the walk
carries an explicit trip bound, and the numbers say exactly what it buys:

| | loops proven terminating |
|---|---|
| with the `steps` bound | **16 of 20** |
| without it | 12 of 20 |

The four still unproven are the scanners, for the relational reason
([json-2026-08-26 §2](json-2026-08-26.md)). Overall the program is **408 of 448 integer operations
bounded**, against the tokeniser's 80 of 124 — the clamped addressing helpers are why, and they are
the same construct that discharges the index obligations.

## 5. ADR 0015 chose the shape, again, and chose better

`again` may not go under an `if`. Three scalar kinds — string, number, literal — would therefore need
three clauses, each repeating the whole allocate-and-link expression. Computing the tag and the next
index with `let` first, which ADR 0015 *does* permit above `again`, leaves one copy:

```lisp
(scalar? (src i))
  (let (if (= (src i) 34) 2 (if (numeric? (src i)) 1 3)) (fn (tg)
  (let (if (= (src i) 34) (scan-string src i) …) (fn (ni)
    (again (link (set (set nodes (nsl nn 0) tg) (nsl nn 1) (go.- ni i)) stk sp nn)
           (mark stk sp nn) ni (go.+ nn 1) sp ok)))))
```

This was not the first thing tried. The rule that looked like a restriction produced the smaller
program.

---

## 6. So what does this settle

[general-purpose.md](../../docs/general-purpose.md) moved recursion from *deferred* to **owed**, on
the argument that *"a JSON parser, a DOM walk and a recursive-descent parser all recurse to a depth
the input decides"*. **Two of those three now run here without recursion** — the tokeniser is the
parser, and this walk is the DOM walk. The superseding ADR is not owed **on the grounds it gave**.

What is *not* settled is **ergonomics**, and it should not be smuggled in. 107 lines against maybe
60 for a recursive-descent JSON parser in a language that has recursion, and three of this program's
constructs — the clamps, the `steps` bound, the last-child slot — exist because of what the language
refuses. Whether that trade is worth making for a general-purpose language is a real question, and
it is a different argument from the one general-purpose.md made. It has not been made with a
measurement.

Two things that are settled and worth carrying:

**Two live buffers work.** A `build` nested inside a `build`, both threaded through one loop, with
the linearity check and the termination proof both intact. Nothing in ADR 0018 promised that and
nothing had tested it.

**A buffer can outlive the loop that filled it.** The parse loop returns the node table, it is frozen
on the way out of `build`, and the walk reads it as an ordinary `array`. That is ADR 0018's freeze
doing exactly what it says, on the first program that needed it.
