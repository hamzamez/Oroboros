## 1. What was built

**The tests are J.** The inline snippets in `core`, `emit`, `ir` and `gauntlet` were rewritten, most by a one-off translator over Go's AST (`cmd/zzsnip`, deleted), the rest by hand. A test's entry
term is the definition `t` (J has no bare term at the top level). Two things stay s-expressions, as
they are not the surface:
- **the core term's printed form**, an expected residual or a core-level test term, read by
  `core.ParseTerm`, the inverse of `Term.String`;
- **the IR's text**, read by `core.ReadRaw` (spec/ir.md §2.1).

Both are read by the raw reader, `core/raw.go` (230 lines): atoms, literals, strings and lists, with
the same UTF-8, NFC and bidirectional-control checks as J's lexer, and nothing desugared.

**No refusal passes vacuously.** With the bridge gone, a must-refuse test still written in today's
notation passes for the wrong reason: J refuses a top-level `(` whatever follows. To find them, the J
readers (`ReadProgram`, `ReadTarget`, `ReadTerm`) were instrumented to log every source in today's
notation they refused, with the test's line. The whole suite ran under it, a planted case was logged,
and the instrumentation was removed. It found four:

| test | today's snippet | the rule, now refused in J |
|---|---|---|
| `TestNonNFCIsRejected` | `(def café 1)`, decomposed | `café = 1`: J's lexer had no NFC check (below) |
| `TestDuplicateParameterIsRejected` | `(fn (x x) x)` | `fn t(x, x) { x }` |
| `TestReaderRejectsBidiControl` | `(add 1 ‮2)` | `t = add(1, ‮2)`: J's lexer had no bidi check |
| `TestTheUnitAndADiscardInsideASequence` | `(def x (tuple 1))` | `x = tuple(1)`: J accepted it (below) |

Two more were found by deleting today's reader. `TestTreeUsageOnTheShapesRelevanceTurnsOn`
(`core/usage_test.go`) still read today's notation through `ReadTrees`, today's reader of declaration
trees, so it tested μ's trees, not J's. Its 34 shapes are now J, with `case { c -> r; else -> r }` for
`cond` and a guarded `loop` for `match`. And `TestAProvidesThatDoesNotParseIsRefusedNamingTheFile`
passed by accident: J's lexer meets the bad escape before the parser meets the `(`.

**Today's reader is deleted** (5b.4): `core/mu.go` (μ), `core/concrete.go`, the reader in

## 2. What failed first

The J reader's faults, each found by a test, a generator or a program the move put through it:

1. **No NFC and no bidirectional-control check.** Today's reader called `validSource`; J's lexer never
   did, so `café` and `café` were two identifiers that display alike. Now the lexer's first step.
2. **A λ's parameters were any tokens.** `fn(m ∈ 0..9) { m }` read as a λ of five parameters, `m`, `∈`,
   `0`, `..` and `9`, and failed at its call with an arity no source states; `fn(a b)` read as two. Now
   names separated by commas, and a claim on a λ (ADR 0066's header, not built) is refused at the `∈`.
3. **`tuple(1)` was accepted**: J's application of the core's constructor name built a product of one.
   Refused, as today's reader did.
4. **A quoted name went through the set convention.** text/scanner's constant `Int` read as the
   language's `int`; `underlying `elf-R_386` -1..1` read the range as subtracted from the name; and a
   splice `${`scope_id`}` was unspelled to `scope-id` and matched no parameter. A quoted name is now the
   name itself in each place, and σ_J quotes a name spelled as a language set (`core.Spell("Int")` is
   `` `Int` ``), so the spelling is injective.
5. **An x86 hole past the ninth operand** was read back as `%10`, which the filler reads as operand 1
   and then `0`. Now `%{10}` (emit/host.go). No hand file had ten parameters; Win32's generated files
   have up to seventeen.

Earlier in 5b.2, each found when a test's J snippet was refused or read differently: a binder group
repeating a name (abstract.md W2) and `again` outside a tail or of the wrong arity (W3) were not refused
by the J reader; a loop whose last arm was not `else`; a top-level item that is no declaration; a
variant's markers followed by more text; a raw tab, line feed or return in a string, and the escape
messages; a table former whose binder set does not start at 0; a fill `array { e : _ ∈ … }` with a
computed element, which must be a constant λ; a parenthesized product inside a chain, which is a
component and not flattened (TLA+'s ×, ADR 0065); `2^k` folded for any k; the end of input consumed by
`next`; `map { k : v }`; a `-` in a path segment.
