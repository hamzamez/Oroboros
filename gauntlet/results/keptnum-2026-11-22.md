# A kept definition's numeral, and the JVM's map literal

Date: 2026-11-22. hamza, 2026-11-22: "after that fix the two separate tasks about windows and the
jvm", the two build failures split53-2026-11-21 found with every differential case's inputs unknown
(`// opaque`): windows' IR_P on six cases, the JVM's map literal on one.

## The law

**A representation is an abstraction function (H, d)** (ADR 0083), and a kept definition (ADR 0113)
is read through its interface, a Hoare triple whose result its callers hold. Above the word the
carrier H is a table and d its value:

- on K(ℕ\*) (ADR 0099), d(t) = Σ tᵢ·Bⁱ with the signed size last: **no width**, so the callee's d is
  every caller's. A kept definition's numeral is an integer at its call (`core.BigType`), held
  exactly there as any other value is, its digits in [0, B) the claim its body proved
  (`proveResultElems`), which the limb library's operations on it read;
- on fixed limbs (ADR 0029, 0098), d is at the width of the one set of the program it was lowered
  in, which a caller lowered under its own set does not share: the interface has no one meaning, so
  such a definition is not kept (P4 inlines it, and the program has one set). A definition on fixed
  limbs that calls a kept numeral leaves them for K(ℕ\*) whole, as for an operation with no limb
  form (V_n's carrier lies inside K(ℕ\*)'s, both injective into ℤ, so the move changes no answer).

**A map literal is a finite function K → V**, its JVM carrier `Map<Box ρ(K), Box ρ(V)>`: each entry
is taken into it by the inclusion ρ(a) ↪ ρ(K) before it is boxed. Java boxes an `int` only to
`Integer` (JLS §5.1.7), so `Map.entry(1, 10)` was a `Map.Entry<Integer, Integer>`, no member of a
`Map<Long, Long>`.

## Measured first

- **The six windows cases**: with its input unknown, `calc` is kept, and its result was registered by
  its carrier, `array int 0 18446744073709551615` (K(ℕ\*)) or `array int -16777214 16777215` (fixed
  limbs, big-signed-ops). The caller's `decimal` of it took the word's rendering (`lang.render`, its
  realization when the argument is not `big`), its domain −2⁶³..2⁶³−1 *assumed* after the decision,
  and W5 and W6 found the table in the comparisons. A false fact stated to the printer, caught by the
  verifier: no wrong answer reached a program. With literal inputs `calc` is inlined at each constant,
  and nothing crossed an interface.
- **record-map and tuple-map no longer fail W5** on HEAD (cb5db9b6): with their inputs unknown they
  build and answer, and the differential refuses them for another reason, an operation trapped under
  `-checked` and not proven: `r.x * 3 + r.y` over a value read from a map built in a loop, whose
  value facts reach the read only at the literal inputs (the owed presence and value facts of a
  built map). They join quotient-corner and sum-slots, proven only at their literal inputs.
- **The JVM**: map-static folds at its literal inputs; with the key unknown the literal is built, and
  javac refused `Map.ofEntries(Map.entry(1, 10), …)` into `Map<Long, Long>`: "inference variable K
  has incompatible bounds".

## What was built

1. **`keptNumerals`** (ir/keep.go): a kept definition's result LowerLimbs held on K(ℕ\*) is
   registered as `core.BigType` at its callers; the call's text is the carrier's, the same pointer.
   `Func.exactResults` (ir/ir.go) records, per result, the rung LowerLimbs lowered it on, so a
   program's genuine `Array(0..2^64-1)` result, whose type is the numeral's carrier's, is not taken
   for one. `PlantKeptNumeralAsTable`.
2. **`keptLimbs`** (ir/keep.go): a result on fixed limbs drops the definition from K (`KeepDrop`, P4
   inlines it). `PlantKeepFixedLimbs`.
3. **LowerLimbs** (ir/limbs.go): a kept numeral's call result typed the numeral's carrier, its digits
   in [0, B); a call of one on fixed limbs is `ErrNoLimbForm`, so the definition moves to K(ℕ\*)
   whole. `PlantNumeralOnFixedLimbs`.
4. **The interval analysis** (ir/interval.go): a call whose declared result is `big` and whose value
   is a table once held takes its facts from the value's own type, the carrier's digits.
5. **The JVM's map literal** (ir/java): each entry cast into the map's key and value types
   (`entry`), the identity where they agree. `PlantMapEntryUncast`.
6. **Tests**: `TestAKeptNumeralIsAnIntegerAtItsCallers` and
   `TestAKeptNumeralIsReadByItsAbstractionFunction` (cmd/build, three planted faults: W5's refusal, a
   stop, and a wrong answer, "475368976382895821502451548160 31664747899972011163649" where 3¹⁰⁰'s
   digits were read as 301-bit limbs); `TestAMapLiteralsEntriesAreItsCarriers` (javac refuses the
   planted form). The differential's big-bits, big-nat-div, big-nat-ops and big-signed-ops opaque,
   and a new case, `map-built`, a literal map read at a key not known when compiling, on every
   target (map-static stays literal: its claim is that the map folds away).

## What failed first

- **A debug run hung five hours**: a `println` of the whole function into a pipe. Writing the IR to a
  file found the cause in a minute.
- **Comparing types**: the first form recognised a numeral by its carrier type, missing big-signed-ops
  (fixed limbs, another carrier) and taking a genuine table of U₆₄ for one; the marker replaced it.
- **The caller refused, and P4 inlined the program whole**: the call's value typed `array int` had no
  element facts, so the rendering's division of the signed size was unbounded (7 of 570 operations);
  big-nat-ops compiled in 3m15 so, big-bits in 5m51. Typed by the carrier, its digits in [0, B), both
  keep `calc`: 1m18 and 2m06.
- **The tests' first witnesses**: a small `calc` is inlined by P2's threshold, so the test lowers it;
  a fixed-limb witness past its own declared set stopped at the claim (ADR 0152), correctly.
