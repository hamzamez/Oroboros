# A target is a chain of layers, and a library may be one of them

2026-09-07. [target-system.md](../../docs/spec/target-system.md) §7.2 and §8 —
items 3 and 4 of its build order, and the answers to questions 3 and 4 of the
brief that produced that specification.

> **Before:** a user's target could not coexist with the built-ins, and a
> portable library with a native fast path needed a file inside `targets/` for
> every host it supported.
>
> **After:** a target is `Δ_T = L₁ ▷ L₂ ▷ … ▷ Lₖ`, the source's own directory is
> the nearest layer, and a library's `(provides T M …)` is one more fragment in
> the same chain.
>
> **And the algebra paid for itself twice**: the two operations turned out to be
> *one fold with two combiners*, which deleted about sixty lines; and `provides`
> turned out to need **no new operation at all**.

---

## 1. The two operations are one fold

[target-system.md §2](../../docs/spec/target-system.md) says composing targets is
always one of exactly two things:

```
    ⊔  GLUE, within a layer.      They must agree; a collision is an error.
                                  Commutative, associative, idempotent.
    ▷  OVERRIDE, between layers.  The nearer wins, silently. Ordered, and
                                  licensing disagreement is its whole purpose.
```

Written out, `merge` was sixty lines of the same rule repeated per field: *if the
accumulator has it and they differ, error; else take the incoming*. Override is
**the same walk with a different answer at the collision** — nothing else about
it changes.

So it is one function and a `combiner`, with two generic helpers:

```go
func combineOne[T comparable](dst *T, src T, what, from string, how combiner) error
func combineMap[T comparable](dst, src map[string]T, what, from string, how combiner) error
```

`zero` means *not declared here*, which is what makes a fragment a **partial**
map rather than a total one — the sheaf condition falls straight out of that, per
name.

**One place is deliberately stricter than the algebra.** Under glue a repeated
`prim` is an error even when the two declarations are *identical*, where the
sheaf condition would allow it. That is on purpose: within one layer a repeated
declaration is a mistake rather than a coincidence, and saying so has caught real
ones. Between layers the nearer simply wins.

This is the part worth keeping: **the reason the two operations can be reasoned
about together is that they are now written together**, and the single point of
difference is one enum.

## 2. §7.2 — the layer chain

```
    Δ_T = L₁ ▷ L₂ ▷ … ▷ Lₖ        Lᵢ = ⨆ { fragments for T in layer i }
```

`-targets` is a search path on all three commands — the same shape `-path`
already had for modules — and **the source's own directory is always the nearest
layer**, which is what `libDirs` already did and what `targetDirs` now does.

Three consequences fall out rather than being coded:

**A layer that does not have the target contributes nothing.** The empty fragment
is `⊔`'s identity, so an absent layer needs no special case — it is skipped, not
refused.

**One lookup rule, both spellings.** A layer's contribution for target `T` is the
*directory* `L/T` or the *file* `L/T.oro`, and the caller may write either with
or without the extension. `targets/go` is a directory and `targets/blas.oro` is a
file; nothing above the loader has to know which.

**`addCore` runs once, at the end.** The language's names are resolved by
*spelling* against the whole target, so injecting them per layer would resolve
`concat` against a fragment. Moving it out of `loadTargetDir` is what makes a
directory a *layer* rather than a target.

Demonstrated:

```lisp
; /tmp/proj/mygo/mygo.oro — a user's own target, beside the program
(target mygo (backend go) …)
```

```
$ gen /tmp/proj/hi.oro mygo …
wrote …        # and targets/ is still on the path, untouched
```

and the override half, which is the one that was impossible before:

```lisp
; /tmp/proj/go/override.oro — the project's opinion about ONE name
(target go (module go/strings
  (prim ToUpper (string) string expr "strings.ToUpper(/*project*/ %s)" pure …)))
```

```go
return (strings.ToUpper(/*project*/ x))   // and the rest of targets/go is intact
```

**Override replaces a NAME, not a layer** — everything the nearer layer did not
mention still comes from below. That is `▷` being a per-name left bias rather
than a whole-map preference, and it is what makes a one-line project override
practical.

## 3. §8 — a library may declare a target's native

**`(provides T M decl…)` is exactly `(target T (module M decl…))`, written where
the library lives.** That is the whole finding, and it is why this cost almost
nothing: it needs no new operation, no new precedence, and no new cell in
modules.md's four-cell table. It is a target **fragment**, and §7.2 already says
a target is the glue of its fragments. The only thing that changed is *where
fragments are found*.

It was specified in [modules.md §6](../../docs/spec/modules.md) in August and
**nothing parsed it**, which is why a library with a native fast path needed a
file inside `targets/` per host.

It is the **lowest** layer: a library's opinion about a host loses to that
target's own files, which are the authority on it.

### 3.1 Conditional lowering, executable at last

One library directory, no edit to `targets/`:

```lisp
; std/words.oro          — the portable definition
(module std/words)
(export shout)
(def shout (fn (s) (concat s "!")))

; std/words-go.oro       — the Go native, declared by the LIBRARY
(provides go std/words
  (prim shout (string) string expr "strings.ToUpper(%s)" pure (import "strings")))
```

```go
return (strings.ToUpper(x));      // go — the native, from P_T ∩ D
```
```js
return (x + "!");                 // js — no native, so δ unfolds the definition
```

That is modules.md §6's conditional lowering — *three targets, three outcomes,
from `P_T ∩ D` and δ* — running for the first time.

## 4. Cost

| | |
|---|---|
| emitted files | **65 of 65 byte-identical** across four targets |
| differential suite | 28 cases, four targets, green |
| unit tests, `go vet` | green |
| `merge` | ~60 lines → two generic helpers plus a field list |

Three tests, each verified to fail against its bug: override reversed (the far
layer wins), an absent layer refused rather than skipped, and `provides` not
parsed.

**No emitted file changed**, which is the right result for a change that is
entirely about *where declarations are found*. Nothing about what a declaration
means moved.

## 5. What this leaves

**§6, `(library PATH)` — no live demand.** It was listed here as next, on the
strength of windows' `concat`/`string-of` being the fourth Oroboros library that
would force it. [winstrings-2026-09-07](winstrings-2026-09-07.md) wrote those as
two assembly templates instead — smaller, no new mechanism, and what a target
file is already for. The item should wait for a genuine case rather than be built
on one that no longer exists.

**§5.4, the interface/implementation split** — still waiting for a second Windows
ISA. A family with one member proves nothing.

**And T5′ now has teeth in practice.** Adding a `provides` fragment is monotone
on *coverage* and **not** on *emission*: a name in `P_T ∩ D` takes the native, so
shipping one changes what an existing program compiles to. That is conditional
lowering working as designed and also how a library could silently change a
program's answer — `split-words` passed every mechanical check for two months
while returning different answers on different targets. The conformance
obligation in [target-files.md §7](../../docs/spec/target-files.md) is what
answers it, and it is unchanged: nothing here checks that a native means what the
portable definition means.
