# layers-2026-11-04: the LLVM layer, a theory with a parameter, and windows its first member

6b′ step 1 (hamza, 2026-11-04: "go ahead. always mathematical and algebraic"), ADR 0093.

## The algebra

A target family over an interface (target-system.md §5.3), with LLVM's fibre a triple:

```
T_LLVM[Σ_OS]   Σ_LLVM, ι's terms, the representations           targets/llvm/
windows        (llvm, T_LLVM[Σ_OS ↦ Win32] ⊔ Σ_win32, x86_64-pc-windows-msvc)
```

- **Σ_OS**, the parameter, is what ι's terms need from an operating system and no instruction
  computes. It is three operation symbols with their contracts:
  - `region(b) (ptr)`: b zeroed bytes, or the trap;
  - `write_err(b) (Bool)`;
  - `exit(code) (∅)`.
- **A header with no body is an operation symbol.** It is a section of the sheaf of declarations,
  so it glues with a definition exactly when their headers are equal (§2.1's agreement), and the
  glue is the definition.
- **A theory with a parameter is not a model**: the layer loaded alone is refused, naming
  `llvm/os.exit`, `llvm/os.region` and `llvm/os.write-err`.
- **Windows is the view Σ_OS → T_Win32**, its module `llvm/os` defining the three over kernel32.
- **A run is exit(0) ∘ main**: `cmd/build` composes the entry, so the printer's `main` calls it and
  names no operating system.

## What was built

  - under glue, two headers of one name must agree (`sigText`);

  - a backend-`llvm` target with no triple is refused.

- **`targets/llvm/`**:

- **`TestATargetIsTheGlueOfItsLayers`**:
  - a member defining the base's header under the same header is a model;
  - refused, each naming its reason: a header defined under another header, a header nothing defines,
    no triple, a cycle;

## What failed first

- **The reader had no form for a header without a body**, so the first load stopped at `os.oro`'s
  `fn region(…) (ptr)`.
- **`llvm/os.exit` was left unreduced in the composed entry.** A target module joins a program only
  when the program uses it, so the driver loads `llvm/os` with an LLVM program.
- **The toy LLVM target in a backend test named no triple**, which the new rule refuses.

## What was measured

- The three Windows programs build and run on the glued target: `hello`, `222 111`, `1798400`, each
  exit 0.
- The differential suite: every case agrees on four targets.
- **Emission**: one program changed, `expect.oro` on windows, whose crash now gets the standard-error handle inside each `write_err`; refusal texts on the other targets name `llvm/str`. The counts are unchanged, 4,999 of 5,059 operations and 492 of 516 loops; the gauntlet is byte-identical; the surveys and every acceptance program pass; compile time 1.07×.
