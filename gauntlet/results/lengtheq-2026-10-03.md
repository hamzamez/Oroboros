# Two equations under one key: the order of a precondition decided a proof

2026-10-03. Found while writing an elementwise add for a reply about IR text formats: with the
precondition `len a = len out ∧ len b = len out` the compiler refused `(b i)` under `i < len a`, and
with `len out = len a ∧ len b = len a` it proved it. The two are the same set.

## 1. What it was

Over three tables, varying only the orientation:

| precondition | `(b i)` |
|---|---|
| len a = len c ∧ len b = len c | refused |
| len c = len a ∧ len b = len a | proven |
| len a = len c ∧ len c = len b | proven |
| len b = len a | proven |

The refinement layer keeps equations as a substitution, a map `eq[x] = e`, and `assumeEQ` assigned
to it. `(= s t)` is stored under t's variable when t is one, so `len a = len c` stored
eq[len c] = len a, and `len b = len c` then stored eq[len c] = len b. **The second true fact
overwrote the first.** Every other orientation stores its two equations under two keys, and nothing
collides.

It loses information and invents none, so it was incomplete, not unsound. But it was non-monotone,
the worst shape a prover can have: adding a true conjunct, or reordering one, lost a proof. The
comment above `assume` records the same failure once before, for `!=`.

## 2. The algebra

A conjunction of linear equations kept as a substitution σ, x ↦ eₓ, with no eliminated variable on
a right side, is a **solved form**: Gaussian elimination over the variables. An equation is added
to it, not assigned. To add s = t, rewrite L = σ(s − t), which mentions no eliminated variable:

- L = 0: redundant;
- L = c ≠ 0: a contradiction, so the facts entail everything, which is right for a path that cannot
  be taken (recorded as 1 ≤ 0);
- otherwise, solve for a variable whose coefficient is ±1, so the solution is integral, and extend
  σ. Each new binding maps a variable not yet eliminated to variables not yet eliminated, so the
  bindings stay acyclic;
- no unit coefficient: keep L ≤ 0 and −L ≤ 0. The inequalities' entailment reads them, and over the
  rationals 2x = 2y and x = y give the same consequences.

The variable named is solved for when its coefficient is ±1, so an equation about a fresh name is
stored as it always was, and the old behaviour is unchanged wherever it was right.

**It needs a key to name one variable wherever the facts reach.** Combining two equations under one
key would be unsound if the key could name two variables. It cannot: a residual's binders are named
apart along the scope chain (ADR 0036), and every caller of `assumeEQ` assumes a binder's equation on
its own scope's copy of the facts. Six call sites, read one by one.

## 3. Witnesses

`emit/lengtheq_test.go`, through the whole pipeline: ten preconditions, four orientations of
len a = len b through a third length, a redundant third equation, b one longer (in range) and one
shorter (refused), and a pair with no unit coefficient on each side.

| rule | planted fault | caught by |
|---|---|---|
| an equation is added, not assigned | the assignment restored | the two colliding orientations refused |
| the elimination solves with the right sign | `v = c·rest` for `v = −c·rest` | b one shorter, and 2·len b = len out, accepted: indices out of range |

The second row is why the first is not enough. An overwrite only loses facts; a wrong elimination
invents them, and the negative cases are what show it.

## 5. Not built

- **A contradictory precondition is not reported.** `len b = len a ∧ len b = len a + 1` makes the body
  vacuously provable, which is sound: no call can satisfy it, so every call site is refused. A
  definition whose `where` is unsatisfiable is still almost certainly a mistake, and nothing says so.
- **The other maps in the fact set were read too**: `content` and `zero` are assigned once per
  binder, on that binder's scope, so they hold one fact source each and have no such collision.
