# A table's length read once; why not `noalias`; where fact's time goes (item 1)

Date: 2026-11-10. Item 1 of fitreuse-2026-11-10's list, under hamza's standing measure (windows
faster than Go, the gap owed): every operand's length reloaded at every digit.

## The question

In fib's addition loop, every digit reloads each operand's length (`movq (%rbp), %r10; decq; cmpq`).
LLVM cannot know that the store into the output leaves the inputs' headers alone. Two facts would
let it, each true in the language:

- **separation**: two live tables own disjoint regions (ADR 0084's views; Theorem V);
- **invariance**: a table's length is fixed at its birth, len(build(n, …)) = n, and the table is
  immutable, so len(t) is a pure function of the value.

## Why not `noalias`, as the item first said

LLVM states separation two ways, and their semantics decide (LangRef, read for this step):

- **Parameter `noalias`** holds "during the execution of the function": a call is the dynamic scope,
  exactly a view's lifetime. Sound. But the library's instances are inlined into the program, so
  there is no call to carry it. Emitting each instance as a function is on the plan's deliberately
  not next list; this measurement is the first reason to revisit it.
- **Scoped metadata** (`!alias.scope`, `!noalias`) is a claim about static instructions, with "If
  accesses from different collections alias, the behavior is undefined". That is a dynamic UB
  definition. The process heap may hand back part of a freed block at a different base, so one
  table's element and a later table's header can share an address over a run. Tagging the two kinds
  of access disjoint would make such a program undefined. **Unsound here.**
- **Reading the header eagerly where each table is defined**, in the LLVM printer, is unsound too: a
  variant's table slot is null when its tag names another constructor, and an eager load there
  dereferences null where the lazy one never ran.

## What was built: the length by β

Invariance needs no aliasing claim. len(t) is a pure function of an immutable value, so binding it
once before a loop gives the same number at every digit, by β. `emit/natnum.oro` gains readers that
take the length as an argument:
- `dg`, a numeral's digit, given len t − 1;
- `pg`, a plain table's, given len t;
- `rg`, a buffer's being built;
- `wg`, the window's.

Every digit loop binds its operands' lengths before it: `mcmp`, `addsub`, `macrow` and `mul`,
`mul_small`, `qsmall`, `rem_small`, D's `msub`, `addv`, `topcmp`, `slice`, `unnorm` and its two
machine loops. The theory checks unchanged, since each index is still below its length by the
bound's own equation. No compiler rule was added.

## What was measured

Best of five, two rounds, serially; "R1d" is fitreuse-2026-11-10's build:

| program | R1d | lengths once | Go, `math/big` |
|---|---|---|---|
| fib(10⁵) | 244.8 / 242.1 ms | **228.8 / 227.9** | 29.4 / 34.0 |
| 2,000 quotients (D) | 289.6 / 269.7 | **264.3 / 265.9** | 100.9 / 94.4 |
| fact(20,000) | 407.2 / 408.5 | 411.0 / 406.1 | 38.4 / 35.3 |

fib gains 6.5%, as the experiment before the change predicted (233 / 228 ms), and D about 5%.
**fact does not move**, and was made to explain itself.

**The check**: only `examples/big/`'s four windows programs change, and their functions print what
Go prints. The count went from 6,070 of 6,124 operations to 6,062 of 6,116, eight header reads
fewer; the unproven 54 and 24 are unchanged.

## Where fact's time goes

fact(20,000) printing only its residue mod 10⁹ + 7, the product alone:

| | windows | Go |
|---|---|---|
| the product | 158.3 / 150.9 ms | 34.2 / 33.6 |
| product and printing | 411.8 / 406.0 | 37.9 / 37.2 |

**Printing is 62% of fact on windows** (about 255 ms) and about 4 ms on Go. fact(20,000) has 77,338
decimal digits, and `render` divides the whole numeral twice per nine of them: O(m²) work, twice.
This is a new owed item, with its algebra:
- **Short division's quotient and remainder are one fold**: the remainder is the Mealy machine's
  final state. One pass per chunk gives both, which halves render.
- **`math/big` converts by divide and conquer** (Brent and Zimmermann 2010, §1.7), O(M(n) log n)
  against O(n²): split by 10^(9·2^k), recursively. integers-research §3.3 listed it, to be measured;
  it is now measured.

## The owed list, restated

Under the standing measure, windows is still 4.4× (fact's product), 2.8× (D), 7.7× (fib) and 11× (fact
printed) Go:

1. ~~the length reloaded~~ **done** here, by β, not by `noalias`. Parameter `noalias` waits on
   instances as functions;
2. every digit read masked: the invariant d ∈ [0, B) as a fact;
3. the sign case selected per digit: unswitched;
4. the carry by comparisons: M4, 64-bit digits with `uadd.with.overflow` and i128 (native iN);
5. the size tracked per digit: a sum's from its carry;
6. **render**: one pass per chunk, then divide and conquer.

## What failed first

- The item as first written (`noalias` from the views) is unsound in LLVM's semantics for inlined
  code. Found by reading the LangRef's definitions before building, not by a wrong answer.
- The product-only measurement first compiled in the word: with `big_str` reading only the residue,
  nothing demanded the product exactly. A declared `Nat` result states the demand.
