# A binding writes its name first

2026-09-19. `core/let.go`, `core/read.go`, `core/binding_test.go`, the whole corpus, and
[spec/binding.md](../../docs/spec/binding.md). Research first:
[binding-surface.md](../../docs/binding-surface.md), on hamza's question about Shen's
`(let v1 e1 … body)` against ours.

```lisp
(let x VALUE  (tuple a b) VALUE  …  BODY)
```

replaces `(let VALUE (fn (x) BODY))`, which is refused naming it. **Emission is byte-identical**
across all 456 runs, which is the whole claim: this is a change to what a program looks like, and to
nothing else.

## 1. The refutation was checked first

The research named what would kill the flat form: *a program where the pipeline order reads better —
a long chain of transformations, each feeding the next, which is what `|>` exists for* (§7.4). It
named `freq`'s sort passes as the corpus's one candidate, and said to check it **before** rewriting.

Checked. `freq`'s pipeline under the flat form:

```lisp
(def freq (src)
  (let nw   (nwords src)
       sp   (spans src nw)
       ord  (msort (fn (u v) …) nw)
       nd   (ndist src sp ord nw)
       dt   (dists src sp ord nw nd)
       ord2 (msort (fn (u v) (> (dcount dt u) (dcount dt v))) nd)
    (report src sp dt ord2 nd)))
```

It reads better, and the reason generalises: **`|>` wins where the intermediate needs no name.**
Ours never had that option — every stage was already `(fn (nw) …)`, a named binder — so the pipeline
order was paying `|>`'s price without collecting its benefit. The refutation does not fire, and the
one shape that could have raised it is the strongest case for the change.

## 2. What is built

| | |
|---|---|
| grammar | `(let LHS VALUE … BODY)`, k ≥ 0 pairs and one body, **sequential** |
| left-hand side | a name, `_`, or a tuple pattern `(tuple a b …)` |
| desugaring | `((fn (x) b) e)` for a name, `(e (fn (a b) body))` for a pattern — the product's eliminator, in binding order |
| n-ary | because nesting is **associative**; `(let b)` is legal because the body is its **identity**, the same law that makes `(and)` be `true` |
| `seq` | unchanged, and now specified as a binding whose name is discarded: `(seq a b)` is `(let _ a b)` |

**No new word**, so [inventory.md](../../docs/spec/inventory.md) stays at 136. The reader owns all of
it; `core/let.go` is 90 lines and nothing below it changed.

**Several results stop needing a call-site continuation**, which was hamza's second question:

```lisp
(let (tuple src err) (os.ReadFile (av 1))
  (if (os.err-nil err) … ))
```

still emits `src, err := os.ReadFile(av[1])`. The line that decides this is refutability, and it
falls out of the algebra rather than being imposed: a product has one constructor, so its eliminator
is total and belongs in a binding; a sum has several, so it belongs in `case`. *Irrefutable patterns
bind; refutable patterns branch.*

## 3. The parity discriminator, and the edge cases

A `let` with an **even** number of elements after the head is the old form or a missing body; an odd
number is the new one. So the two are distinguishable, which is what let the old spelling be refused
with a message naming the new one rather than silently reinterpreted — the `sum`→`variant` and
`values`→`tuple` precedent ([data.md §10](../../docs/spec/data.md)).

Every edge case is in [binding.md §7](../../docs/spec/binding.md). The ones that took a decision:

- **`(let b)` is accepted**, because the identity law says what it means. Refusing it would have been
  a choice where there is a theorem.
- **A repeated name across bindings is legal** (nested binders, [def.md §11](../../docs/spec/def.md))
  and **a repeated name in one tuple pattern is not** (one parameter list). Both fall out of reusing
  `paramListOf`, so a binder obeys exactly the rules a λ's parameter does — including the refusal of
  a module-qualified name.
- **`again` under a tuple binding is refused.** ADR 0015 permits `again` under a `let`, and a chain
  of flat one-name bindings is exactly that shape. A tuple binding is an application of the producing
  call, so the jump would sit inside a host call's continuation and no backend emits it. Named and
  refused rather than discovered later.

## 4. Witnesses

`core/binding_test.go`, four tests, each shown to fail against a planted bug:

| test | what it pins | fails when |
|---|---|---|
| the commuting square, 8 cases | each flat spelling reads to the **same term** as the explicit one — one name, sequential pairs, three bindings, a tuple pattern, a mixed chain, `_` = `seq`, `(let b)` = `b`, shadowing | the application is built the other way round |
| the refusals, 11 cases | the old spelling, a missing body, an even count, a non-name left-hand side naming `case`, a nested pattern, a tuple of one, a repeated name, a qualified name, `(seq a)` | the old spelling is read instead of refused |
| `again` through a chain | legal under nested bindings, refused under a tuple one | either half is dropped |
| a written λ is not a pattern | the discriminator is the binder `#k`, which no source term can contain | `patternNames` accepts any one-parameter λ |

The last is the anti-vacuity control: `(tuple a b)` has already been desugared by the time the head
is dispatched on, so a pattern arrives as `(fn (#k) (#k a b))`, and the test proves a λ the
programmer wrote is not mistaken for one.

## 5. The corpus, and what the rewrite cost

**169 `let`s in 64 `.oro` files**, rewritten mechanically by a throwaway s-expression rewriter that
merges nested bindings into one flat list, plus ~70 inside Go test sources. The acceptance was the
emission baseline: **456 runs, byte-identical**, proof counts unchanged, the differential suite green
on four targets and the tooling suite green.

`tally`'s pipeline is the change in one picture — eight bindings that closed with eighteen parens
now close with three, and every name is written before its value:

```lisp
(let re   (h.compile p)
     ls   (h.lines text)
     n    (nhits h.hit? re ls)
     cs   (captures h.hit? h.capture re ls n)
     ord  (msort (fn (u v) (< (h.cmp (cs u) (cs v)) 0)) n)
     nd   (ndist h.cmp cs ord n)
     dt   (dists h.cmp cs ord n nd)
     ord2 (msort (fn (u v) (> (dcount dt u) (dcount dt v))) nd)
  (report h.show cs ord n dt ord2 nd))
```

`walk` in `tree.oro`, the research's worst case, went from nine bindings under twenty-four closing
parens to nine lines under one.

**Four programs took the destructuring spelling** — `wc`, `jsonfmt`, `freq`, `tally` — and `wc` is in
the emission baseline on Go, JavaScript and the JVM, so the tuple left-hand side is exercised
end-to-end on three hosts and emitted identically on each. The README's `encoding/hex` example uses
it inside a `build`, was compiled and printed `686921`.

## 6. Two things the rewrite taught

**The residual's spelling must NOT move, and the test suite proved it.** Seven expectations in
`core/reduce_test.go` compare a *printed residual*, and the rewriter respelled them along with the
sources; the tests failed, correctly, because `(let e (fn (x) b))` is what the reducer produces when
call-by-need declines to substitute. That is the split [def.md §6](../../docs/spec/def.md) records as
once-conflated — and respelling only the source half now makes the two roles impossible to confuse by
eye, which is a small improvement the change was not made for.

**A rewriter that edits comments is a rewriter that edits code it cannot parse.** The first pass over
the Go files treated backticked Oroboros snippets inside `//` comments as code and mangled six
non-test files, including the refusal message in `core/let.go` — the message the tests check. Caught
by reading the diff, and fixed by making the scanner skip comments; the documentation snippets were
then moved by hand. The lesson is the corpus's own: *a path nothing runs is a path nothing checks*,
and a comment is exactly such a path.

## 7. Not built

- **`cond`.** Recommendation 3 of the research, still measured at zero uses in the corpus and still
  free (same proof counts, same emitted code). It is a style change to programs, not a language
  change, and it is separate work.
- **The reader owning arity** (`(+ 1 2 3)` refused where it is written, recommendation 4), and any
  n-ary `+`. That decision rests on the monoid law and a measurement, not on this change.
- **A new differential case for the tuple binding.** The reader's output is the *identical term* the
  continuation spelling produced, pinned by the commuting square, and `wc` already carries it through
  the whole pipeline on three targets. A four-target case would have been testing the same bytes
  twice.
- **`again` under a tuple binding**, §3.
- **Parallel `let`, `letrec`, refutable patterns, binding vectors, user macros** — binding.md §9.
