# llvm-2026-11-02: `ir/llvm`, the printer, at the windows target's differential parity

Step 6b of the 10-24 plan, its first step ([llvm.md](../../docs/spec/llvm.md) §9 item 1): the printer
of [ADR 0080](../../docs/decisions/0080-the-native-targets-print-llvm-ir.md), specified first, built,
and run on every differential case the MASM target runs. MASM is not retired here; that is §9 item 4.

## The algebra

h_L : IR_P → LLVM IR is correct when it preserves meaning, ⟦h_L(p)⟧ = ⟦p⟧ (Leroy's semantic
preservation). LLVM adds no check: an instruction with a flag is poison outside the domain the flag
asserts (Lee et al., PLDI 2017), so a flag is a claim, and h_L may write one only where the IR proved
it. The IR's proofs are its modes and IR_P's types: `exact` is ℤ's result inside the word (`nsw`); an
operand's proven range gives `nuw` (a + b, a·b with a, b ≥ 0; a − b with 0 ≤ b ≤ lo(a)); an index
proven in [0, len) gives `inbounds`; a π's type holds on its arm (W6, pijustified-2026-11-02).

Control is structured SSA printed as blocks, a join's values as `alloca` slots that mem2reg makes φs
(Cytron et al. 1991; the regions give a reducible graph). A branch whose two arms both continue
computing only operations with no undefined behaviour is one back edge choosing its arguments by
`select`, sound because `select` takes no poison from the operand it does not choose.

A shift is total in ℤ and poison in LLVM past 63; each is the instruction where the count is below 64
and its limit past it, a·2ᵏ = 0 (a is 0 by the obligation) and ⌊a/2ᵏ⌋ ∈ {0, −1}, chosen by `select`.
So `>>` past a count of 63, refused on MASM, is total here (CLAUDE.md's "`>>` past 63 on windows").

## What was built

- **[docs/spec/llvm.md](../../docs/spec/llvm.md)**, the specification: types, the table layout, every
  operation with its flag and the proof it states, templates, control, the function and the entry.
- **`ir/llvm`**, the printer (h_L), read from IR_P and the target alone, like the other four printers;
  wired into `cmd/build`, `cmd/gen` and `cmd/check`'s reprint, and `emit` gains backend `llvm`.
- **`targets/windows-llvm/`**: `llvm.oro` (LLVM's integer instructions as they are, each with its
  domain), `lang.oro` (the forms realizing a language name where no instruction is its operation on
  the whole domain), `kernel32.oro`, `strings.oro` (`string_of` and `++` as helper functions the module
  defines) and the target file, whose `realize` lines state which declaration interprets each of the
  language's names (ADR 0088, the second half of this step). clang `-O2` on the
  module, MSVC `link`, `-entry:main`, kernel32 only: no C runtime, and every function `"no-builtins"`
  so no loop becomes a call to the runtime's `memcpy`.
- **`lib/win/print.oro`**: printing in the language's own operators over a byte table, where
  `lib/win/fmt.oro` names x86 mnemonics. Every operation of it is proven (48 of 48 in a test program, its guard included).
- **`emit/winmap.oro`**, the map the language supplies on Windows, ported from x86's mnemonics to the
  language's operators (ADR 0080 item 5), so one source serves both printers.
- The differential runner runs a fifth target, `windows-llvm`, on every case `windows` runs.

  | merge sort | 117.2, 1.00 | **42.0, 0.36** | 42.2, 0.36 |

  **Against hand-written MASM** (`gauntlet/windows/sieve.asm`, the same program as a process, 21
  interleaved runs of each whole process): hand-written 52.1 ms, `ir/x86` 48.0 (0.92), **`ir/llvm` 33.1
  (0.64)**, the `ir/llvm` build being `experiments/backend/sieve.oro` with `lib/win/print.oro` printing

  The printer is the prototype's speed, which is the measurement ADR 0080 was decided on (0.63 and
  0.35 then, on a machine running slower that day). Every build gives 1,798,400 and 6,689,817,084.
- **The allocator, made to explain itself**: the first printer ran the sieve at 0.72, 10% behind the

  27.1). `VirtualAlloc` reserves 64 KiB a call, so the allocator chooses by size, from 64 KiB.
- **The printing library** proves every operation it has (48 of 48 with its −2⁶³ clause live, 7 of 7
  loops), and prints 0, 100, −2⁶³, 2⁶³ − 1 and UTF-8 text as the other targets do.
- **The flags' rule** (`TestAFlagIsTheIRsProof`): `nuw nsw`, `nsw` alone, and no flag on a wrapping
  operation, each where the IR's facts say; a witness reads every printed flag back against the IR's
  modes and ranges. **Planted** (`TestAFlagWithoutItsProofIsCaught`): `nuw` on every proven add and

- **`-checked`'s unproven operations**: one with no checked form keeps mode `exact` (ir/decide.go), so
  a flag would be written without its proof. Every operation this target realizes that can leave the
  word has a checked form: `+ − ·` by LLVM's overflow intrinsics, `<<` by `lang.shl_checked`; the
  realization of a host `neg`, which LLVM does not have, is gone with it.

- **The corpus** (`cmd/check`, accepted): `windows-llvm` joins the emission sweep, so every source is
  emitted or refused on it and reprinted from its IR text byte for byte; no existing source × target
  changed, `emit/winmap.oro`'s port included, so MASM's emission is byte-identical. The counts become
  **5,027 of 5,093** operations and **557 of 580** loops, the new target's 226 of 240 and 55 of 55 (legality counted before ι, ADR 0090): it
  leaves unproven exactly the 15 operations MASM does, in the same four differential cases. Compile
  time 1.02× the baseline.

## The second half: a host operation as it is (ADR 0088)

hamza's correction, the same day: `<<` means one thing on every target, and LLVM's `shl` is not the
language, it is a target instruction to be stated as it is and reasoned about. The first build had
made `llvm.shl` a total form of three instructions, because the compiler found the language's `<<` by
looking for a declaration spelled `shl`: the host's operation was falsified to fit the guess.

A target is a model of Σ_L (ADR 0021), and its interpretation of a name is a function, so it is now
stated: `realize `<<` = lang.shl, llvm.shl checked lang.shl_checked`. `llvm.shl(a, b ∈ 0..63)` is
LLVM's instruction with its domain; `lang.shl` is the total form; the IR chooses `llvm.shl` per instance
where the count's proven set lies in 0..63 (ADR 0083 item 2's selection), and the printer writes its
flags. Measured (`ir/llvm` tests): `a << k` with k ∈ 0..40 prints `shl nuw nsw` and no `select`; with
k ∈ 0..100, the total form; `llvm.shl(0, k)` with k ∈ 0..100 is refused, with k ∈ 0..63 accepted. Every
language name the target realizes is the declaration it states (`TestATargetStatesItsRealizations`);
**planted**, names found by spelling on a stating target, which the witness catches (by luck `<<`
spells to `lang.shl` too, so the witness compares every stated name, and `/` is found by no spelling).

Stating `sdiv` as it is surfaced two more facts:
- **its domain excludes −2⁶³ by −1** (LangRef), where ℤ's remainder is 0. `%` is realized by `lang.rem`
  and `/` by `lang.div`, which read a divisor −1 as 1: `%` gives 0, and `/` gives −a, which for −2⁶³ is
  −2⁶³, as Go and the JVM answer;
- **that quotient, 2⁶³, is outside the word, and nothing decides it**: `/` is not among the operations
  `ir.Decide` proves inside the word. Go and the JVM answer −2⁶³, MASM traps. A language-level defect,
  item 8 of the plan, not repaired here.

`kernel32.WriteFile` is Win32's again, its domain the segment inside the table and a DWORD count; the
library's `write` guards it, `false` outside. That guard met the refinement layer's defect below, so
it was repaired rather than worked around.

## The third: a realization is a term (ADR 0089)

hamza's next question: why are the realizations templates, LLVM text, and not definitions over LLVM's
own operations? Because MASM had no other way, and the habit came over. A target interprets each
language symbol f by a derived operation of its host's signature, ι(f) ∈ T(Σ_LLVM): a theory
interpretation (Goguen and Burstall). Written as a term, the interpretation is in the algebra the
compiler checks; written as text, it is trusted. So `lang.oro` now holds, in the language:

    fn shl(a ∈ Int, b ∈ Nat) (Int) { if b <= 63 { llvm.shl(a, b) } else { 0 } }
    fn div(a ∈ Int, b ∈ Int) (Int) where b != 0 { if b == -1 { 0 - a } else { llvm.sdiv(a, b) } }

and `~`, `>>`, `mod`, `%` alike. The algebra fixes four rules (`ir/realize.go`):
- **a term is substituted after the decision**, inlined for the operation, and the decision taken
  again. The site's obligation is what makes `else 0` right (a·2ᵏ in the word forces a = 0), so the term
  is an interpretation of a decided operation, never an ordinary function;
- **its header is the operation's domain**, the obligation at every site;
- **inside a term, a host operation is read as the language operation it is stated to realize**
  (`llvm.shl` in `<<`'s list is `<<`), so its interval transfer, exactness and flags stay; the IR records
  it, `(shl exact via llvm.shl %1 %2)`;
- **per instance, the narrowest later realization whose domain the facts prove**: its parameters' sets
  and its `where`, decided on intervals (`/` by 10 is `sdiv`, `<<` by k ≤ 40 is `shl nuw nsw`).

Soundness is two conditions, each checked. **Definedness**: each host operation in a term is used in
its domain, decided once when the term's instance is built. **Agreement**: ⟦ι(f)⟧(x) = f(x) on f's
domain, on the IR's interpreter against ℤ at the domain's edges (the word's ends, 0, ±1, counts 62–65),
every operation of the term in the word and every host operation inside LLVM's domain
(`TestTheInterpretationAgreesWithTheLanguage`, all six terms). **Planted**: `<<`'s guard at 64, which
the check refuses (`TestATermPastItsHostDomainIsCaught`).

What the terms changed:
- **−2⁶³ / −1 is decided on this target**: `/`'s term computes it as `0 − a`, the language's `−`, so
  the site is refused or traps as ℤ says. Item 8's defect remains on the other targets.
- **¬(a = b) is a ≠ b in the refinement layer** (`emit/linear.go`): `div`'s header `where b != 0`, in the
  language's words, is D's negation of `==`, which the layer read as an opaque atom, so every division
  in the limb library was refused. `TestTheLanguagesNotEqualIsADisequality`, the opaque reading planted.
- **The target reader kept only the first form of a definition with a header** (`DeclTerms(ds)[0]`):
  the header, so the body was lost and the header read as a host declaration. Both are kept; a header
  with no host body is the target's own library's, and the loader takes it with its definition.

Templates remain, each for a stated reason: the checked arithmetic (LLVM's overflow intrinsics answer
two results, which the printer does not receive yet), `trap_if` and `abandon` (a call that never
returns), the allocator and `WriteFile`'s buffer and cell (pointers as values, ADR 0084's LLVM part),
and the string operations (UTF-8 validity as a claim).

## The fourth: a call into ∅, and a host's product (ADR 0090, 2026-11-03)

The last templates but one were there because the language could not say two things. Both are
universal properties:
- **∅ is the initial object**: there is exactly one arrow 0 → Y for every Y, so a call h : A → ∅
  satisfies k ∘ h = h for every continuation k. The compiler knew this of one name, `abandon`, in the
  reducer, the checker, lowering and the verifier; it now knows it of every declaration whose result is
  ∅, a set the surface writes `∅` or `\emptyset` (settypes-research §1 had named it the type of
  `abandon`'s value). `llvm.trap() (∅)` and `kernel32.ExitProcess(n) (∅)` are declared as they are.
- **a product is determined by its projections**: a host operation into B₁ × B₂ answers LLVM's
  aggregate `{ρB₁, ρB₂}`, and the printer binds each result to `extractvalue j`. The overflow
  intrinsics are declared as they are, W × W → W × 𝔹, (a, b) ↦ (the residue of ℤ's result, whether it
  left the word).

So the checked arithmetic, `<<`'s checked form, `trap_if` and the crash are terms:

    fn add_checked(a ∈ Int, b ∈ Int) (Int) { (s, o) = llvm.sadd_with_overflow(a, b); if o { llvm.trap() } else { s } }

and one template remains, the allocator, whose answer is a pointer as a value (ADR 0084's LLVM part).

Two consequences of the algebra had to be built with it:
- **substitution keeps the site's facts**: the interpretation is a homomorphism, so what was proven of
  f(x) holds of ι(f)(x); the instance's value is ascribed the site's fact met with the word, which a
  trapped operation's result is in wherever it returns. Recomputed on the term alone, the overflow
  intrinsic's result was only the word;
- **legality is the program's**, decided before ι: a realized operation is counted where it stood,
  with its first decision's mode, and a term's own operation only where it is unproven. The first
  build counted after substitution, and map-keys, whose accumulator traps on every target, reported
  everything proven on windows-llvm: its trapped `+` had become a call and a branch.

Measured: a `-checked` loop of products prints 3³⁹ and traps at 3⁴⁰ (exit 132, `ud2`), printing the
intrinsic, its two projections, and `call void @llvm.trap()` then `unreachable`. The agreement check
covers the new terms: each checked form equals ℤ's f(x) where f(x) is in the word and traps everywhere
else, at the domain's edges, the intrinsics and the trap given their stated meanings
(`TestACheckedFormTrapsExactlyOutsideTheWord`); **planted**, the checked `+` with its arms swapped
(`TestACheckedFormTrappingTheWrongWayIsCaught`). The ∅ rule: a branch ending in `llvm.trap()` is typed
by its other arm and prints `unreachable`; **planted**, only `abandon` never returning, which refuses
it (`TestACallIntoTheEmptySetNeverReturns`). All 63 differential cases agree on five targets. The corpus: 5,027 of 5,093 operations, the new
target's 226 of 240. It now leaves one operation fewer unproven than MASM, in fnv64-fold under
`-checked`: a trapped product's result is known to be in the word, which proves the operation after it.
The sieve and merge sort are unchanged (0.66 and 0.35 of MASM).

## What failed first, what it cost

- **The divisor's `where` written `b != 0`**: J's `!=` is D's negation of `==`, which the refinement
  layer reads as an opaque atom, and the limb library's division was refused (big-divmod). The host's
  own `ne(b, 0)` is what Go's target writes as `` `!=`(b, 0) ``.
- **`print_int` proved its indices only through the loop's trip count** (`m` descends by ÷10 from a
  word, so at most 19 steps). The interval domain has that; the obligations at a call do not, and a
  printed value the analysis leaves unbounded (an accumulator under `-checked`) refused the program.
  Rewritten as exactly 19 steps of a counter the guard bounds, every index linear in it.
- **A goal the refinement layer holds as a fact, refused** (product): `0 <= n1 <= 4294967295` with
  both bounds among the known facts, only in a program that also builds a table of tuples. Renaming
  binders and substituting to a fixpoint changed nothing. The cause: the interval route leaves every
  range mark of a program it cannot lower (a table of tuples is one), and the refinement layer read a
  leftover mark as one above the word, refusing it without the facts. Repaired: an in-word mark is
  decided as the interval route would hand it on, its ends a condition the facts prove
  (`emit/requires.go`). `TestARangeMarkTheIntervalsLeftIsDecidedByTheFacts` accepts the guarded call,
  refuses an unguarded one naming the parameter, and with the bug planted refuses the guarded one. Before
  the repair `WriteFile` had been made total to avoid it, which falsified Win32's function as `shl` had
  been falsified; both are undone.
- **The spec said clang makes the `select` itself** (SimplifyCFG). backend-2026-10-26 had measured that
  it does not on the sieve (0.99 against 0.63); the spec was corrected before the printer shipped.
- **An accept that should not have passed review**: ADR 0089's first accept took codecs on
  `windows-llvm` as refused, "no spelling for (shl trap)". Under `-checked` the `shl` inside `<<`'s term
  is unproven there and traps, and its trap form was looked up through `<<`, whose own form is empty
  (a term realizes it), so the lookup skipped it. Fixed (`ir/plan`, the checked form kept), accepted
  again as "now emits"; run by hand, codecs traps where its 64-bit codec leaves the signed word, the
  unsigned word being what the case's skip on Windows waits for.
- **Heredocs ate backslashes** four times (Go strings, a batch line, two LLVM helpers in J strings);
  repaired with the Edit tool.

## What was not built

- MASM's retirement (§9 item 4), and the programs naming x86 (`examples/native/sieve-win-bench.oro`,
  `lib/win/fmt.oro`) not yet ported.
- Σ_LLVM beyond the integer instructions (§9 item 3); doubles, the unsigned word, `restrict`, a call
  with several results, `noalias`, the narrow scalar widths, 32-bit.
- **The four older targets restated** with `realize` (ADR 0088): they are found by spelling, and
  agree with the language as they are; each when next touched, MASM never.
- **The quotient −2⁶³ / −1 decided** (plan item 8).
