# llvm-2026-11-02: `ir/llvm`, the printer, at the windows target's differential parity

Step 6b of the 10-24 plan, its first step ([llvm.md](../../docs/spec/llvm.md) §9 item 1): the printer
of [ADR 0080](../../docs/decisions/0080-the-native-targets-print-llvm-ir.md), specified first, built,
and run on every differential case the MASM target runs. MASM is not retired here; that is §9 item 4.

## The algebra

h_L : IR_P → LLVM IR is correct when it preserves meaning, ⟦h_L(p)⟧ = ⟦p⟧ (Leroy's semantic
preservation). LLVM adds no check: an instruction with a flag is poison outside the domain the flag
asserts (Lee et al., PLDI 2017), so a flag is a claim, and h_L may write one only where the IR proved
it. The IR's proofs are its modes and IR_P's types: `exact` is ℤ's result inside the word (`nsw`); an
operand's proven range gives `nuw` (a + b, a·b with a, b ≥ 0; a − b with 0 ≤ b ≤ lo(a)); an index
proven in [0, len) gives `inbounds`; a π's type holds on its arm (W6, pijustified-2026-11-02).

Control is structured SSA printed as blocks, a join's values as `alloca` slots that mem2reg makes φs
(Cytron et al. 1991; the regions give a reducible graph). A branch whose two arms both continue
computing only operations with no undefined behaviour is one back edge choosing its arguments by
`select`, sound because `select` takes no poison from the operand it does not choose.

A shift is total in ℤ and poison in LLVM past 63; each is the instruction where the count is below 64
and its limit past it, a·2ᵏ = 0 (a is 0 by the obligation) and ⌊a/2ᵏ⌋ ∈ {0, −1}, chosen by `select`.
So `>>` past a count of 63, refused on MASM, is total here (CLAUDE.md's "`>>` past 63 on windows").

## What was built

- **[docs/spec/llvm.md](../../docs/spec/llvm.md)**, the specification: types, the table layout, every
  operation with its flag and the proof it states, templates, control, the function and the entry.
- **`ir/llvm`**, the printer (h_L), read from IR_P and the target alone, like the other four printers;
  wired into `cmd/build`, `cmd/gen` and `cmd/check`'s reprint, and `emit` gains backend `llvm`.
- **`targets/windows-llvm/`**: `llvm.oro` (Σ_LLVM's integer instructions, the language's operators
  found in it by spelling: `+` is `add`, `/` is `sdiv`, `<` is `slt`), `kernel32.oro`, `strings.oro`
  (`string_of` and `++` as helper functions the module defines) and the target file. clang `-O2` on the
  module, MSVC `link`, `-entry:main`, kernel32 only: no C runtime, and every function `"no-builtins"`
  so no loop becomes a call to the runtime's `memcpy`.
- **`lib/win/print.oro`**: printing in the language's own operators over a byte table, where
  `lib/win/fmt.oro` names x86 mnemonics. Every operation of it is proven (39 of 39 in a test program).
- **`emit/winmap.oro`**, the map the language supplies on Windows, ported from x86's mnemonics to the
  language's operators (ADR 0080 item 5), so one source serves both printers.
- The differential runner runs a fifth target, `windows-llvm`, on every case `windows` runs.

## What was measured

- **The differential suite, five targets**: every one of the 43 cases the MASM target runs builds on
  `windows-llvm` and agrees with Go, JavaScript, the JVM and MASM, the 63 cases' `// expect:` answers
  included (`go run run.go`, all cases agree). map-keys declares `-checked` on `windows-llvm` for the
  reason it declares it on `windows`: an accumulator the intervals widen.
- **Speed**, backend-2026-10-26's harness and programs (one IR_P each, one C driver timing the
  generated function in-process, interleaved rounds, one process at a time, two sweeps of 15):

  | median ms, ratio to MASM | MASM (`ir/x86`) | `ir/llvm`, clang `-O2` | the prototype, with `select` |
  |---|---|---|---|
  | sieve | 37.5, 1.00 | **24.3, 0.65** | 24.4, 0.65 |
  | merge sort | 117.2, 1.00 | **42.0, 0.36** | 42.2, 0.36 |

  **Against hand-written MASM** (`gauntlet/windows/sieve.asm`, the same program as a process, 21
  interleaved runs of each whole process): hand-written 52.1 ms, `ir/x86` 48.0 (0.92), **`ir/llvm` 33.1
  (0.64)**, the `ir/llvm` build being `experiments/backend/sieve.oro` with `lib/win/print.oro` printing
  its answer, since `examples/native/sieve-win-bench.oro` names x86's mnemonics.

  The printer is the prototype's speed, which is the measurement ADR 0080 was decided on (0.63 and
  0.35 then, on a machine running slower that day). Every build gives 1,798,400 and 6,689,817,084.
- **The allocator, made to explain itself**: the first printer ran the sieve at 0.72, 10% behind the
  prototype, whose only difference that mattered was the allocator: with `HeapAlloc` and
  `HEAP_ZERO_MEMORY` every round clears the 200 KB table; `VirtualAlloc` hands out pages the system has
  already zeroed (24.6 ms against 27.1, the prototype 24.3). `"no-builtins"` cost nothing (27.5 against
  27.1). `VirtualAlloc` reserves 64 KiB a call, so the allocator chooses by size, from 64 KiB.
- **The printing library** proves every operation it has (39 of 39 with its −2⁶³ clause live, 7 of 7
  loops), and prints 0, 100, −2⁶³, 2⁶³ − 1 and UTF-8 text as the other targets do.
- **The flags' rule** (`TestAFlagIsTheIRsProof`): `nuw nsw`, `nsw` alone, and no flag on a wrapping
  operation, each where the IR's facts say; a witness reads every printed flag back against the IR's
  modes and ranges. **Planted** (`TestAFlagWithoutItsProofIsCaught`): `nuw` on every proven add and
  sub, which the witness refuses. Printed twice, one text.
- **`-checked`'s `neg`**: an unproven negation printed `sub nsw` before it had a checked form (an
  unproven operation with none keeps mode `exact`, ir/decide.go), a flag without its proof. It now
  traps through `llvm.ssub.with.overflow`; the proven `0 − n` of `print_int` keeps its `nsw`.

- **The corpus** (`cmd/check`, accepted): `windows-llvm` joins the emission sweep, so every source is
  emitted or refused on it and reprinted from its IR text byte for byte; no existing source × target
  changed, `emit/winmap.oro`'s port included, so MASM's emission is byte-identical. The counts become
  **5,023 of 5,090** operations and **557 of 580** loops, the new target's 222 of 237 and 55 of 55: it
  leaves unproven exactly the 15 operations MASM does, in the same four differential cases. Compile
  time 1.02× the baseline.

## What failed first, what it cost

- **The divisor's `where` written `b != 0`**: J's `!=` is D's negation of `==`, which the refinement
  layer reads as an opaque atom, and the limb library's division was refused (big-divmod). The host's
  own `ne(b, 0)` is what Go's target writes as `` `!=`(b, 0) ``.
- **`print_int` proved its indices only through the loop's trip count** (`m` descends by ÷10 from a
  word, so at most 19 steps). The interval domain has that; the obligations at a call do not, and a
  printed value the analysis leaves unbounded (an accumulator under `-checked`) refused the program.
  Rewritten as exactly 19 steps of a counter the guard bounds, every index linear in it.
- **A goal the refinement layer holds as a fact, refused** (product): `0 <= len(u)` was not proven
  with `-len(u) <= 0` among the known facts, only in a program that also builds a table of tuples;
  renaming every binder changed nothing. Not repaired here: flagged as its own task. `WriteFile` was
  made total instead, checking its segment at run time and answering false outside it, as Win32
  answers FALSE for arguments it refuses, which is the honest binding of a host limit (a DWORD count)
  anyway.
- **The spec said clang makes the `select` itself** (SimplifyCFG). backend-2026-10-26 had measured that
  it does not on the sieve (0.99 against 0.63); the spec was corrected before the printer shipped.
- **Heredocs ate backslashes** four times (Go strings, a batch line, two LLVM helpers in J strings);
  repaired with the Edit tool.

## What was not built

- MASM's retirement (§9 item 4), and the programs naming x86 (`examples/native/sieve-win-bench.oro`,
  `lib/win/fmt.oro`) not yet ported.
- Σ_LLVM beyond the integer instructions (§9 item 3); doubles, the unsigned word, `restrict`, a call
  with several results, `noalias`, the narrow scalar widths, 32-bit.
- **`<<` under `-checked`** has no checked form: an unproven shift wraps, as it does on every target
  (ir/decide.go keeps an unproven operation with no checked form `exact`); its template prints no flag,
  so it is not poison.
