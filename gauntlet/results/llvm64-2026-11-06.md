## The algebra

**U₆₄ = [0, 2⁶⁴) is `i64` read unsigned** (ADR 0083's (H, d): H the 64 bits, d their unsigned
reading; llvm.md §3a). An `i64` has no sign; a reading gives it one. The residue map
r : ℤ → ℤ/2⁶⁴ is a ring homomorphism, and the bitwise operations act on the bits, so under either
reading `add sub mul and or xor shl` are one instruction each: where the result is proven inside U,
that instruction computes ℤ's answer. Order, the quotient, the remainder and the right shift do not
commute with r: 2⁶³ < 1 is false in ℤ and true in S₆₄'s reading of the same bits. So these four are
U's own instructions, `icmp ult ule ugt uge`, `udiv`, `urem` and `lshr`. On [0, 2⁶³) the two readings
agree, so a value moves between S₆₄ and U₆₄ as its bits (`u_of` and `int_of_u` print nothing).

On LLVM, ℤ/2⁶⁴'s shift by k ≥ 64 is 0, while `shl` and `lshr` past 63 are poison. So `u64<<` and
`u64>>` are terms over the instructions (ADR 0089), as `<<` is: `if b <= 63 { llvm.u_shl(a, b) } else
{ llvm.u_of(0) }`.

**A comparison the facts decide is its truth value.** The representation pass refused any order
between a U value and a value that may be negative, since no one word holds both. But x < c with
x ∈ [0, 2⁶⁴) and c < 0 needs no word: it is false for every x. Let I(x) and I(y) be the operands'
intervals. If every element of I(x) is below every element of I(y), then x < y is true; if every
element of I(y) is at most every element of I(x), it is false; otherwise it is undecided. ≤, >, ≥, =
and ≠ follow by the same order on the ends (`decided`, ir/words.go). A decided comparison is replaced
by its constant. This is the rule for an operation whose value the facts determine, so it moves no
answer.

**Then its πs go** (Theorem E, spec/ir.md §6). A π states a literal that its arm's guard implies. A
constant guard, or a connective over one, implies no literal about the operands, though the facts
make it true. So a branch on a decided guard loses its πs. So does every π whose (Of, Other) are a
decided comparison's operands, which is the literal one side of a `||` states. A π is a renaming with
a fact: its uses become what it renamed, and a fact dropped only weakens.

**render : ℤ → Σ\*.** `lib/win/print`'s `print_int` claimed −2⁶³..2⁶³−1 and was exported, so it was
compiled once, at the signed word. render is defined on every integer, so its header now claims ℤ
(`n ∈ Int`), which has no end to enforce, and it is no longer an entry point. It is inlined at each
call, where the facts choose ρ (ADR 0079): S₆₄ at most calls, U₆₄ at a 64-bit hash, where its sign
tests are decided false. A value of either word has at most 20 decimal digits (2⁶⁴ − 1 has 20), so
the loop takes 20 steps where it took 19.

## What failed first

- **Three cases had skipped the JVM since October for nothing.** Their comments said its unsigned
  word was not built, and it had been since bits-2026-10-27. A skip is a path nothing runs, and
  nothing checks that a skip's reason is still true; these were found only because windows' half of
  the same reason was being lifted.
- **The old refusal test pinned a refusal that was not needed.** x > y with y ∈ [−6, 6] is true for
  every n, and the test asserted it was refused. It failed when the rule went in, as it should have,
  and now states the premise that makes a refusal true.
- **fnv64's probe met three refusals in turn:**
  1. print_int's sign test against a U value: the decided comparison;
  2. the exported print_int's header, a hull of the two words, −2⁶³..2⁶⁴−1, "admits negative
     values" above the word: render claims ℤ and is inlined;
  3. W6 on the πs of the folded guard: `dropDecidedPis`.
- **The rule first fired on every decided comparison**, U or not. In `codecs`' `write`, inside a
  `||`, it folded a comparison of n ∈ [2, ∞) and left the other side's πs stating it: W6. It is the
  representation pass's rule, so it now fires only where a U value is involved, which is where the pass
  would refuse. πs are dropped by operand pair as well as by guard.
- **`codecs` traps on windows.** print_int is inlined five times into main, and the result is so many
  constants that the intervals' 16 threshold rounds end before `top` descends to its bound. Plain
  widening then loses it: 22 − start is unbounded, and 5 of 337 operations go unproven. With 32 rounds
  all 337 are proven (tried, then reverted). The fix is per-loop thresholds, an analysis change that
  waits for a second program to name it. The case says `checked: windows` with that reason, and the
  differential confirms that a trap is taken there.
