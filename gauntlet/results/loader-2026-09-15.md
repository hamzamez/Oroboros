# The loader, target half: a file is the glue of its forms, and the translation was a commuting square

2026-09-15. [theories.md §9](../../docs/spec/theories.md)'s first build, for target layers and
`provides`. hamza: *"be mathematical and algebraic about everything you do. If you do it right, the
code may get smaller and clearer."* It got clearer. It did not get smaller, and §5 says by how much
and why.

## 1. Loading a file was not a homomorphism

A layer is the glue ⊔ of its fragments (target-system.md §2). A file is a sequence of forms, and
sequences are the free monoid under concatenation. So there is exactly one reading of a file that
agrees with the reading of a directory, the monoid homomorphism

```
load(F₁ ++ F₂) = load(F₁) ⊔ load(F₂)
```

and its consequence is the property every target author assumes without knowing it: **splitting a
file in two, or merging two, changes nothing.**

`parseTarget` assigned fields as it read them. Measured with `TestSplittingAFileChangesNothing`,
fifteen pairs of forms each loaded as one file and as two files of one directory:

| | one file | two files |
|---|---|---|
| two different `(array-type …)`, `(map-type …)`, `(type t …)`, `(boxed int …)`, `(narrow …)`, `(max-len …)`, `(shift-width …)`, `(big-repr …)`, `(build …)` | **the second silently wins** | refused |
| two different `(prim f …)` | refused | refused |
| agreeing or ordered forms (`type` twice alike, `int-repr`, `link`, `implements`, two prims) | loads | loads, identical |

**9 of 15 failed against HEAD.** A file boundary changed the meaning of a target.

The fix is the homomorphism itself: each form elaborates to a fragment and `merge` folds them, so
a file is glued exactly as a directory is. It removed the per-form duplicate checks too, since glue
already refuses a repeated primitive. All 15 pass.

It has a second consequence the spec now uses: **a form inside the header's parentheses and the
same form after them are the same fragment**, so a target file may put its declarations after
`(target NAME …)` or inside it (`TestFormsAfterTheHeaderAreTheSameFragment`). There is no layout rule
to state.

## 2. The translation was checked as a commuting square

Let P read the old forms, E read theories.md §8's, and T translate old text to new. The translation
is correct exactly when

```
E ∘ T = P
```

on every file. `cmd/retarget` was T: a text rewrite, because the reader erases `and`, `cond` and
comments, so printing a term cannot give a target author their file back. Each moved clause
carries the whitespace and comments before it.

Its test loaded every target in `targets/`, with `lib/` as the library layer, through
`LoadTargetLayers` before and after translating a copy of both trees, and required
`reflect.DeepEqual` targets: whole models after glue, override and the core's injection, not
fragments. It also required T to be a **projection**, T ∘ T = T, so a translated file holds no old
form.

**It passed on the first run, so it was made to fail**: with the translator planted to drop every
sig clause, it failed on `blas` (`aindex` lost `pure`) and on `go` (`fmt.Sprintf` lost `pure`), and
passed again restored.

| translated | forms | files |
|---|---|---|
| `targets/` | 1,017 | 29 |
| `lib/` (`provides`) | 27 | 6 |
| Go tests, inline targets | 42 by the tool, 5 literals by hand (concatenated strings the tool could not read as whole forms) | 11 |
| generators: `survey.go`, `win32.go`, `jvm.go`, `js.go` | every emitted `prim` and `type` line | 4 |

Then the old forms were deleted and `cmd/retarget` with them: once the repository is translated
the square has no inputs.

**One bug in T, caught before it mattered.** `go/scanner` strips carriage returns from a raw string
literal, and this checkout is CRLF, so replacing `len(lit)` bytes left each literal's tail behind —
`…(host expr "io.ReadAll(%s)"))))`l(%s)")))` — and `portable_test.go` stopped compiling. A raw
literal's span is now read from the source.

## 3. What the new forms are

```lisp
(sig NAME (param…) result sclause… (host KIND "template" hclause…))
(type NAME (host "spelling"))    (type (array A) (host "[]%s"))    (type (map K V) (host "…"))
(repr (int LO HI) (host "s"))    (repr (ref T) (host "s"))    (repr big host|limbs)
(repr map host|library)          (repr shift N)               (repr narrow (host "…"))
(fact NAME ((a (array A))) (<= (len a) N))
```

**A `sig` makes two kinds of claim and the `host` clause is where they part.** `pure`, `index`,
`where`, `ensures`, `length` and `length-of` are about what the operation means; `import`, `lib`,
`checked` and `jump` are text for, or facts about, one host. A host word outside `(host …)` and a
sig word inside it are refused, and so is a sig with no host clause in a target file: a target
realizes declarations, and one with no realization belongs in a module. That is what makes
*"no host clause"* a checkable portability property later.

The old words are refused naming the new spelling (`(int-repr …) is spelled (repr (int LO HI)
(host "spelling"))`), not kept as aliases, for data.md §10's reason.

`(repr …)` and `(fact …)` are refused off their shapes. Facts are specified and not built, so
`max-len`'s shape is the one fact a target may state, and any other is refused rather than read as
it. `()` is now a legal parameter list after `sig NAME`, as it already was after `fn`.

## 4. Three defects fixed on the way

**`builtin-map` could be turned on and never off.** Two fragments combined as `a || b`, a join on
`false < true`, not override. It is now `Target.MapRepr`, a word composed by `combineOne`, so a
nearer `(repr map host)` wins (`TestANearerLayerCanTurnTheLibraryMapOff`; HEAD had no spelling for
the override at all).

**A library's broken declaration vanished.** `loadProvides` skipped every form that was not a
`prim` and ended a file's walk on the first declaration error, returning success, so a native fast
path could disappear from a build with no diagnostic (theories.md §10.1, D1). Errors now propagate
(`TestABrokenProvidesIsRefusedNotDropped`).

**`go vet ./...` failed on the last commit.** `cmd/check`'s baseline put one emitted Go file per
program under `gauntlet/check/emitted/`, all `package main`, which the go tool read as one package
with a hundred `GenMain`s (`vet.exe: gauntlet\check\emitted\examples_io_freq.go.go:8:6: GenMain
redeclared in this block`, the first run of this session). The baseline moved to
`gauntlet/check/testdata/emitted/`, which the go tool never builds.

## 5. Size

| `emit/target.go` | lines | code lines (no blank, no comment) |
|---|---|---|
| HEAD | 3,676 | 2,184 |
| now | 3,850 | 2,313 |

**+129 lines of code.** The old per-form cases went (about 60 lines), and the new front end is
larger than what it replaced because it checks more: that a sig's claims are in the right clause,
that a sig has a host clause, that a fact has the one admitted shape, and it carries a table naming
every respelled form. The homomorphism removed the duplicate checks and fixed a real inconsistency,
but it is a clarity result, not a size one. The place size can come from is where both front ends
still exist in spirit: `primOf` still reads a positional attribute list, and the program side's
`sig` reader in `core/read.go` parses the same parameter grammar separately.

## 6. Cost

`go run ./cmd/check`, every step: vet, compiler, differential (four targets) and tooling (all
surveys twice, thirteen acceptance programs, the hand declarations against the host) **pass**.
Emission: **194 of 194 emitted files byte-identical** across 456 source × target runs, and the proof
counts identical — 2,307 of 2,413 integer operations bounded and 345 of 382 loops proven, as in the
baseline.

The 18 changes the check reported were all one line of compiler output: the six `lib/io` and
`lib/os` library files, which the sweep hands to `gen` as sources and which are refused because a
`provides` file is not a target, now say *"a target file begins with (target NAME …)"* where they
said *"expected (target NAME …)"*. Same refusal of the same inputs, accepted into the baseline with
that reason.

## 7. Not done, and named

- **The program half** of §9: `type`, `variant`, `const` and `use`'s paths in modules, into
  `core.Module`.
- **A range on a target `sig`'s parameter is not a premise, and on a program's it is.** A program
  sig desugars `(n (int 0 9))` into a `where`, and a target sig keeps it only as a type, which is
  what `prim` did. §8.2 says a sig with a host clause *is* what prim was, so the two readings of the
  same parameter should agree; making them agree adds call-site obligations to every hand
  declaration with a ranged parameter and wants its own measurement.
- **`length` and `length-of`** stay sig clauses until pure-call `ensures` can say them (§8.4, gated).
- The survey reports still print *"declarable as a (prim …)"*; the label is pinned by the tooling
  suite and was left alone.
