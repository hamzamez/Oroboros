# localtab-2026-10-14 — a filled table's length, and a table nothing stores into

Two gaps with `local` tables, found on 2026-10-14 and present at 32d5134 and later. Neither is
new with `local`: `(table n f)` is reader sugar for `build` (local.md §1), and both gaps are in what
the compiler does with `build`'s core form.

## 1. What failed first

**A table filled with a nonzero value had no length.**

```lisp
(use go) (export f)
(sig f ((n (int 1 100))) int)
(def f (n) (let src (local s (table (+ n 1) 7) s) (src n)))
```

was refused: *(src n) is an indexing, and (< n (len src)) does not follow*. The same program with
`(table (+ n 1) 0)` was proven. The two read differently. The zero fill is `build`'s core form with
the size inline, `(build (+ n 1) (fn (s) s))`. A fill uses the size twice, as the length and as the
fill loop's bound, so the reader binds it:

```
(let (+ n 1) (fn (#n) (build #n (fn (s) (loop (fn (#i s1) …) 0 s)))))
```

The length abstraction (`valueLength`) read `build`'s count as written, `#n`, and returned a linear
form naming a binder of the value. `(let src V …)` then assumed `len src = #n` in src's scope, where
nothing constrains `#n`.

**That was also unsound, which the report did not show.** The reader spells every fill's binder
`#n`, and ADR 0036 names binders apart only along the scope chain, so siblings keep a spelling. Two
filled tables' lengths were then one variable:

```lisp
(use go) (export f)
(sig f ((n (int 1 100)) (k (int 0 1000))) int)
(def f (n k)
  (let src (local s (table (+ n 1) 7) s)
       dst (local d (table (+ n 5) 7) d)
    (if (< k (len dst)) (src k) 0)))
```

was **accepted**. It reads src, n + 1 long, under a guard against dst, n + 5 long. Built on Go and
run at n = 1, k = 5: `panic: runtime error: index out of range [5] with length 2`. Go checks the
index; JavaScript and x86 do not, and an unproven index there was `undefined` from an `int` function
or a read past the table (noprop-2026-09-25). Only Go was run.

**A zero-filled table that is never written failed the verifier.**

```lisp
(use go) (export f)
(sig f ((n (int 1 100))) int)
(def f (n) (let src (local s (table (+ n 1) 0) s) (src n)))
```

`gen` printed *IR_P does not verify: W9: %11's type array any is not final*. The IR types by
unification (`ir/typing.go`), and the table's element had no constraint: no store, and a read whose
only destination is the function's result, which carried no equation ("the function's own results
carry no equation"). The same happened at every declared result (`f64`, `bool`), and with `(len src)`
as the only use, where nothing at all fixes the element. `(table n false)` failed too: its sort
ascription is read by the type checker and erased before the IR (`KeepSortAscriptions`).

## 2. What was built

**The length abstraction closes a count over the value's binders** (refinements.md §5b, *A length
names no binder of its value*; `lenEnv` in `emit/refine.go`):

```
λ(let e (fn (y) b))  =  λ(b)[y := ē]     ē: e with the binders of V above it replaced, when linear
λ(V)                 undefined           when a count names a binder of V with no such value
```

It is sound by β: y's value is e, a linear term is pure and e is evaluated where y is bound. ē names
no binder of V, so it denotes the same integer where the value is used. The environment
`valueLength`, `threadLengths` and `againDisagrees` share is now a `lenEnv`: each inside binder's
length, as before, and its value when linear.

**The IR's typing** (spec/ir.md §2.2, types.md §3.1, local.md §1):
- **the declared result is a demand** on each yield, σ ≤ ω, met last with the primitives' parameter
  demands, filling only what is still unknown. A yield flows into the result as an argument flows into
  a parameter. The signature already typed a yielded zero (`settleZeros`) and overrode a declared
  table result after typing; now it also reaches what the yield was computed from;
- **a zero-filled element that nothing fixes is the integer.** No store writes the buffer and no
  demand reaches a read of it, so no element is observed at any sort, and every choice gives the same
  observations. The one chosen is the sort the literal names. This is defaulting an unconstrained type
  variable (the Haskell Report §4.3.4), the rule `settleZeros` already applied to a slot's zero;
- **a value still `any` on a target that types its values is refused in words** at the end of the
  step to IR_P (`untypedValue`, `ir/final.go`), naming its operation, before W9 says it by number, as
  a parameter nothing types already was. The one shape known to reach it is a map built and never
  written or read: *cannot determine a type for the value of (build-map …), of type map any any*.

What the four programs now print on Go: the first two compile, `make([]byte, v10)` with the zero fill's
range; the escape witness is refused, *(src k) is an indexing, and (< k (len src)) does not follow*;
`f64` and `bool` results give `make([]float64, …)` and `make([]bool, …)`.

## 3. Tests, and the faults they catch

| rule | test | planted fault, and what it does |
|---|---|---|
| a filled table's length is its size | `TestAFilledTableHasItsSizeAsLength` (emit) | fills 0, 7 and a rule: `(src n)` proven, `(src (+ n 1))` refused |
| a count is closed over the value's binders | `TestALengthNamesNoBinderOfItsValue` (emit) | `plantLenEscapeFault`, the count read as written: the escape witness is accepted again |
| the declared result is a demand | `TestATableNothingStoresIsTyped` (ir), on Go and Java | `plantResultDemandFault`: `f64` and `bool` reads fail again |
| a zero-filled element defaults to the integer | the same test | `plantZeroFillFault`: `(len src)` fails again; with both faults, the `int` read |
| an untyped value is refused in words | `TestAValueNothingTypesIsRefusedInWords` (ir) | the map, and the zero-fill fault, refused by name and not by W9 |

The `int` read is typed by either rule, so only both faults together lose it.

## 4. The check

`go run ./cmd/check -skip tooling` passes every step. **Emission is byte-identical**: 556 runs, 300
emitted and 256 refused with the same refusal text, 2,039 of 2,084 integer operations bounded and
351 of 369 loops proven, as before. No program in the corpus had either shape: no filled table whose
length decided an index, and no table its program neither stores into nor reads at a sort. The IR step
lowers and verifies all 300, and the differential suite passes on four targets.

The sweep's median compile time read 1.16× the baseline's on the first run and 1.25× on the second,
with another session's tests running on the same machine. No compile was flagged by the rule
(1.5× and 250 ms). The drift was paired anyway: `gen` built at be8bd22 in its own worktree against
this branch's, five interleaved serial compiles each at `GOMAXPROCS=1`, in ms:

## 5. What was not built

- **A differential case.** The harness calls `run` with literals and inlines it, so `(+ n 1)` folds
  and no `#n` binder remains. Arithmetic on a read fixes its element, and printing one demands it.
  Neither gap is reachable from the suite's shape, so the witnesses are unit tests on the pipeline.
- **A map's key fixed by the language.** `(map int V)` is the only map type (maps.md), so an unused
  map's key could be `int` by definition. Its value has no zero to default to, since a read gives an
  option. The map is refused in words, and no program builds a map it never uses.
- **An audit of every rule that reads a value's internals into facts about its binder.** `joinConditional`
  already excludes the value's binders from its templates (§5a). `valueLength` was the one that did
  not, and this round audited no other.
- **The facts.md census row S5** still cites `valueLength` by a stale line number, as every row
  there does.
