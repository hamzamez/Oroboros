## 1. The algebra

- **A directory tree is a finite rooted tree.** `os.ReadDir` lists a node's children in name order. A
  symbolic link is a leaf: its entry is not followed, and `DirEntry.Info` describes the link itself,
  as `Lstat` does.
- **`ls -R` is the depth-first pre-order over directories.** Each directory's listing is printed whole
  before its first subdirectory is entered.
- **A line is a function of one FileInfo**: `Mode`, `Size` and the rendered time. The program prints
  `MODE SIZE YYYY-MM-DD HH:MM NAME` and nothing Go's portable FileInfo does not hold: no `total`, no
  owners, no link counts.
- **The time is `t.UTC().Format(L)`.** `UTC` is the projection onto the UTC presentation. It keeps the
  instant, so it is idempotent and `t.UTC()` is `Equal` to `t`. `Format` is a rendering of the
  presented fields through the reference layout. The composite is therefore constant on each
  `Equal`-class: the output depends on the instant alone, not on the machine's time zone. This is
  why the acceptance case can compare text.
- **`FileMode.String` renders the type bits, then the nine permission bits** (`drwxr-xr-x`, `-rw-r--r--`,
  `Lrwxrwxrwx`). It is a function of the mode, so it is `pure`.

## 2. The program

`examples/os/ls.oro`: 60 lines of J, 31 lines of header comment.

- **No recursion (ADR 0014).** The pre-order's frontier is a stack of waiting paths in a buffer of
  `cap = 4096`, written in program order (ADR 0052): `stk[sp] := filepath.Join(dir, …)`.
  - A directory's subdirectories are pushed **last first**, so the first is popped first.
  - One loop over a cursor does both halves of a listing. In phase 0 it prints the entries forward;
    in phase 1 it walks them backward, pushing the subdirectories.
  - A directory found while the stack is full is listed, not entered, and counted.
- **Counters saturate, as in `du`.** `sat(x, y) = min(x + y, C)` on ℕ_C, with C = 2⁶² − 1. Each
  operand is in the set, so the sum is inside the word, and that bound is one the interval
  analysis can see.
- **Failures are values.**
  - An entry gone between the listing and its Info prints `?` and its name; the error is relevant,
    so it is `ignore`d explicitly (ADR 0043).
  - A directory it cannot read is listed as far as `ReadDir` got (a partial success, ADR 0044) and
    counted. The count is reported at the end.
  - A root that does not exist prints `ls: ` and the error.
- **Proofs.** 13 of 13 operations and 1 of 2 loops. The unproven loop is the walk, as in `du`: its
  length depends on the file system, which nothing in the program bounds.
- **Go only, as `du` is.** It is refused on JavaScript, Java and Windows with
  `` `go/io/fs/DirEntry`.Info is not bound ``, which is true: it calls Go's packages by name.

## 3. The declarations

- `targets/go/time.oro`, new. It declares `set Time = host "time.Time"`, `Time.UTC` and
  `Time.Format(layout ∈ bytestring) (bytestring)`. Its header states the algebra above, read off
  `src/time/time.go` and `src/time/format.go`, and lists what is not declared, each item work and

- `targets/go/os.oro`: `os.Lstat(name) (result(fs.FileInfo, error))`, Lstat-like as `DirEntry.Info`

- **Each is checked against the host** by `TestHandDeclarationsAgreeWithTheHost`. `time.oro` has its
  own planted mistakes, each caught: `Format` returning an integer, `UTC` returning a string, and a
  template naming `time` with no import.

## 4. What failed first: the survey

The hand check refused `os.Lstat`'s result `fs.FileInfo`: the survey generated `os.Lstat` returning
`os.FileInfo`, a type it did not relate to `fs.FileInfo`. The declaration was right and the checker
was wrong, twice.

1. **An alias was a type of its own.** Since Go 1.16 the manifest says `type FileInfo = fs.FileInfo`
   in package `os`, an alias declaration: a second name for one type. The survey read the line as a
   type and ignored the `=`. Any function listed once with the alias's spelling, like
   `func Lstat(string) (FileInfo, error)`, which go1.txt states and no later manifest re-lists,
   returned a type that `fs.FileInfo`'s methods could not take. Now `survey.go` records every alias
   before anything is spelled, and `qual` resolves a qualified name through the chain.
2. **The manifests were read in lexical order.** `filepath.Glob` gives `go1.16.txt` before
   `go1.2.txt`, and `go1.txt`, the oldest, last of all, so "the last spelling wins" was not "the
   newest wins". go1's `type FileInfo interface {…}` overrode go1.16's alias, which is why the first
   fix changed nothing. Now the files are sorted by release (`apiVersion`: go1.txt is 0, go1.N.txt
   is N).
   - **The same order was wrong in two other readers.** `coverage.go` keeps a name's first spelling
     and `tooling_test.go`'s `manifestFuncs` its last. Both now read in release order and keep the
     newest spelling. No count moved in either (§4's coverage figure); only the spelling shown.
   - `callbacks.go` and `generics.go` collect lines as sets, so order does not matter to them.
