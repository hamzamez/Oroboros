# mapbuf-2026-10-16 — a map buffer in program order (ADR 0058), behind the gate

ADR 0058 extends ADR 0052 from tables to maps: a map buffer is a state binder whose value is a map,
written in program order, `var m := map(8)`, `m[k] := v`. Built on storeorder-2026-10-15's machinery;
every buffer J writes, table or map, now has one form.

## 1. The algebra

A map buffer's value is a finite partial function K ⇀ V of a declared capacity. `insert` is McCarthy's
store on it, with the same two axioms as `set` on a table; a read gives `option` where a table's is
total. The discipline is about aliasing, which does not care what the index set is (maps.md §3.3), so
R0–R4, the state translation S and unthreading U carry over unchanged, and the element write's
equation is the table's with the store renamed: `m[k] := e` ≝ `m := insert(m, k, e)`.

Only the scope knows the index set, so a map buffer's place scope has its own mark,
`(#mapplace m (fn (m) …))`, inside build-map's region, and S picks `insert` there where it picks `set` in
a table's (`core/cell.go`). D writes the element write one way for both.

## 3. Planted fault

S storing into a map with `set` instead of `insert` fails
`TestABufferInProgramOrderMeansTheThreadedBuffer/a map buffer's store` and nothing else. A map's R1
refusal (`d = m`) joins `TestEachRuleOfAPlaceRefusesWhatItForbids`.

## 4. Not built

A borrowed map parameter, `fn f(m ∈ Map(K, V) linear)`: no program lends a map, and U infers a borrow
only from a definition that stores into its parameter, which no definition over a map does.
