# A record or tuple as a map's value (ADR 0128 item 7, the third lifted position)

2026-11-18. hamza: "go ahead with the product as a map's value". The last piece of ADR 0128's step 1,
records-2026-11-17 §4's first "not built": `m[1] := record {…}` then `case m[1] { 'some(r) -> r.x }`
was refused on every target, and so was the same program with a tuple.

## 1. What it is

A map is a partial function m : K ⇀ V, and for V = V₁ × … × Vₙ its value at a key is n components.
data.md §3.3 decided where they are held: "its components' cells (ADR 0120 on LLVM), the host's
struct value elsewhere". A table of products is flattened into ordinary tables before any backend
reads it (products.md). A map is not flattened that way. Two alternatives were set aside:
- the iso Map(K, A × B) ≅ {(f, g) ∈ Map(K, A) × Map(K, B) : dom f = dom g}, which would probe n
  times and store each key n times;
- a flat key k·n + j, which is not even total, since n·k leaves the word.

The host's own map holds the struct where hand-written code puts one.

So **the IR says so directly**:
- `insert m k v₁ … vₙ` stores the components;
- `read m k` yields the option's tag and n slots (ADR 0042), one result per component;
- the map's type is `(map K (prod V₁ … Vₙ))`, and the verifier checks each read and insert against
  it (W4, `mapSlots`).

## 2. What failed first, and what each was

1. **Lowering**: `(10, 20) is 2 values where one is wanted`. Lowering binds one value per name, and
   a read's eliminator had exactly two, `(fn (#t #p) …)`. Built: `emit/mapprod.go`, run at `ir.Lower`'s
   start, so every path to the IR passes through it, after the checker has read the tuples:
   - an insert of a tuple becomes an n-ary insert;
   - a read's payload binder becomes n slots, `#p·0 … #p·n−1`, named in a way no program can write,
     so lowering tells them from a tuple bound to n + 1 names;
   - the payload is replaced by the tuple of its slots, and each destructuring `(p (fn (x…) M))` is
     β-reduced in place;
   - a map's arity is read off its inserts, followed through every let and loop that holds a version
     of it, and through a contract mark, whose value is its body's.
2. **A record's projection `r.x` in a case arm**: *r is not imported*. Case expansion substitutes the
   pattern's binder, `r` ↦ `#p`, and `r.x` is one name token, which the substitution did not touch.
   It then reached resolution as a qualified name. Fixed in `renameFree`: a projection of a renamed
   binder is renamed with it, which is ADR 0128 item 3's binder rule (the binder decides what a.b
   is). This is a records fault, independent of maps: any case arm projecting its pattern variable
   met it.
3. **The record erasure** (`core/recerase.go`): *the projection x reads a term whose record labels
   are not known*. Three rules added beside the table's:
   - `insert` and `build-map` as `set` and `build`;
   - a read under its eliminator teaches its payload the map's element shape;
   - a contract mark's shape is its body's (an insert carries its capacity's `where`, ADR 0121).

   Then the payload's leaf projections `(#p j)` reached the refinement layer as a table's indexing.
   So the erasure takes a record payload apart once at the arm's head, as `(a, b) = p` takes a tuple
   apart, and each projection becomes the j-th name.
4. **The JVM's built program**: `javac` could not find the record class. `cmd/build`'s `Main.java`
   never wrote the records shared by shape, which only `gen`'s `JavaFile` wrote. Fixed in the build:
   any built program needing a record had this fault, a map's value only the first.
5. **windows**: the map is a table of 3-cell slots (ADR 0120), fixed at one `Int` value. Built:
   `lang.oro`'s `mapw_*`, a slot of s = 2 + w cells (flag, key, w components), with abstraction
   d(t) = {(t[s·i + 1], (t[s·i + 2], …)) : t[s·i] = 1}; w = 1 is the old map.
   - **insert** is `mapw_claim` (the key's slot and its first component's cell) and w guarded stores;
   - **read** is `mapw_find`, the tag, and w guarded loads;
   - **len** and **keys** are at stride s.

   `ir/maps.go` writes these for the program's w from the instances, each decided once (ADR 0101).
   The scalar map's terms are untouched, so no existing program's text changed. `mapw_claim`
   declares no result, as `map_put`: an instance with a lent table yields its version and its value,
   and a declared result counted one.

**A map literal of products** is the map its inserts build, `map {k₁ : v₁, …} =
build-map(c){m. insert(…)}`, rewritten by the same pass, so every printer and windows' realization
apply unchanged.

## 5. Found, not built

- **A header's declared `Map(K, A × B)`**, a set a definition's parameter would claim, is still
  refused by the reader as no type (`TestAProductIsAnElementTypeAndNothingElse` pins it). A
  definition taking such a map unclaimed is inlined and works.
- **A hull per component**: the intervals keep one hull for every slot, the diagonal's join of the
  product of their lattices. That is sound and coarser, and waits on a program it refuses.
- **A map literal read at a run-time key inside a host call's argument on windows** is refused at
  lowering, *an application whose operator is an application*. This predates the step: a scalar
  literal fails the same way on HEAD.
- **The capacity facts** prove `len(m) < c` only for one insert arm whose index bounds `len`
  (`map-dynamic`'s shape). Two inserts in one iteration, or an insert in an arm guarded by
  k = n + 1, are refused for scalar values too, on HEAD. The cases were written in `map-dynamic`'s
  shape, the overwrite from repeated keys. This is the capacity item CLAUDE.md lists as owed.
- **`len(m)` on Go is unbounded** in arithmetic, `len(m) * 10` refused: the same owed item.
