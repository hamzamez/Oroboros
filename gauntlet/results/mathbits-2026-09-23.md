# math/bits, declared by hand

2026-09-23. Plan item 3 of [assessment-2026-09-23](../../docs/assessment-2026-09-23.md), first
package. `targets/go/math/bits.oro`, `gauntlet/stdlib/acceptance/math-bits.oro`, and two compiler
changes the acceptance program demanded, each by a named refusal.

It is the package of the words [ADR 0026](../../docs/decisions/0026-an-int-is-an-integer.md) built:
39 of its 55 names take or return a `uint64` or `uint`, which is U on the Go target, held natively.
The package is *supported* in ADR 0022's sense:
- **declared by hand**, from Go 1.27's `bits.go`;
- **checked against the host**, all 55 names, with four planted mistakes each caught;
- **exercised by a program**: 331 lines of output identical to the real package's.

## 1. The algebra

```
W_n = [0, 2^n), n ∈ {8, 16, 32, 64}; `uint` is n = 64 here, so it is U.   x = Σ b_i·2^i uniquely.

MEASURES, each onto [0, n]:
  Len            2^(Len x − 1) ≤ x < 2^(Len x) for x > 0;  Len 0 = 0
  LeadingZeros   n − Len
  TrailingZeros  ν₂(x), the 2-adic valuation;  n at 0
  OnesCount      the Hamming weight;  ≤ Len

PERMUTATIONS of positions, bijections W_n → W_n:
  Reverse        i ↦ n−1−i, an involution
  ReverseBytes   the same on bytes, an involution
  RotateLeft     the action of ℤ/n on positions: by a then b is by a + b

THE DOUBLE WORD, W_n × W_n ≅ [0, 2^2n) by (h, l) ↦ h·2^n + l:
  Add(x, y, c) = (s, c′)   s + c′·2^n = x + y + c,       c, c′ ∈ {0, 1}
  Sub(x, y, b) = (d, b′)   d − b′·2^n = x − y − b,       b, b′ ∈ {0, 1}
  Mul(x, y)    = (h, l)    h·2^n + l  = x·y,             h ≤ 2^n − 2
  Div(h, l, y) = (q, r)    q·y + r    = h·2^n + l,  0 ≤ r < y,   defined iff h < y
  Rem(h, l, y)             (h·2^n + l) mod y,               defined iff y ≥ 1
```

**Read off the source, and declared:**

| claim | where it comes from |
|---|---|
| every measure's range, [0, n] | the definitions |
| a carry-out (or borrow-out) in {0, 1}, narrower than the host's `uint64` | it is `((x & y) \| ((x \| y) &^ sum)) >> 63`, a top bit shifted down |
| a carry-in `≤ 1` | "The carry input must be 0 or 1; otherwise the behavior is undefined" |
| `Mul`'s high word ≤ 2ⁿ − 2 | ⌊(2ⁿ − 1)² / 2ⁿ⌋ = 2ⁿ − 2 |
| `Div`'s precondition **h < y** | the host panics on y = 0 and on y ≤ h. Since h ≥ 0, the one linear inequality excludes both |
| `Div`'s remainder ≤ 2ⁿ − 2 | r < y ≤ 2ⁿ − 1 |
| `Rem`'s precondition y ≥ 1, and **`(ensures (< result y))`** | `Rem64(h, l, y)` is `Div64(h % y, l, y)`'s remainder, so only y = 0 panics. It has one result, so the bound is an `ensures` |

**Not said, and named:**
- **The double-word laws.** Each relates the *components* of a tuple result, and an `ensures` names
  one `result`. The 64-bit ones also carry the coefficient 2⁶⁴, past the linear fragment's int64
  coefficients.
- `Len`'s logarithm, `OnesCount ≤ Len`, and the rotation group law, none of which is linear.

**`uint` is not `uint64` to Go**, though both are 64 bits here. So every `uint` result is converted to
the `uint64` the target holds U in, and every narrow result to Go's `int`.

## 2. The program, and what it met

`gauntlet/stdlib/acceptance/math-bits.oro` checks one law per section:

| section | law |
|---|---|
| measures | at x = 2ᵏ = `RotateLeft64(1, k)`, the rotation of the unit: Len = k+1, TrailingZeros = k, OnesCount = 1, and LeadingZeros + Len = 64 |
| involutions | Reverse ∘ Reverse = id, ReverseBytes ∘ ReverseBytes = id |
| rotation | by 13 then 29 is by 42; by 64 is id; by −13 undoes 13 |
| carries | a two-word sum whose low carry feeds the high Add; Sub with the same borrow undoes Add |
| product | Mul64 then Div64 recovers the factor, remainder 0 |
| long division | a two-word number divided by a word |
| narrow | every 8-, 16-, 32-bit and `uint` form |

**Two sections meet the wall the declaration names, and take it two different ways:**
- **product.** Mul64's high word is < y because x < 2⁶⁴. That is a law of Mul64's tuple, which cannot
  be stated, so the program *guards* `hi < y`, and the unreachable branch is marked as such.
- **long division.** Here no guard is needed. The second step's high word is the first step's
  remainder. Div64's remainder is not said to be < y, but Rem64's is, by its `ensures`. So the
  program takes the chained remainder from `Rem64 0 a1 y`, and the precondition is **proven**. That
  is the remainder law, stated where the language can state it.

**Two refusals, both compiler faults, both fixed:**

1. **A tuple component's range was not a fact.** `Add64 requires c0 ≤ 1 … known: nothing`, on the
   carry chain. A range in a result position is an `ensures` (scalarrange-2026-08-31), and a single
   result's already reached the refinement layer as one. A host call's several results were bound
   with nothing known, so a carry chain, the most basic use of `Add64`, was refused. Now each
   component's statable endpoints are assumed of its binder. `TestATupleComponentsRangeIsAFact`
   checks the chain and still refuses an unbounded carry-in, and it fails when the upper endpoint is
   dropped.
2. **An extra argument to a primitive was silently dropped.** Printing four values with
   `(fmt.Println a b c d)`, against the target's one-argument `Println`, emitted `fmt.Println(a)`.
   Go refused only because the dropped values were unused variables. Had they been expressions, the
   program would have printed less than it said, and no check would have seen it. The type checker
   now applies a primitive to exactly its declared arguments. **No program in the corpus relied on the
   drop**: all 476 compiles are byte-identical. `TestAnExtraArgumentIsRefusedNotDropped` fails without
   the check.

The checker's `rangeWithin` now reads ranges at full precision, because a justified narrowing lies in
U. It still allows a narrowing that is too tight: claiming `Mul64`'s high word ≤ 2⁶⁴ − 3 is inside
the host's type, and that claim is the reader's to justify, which is what the declaration's header
does.

## 3. What is next from it

- **The tuple-law wall**, now demanded twice: `Mul64 → Div64` needs a guard, and `Div64 → Div64`
  needs `Rem64` as a workaround. The general form is an `ensures` over a tuple's components, as in
  `(ensures (< (result 1) y))`, plus coefficients past int64 for the 64-bit double-word laws. Per the
  plan's rule it is named here, and it is built when a program's cost of the workaround is real.
- **The program the plan asks for, one per two packages:** `math/bits` with `strconv` is a 128-bit
  integer written in the language. A multiply by a word is a Mul64/Add64 chain, a divide by a word is
  Div64/Rem64, and decimal output goes through strconv. It is next.
