# Octagons refuted by measurement; a length bound built instead — 2026-08-28

[decidability-map.md](../../docs/decidability-map.md) calls octagons **"the highest-value move
available"**, and three results named a demand for them. Before building an O(n³) domain, every
unproven operation in the corpus was classified by *what fact would settle it*.

**Not one of them needs an octagon.**

---

## 1. The classification

Every unproven integer operation, each program measured against its own target:

| shape | count | the missing fact | octagonal? |
|---|---|---|---|
| `(+ i 1)`, `(+ i 2)` — a counter under a `(>= i (len a))` guard | 24 | an upper bound on `(len a)` | **no** |
| `(- (len a) 2)` | 6 | the same | **no** |
| `(+ (/ a b) (% a b))` | 2 | a declared range on the parameters | **no** |
| `(+ (at-map m w) 1)` | 2 | a map's value range | **no** |
| collatz, power, fib | 8 | nothing — **true negatives**, deliberate | **no** |
| `tree.oro`'s `d` chain | 42 | `d ≤ steps`, quantified over the worklist's slots | **no** |

*(An earlier sweep measured portable-layer programs against the native target, so `num/f64.*` names
were unknown to the target, fell through the `Result` gate and were counted as integer arithmetic.
That was a measurement error, not a compiler one, and the table above is the corrected sweep.)*

## 2. Why the relational domain does not fire, and it generalises

> An octagonal constraint `i − n ≤ c` becomes a **bound on `i`** only when `n` is itself bounded.
> But if `n` is bounded, the guard `i < n` already gives `i < n.hi` in the **interval** domain — that
> is what `refine` does today. So the relational fact pays off only in the case the non-relational
> one already covers.

The genuine octagon win is a different shape: an expression over **two variables that are each
unbounded but whose difference is bounded**. The corpus has one candidate — `(go.- ni i)` in the
tokeniser, a token length — and both operands are bounded there the moment anything bounds
`(len src)`. So it never fires either.

**`tree.oro`'s `d` is not an octagon problem at all.** `d` is a depth **read out of the worklist**,
so bounding it needs an inductive invariant over the buffer's *slots* — "every depth slot holds a
value ≤ steps" — which is a quantified array invariant, a strictly stronger domain than octagons.
[frozen-2026-08-28](frozen-2026-08-28.md) §6 called this a witness for octagons; that was wrong, and
this corrects it.

This is [ADR 0008](../../docs/decisions/0008-measurement-over-principle.md) landing on a *decision*
rather than a primitive: *octagons are the highest-value move* was a plausible reading of the
literature that measurement refutes on this corpus.

## 3. What the measurement selected instead

**A length is bounded at both ends, and the upper end needs no declaration.**

> `len` returns an `int`, and [ADR 0012](../../docs/decisions/0012-portable-integer-range.md) says
> `int` is exact within ±(2⁵³−1). A table with more elements has a length this language cannot count
> exactly — so `(len t)` is not a number the program can compare, index with, or carry, and every
> guarantee about `dom(a) = [0, len a)` has already failed. Assuming `(len t) ≤ 2⁵³−1` therefore
> assumes nothing ADR 0012 did not already require.

It was **relied on without being stated**, which is `split-words`'s shape and the zero-fill
guarantee's shape. Now [tables.md §2.3.1](../../docs/spec/tables.md).

**And a target may say something tighter**, with `(max-len N)`. One of ours can: a Java array holds
at most 2³¹−1 elements, because `arraylength` returns an `int` and `new T[n]` takes one. Go cannot —
a slice length is a 64-bit `int` and the real limit is the address space, which is neither specified
nor stable — so `targets/go/` declares nothing and keeps the language's bound. `N` past 2⁵³−1 is an
**error**.

That is the platform fact [indextype-2026-08-25](indextype-2026-08-25.md) hardcoded in Go, moved to
where a target author can state it — the same shape as `int-repr`.

## 4. Result

Thirteen programs improved, several to complete provability:

| | before | after |
|---|---|---|
| `smooth-go` | 0/13 ops, 0/2 loops | **13/13, 2/2** |
| `smooth-java` | 0/16 | 14/16 |
| `generic-go`, `generic-java` | 0/2 | **2/2** |
| `search`, `search-go`, `search-java` | 0/1, term 0/1 | **1/1, term 1/1** |
| `report-go` | 1/2 | **2/2** |
| `centroid-go` | 0/1 | **1/1** |
| `wordcount-go`, `wordcount-java` | 0/3 | 2/3 |
| `smooth`, `stencil` (portable) | 0/3 | 1/3 |

`wordcount`'s residue is `(+ (at-map m w) 1)` — a map's *value* range, which nothing declares. That
is the honest next gap and it is not relational either.

**Exactly one emitted file in the whole corpus changes**, across 53 programs × 5 targets:

```
 search-java.java
-  long r1 = 0;
+  int r1 = 0;
```

Java's index narrowing now fires on a program `indextype-2026-08-25`'s syntactic rule explicitly
could not help — its counter is bounded by a length rather than stepping to a constant. Both versions
compile and agree on every input. No benchmarked program changed, so **there is no speed claim
here**: this is a provability gain with one narrowing, on a program the gauntlet does not time.

## 5. Tested

The **differential suite** — one program built and *run* on all four targets — passes on all
eleven cases, including a new one. `len-bounded.oro` builds a table sized by a **parameter**, so
nothing knows its length; walks it with a `len`-bounded counter; and reads it back from a **frozen**
buffer, which also covers [frozen-2026-08-28](frozen-2026-08-28.md). Verified non-vacuous: the
emitted Java declares the reader's counter `int`.

Three inputs rather than nine, deliberately: reduction inlines `run` at every call site and each call
builds a table, so more of them exhausts x86's scratch registers — which measures the harness rather
than the compiler.

`TestLengthIsBounded` pins **both** claims on one program, because a test for either would pass
without the other: the counter is *bounded* on every target, and it *fits an index* only where a
target declared something tighter. `TestMaxLenBeyondTheWindowIsRefused` pins the refusal.
