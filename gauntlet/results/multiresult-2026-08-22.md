# The negative product on four targets, 2026-08-22

The product, rebuilt after [the first attempt was reverted](../../docs/spec/values.md) for making a
language construct declinable. This time every target implements it in its backend, like
`if`/`let`/`loop`, and there is no declaration to forget.

Two things were genuinely unknown and both are now measured. One bug was found by reading emitted
assembly.

## 2. The Java question, which is why this build happened

[product-2026-08-19](product-2026-08-19.md) measured C2 scalar-replacing a record returned from a
hot call at **0.96×, inside the noise** — but the record and its caller were in *one source file*.
Nobody had measured whether the escape analysis still fires when **the record is generated by us in
one class and the caller is hand-written in another**, which is the shape a real program has. That
unknown is why the first attempt at this feature dodged Java entirely.

| | ns/op | |
|---|---|---|
| `divmod` hand-written, record and caller in the same class | 296.700 | |
| **`divmod` emitted, record in `GenDivmod`, caller in `DivmodBench`** | **287.950** | **0.97×** |
| `divmod-sum` — the same arithmetic with **no product at all** | 284.650 | |

**The product version and the no-product version are within 1.01%.** So the record costs nothing:
**C2 scalar-replaces a generated record across a class boundary.**

*Caveat, stated rather than buried*: the absolute numbers work out to about one cycle per division,
which is far too fast for an `idiv` — C2 has almost certainly speculated on the static `divisor`
field and strength-reduced to a multiply and a shift. The **comparison** is unaffected, because all
four rows get the same treatment; only the absolute scale is not what it looks like.

The design that made it free is worth recording: **the record is shared by result *shape*, not
generated per function**, so every function returning `(int int)` uses one `Tup_long_long`. Two
functions of one shape make one type, which `emit/values_test.go` pins.

## 3. The bug, found by reading the assembly

x86 needs **two passes**, and the first draft had one.

Win64 returns a single value in `rax` or `xmm0`, so a second register is *our* convention — which
is legitimate because both sides of these calls are ours. The convention mirrors Win64's *argument*
convention: integers in `rax, rdx, r8, r9`, floats in `xmm0..xmm3`.

Placing each result into its register **as it is computed** clobbers the earlier ones, because
`rax` and `rdx` are `idiv`'s own operands:

```asm
mov rdi, rax     ; quotient held
mov rax, rdi     ; result 0 placed
mov rax, rbx     ; ...and immediately destroyed by the second computation
cqo
idiv rcx
```

Compute everything into the places the allocator chose, then move into the convention registers
once nothing else will run:

```asm
mov rdi, rax     ; quotient held
mov rax, rbx     ; second computation
cqo
idiv rcx
mov r12, rdx     ; remainder held
mov rax, rdi     ; both placed, last
mov rdx, r12
```

**Nothing about the design predicted this**; it came from generating the file and reading it.
`TestAsmPlacesResultsAfterComputing` pins it by checking that no write to a convention register
appears before the last computation.

## 4. What each target does, and none of it is declared

| | |
|---|---|
| **Go** | multiple return, in registers. Nothing built. |
| **Java** | a `record`, shared by result shape, scalar-replaced by C2 (§2) |
| **JavaScript** | an array literal. It **costs**: product-2026-08-19 measured an array at **1.32×** against an object literal at 1.11× for a create-and-consume pair. The array is chosen because it is what `const [a, b] = f()` destructures, and the price is recorded in the backend rather than hidden. |
| **windows** | `rax`/`rdx` by our own convention (§3) |

**No target declares any of this.** The first attempt carried a `(multi-return "…" "…")` target
declaration and refused on Java and windows, which makes a construct in the core declinable — a
library with a portability claim rather than part of the language. It was reverted for exactly that,
and `TestEveryTargetHasMultipleResults` is the test the reverted version could not have passed.

## 5. What is still true from the first attempt

`(values a b)` is **reader sugar** for `(fn (#k) (#k a b))` — the negative product, linear logic's
`&`. Its β law is β, so the reducer needed nothing: three reduction rules before, three after;
seven term kinds before, seven after.

Consumed in the same reduction it **vanishes** — `((divmod a b) (fn (q r) (go.+ q r)))` reduces to
`(go.+ (go./ a b) (go.% a b))` — which is the free half and always worked. What reaches a backend
is only the case that crosses a boundary.

And **the signature is what decides**: `(fn (k) (k a b))` read one way is a pair and read the other
way is a genuine higher-order function, and they are the same term. `(sig f (…) (int int))` means
product; without one it is an escaping closure and stays refused.
