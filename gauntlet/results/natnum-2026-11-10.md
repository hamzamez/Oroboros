# K(ℕ*): integers of any length on a target with no bignum (R3b, ADR 0099)

Date: 2026-11-10. R3b of the plan, after R3a ([signfuse-2026-11-09](signfuse-2026-11-09.md)). Decision:
[ADR 0099](../../docs/decisions/0099-an-unbounded-integer-is-a-numeral-of-any-length-with-its-signed-size-last.md);
spec: [integers.md §1c](../../docs/spec/integers.md).

## What it is

A set with no bound has no representation of finite carrier (integers-research Proposition 1), so
on windows, where every carrier was finite, `big-fib` compiled only in the word and trapped at
fib(93). ℤ is the language's integer sort, and a target may not decline it.

**ℕ\*** is the positional numerals in base B = 2³². Each m ∈ ℕ has one numeral with a nonzero top
digit (Knuth TAOCP 2 §4.1). **ℤ is K(ℕ\*)**, the group completion over them. A value is one table:
- digit i at index i;
- the last entry the signed size h = ±m, GMP's `_mp_size`, so h = 0 is the one zero and the normal
  form needs no rule;
- every slot between the size and the header holds 0.

Every operation's build writes [0, len t) at its counter, the header last, so a result is born full
(ADR 0097, extended in R3a). The library is `emit/natnum.oro`, about 230 lines of the language,
checked once per target as a theory (ADR 0035). Programs never name it.

## What was built

- **The library**:
  - `of`, a word of either sign, −2⁶³ exact;
  - Knuth's A and S as one recurrence over x + σ·y (R3a's), carries in {−1, 0, 1};
  - M, schoolbook, its step u·v + w + k ≤ B² − 1 in U₆₄;
  - the word forms, `mul_small`, `div_small` (the quotient's size known first from a's top digit
    against k, so its descending build writes the header first) and `rem_small`;
  - the five comparisons by sign, then size, then digits;
  - `render` by 10⁹.
- **The plan** (`emit.PlanBig`): on a target with no bignum, a program that holds a value exactly
  and whose set is unbounded takes `BigPlan{Var}`. Every consumer asks `plan.Holds()`, so none misses
  the third rung.
- **The lowering** (`ir.LowerLimbs`): the same plan names, each an instance of `emit.NatFunc`,
  signed by construction and with no width. `emit.NatFunc` shares `LimbFunc`'s theory check
  (`libFunc`).
- **Rendering demands an exact integer on every target** (`ir/big.go`): render : ℤ → Σ\* is ℤ's,
  so `big-str`'s argument is in B iff its fact leaves S, whatever the target declares its parameter
  to be. Before, windows declared it `Int`, so nothing was demanded and `fib`'s accumulators stayed
  in the word. A word value still renders in the word (ADR 0095): only the widening is the target's.
- **The machine's bound**: no machine represents ℤ. A numeral is held while its table fits,
  len t ≤ max_len, which every definition takes as its first argument (2⁴⁷ − 9 on x64). A capacity
  past it is `abandon`, a crash, as a host bignum's allocation failure is, never a numeral cut short.
  It is written as a case's guard, the let commuted into the arm that continues (ADR 0090's
  absorption), so the bound is a path fact for both the IR and the refinement layer.
- **Houdini's frame templates run both ways** (`emit/refine.go`): z ≤ v for a counter rising from
  z, and now v ≤ z for one falling from it, the same template under x ↦ −x. Houdini checks each, so
  a direction a loop does not keep is discarded. `render`'s scan from n − 1 down needed it.
- **`big-fib` runs on windows**: its skip is gone, and it gained `// prints: string`, which selects
  windows' string driver.
- **`big-nat-ops`**, a new differential case: twelve inputs, one per operation, at sizes up to
  951 bits, against the hosts' bignums and Python's values.

## Witnesses

- **`TestTheNumeralsOfAnyLengthCheckAsATheory`** (`emit`): each of the thirteen definitions types,
  is linear, and has its indices and divisors discharged on windows.
- **`TestAnUnboundedDifferenceIsTheNumeralsOfAnyLength`** (`cmd/build`), on windows:
  3²⁰⁰ − 7⁹⁰ and −7⁹⁰ − 3²⁰⁰ print Python's numerals. **The planted fault** `ir.PlantNatFault`
  takes the library's sum for its difference, and the numerals differ.
- **`TestAFallingCounterIsBoundedByItsStart`** (`emit`): a scan from len t − 1 down reads t[l],
  proven. A counter rising past its start is refused, so the template is checked, not assumed.
  **The planted fault** `PlantNoUpperFrame` drops v ≤ z, and the index is refused.
- `big-fib` and `big-nat-ops` agree on go, js, java and windows.

## What was measured

**Correctness**: fib(10⁴) (2,090 digits) and fib(10⁵) (20,899 digits) on windows equal Go's
`math/big` and Python, digest for digest.

**The check**: no existing program's emission changed, and the counts stay at 5,656 of 5,710
operations and 638 of 662 loops. Neither new case exports a function, so the emission baseline
records no K(ℕ\*) code; the differential runs it.

**Time** (M3's first figure; M3 itself is R3c): fib(n), rendered, best of five, two rounds. The
same source is compiled for windows (K(ℕ\*)) and for Go (`math/big`):

| n | windows, K(ℕ\*) | Go, `math/big` | ratio |
|---|---|---|---|
| 10⁴ | 8.9 / 8.9 ms | 8.5 / 8.6 ms | 1.04 (process start dominates) |
| 10⁵ | 256.8 / 257.3 ms | 29.1 / 35.1 ms | **≈ 8×** |

At 10⁵ the additions dominate: 10⁵ of them over about 1,085 digits on average, about 2.4 ns per
digit. `math/big` adds 64-bit limbs in an assembly carry chain, so half the digits, and no masked
read or operand selection per digit. Each K(ℕ\*) result is also a fresh heap table, since run-time
sizes take no reuse token (R1d). Which of these is the cost is M3's measurement, not assumed here.

## What failed first

**`render` took six forms before it checked.** Each failure named an analysis's real limit:
- **an unbounded width**: m·32·30103 leaves the word for m near 2⁴⁷. The width 10·len a + 9 is
  linear and bounded by the table's length.
- **a claim's upper end the theory could not see** (len t ≤ 2⁴⁷ is a site's fact). I briefly added
  `max_len` as a fact of the refinement layer, then removed it once the case guard made it
  unnecessary, since a rule nothing needs has no witness.
- **a join through an impure `let`**: `room`'s result, bound to a name, gave no facts. The
  commuted form, the guard of a case, gives them as a path fact.
- **two buffers in one loop**: dividing a copy in place while writing the field was refused (a
  value-returning borrow freezes its buffer). Render carries the quotient as a table instead, as
  the fixed limbs do.
- **a relation the IR's intervals cannot keep**: `n − 1 − top`, and a significant length rising
  with k. The scan for the numeral's length descends, and the copy happens in its exits, where the
  length is the scan's own variable.
- **a join on the sign**: w = t + s with s = sgn(a) gave no bound. The case on the sign is split at
  the call, with s a constant on each arm.

**`fib` stayed in the word**: windows declared `big-str`'s parameter `Int`, so no demand reached
the accumulators (above).

**An entry point's unbounded parameter** (`fib(n ∈ Nat)` exported) is refused, "int 0 +inf is not a
table". A K(ℕ\*) value at windows' ABI is not built; the harness inlines `run`, so no case needs it.

## What was not built

- **Algorithm D**: a quotient by a numeral is refused by name, on both rungs (R3c).
- **Render dividing one copy in place**, which needs two live buffers in one loop.
- **A K(ℕ\*) value at an entry point's boundary** on windows.
- **Reuse for run-time sizes** (R1d's data stack), and B = 2⁶⁴ with i128 products (M4).
