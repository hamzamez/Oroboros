# A module may contain a module

2026-09-20, the same day as [modpath](modpath-2026-09-20.md) and on hamza's question about it: the
file is now at the module's path, so why does the file repeat the path — and why is a companion
`(module go/encoding/hex/InvalidByteError …)` rather than `(module InvalidByteError …)`?

Two questions, two answers. **The first is refused and the second is built.**

## 1. The path cannot come from the file, because a file is not a module

A target file is a **fragment**. Counted across the 30 files in `targets/`:

| | |
|---|---|
| declare a module whose name is unrelated to the file name | `go/builtin.oro` → `go`; `java/lang.oro` → `java`, `java/Math`, … (ten); `windows/strings.oro` → `win/str`; `blas.oro` → `num/f64`, `num/vec` |
| declare **several** modules | 8 files, up to ten each |
| declare the **same** module from two files | three pairs — `go` from `builtin.oro` + `bigint.oro`, and the same shape on the JVM and JS |
| declare **no** module | 4 files, which carry the target header |

So "the file names the module" is false for 24 of 30, and the third row is the one that settles it:
a target is the glue of its fragments, `Δ_T = L₁ ▷ … ▷ Lₖ`, so a fragment must be free to contribute
to any module. A file-derived name forbids exactly that.

The rule the question was reaching for already exists, for **library** files — *"one file, one
module, matching the path it was found at"*, where `(module …)` is optional
([modules.md](../../docs/spec/modules.md)). A library file *is* a module; a target file is a
statement about someone else's.

And [ADR 0025](../../docs/decisions/0025-a-module-path-is-the-hosts.md) put the package file at its
path as **layout, not mechanism**. Promoting the file name to meaning would let a `git mv`, an
editor's "save as" or a build step silently change what a file declares — the same objection that
refused `#;` the day before ([comments.md §6](../../docs/spec/comments.md)): a thing that is not the
text must not change what the text means.

## 2. A companion is a child, and now it is written as one

```lisp
(module go/encoding/hex
  (sig EncodeToString …)
  (module InvalidByteError
    (sig Error ((self go/encoding/hex.InvalidByteError)) string …)))
```

The prefix here comes from the enclosing **module**, not from the file, so §1's objection does not
apply.

**It adds no structure, which is why it costs nothing.** A module path is a word in `Seg*`; a set of
paths ordered by prefix is already a trie; nesting writes that trie as a tree instead of as a list of
words, and the loader erases it by concatenation before anything else runs. `Target.Prims` is keyed
by the same fully qualified name either way — which is what the test asserts, as a commuting square
on the loaded target rather than on behaviour.

Depth is unbounded because concatenation is associative, and a child may carry a path of its own:
`(module go (module encoding (module hex …)))` and `(module go (module encoding/hex …))` are the same
word. The one thing refused is an **empty segment**, `(module a (module /b …))`, because `a//b` is a
path no `(use …)` can name and concatenation must not produce one silently.

**The absolute spelling stays legal, and must.** A fragment in another layer has to add to
`go/io/Writer` without nesting inside a `go/io` it does not declare. That makes this the `def`
shorthand's shape — sugar with a unique expansion, long form still legal — rather than the two
independent spellings [data.md §10](../../docs/spec/data.md) refuses. The corpus therefore keeps
both on purpose: `targets/go/io.oro` and `encoding/hex.oro` nest, `targets/java/lang.oro` does not,
and restructuring it is not required for it to keep declaring.

## 3. What it changed

| | |
|---|---|
| `emit/target.go` | `declareModule`, recursive, ~40 lines; the `module` case becomes a call |
| declarations | `targets/go/io.oro` (three companions) and `targets/go/encoding/hex.oro` (one) |
| spec | [target-files.md §1a](../../docs/spec/target-files.md), with `mdecl` in the grammar |
| README | example 4 now shows the module and its nested companion |

**Emission is byte-identical, 456 runs**, and the tooling suite passes whole — the hand declarations
still agree with the host through the nested spelling, and every planted mistake is still caught.

`io.oro` went from nine mentions of `go/io` to six: three module headers lost their prefix, and the
three that remain are the ones §4 says stay.

## 4. What it deliberately does not change

Nesting abbreviates where a module is **declared**, never where one is **named**:

- a type is still `(self go/encoding/hex.InvalidByteError)`, inside the nested form as outside it;
- `(include go/io/Writer go/io/Closer)` still takes absolute paths.

Making a bare `InvalidByteError` resolve inside its own module is **name resolution**, not sugar: it
would change which type a name binds to when a declaration moves, and it wants a decision of its own.
Named in target-files.md's last section, not smuggled in here.

## 5. Not built

- **A nested spelling in the generator.** The surveys still emit flat modules. A generated file is
  written per package and read rarely; nesting it is a tree build for no claim.
- **Nesting `targets/java/lang.oro`'s ten modules**, §2.
- **Relative names**, §4.
