# A fallible host call: the niche, and the loader's retraction

2026-10-06. Step 4 of errors.md §12 (ADR 0040), on Go. A host does not give the coproduct: Go's
`error` is 1 + E, `nil` the absent point inside its own values. The target now says so once, and a
declaration states its result's shape, which the loader turns into the host's product composed with a
retraction.

## 1. The algebra

```lisp
(repr error (niche (host expr "%s == nil")))                         ; targets/go/go.oro
(sig Open ((name bytestring)) (result.result File error) …)         ; a sum
(sig Read (…) (tuple (buffer (int 0 255)) (int 0 …) (option error)) …)   ; a partial success
(sig Close ((self File)) (result.result (tuple) error) …)           ; 1 + E
```

For a declared result R, H(R) is the list of host values behind it, and r rebuilds R from them:

```
H(T) = [T]                          H((tuple)) = []
H((option E)) = [E]                 r(e) = none if niche(e), else (some e)
H((V T E)) = H(T) ++ [E]            r(t̄, e) = s (r t̄) if niche(e), else c e
H((tuple R₁ … Rₙ)) = H(R₁) ++ … ++ H(Rₙ)
```

H is a functor on result shapes and r is natural in each factor, so one rule covers a sum, the unit
with an error, a partial product, and their composites. V must be marked `(success s)` with exactly one
other constructor `c`, whose payload is E, and E must have a niche; anything else is refused by name.

## 2. What the loader makes

`emit/retract.go` replaces each such declaration with:
- **the raw call**, `#raw:go/os:Open`, declaring H(R), the host's own `(*File, error)`;
- **a niche test** per error type, `#niche:error`, pure, whose template is the niche's;
- **a definition** `Open` in the module's target library (`D_T`), applying r to the raw call's values.

A program reaches `Open` by δ, and where it eliminates the sum, reduction removes it. What
`errors-os.oro` emits:

```go
	v1, v2 := os.Open("go.mod")
	v3 := (v2 == nil)
	if v3 {
		v6 := make([]byte, 64)
		...
		_, v8h, v9 := func(p []byte) ([]byte, int, error) { n, err := v1.Read(p); return p, n, err }(v6)
		v8 := int(v8h)
		v10 := (v1.Close())
		v11 := (v10 == nil)
		if v11 {
			v12 := (v9 == nil)
			...
		} else {
			panic("closing go.mod")
		}
```

No sum, option, unit or tag reaches Go. The raw call cannot be written in a program, so a program
cannot read a failed call's value: the product's leak (errors-2026-10-04) is unrepresentable for these
three names.

## 3. What failed first, in order

1. **The loader refused a variant as a result**: *f has a result that is not a type*. The parser now
   keeps such a result as written (`Prim.Retract`), for the pass.
2. **The view check**: `(implements go/os.File go/io.Closer)` found no `Close`. A view is a fact about
   the host's method sets, and a fallible method is the host's method under its raw name.
3. **A name with a `#` cannot round-trip through the IR's text**, whose reader is the language's. A
   loader-made primitive is printed as a string, `(call "#raw:go/os:Open" …)`, and read back.
4. **A dotted raw name, `go/os.Open#raw`, was read as an import's alias** `go/os`, which a module does
   not import into itself. Core reads any undotted name a module does not define as a primitive, so the
   loader's names contain no `.`.
5. **Types**: the derived types resolve in the declaration's module, the way every declaration's do.
   Running the pass before name resolution lost the module; running it after left the derived types
   bare, so they are resolved in the pass.
6. **A target library's `use` never loaded its module.** Core closed the program's imports before
   gluing `D_T` into a module, so `result.ok` was unbound in every program that loaded the Go target's
   `os` without importing `result` itself. A module's imports are those of the module with its target
   library, so gluing and closing now alternate to a joint fixpoint (`closeImports`): each pass glues
   every module present or wanted that is not yet glued, then closes the imports, and stops when a pass
   glues nothing. Every emitted file is unchanged. One refusal message changed, tally's on Go and Java:
   its target library's `use` of a host module is now closed over, so the refusal names the module no
   file provides.
7. **The tests loaded programs without `D_T`.** `core.Load` predates target libraries; `D_T` became
   load-bearing here. `Target.LoadProgram` loads as the drivers do, and the shared helpers use it.
8. **A target loaded with no library path** had nowhere to read `result` from: `LoadTarget(dir)` in the
   tests and the tooling, and `cmd/portable`'s layered load. Both take the `lib` beside their
   `targets`, the layout the drivers' default `-path lib` assumes; a caller that names library
   directories still decides.

## 4. A mistake, corrected: the generated layer stays the host's product

I first migrated the three acceptance programs that call `Open`, `Read` and `Close`. They failed,
because they build against the survey's **generated** declarations layered above the hand target, and
the generated `Open` is Go's `(T, error)`. That is right, and it stays: whether a call is a sum or a
partial success is a claim about its documentation, which a generator cannot read (ADR 0023). So those
programs were restored, and `errors-os.oro` is a new acceptance program against the hand os alone.
