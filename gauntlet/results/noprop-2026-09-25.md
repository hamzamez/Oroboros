# An obligation is discharged, or the program is refused

2026-09-25. Found while building ADR 0031
([prodresult-2026-09-25](prodresult-2026-09-25.md) §6), fixed at hamza's request, spec first:
[refinements.md §3a](../../docs/spec/refinements.md), [tables.md §6](../../docs/spec/tables.md).

## 1. The hole

The refinement layer gave an obligation it could not decide a note, *"propagated, not proven"*, and
the program was emitted. Two paths did this:
- **an index outside the linear fragment**, such as a value read from another table;
- **a primitive's `where` outside it**.

refinements.md §3 had licensed it: an undecided obligation "can only be discharged by an assumption
that matches it, **or by a runtime check at a boundary**". No runtime check was ever emitted.

**The witness:**

```lisp
(let b (build b 8 (loop ((b b) (i 0)) (>= i 8) b else (again (set b i (% (+ i n) 10)) (+ i 1))))
     t (build c 6 c)
  (t (b 3)))             ; b's cells reach 9, t has six
```

It compiled on every target. Run on JavaScript, `run(6)`, an `int` function, returned **`undefined`**.
Go would panic, Java would throw, and x86 reads past the table. That contradicts README principle 4,
"what cannot be proven is refused, not checked at run time", which names array bounds first.

## 2. What it is

**An obligation is the domain condition of an application.**
- For `(t i)` it is `0 ≤ i < len t`: a table is a function on `[0, len)`.
- For a primitive call it is the primitive's `where`.

Outside its domain an application has no value. A program *denotes* only if every application in it
is defined, so an obligation that is not shown leaves a program that is not shown to mean anything.
There are three ways to show it:
1. a **proof** in the fragment, including by cases (joinConditional, provedBySplit) and from content
   facts about a table (array-facts.md);
2. an **assumption that is the same term**: an opaque atom matched by name;
3. **evaluation**, when the obligation is closed, meaning a comparison of two literals. Comparing two
   literals is exact on every host and folds no arithmetic, so ADR 0009 has nothing to say about it.

Otherwise the program is **refused**, naming the obligation and what was known. "Propagated" survives
only as §6b already had it: an exported definition's own `where` is assumed inside it and is its
caller's to discharge. That obligation is stated in the interface, not dropped.

## 3. Measured before building, and the scope was wrong

**What the emission baseline said.** It recorded no propagated index. The 105 that
joinindex-2026-09-16 left had all become proofs since, through content facts, component facts and
proof by cases. It recorded two propagated preconditions, both in `examples/native/smooth-js.oro` on
JS: `js./ requires (!= b 0)` with `b = 3.0`, a float literal, so the atom is outside the integer
fragment and true. Route 3 decides it. So "the corpus relies on none of it", and the emission sweep
agreed: byte-identical, one change, `smooth-js`'s notes gone.

**What the full check said.** The differential and tooling steps failed. The emission sweep compiles
each source's EXPORTS. Most differential cases export nothing: their `run` is compiled by the harness.
Acceptance programs are compiled by `cmd/build` from `main`. So the baseline had never recorded the
notes those compiles printed. That is CLAUDE.md's "a measurement's scope describes the measurer", met
again. Three programs relied on propagation, and each was a real case:

| program | what was propagated | the fix |
|---|---|---|
| `map-dynamic`, windows | a map read at a CLAMPED index, `(#mv (wm-c #mv #f))` | a guarded read, `wm-at` |
| `map-static`, windows | a literal map's value at a clamped index, `(#vs (wm-c #vs i))` | the same |
| `math-bits` acceptance | `Div64 requires (< hi y)`, guarded by exactly `(u64< hi y)` | an atom keyed by its relation |

**The map lowering was written against propagation.** Its own comment says: "Clamping turns a
refusal into a note". A clamp maps an out-of-range index to 0, and 0 is outside an empty table, so a
read at a clamped index is never proven. A **guarded read** returns 0 *instead of* reading, and on the
path that reads, the guard is the proof: `0 ≤ x < len m`. The two differ only in the impossible case,
and both say what happens there. The reads the library already proved are unchanged.

**`math-bits` was correct all along.** It guards `Div64` with its own precondition. The unsigned-word
pass had rewritten the guard's `<` to `u64<`, which it does only where both operands lie in U, and
there they are one relation. The opaque match compared printed strings, so the two spellings never
met. The key of a comparison atom is now its relation class, with operands printed as they are. That
can only fail to match, never match wrongly.

## 4. What is built (`emit/refine.go`)

- **`indexObligation`:** the note is now a refusal, which says why and that a guard stating the bounds
  is a proof.
- **`discharge`:** a closed comparison is evaluated (`closedComparison`). Otherwise an atom outside
  the fragment is refused.
- **Speculative walks keep reporting and do not refuse.** These are Houdini probes, proof-by-cases
  dry runs and the requires sub-walks. They already returned *not proven* on the fragment's own
  branch, so a failed speculation costs precision, never a refusal.
- **`closedComparison`** compares integers as integers, and anything with a float as float64. NaN
  compares equal to nothing, itself included, though no literal can write one. It recognises every
  host's spelling of the six comparisons through the fragment's own `isOp`.
- **`opaqueKey`** (`emit/linear.go`) keys a comparison atom by its relation.
- **`wm-at`** (`emit/winmap.oro`) is the guarded read. The map lookup (`winmap.go`) and `wm-fill` use
  it.

## 5. Checked, and how each check fails

**New tests** (`emit/noprop_test.go`):
- the witness refused, and its guarded twin accepted;
- a closed precondition: `3.0` accepted, `0.0` refused as false, an open atom refused;
- closed comparisons exact, including 2⁵³ < 2⁵³ + 1, which float64 cannot tell apart;
- an atom matched by its relation (`u64<` against `<`), and not by a different one (`u64<=`).

**Six existing tests encoded the old rule.** Their control halves said "an unprovable read must be
propagated, not refused". They now require the refusal, and their positive halves are unchanged.

The Lemma-1 test (`ensures` not assumed when `where` is unproven) had depended on the walk continuing
past a merely reported precondition. It now asserts the refusal at the precondition, which is
stronger: `Q` is never reached. The bool that withholds `Q` still governs the speculative walks.

| planted | caught by |
|---|---|
| an unproven index propagated again | the witness, and the six rewritten tests |
| an open precondition propagated again | the precondition test, the Lemma-1 test |
| closed comparisons not evaluated | the precondition test (`3.0` refused) |
| a closed comparison always true | the precondition test (`0.0` accepted) |
| integers compared as float64 | the exactness test |
| an atom keyed by its spelling | the relation test; the `math-bits` acceptance program |
| the map read at a clamped index again | `map-dynamic` on windows (differential) |

The first witness for the last row was `(< 2⁵³+1 2⁵³)`, which is false both ways and missed the plant.
Its converse is true only when integers are compared exactly.

**`go run ./cmd/check`:**
- **emission:** byte-identical, one compiler-output change (`smooth-js`'s two notes). The map
  programs' windows code does change, a guarded read where a clamped index was, but only in the
  harness's compiles of `run`, which this step does not record: §3's scope, a second time;
- **every step passes,** including the differential and tooling steps that the first run failed.

## 6. Not built

- **`-checked` for an index.** It would need every target to trap on one; JavaScript and x86 do not.
  A program that cannot prove an index can guard it, and the guard is a proof. A clamp, as always, is
  a missing proof, but an honest one.
- **An export's `ensures` outside the fragment is still reported**, not refused
  (postconditions.md §6: *"postcondition is outside the decidable fragment, propagated and not
  proven"*). It is a different object: a claim the program publishes about its result, not the
  condition for one of its own applications to be defined. It is named as the next candidate for the
  same rule.
- **A dynamic index into a literal table** still carries no obligation in the refiner
  (prodresult-2026-09-25 §6). The emitter refuses that shape, so nothing wrong is emitted.
