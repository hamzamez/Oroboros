# The observer at a host parameter, and `shape` in its own buffer at parity

2026-10-21. hamza: *"go ahead with 1–3. always mathematical and algebraic, and make sure we don't break
the last decisions we made."* These were borrow-research.md §8's revised decisions 1–3: the observer at
a host parameter, effects.md §7c generalized, and `shape` moved to its own buffer.
[ADR 0069](../../docs/decisions/0069-an-observer-at-a-host-parameter.md).

> **`shape` READS ITS OWN BUFFER AND IS AT PARITY.** On the 260 MB TSV file it takes **125 ms**, against
> 113 ms for the same program written by hand (1.11×, inside the 15% noise floor) and 125 ms for
> `ReadSlice` at the same buffer size (1.00×), with **no garbage collection**. The committed `ReadString`
> version took 308–331 ms with 78 collections. All 13 of its integer operations are proven, it matches
> its definition on 17 inputs, and it needs no `lent`.
>
> **THE OBSERVER IS DERIVED, NOT DECLARED.** A pure host call whose results are scalars reads a live
> buffer for the length of the call, ADR 0020's read-borrow extended from `b[i]`. No emitted file
> changed. Growth (G7), the write-borrow, the consume and aspect 2 keep their rules, each pinned by a
> test.
>
> **A TRUSTED CLAIM WAS FOUND AND CLOSED.** The core's ascription `the(S; e)` was trusted: J could write
> `the("int 0 5", 10)` and it compiled, and a binder's claim, `b ∈ S = e`, desugared to it. A claim is now
> an obligation, proven or refused, and `the` is refused in J (ADR 0062). Only a proven claim reaches the
> IR, which reads it as the value's set.

## 1. The observer

`emit/observer.go`. A host declaration is an observer when it is pure, has a table parameter, and every
result is a scalar. Three consumers read that one derived set:
- **the type checker**: at an observed parameter, `Buffer(V)` meets `Array(V)`;
- **linearity**: an observed argument is a read, refused after a move and moving nothing;
- **the reducer**: §7c's "a term that reads a table through a bound variable" counts an observer
  applied to a bound variable.

The theorem is ADR 0069 item 1: the call is pure and its result has no extent, so its value is the same
on the live buffer as on a copy taken at the call.

| test | what it pins |
|---|---|
| `TestAnObserverIsDerivedFromItsDeclaration` | `utf8.Valid` and `RuneCount` are observers. `hex.EncodeToString` (a string result), `File.Write` (impure), `strconv.AppendInt` (G7's growth) and `hex.Encode` (a write-borrow) are not |
| `TestAnObserverReadsALiveBufferBeforeItsNextStore` | the observations precede the store in the emitted Go and keep their values: `true 4 false 255` |
| `TestALiveBufferIsRefusedWhereNoObserverStands` | a non-observer still takes the buffer as a move (the freeze at its last use), so a store after it is refused |
| `TestGrowthIsStillABorrowStatement` | `strconv.AppendInt(b, 42, 10)` builds as before |
| `TestAnObserverAfterAStoreIsAReadAfterAMove` | linearity refuses an observation of a consumed version, whatever the reducer did |

| planted fault | caught by |
|---|---|
| the scalar-result hypothesis dropped | the derivation test, and the refusal test (a string result accepted) |
| linearity's read-after-move refusal dropped | the read-after-move test |
| the observer branch dropped from linearity | the order test and the read-after-move test |
| §7c's generalization withheld from the reducer | the order test: the program is refused, not miscompiled |

## 2. `shape` in its own buffer

`examples/lines/shape.oro`. `os.File.Read` fills a 64 KB buffer. `seg.IndexByte` finds the next LF at
or after the cursor, and `seg.Count` counts a piece's separators. A record crossing a chunk arrives in
pieces, and its counts add because |·|_s and |·| are homomorphisms. So the fold's state, and the output,
depend on the input alone, not on where the reads cut it.

`targets/go/bytes.oro` (new) declares Go's `IndexByte` and `Count`, with their laws:
- `r < len(b)`;
- `r <= len(s) + 1`, which holds for every separator, the empty one included.

Its module `segment` declares each composed with a restriction,
`segment.F(b, lo, hi, x̄) = F(b[lo:hi], x̄)`, with `where 0 <= lo && lo <= hi && hi <= len(b)` and F's law
on `hi − lo`.

What the program needed, in the order it was refused:
1. **io.Reader's law on a component of a tuple result.** `File.Read` now states
   `(q ∈ buffer(0..255), n ∈ 0..2^63-1, r ∈ …) ensure n <= len(q) && len(q) == len(p)`. J's target reader
   takes a group result, its component names renamed to positions (`core.ResultComponent`). The refiner
   assumes the `ensure` at the call's continuation under Lemma 1. The error model's raw call keeps it,
   and refuses one whose host values are not one per component.
2. **The buffer's length through the loop.** `threadLengths` reads a component's length from that
   `ensure`, so the buffer a read refills keeps len b = 65536.
3. **n ≤ len b across iterations.** Houdini's templates gain v ≤ len t, for t a loop variable whose
   length is established: the difference template with a length for the second variable.
4. **A piece's end in [k, n].** A join's templates gain its tails and the names they mention. Each
   template is a candidate checked on every leaf, so this refines the join and keeps it sound.
5. **A where-mark hid its value.** An obligation's where-mark, `(#reqw "def" cond e)`, now reads as e in
   the linear fragment. A claim's undecided mark becomes one, and opaque it hid the piece's end from the
   facts that decide the claim itself. An undecided mark refuses the program, so this is sound.
6. **A claim hid its value** for the same reason: `(the S e)` reads as e.
7. **A loop's status through a buffer's scope** (ownbuf defect 5). A scope's tails are its body's, in
   `tailsLinear` and in the join's walk.
8. **A claim over a conditional.** `proveCond` splits a goal that is not linear instead of reading it as
   opaque.
9. **The IR's word choice.** `k + j` was held in U, because the IR's intervals do not hold `j < n − k`.
   The program states three claims, `got`, `j` and `d ∈ 0..size_buf`, which the refinement layer proves
   and the IR then reads (item 10 below). Each claim is a fact, not a clamp: proven, or the program is
   refused.
10. **A claim reaches the IR** (`emit.EraseAscriptionsButClaims`): a range within the word is kept to
    lowering, where the IR's intervals meet it, and erased after deciding. Within the word only a
    binder's claim makes one, and it is proven before this runs.
11. **Work moved into the loop.** `go.bytes_of_string(sep)`, used once, was substituted into the loop
    and recomputed per piece. The program binds it where it is read twice. The reducer's rule, which
    substitutes a pure application occurring once even under a loop's λ, is recorded below.

**Each rule is load-bearing.** With each one faulted alone, `shape` is refused:

| rule faulted | `shape` refused at |
|---|---|
| the join's tails and names as templates | the claim `d`: 0 ≤ e − k does not follow |
| Houdini's v ≤ len t | the claim `e` |
| a component's `ensure` (`File.Read`'s law) | the claim `e` |
| a component's length through a loop | the claim `e` |
| a non-linear condition split | the claim `e` |
| a claim read as its value | the claim `e` |
| a where-mark read as its value | the claim `e` |
| `transparent`, the join's walk through a claim or a mark | the claim `e` |
| a scope's tails | `os.Exit`'s 0 ≤ status |
| a claim kept to the IR | the IR's word for `k + j` |

**Built on the way and removed** (ADR 0069, "Why not"): entailment on nested subsets of the facts, ex
falso on small variable sets, an obligation's range mark read as its value, and a claim's bounds assumed
of its binder. Each is sound, but `shape` compiles with each faulted, so none has a witness. ownbuf's
reproducer `e2` (Houdini losing 0 ≤ c) is **not** fixed by any of them, and stays open: the facts at its
failing back edge are contradictory, as my diagnosis said, but that diagnosis does not explain why the
goal fails.

## 5. Not built, and found

- **A definition's declared result range inside the word is not proven.** `fn bad(x ∈ 0..100) (0..5) { x + 10 }`
  compiles at HEAD and prints 11. It leaves no ascription: AscribeWide wraps only results above the
  word, and the claim is dropped at inlining, so nothing downstream reads it. It is ADR 0062's logic,
  not built.
- **β substitutes a pure application occurring once into a loop body**, where it runs per iteration:
  GHC's OneOcc-inside-a-lambda case. Changing the rule moves every program's emission. It is a step of
  its own.
- **On the bignum path** the rung selection erases ascriptions before word selection, so a claim does
  not reach ρ there.
- **ownbuf's defect 3, Houdini losing 0 ≤ c** (reproducer `e2`), is open.
- **A string result, an impure observer, and a language segment**: ADR 0069's "Why not", each waiting
  for a program.
- `lent`, for `Peek` and `Scanner.Bytes`.
