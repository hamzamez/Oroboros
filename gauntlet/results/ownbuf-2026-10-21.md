# The caller owning the buffer: what C costs, measured again

2026-10-21. hamza's question after [shape-2026-10-21](shape-2026-10-21.md): *"how is this different
from what we already have? shouldn't the rules for scopes and buffers cover it? do we need a new
mode keyword (lent)?"* The answer was that the lent slice is our buffer turned around: owned by the
callee, written through another name. The cheaper question was whether ownership can simply be given
back to the caller, with no new mode. *"go ahead."*

> **CALLER OWNERSHIP REACHES PARITY, BUT NOT WITH TODAY'S LANGUAGE.** By hand, a 64 KB buffer the
> program owns, filled by `os.Stdin.Read` and searched by segment with `bytes.IndexByte` and
> `bytes.Count`, takes **131 ms against 145 ms** for `ReadSlice` over a `bufio.Reader` of the same
> size (0.90×, within noise), with no garbage collection.
>
> In the language it cannot be written. A pure host call may not read a live buffer: `buffer(0..255)`
> is refused where `Array(0..255)` is declared. So `shape` folds byte by byte, and that costs
> **543 ms**: 1.77× the same per-byte fold written by hand, 2.2× the lent form.
>
> **WHAT IS MISSING IS NOT A NEW MODE.** ADR 0020 already gives our buffers Wadler's `let!` and
> Odersky's observers: *"The read-borrow is already free … an observation produces a scalar or a
> frozen array and therefore cannot alias the buffer."* host-buffers.md §4 types an aspect-3 host
> parameter as *"a read of `B` that does not consume it"*. The observer was built for `b[i]`, not for a
> host's read-only parameter, and that extension is all caller ownership needs. A lent result is the
> same observer of a buffer someone else owns. It needs one thing more, the event that ends it, and
> it is needed only by `Peek` and `Scanner.Bytes`, which have no caller-owned form.

## 1. Measured

The input is the same 260 MB TSV file (shape-2026-10-21 §4). All programs print identical output.
Medians of 9 interleaved serial runs, with no compiler or benchmark process running.

| program | owner | search | median | GC |
|---|---|---|---:|---:|
| `shape`, committed (ReadString) | a new string per record | host | 331 ms | 78 |
| `own`, the language | the program, 64 KB | a per-byte fold in the language | 543 ms | 0 |
| `hown`, by hand | the program, 64 KB | a per-byte fold | 307 ms | 0 |
| `hslice`, by hand | `bufio`, 4 KB | host (`ReadSlice`, `bytes.Count`) | 243 ms | 0 |
| `hslice64`, by hand | `bufio`, 64 KB | host | 145 ms | 0 |
| **`hown2`, by hand** | **the program, 64 KB** | **host, by segment** | **131 ms** | **0** |

What the table separates:
- **The search is the largest factor.** A per-byte fold loses to the host's vectorized
  `IndexByte` and `Count`, even by hand: 307 ms against 131 ms with the same buffer.
- **The buffer's size is the next.** bufio's default 4 KB against 64 KB is 243 ms against 145 ms:
  sixteen times the system calls.
- **Ownership is not a factor.** 131 ms against 145 ms, caller-owned against lent, at equal size.
  With a buffer it owns, the program needs no `bufio` at all: `bufio.Reader.Read` with
  `len(p) ≥` its buffer reads straight into `p` (*"Large read, empty buffer. Read directly into p to
  avoid copy"*). bufio's purpose is the callee-owned buffer.
- **The language's per-byte fold is 1.77× its hand-written form** (543 ms against 307 ms). It emits
  **2,423 lines** of Go for a loop of six arms: every failed conjunct of a guard copies the rest of
  the clause chain. Each byte re-tests `k < n` and `k < len(b)`, and reads `b[k]` once per arm.
  The same copying inflates the proof count: 104 operations "bounded" for about a dozen in the
  source.

`hown2`'s loop, the form a caller-owned `shape` would take:

```go
n, err := os.Stdin.Read(b)
for k < n {
    j := bytes.IndexByte(b[k:n], '\n')
    if j < 0 { c += bytes.Count(b[k:n], sep); z += n - k; open = true; break }
    c += bytes.Count(b[k:k+j], sep); z += j
    close(c+1, z); c, z, open = 0, 0, false
    k += j + 1
}
```

Each host call reads the program's buffer for the length of the call and returns an integer. That
is the observer, at a host parameter.

## 2. The algebra: one observer, three owners

ADR 0020 §"Why this is small": an observation of a buffer produces a scalar or a frozen array, so it
cannot alias the buffer, and effects.md §7c orders it against the buffer's stores. Three cases share
that one concept and differ only in who owns the buffer and what ends the observation.

| observer | owner | ends at | status |
|---|---|---|---|
| `b[i]` | the program's scope | the read (a scalar) | built (ADR 0020, §7c) |
| a host's read-only parameter, `bytes.Count(b, sep)` | the program's scope | the call's return | **not built**: `buffer` refused at `Array` |
| a lent result, `ReadSlice` | the host object | the owner's next write | not built (borrow-research.md) |

**The second row needs no annotation.** ADR 0020's argument is that an observation which produces a
scalar or a copy cannot alias. A host call reading a live buffer is safe when the buffer cannot leak
through its result, and whether it can leak is a property of the result's representation (borrow-research.md
§3):
- a declaration whose results are all scalars or Go strings may take a live buffer at a declared
  `Array` parameter;
- one with a table or host-object result may not. That is host-buffers.md's aspect 2,
  `bytes.TrimSpace`, *"never `B`"*.

The reducer's half is §7c generalized from "a term that reads a table through a bound variable" to
"a term that passes a buffer to a call". It is the same generalization experiment B demanded for lent
values (shape-2026-10-21 §4.2).

**A segment is the declaration's business.** `bytes.IndexByte(b[k:n], c)` is a function of
(b, k, n, c), declared with `where 0 <= k && k <= n && n <= len(b)` and the template slicing. That is
an expression of Go, as the write-borrow's closure wrapper is (`os.File.Read`). No language view is
needed.

## 3. What writing `own` found

Each of these is a defect or a gap that a program now names.

1. **A crash in J's reader, fixed.** A header that claims one binder and leaves another, or leaves
   its result, crashed D: `fn run(s ∈ 0..255) { s + 1 }` panicked with *"a provisional tree reached
   D"*. The corpus has no such header. An unclaimed binder or result now claims nothing, the core's
   `any` (ADR 0062 item 8; types.md §3.3). `TestAnUnclaimedBinderIsAny` pins it, and the panic
   names the tree's type.
2. **The `io.Reader` law cannot be stated.** `File.Read`'s comment says 0 ≤ n ≤ len p, but its header
   can't: J's target reader takes no group result `(q ∈ …, n ∈ …, r ∈ …)`, and the core's `ensures`
   names one `result`, not a component. So `b[k]` under `k < n` is unproven. `own` writes
   `k < len(b)` beside it, a clamp in a program, which is a missing proof.
3. **Houdini loses `0 ≤ c`** when the clause chain has a guard comparing a buffer read with a read of
   a table a host returned. The reproducer is `e2` below. With the separator a literal, a `len`, or a
   read of a literal table, the invariant holds. At the failing back edge the hypotheses are
   contradictory: the candidates `c = k`, `c = n` and `k = n` are all assumed beside the path's
   `k < n`. Yet the goal is not entailed, and the split budget is unspent. Not diagnosed further.
   `own` declares no range on `inc`'s parameter to avoid it, which is a smaller claim, not a clamp.
4. **An element of a host-declared `Array(0..255)` result has no range fact.** `run(go.bytes_of_string(a)[0])`
   against `run(s ∈ 0..255)` fails with *"known: nothing"*.
5. **A loop's result summary does not pass through a buffer's scope.** `os.Exit(status)`, where
   `status` comes from a loop inside `var b := …`, fails `Exit`'s `0 ≤ status ≤ 255`, even written as a
   conditional over the literals 0, 1 and 2. The same loop without the buffer, the committed `shape`,
   passes.
6. **Lowering refuses indexing a call's result**, `go.bytes_of_string(sep)[0]`: *"an application whose
   operator is an application"*.
7. **`bytes_of_string` states no length law**, len([]byte(s)) = len(s). And the guard `len(sep) == 1`
   does not appear among the known facts, only `len(sep) ≥ 0`.
8. **The clause chain is copied under every failed conjunct** (§1): 2,423 lines and 104 counted
   operations.

Reproducer for 3 (`e2`); `t[0]` of a literal table passes:

```
fn run(s) {
    in = gos.Stdin()
    var b := array { 0 : _ ∈ 0..4095 }
    loop k = 0, n = 0, end = false, c = 0 {
        k < n && k < len(b) && b[k] == 10 -> again(k + 1, n, end, inc(c))
        k < n && k < len(b) && b[k] == s -> again(k + 1, n, end, inc(c))
        k < n && k < len(b) -> again(k + 1, n, end, c)
        end -> fmt.Println(c)
        else -> { (n2, r) = File.Read(in, b); again(0, n2, done?(r), c) }
    }
}
export fn main() { run(go.bytes_of_string(gos.Args()[0])[0]) }
```
