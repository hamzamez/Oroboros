# pairs-2026-10-28: the unsigned word on JavaScript, as two 32-bit digits

The last piece of the 10-24 plan's 6b step 2 ([ADR 0083](../../docs/decisions/0083-a-representation-is-an-abstraction-function-chosen-by-place.md)),
which [bits-2026-10-27](bits-2026-10-27.md) left unbuilt: U = [0, 2⁶⁴) on JavaScript, so FNV-1a 64 runs
there. hamza: "finish the javascript split pair".

## 1. What it is

JavaScript's word is ±(2⁵³−1). U is held as two digits base B = 2³², the representation (hi, lo) ∈
[0, B)² with d(hi, lo) = hi·B + lo, a bijection onto U. u64repr-2026-09-22 measured this split pair
4.8× ahead of `BigInt`.

**It is a rewrite on the IR, not a printer** (`ir/pairs.go`, `SelectPairs`). The pass:

- runs after the unsigned-word selection on a target declaring `repr 0..2^64-1 pair`;
- gives two values to every value whose fact lies in U and outside the word, and to every operation
  fused under `mod 2ⁿ` with 32 < n ≤ 64 (mode `wrap64`);
- expands each operation on one into the language's own operations on the digits.

| operation | expansion (a law of arithmetic in base B) |
|---|---|
| a + b, a − b | the low digits' sum or difference s, its carry or borrow ⌊s/B⌋ into the high digits, each digit mod B |
| a · b | aₗ·bₗ exactly by 16-bit digits (each product below 2³², exact in a double); the high digit is ⌊aₗbₗ/B⌋ + aₕbₗ + aₗbₕ mod B, the cross terms by fusion's 32-bit wrapping multiply (`Math.imul`); aₕbₕ·B² vanishes mod 2⁶⁴ |
| & \| ⊕ | digit by digit |
| ~ (wrapped) | B − 1 − each digit |
| << k, >> k, k constant | the digits' shifts, the bits that cross the boundary carried between them |
| / 2ᵐ, % 2ᵐ, mod 2ᵐ | a right shift and a mask |
| a join (a loop variable, an `if`'s result) | two values |
| into the word | hi·B + lo, which the decision proves below 2⁵³ or refuses |
| at a host's argument / an entry point's result | `pair_box`, a decimal string / `pair_bigint`, the caller's `BigInt` |

**Soundness is the decision's.** Every operation the pass writes acts on integers below 2³⁴ or is fused
under `mod 2³²`, so `ir.Decide`, run again after the pass, proves each one inside the word or refuses the
program. The expansions themselves are checked against Python by the differential suite, with planted
faults (§3).

**Not built**, each refused with its reason: a comparison of two pairs, a shift by a count not known when
compiling, a division by anything but a power of two, a pair crossing a `build`'s region, and an entry
point's parameter held as a pair.

## 2. Measured

**Correctness**: `examples/hash/fnv.oro` on JavaScript prints Go's `hash/fnv` values on the 1 MB file
(`d719c8a0`, `ce39f5e253631a40`). The differential cases `fnv64`, `fnv64-fold` and `pairs` agree with
Python on Go, JavaScript and the JVM. `pairs` runs every expansion at run time: its loop over a value in U
is something inlining cannot fold.

**Speed**: FNV-1a 32 and 64 over 128 MB, end to end, best of three (`experiments/hashbench/fnv.mjs`):

| | ms | ratio to the hand-written pair |
|---|---:|---:|
| generated | 661 | **0.80** |
| hand-written split pair (u64repr's) | 822 | 1.00 |
| hand-written `BigInt` with `asUintN` | 976 | 1.19 |

**A result in our favour had to explain itself.** The hand-written pair carries through a float division,
`Math.floor(t / 2³²)`. Rewritten without it, exactly, it ran 861 ms, so that is not the cause. The
generated loop prints the same hash, so it does the work. One hypothesis remains untested: its 16-bit
digit products keep every intermediate small enough for V8 to stay in 32-bit integer registers, where the
hand-written `x << 8` sum passes 2³¹. Recorded as measured, inside no claim beyond "no slower".

## 3. What failed first

- **A harness that could not fail.** The first `pairs` case gave every right answer with its carry
  removed, because the compiler folded it: the harness inlines each input, and constant digits were
  computed when compiling. Its second version still passed with the carry dropped, because its constants
  rarely carried. The third runs a loop and adds `0x00000001FFFFFFFF`, which carries almost always. It
  fails with a dropped carry and with a cross term replaced (both planted).
- **A constant under `mod` after inlining**: `(C · (0 + 1)) mod 2^64` reached `Fuse` as `C mod 2^64`.
  `Fuse` now evaluates closed constants (shifts, Boolean operations, `mod`, `/`, `%` included) and folds
  a constant subterm of a fused term to its residue. Go refuses a constant expression that overflows, and
  `C << 13` under wrap had printed as one.
- **`&`, `|`, `⊕` and `<<` with a result in Go's and the JVM's unsigned word were not built**, found by
  `pairs`' `(a | b) & mask`. They are those hosts' own operators on the residues (`u64&` …).
- **An exact sum's high digit** was bounded only below 2³³, so a later `⊕` had no JavaScript
  realization. It is now masked, the identity on a value proven in U.
- **A statement's value is its first argument**: the `println` of a pair had to carry the pair's digits.
- **The hex printer** shifted by a variable count; it now takes the digits off the low end, `x >> 4`, the
  same on every target.

## 4. What it cost

`ir/pairs.go` is about 820 lines; `Fuse`'s constant folding and the unsigned word's Boolean operations
about 120; the target data a dozen lines. The language's code changed only in the hex printer.
