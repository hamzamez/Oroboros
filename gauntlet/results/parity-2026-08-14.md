# First parity measurement — 2026-08-14

The claim the whole project rests on, measured for the first time.

Every previous number in this directory measured **hand-written host code** — the bar. This one
measures **code Oroboros produced**: `examples/dot.oro`, reduced to normal form by `core/`,
emitted to Go by `emit/`, compiled into the gauntlet package, and benchmarked in the same binary
against the hand-written references it must match.

**Result: parity.**

---

## The path

```
examples/dot.oro
  ⟶ core.Read / core.Load          reader
  ⟶ core.Normalize (target "go")   β + δ to normal form
  ⟶ emit.Func                       Go source
  ⟶ gauntlet/go/generated.go        compiled into the benchmark binary
```

The whole of it is `cmd/gen`. The generated function:

```go
func GenDot(p []float64, q []float64) float64 {
	acc := 0.0
	n1 := (len(p))
	for i := 0; i < n1; i++ {
		acc = (acc + ((p[i]) * (q[i])))
	}
	return acc
}
```

Nothing in `examples/dot.oro` mentions a loop. It says `dot` is `sum` of `zip`, over vectors
represented as a length paired with an index function. **The loop is what is left after
everything else reduced away.**

## The numbers

n=1024, L1-resident, `-benchtime=3s -count=5`, medians:

| | ns/op | vs generated |
|---|---|---|
| `DotNaive` — hand-written, idiomatic | 772.1 | 1.02× |
| `DotHoisted` — hand-written, BCE idiom | 738.1 | 0.97× |
| **`GenDot` — generated by Oroboros** | **758.0** | — |

Generated lands **between** the two hand-written forms, 2% faster than the naive one and 3%
slower than the hoisted one. Both differences are far inside the ~15% noise floor of this
machine.

**Compare within this run only.** The absolute figures differ from
[baseline-2026-08-13](baseline-2026-08-13.md)'s ~1,389 ns for the same code, because this is a
hybrid P/E-core laptop and machine state moves the absolute numbers substantially. The three
benchmarks here ran in one binary, interleaved, which is what makes the comparison meaningful.

Correctness is asserted separately: `TestGeneratedDotAgreesWithHandWritten` requires bit-equal
results against `DotNaive` over 65,536 elements.

## What this settles

[The assessment](../../docs/assessment-2026-08-13.md) said, under *Revised verdict*:

> **Not established: that it works.** Nothing has been compiled. […] The parity claim the whole
> design rests on has never been tested.

It has now, for one program. The reduction pipeline produces a residual that compiles to Go
indistinguishable in speed from what a person would write — and it does so with **no fusion
rules, no optimiser, and no type system**. β and δ, plus a table mapping five primitives to Go
expressions.

That is one program of five, on one target of three. It is not the gauntlet passed. It is the
first evidence that the central mechanism produces competitive code rather than merely plausible
terms.

## What building the emitter found

Six things, all of which are the point of having built it rather than specified it.

**1. Name mangling has two jobs, and conflating them is a bug.** Making a name *legal* for the
target and making it *exported* are different. The first version capitalised every identifier, so
locals came out as `P`, `Acc`, `I`. Caught by the first emission.

**2. ANF arrived for a third time.** [g3 §6](../../docs/derivations/g3-generics.md) and
[g5 §4](../../docs/derivations/g5-bindings.md) each demanded a statement/expression split for
unrelated reasons. The emitter needs it too — `emit` returns *(statements written, expression
returned)*. Three independent arrivals is a strong signal it belongs in the design rather than in
each consumer.

**3. Types are the backend's problem, and that keeps the language clean.** Go needs types; the
core has none. The emitter carries a four-point lattice (`f64`, `int`, `[]f64`, unknown) and
propagates from primitive signatures. **Nothing was pushed up into the source language.** That is
the right division and it should be defended — the pressure to add types to the core will come
from somewhere else, not from emission.

**4. `fold-range` is the one primitive that is a statement, and how that generalises is the open
question.** Every other primitive is a format string with holes. `fold-range` binds two
variables, emits a loop, and returns an accumulator. It is special-cased. What the general form
looks like is the main thing the *next* emitter target will decide.

**5. Escaping closures are a refusal, not a crash.** A bare λ reaching the emitter produces a
diagnostic naming it as an escaping closure and pointing at g6, rather than emitting Go that does
not compile.

**6. The parentheses are noise and harmless.** `(acc + ((p[i]) * (q[i])))` rather than tracking
precedence. Go's parser does not care and neither does its optimiser — confirmed by the number.

## What a binding format has to carry

This was the question that would otherwise have been designed in advance. Read off what the
emitter actually needed:

| Field | Why |
|---|---|
| A **template** with numbered holes | `"%s + %s"`, `"len(%s)"`, `"%s[%s]"` |
| **Argument types** | to type the enclosing function's parameters |
| **Result type** | to type the enclosing function's return |
| **Expression or statement** | `fold-range` is a loop, not an expression |

Four fields covered five of six primitives. The sixth needed code. That is a much more concrete
starting point than a designed format would have been, and it is [ADR 0007](../../docs/decisions/0007-exploration-over-specification.md)
applied to the backend.

## Reproducing

```bash
go run ./cmd/gen examples/dot.oro go gauntlet/go/generated.go
```

```bash
cd gauntlet/go && go test -bench='SmallDotNaive|SmallDotHoisted|SmallGenDot' -benchtime=3s -count=5
```

## What is still not measured

- **Programs 2 through 6.** Only the dot product has been emitted.
- **JS and Java.** One target of three, and JS is the hostile one that
  [ADR 0004](../../docs/decisions/0004-first-targets.md) says surfaces core flaws.
- **The duplicated-read cost.** [concerns.md §1.1](../../docs/spec/concerns.md) claims the
  missing call-by-need discipline is "a silent 2× on the hot loop" in the filter case. That is
  still an unmeasured prediction, and the filter residual has not been emitted. It is now the
  cheapest measurement available.
- **Allocations.** Not reported here; the dot product should be zero and almost certainly is,
  but it was not checked.
