# A partial success's error is relevant

2026-10-07. hamza's decision on relevance-2026-10-07 §6, ADR 0044: the error factor of a partial
success is the relevant 1 + E, `(result (tuple) error)`, and `(option error)` stays only where the
host's algebra makes the error ignorable.

## 1. The algebra

ℕ × (1 + E). As a set, 1 + E is `(option E)` and `(result (tuple) E)` alike, and the retraction is
the same, H = [E], so the host call is unchanged. The role differs: absence of a value against
presence of a failure. Relevance (ADR 0043) is a property of the role, so the declaration with the
failure role carries it.

## 2. The declarations

| | declarations |
|---|---|
| **now `(result (tuple) error)`**, 34 | every `Read`, `ReadAt`, `Write`, `WriteString` of `io`'s interfaces, `os.File`, `io.PipeWriter`; `io.Copy`, `CopyN`, `ReadAll`, `ReadFull`, `ReadAtLeast`, `WriteString`; `fmt.Fprint*` (9); `hex.Decode`, `DecodeString`, `AppendDecode`; `strconv.ParseInt`, `ParseUint`, `Atoi`, `ParseFloat`; `strings.Reader`'s `Read`, `ReadAt`, `WriteTo`; `bufio.Scanner.Err` |
| **kept `(option error)`, with the reason in the file**, 5 + 1 | `strings.Builder.Write`, `WriteRune`, `WriteString`, and `WriteByte` (moved from a relevant unit + E): "a nil error", always; `bufio.Writer.Write`, `WriteString`: sticky, reported by `Flush` |

`fmt.Print*` is unchanged: its declarations already forget `(n, err)`.

Seven modules gained `(use result)`, which the loader names when it is missing.

## 3. The programs

- **Emission is byte-identical** across all 532 runs.
- `examples/lines/lines.oro`: three `Fprint*` to its `bufio.Writer` and one to standard error now
  write `(ignore …)`. Each states its reason: the writer's errors are sticky and `Flush` reports the
  first; or the run is already failing and standard error is the last channel. `ok?` and `finish`
  read `Scanner.Err` and the parses through `result.ok` and `result.err`.
- `acceptance/strconv`, `encoding-hex`, `errors-os` reproduce their reference outputs. One
  real discard was found: `encoding-hex`'s `projection` dropped `DecodeString`'s error unread, and
  now says why (the input is a valid encoding).
- Three emit tests that dropped an error in passing write `(ignore e)`. The residual each one tests
  is unchanged, because `ignore` erases.

## 4. What failed first

- A program still reading the error as an option, `(case o none … (some e) …)`, is refused with an
  **arity error**, because `case` does not check its scrutinee's variant before reduction: a
  three-component result met a two-parameter eliminator. It is correct and unhelpful. A type-directed
  message is not built.
- The relevance message named a reduced value by its head, *the result of if*. It now names the
  call when the program wrote one, and otherwise the binder: *the value bound to e*.

## 5. Witnesses

`emit/partial_test.go`, on the Go target: a dropped `File.Write` error and a dropped `Atoi` error are
refused; read or ignored, accepted; `strings.Builder`'s and `bufio.Writer`'s drops accepted. Each of
four planted faults is caught: `File.Write` or `Atoi` declared an option again, and `Builder.Write`
or `bufio.Writer.Write` declared relevant.

## 6. Not built

- A type-directed refusal for a `case` on the wrong variant (§4).
- The relevance message names the binder, not its source line.
