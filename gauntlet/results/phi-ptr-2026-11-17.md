# φ's third kind: a table's pointer as `nonnull dereferenceable(8) align 8`

2026-11-17. Item 5 of [assessment-2026-11-16](../../docs/assessment-2026-11-16.md) §5, after
[phi-range](phi-range-2026-11-17.md) and [phi-samesign](phi-samesign-2026-11-17.md).

**A table or string at a printed function's boundary carries `nonnull dereferenceable(8) align
8`.** Neutral where measured, like the first two kinds.

## 1. The algebra

- **A table's pointer is a region's.** A table or string value is the address of one of:
  - a region `region`/`region_raw` answered, which traps on null (`if llvm.is_null(p) {
    llvm.trap() }`) and holds n·w + 8 bytes and the zero byte past them (ADR 0092, 0117), 8-aligned
    by HeapAlloc and VirtualAlloc;
  - a dead region's token handed to `reuse`, the same region;
  - a string literal's global, `{ i64, [n x i8] }` with its NUL, `align 8`.

  Each is non-null and 8-aligned, and each holds its 8-byte length, so `dereferenceable(8)` claims
  only the length's word, which a table of no elements has too.
- **What is excluded**:
  - a segment is a rule and never an interior pointer at a boundary (a segment at a kept boundary
    is not built);
  - a dead region's token, which may be null, is a loop's variable, never a function's parameter;
  - a cell (an `alloca`'s address) and a raw `ptr` (a Win32 handle, a C string from Win32) take no
    attribute.
- **Why 8 and not more**: a table's region holds n·w + 9 bytes, and n is a run-time value, so
  `dereferenceable` can state only what every n gives. `dereferenceable_or_null` would add nothing,
  since the pointer is never null.

## 2. The witness

`TestATablesPointerIsARegions` (ir/llvm), on the printed text:
- a table parameter takes the attribute, and an integer none;
- every `dereferenceable(n)` claims n ≤ 8;
- **THE PLANTED FAULT** (`PlantTableAttrWide`) claims 4096 bytes, past a short table's region, and
  the second assertion catches it.

The witness reads text, as samesign's does: a false `dereferenceable` would let LLVM speculate a
load past a short region, which shows only where LLVM chooses to speculate. The rule's premise,
that every table's region holds its length word, is what is checked.

## 3. What failed first

1. **The witness's own regular expression** for "an integer takes a pointer's attribute" matched
   across `define i64 @f(ptr nonnull`. It now requires the attribute right after the integer's
   type (and its `range`).

- **Compile time**: 1.00× the baseline in the reviewing run. A second sweep kept 5 of 5 suspects,
  and none was confirmed slower serially against `gen` at e88addc.
- **Run time**: serial, interleaved, 11 rounds, whole processes, quiet machine, medians (minima),
  ms, against HEAD in a worktree. Outputs are identical, and so are executable sizes.

  | program | before | with the attributes | ratio |

  | `fib(10⁵)`, printed | 30.7 (30.2) | 31.0 (30.0) | 1.009 |
  | `cnt` | 437.7 (436.6) | 440.3 (434.1) | 1.006 |

- **The gauntlet's generated cases**: all 22 agree with Go in both builds. Five interleaved rounds,
  medians, ratios after/before: g1 dot 1024 1.004, dot 65536 1.002, g2 centroid 0.993, g3 sum
  1.000, g6 alloc 0.990, g6 into 1.003, g7 tok 1.002.
- **Emitted text**: 35 windows files and 7 of the gauntlet's 33 change, and with the attribute
  removed every one is identical to the baseline. Go, JavaScript and the JVM are byte-identical.
  Accepted with `-accept`. `TestAnExportsNumeralIsANumeralsTable` asserted `define ptr @nat.add(`,

- **Rules made less general**: none.

## What was not built

- **`noalias`** on a `linear` buffer, the uniqueness ADR 0018 proves. It is the kind most likely to
  pay, for a kept function writing a lent buffer while reading another table, and it needs a
  witness that LLVM's alias analysis reads.
