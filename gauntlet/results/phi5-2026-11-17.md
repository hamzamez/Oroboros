# φ's remaining kinds: `memory(…)`, `willreturn`/`mustprogress`, `noundef`, measured and not built

2026-11-17. Item 5 of [assessment-2026-11-17](../../docs/assessment-2026-11-17.md) §5, "φ maximal"'s
last three kinds. A measurement: no compiler code changed.

**None of the three changes what LLVM does on the corpus in a way that pays, and the algebra says
why.** An attribute matters only to a consumer that lacks its fact. Here LLVM either computes the
fact itself, or has no consumer for it:
- **`memory(…)`** is the same join LLVM's `function-attrs` computes over the same module;
- **`willreturn`** reaches no caller;
- **`noundef`** on a parameter removes no freeze, and on an element load changes 3 of 105 files'
  machine code, each neutral when timed.

Each attribute is a claim LLVM may exploit if false. A claim with no consumer is a soundness
obligation that buys nothing. So none is built, per ADR 0008 and phi-range's rule: the next kind is
chosen by a measurement that shows LLVM missing a fact. Each kind's theorem and premise is kept in
§3 for its trigger.

## 1. What LLVM already infers

Every function the windows printer writes is `define internal` in one module (exports aside), so
LLVM's `function-attrs` pass sees all of it at -O2. Each of the 105 windows files in the emission
baseline was compiled with `clang -O2 -S -emit-llvm`, and each function surviving inlining
classified (`scratchpad/phi5/survey.py`, `pure.py`):

| surviving functions, 141 | count | LLVM infers |
|---|---|---|
| call an external (kernel32) function | 114 | neither `memory(…)` nor `willreturn` |
| call nothing external, no loop | 18 | `memory(…)` and `willreturn`, all 18 |
| call nothing external, a loop | 9 | `memory(…)` on all 9; `willreturn` on none |

- **Inlining removes most kept definitions** (ADR 0113) before attributes could matter: fib keeps 2
  of its functions.
- **The 114** are blocked by a call LLVM knows nothing of (HeapAlloc through `region`, WriteFile,
  ReadFile). Its effects are kernel32's, a fact about the host, which no proof of the program
  supplies.
- **The 9 with a loop are all exports**: `gen_dot`, `gen_run`, the gauntlet's functions, called
  from another object. Size-change termination proves each loop, so `willreturn` would be
  derivable, but without LTO no caller in their module reads it.

## 2. The three measured

- **`memory(…)` from the effect discipline.** The function's effect is the join, in the lattice
  none < read < readwrite per location kind, of its statements' effects (ADR 0010, 0070). That is
  the computation `function-attrs` does. On the 27 functions our proofs could speak for, LLVM finds
  the element on 26 itself. The 27th, `shortcircuit-win`'s `gen_main`, has no loop and no external
  call, and its result reaches nothing. **Not built: redundant.**
- **`willreturn`/`mustprogress` from SCT.** It adds to the 9 exports of §1 only. **Not built:
  unobservable without LTO.**
- **`noundef`.**
  - On every parameter and result: identical machine code on the seven big-integer and `freq` files.
    The 91 freezes of `big-sign`, and the others, are of **loads**, not of parameters.
  - `!noundef` on every load of a table element, whose premise holds (a table is zeroed at birth,
    or born full with every element written first, ADR 0097, and nothing stored is poison since
    every flag is proven): machine code changes in 3 of 105 files.
    - In `fact` and `power`, 4 and 9 lines.
    - In `freq`, 1,769 lines, and freq is 0.987 of its time on a 60 KB input, 100 runs per sample,
      ten rounds: inside the noise.

  **Not built: neutral.**

## 3. The theorems, for their triggers

- **`memory(…)`**: the effect of a function is the join of its statements'. A host call is the
  declaration's effect, unknown when undeclared. Trigger: a module boundary LLVM cannot see across
  (a library compiled apart, `define` without `internal`), where the join is ours to state.
- **`willreturn`**: every loop proven by size-change termination, every callee `willreturn`, and no
  path into ∅ (`abandon`, `exit`, `llvm.trap`, a checked form's trap): a trap is not a return.
  `mustprogress` is implied by the same proof. Trigger: LTO, or a caller in the module.
  - Its planted fault: claim it of a function that can trap, and LLVM may delete an unused call, so
    the program prints where it should crash.
- **`noundef`**:
  - **on a value**: no flagged operation unproven, no undef reaching a use, and `selects`'
    speculated poison only into its `select`;
  - **on an element load**: the table zeroed or born full, and its stores non-poison.

  Trigger: a measurement where a freeze costs.

## 4. The host's side, measured too

What blocks inference on the 114 is kernel32's effects. Stating them on the declarations (the
experiment's form: HeapAlloc `memory(inaccessiblemem: readwrite)`, HeapFree the same plus
`argmem`, GetProcessHeap `memory(none)`, RtlZeroMemory `memory(argmem: write)`, each `nounwind
willreturn`) changes machine code widely: thousands of lines in a dozen files. Timed:

- **the gauntlet** (two harnesses, all 22 cases agreeing with Go on both, five rounds): every
  ratio between 0.948 and 1.039, the unchanged files and a hand control among them at 1.037 and
  1.039: neutral;
- **the big integers** (nine rounds): 20000! 1.020 and 1.017, fib 0.989, pair 1.020: neutral.

**Not built.** These are Win32's facts, and would be Win32's declarations' (ADR 0126's headers), each
read off its documentation, with no measured gain.
