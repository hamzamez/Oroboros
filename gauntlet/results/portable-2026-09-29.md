# The portable layer is deleted

2026-09-29. `targets/portable-go.oro`, `portable-js.oro` and `portable-java.oro` are deleted. So are
ten of the fourteen top-level `examples/*.oro`, which were written against those files. The last
commit that holds them is `870de46`.

## 1. What was measured first

**The layer could no longer compile its own programs.** Every top-level example was compiled with
`cmd/gen` against each of the three portable targets:

| outcome | examples |
|---|---|
| compiles | `converge`, `search` |
| refused at lowering: *"a λ in value position is a closure"* | `dot`, `smooth`, `report`, `generic`, `wordcount`, `filter`, `norm`, `stencil`, `centroid`, `build-vec`, and `modules` on JS |
| refused by `aindex`'s precondition | `modules` on Go and Java |
| not a portable program (it calls `go/fmt`) | `hello` |

It is the same at `f8c07f2~1`, the commit before step 4a deleted the term backends. So the break is
not recent. It came when the IR's printers became the default.

**It is a signature, not a bug.** A target is a model of a theory (ADR 0021). The portable signature
has second-order symbols: `fold-range` takes a step function S × ℕ → S. The IR's Σ is first-order,
because the dynamic level is tables and loops (closures-direction.md). So no backend can interpret
`fold-range`, and a program that uses it has no realization. The only way to revive the layer
would be to rewrite `fold-range` as a `loop`. The host-native targets, `lib/`'s `provides` cells and
per-program portability (ADR 0026) are what replaced it.

**Nothing checked it.**
- `cmd/check`'s sweep covers `go`, `js`, `java` and `windows`, never a portable target.
- Of the fourteen top-level examples it pins, thirteen were pinned as *refused on all four*,
  because their names are unbound there. That looks like coverage and checks nothing: a path
  nothing runs is a path nothing checks.
- The gauntlet reads `examples/native/`. The native targets' header comments said the portable files
  were "kept because the gauntlet is written against it", and that had stopped being true.

## 2. What changed

- **The three target files are deleted:** 655 lines.
- **Ten examples are deleted:** 206 lines.
  - Five have native twins in `examples/native/`: `centroid`, `generic`, `report`, `search` and
    `wordcount`. (`dot` and `smooth` have twins too, and are kept for the book.)
  - Five have none. `build-vec`, `converge`, `norm` and `stencil` show nothing another program or
    test does not: `search`, `smooth` and the refinement tests cover them. `filter` is ported. (The
    sixth with no twin, `modules`, is kept for the book.)
- **`filter` is ported** to `examples/native/filter-go.oro` (29 lines). It is the one program in the
  **push** direction, a collection represented as its own fold, λ step z. `dot` and `smooth` are pull
  vectors.
  - Staging erases every λ of the pipeline into one loop with the test inside it.
  - The read `a[i]` is made once. The portable original duplicated it; call-by-need shares it now.
  - It is 1 of 1 operations and 1 of 1 loops proven. On `[1.5, −2, 3, 0, −0.5, 4]` it gives 8.5, and
    on the empty slice 0.
- **Kept, for the book:** `examples/modules.oro`, `dot.oro` and `smooth.oro`, and `lib/num/vec.oro`,
  which two of them import. `docs/book/` cites them, and the book and its `tutorial*` targets are
  updated together, later (hamza). `-target=blas` still reduces `modules.oro` and `dot.oro`, as the
  book says. Its `-target=go` commands were already refused before this change.

## 3. The tests, respelled

About 24 test functions in `check_test`, `refine_test`, `target_test` and `backend_test` loaded a
portable target.

**Pointing them at `targets/go` unchanged failed five.** The refusal tests kept passing, because
*"aindex is not bound"* is also a refusal. So each one was respelled rather than re-pointed:
- onto the native target, using the language's own table operations (application, `len`, `loop`, `+`,
  `>=`) and a host name only where the language has none (floats);
- every refusal test asserts its reason: *"is an indexing, and … does not follow"*, the conflicting
  types, the arity.

Every rule these tests rely on has a planted fault:

| rule | planted fault | caught by |
|---|---|---|
| an index's upper bound is demanded | only `0 ≤ i` demanded | `RejectsOutOfBounds`, `RejectsASecondArray`, `OpaqueAssumptionIsKept`, `LoopGuardsDischargeBounds`, `StridedIndexPastItsGuardIsRefused` |
| an index's lower bound is demanded | only `i < len` demanded | `RejectsBeforeTheStart`, which is new. **No test demanded the lower bound before.** |
| a goal must follow | every goal entailed | all five refusal tests above |
| a strided index has a certificate | `scaleTo` and the Farkas elimination both disabled | `StridedIndexIsProvable` |
| `agree` detects a conflict | accepts everything | `RejectsTheMeasuredBug`, `RejectsConflictingUse` |
| a conditional's branches agree | not compared | `RejectsMismatchedBranches` |
| a use infers a parameter's type | inference off | `RejectsConflictingUse` |

**Two routes, one certificate.** `scaleTo` and the Farkas elimination each prove every strided case
alone, so disabling either one by itself changes no outcome. The old portable strided test had the
same property: its guard is written in 4k, so it needs no multiplier at all. A new case, "stride 4,
guard on k", needs the multiplier 4 (`k < n`, `len a = 4n`). Only disabling both routes fails it.
`scaleTo`'s soundness half, which refuses a negative or fractional multiplier, is pinned by its own
unit test.

**The opaque assumption, measured.** The first respelling, `k·k < len a`, was *proven*. That is
right: for k ≥ 0, k ≤ k² < len a. The test now uses `len a < k·k`, which does not imply the
obligation, and asserts that the refusal reports it as assumed.

Also deleted:
- two `goTarget` helpers that loaded `portable-go.oro` and were never called;
- `dotSrc`, a constant that was never used;
- `TestJSTargetIsUntyped`. Its claim, that JavaScript declares no types, was true of the portable
  file and is false of `targets/js`, which spells `int`, `f64` and `bool`
  (`TestNativeTargetsAreThreeStructural` pins that).

## 4. Found, and fixed the same day

**Fixed in [tabletype-2026-09-29](tabletype-2026-09-29.md)**, which types a table form by its
constructor (types.md §3.1). What was found:

**A signature is not checked against a table-valued body.** The checker types a term by its
primitive's declared result. `array`, `table` and `build` declare none, so their type is unknown,
and unknown agrees with everything. On the native Go target, with `(sig bad ((a slice-float64)) f64)`:

| body | outcome |
|---|---|
| `(go.make-float64 3)` | refused by the checker: *"slice-float64, but f64 is required"* |
| `(array 1.0 2.0)` | **emitted**, as `func XBad(v0 []float64) []float64`: the claim is false and nothing says so |
| `(table 3 (fn (i) 1.0))` | refused at lowering: *"a table rule that was never allocated"* |
| `(build b 3 b)` | refused by the IR verifier: *"W9: %2's type array any is not final"* |

The first row is correct. The second is a wrong answer: an exported claim that the program does not
keep. On Go the host's compiler would catch a Go caller; on JavaScript a caller that expects a
number gets an array. The last two refuse for the wrong reason, and their messages are internal.

The portable test used `make-vec`, a declared primitive with a declared result, so it never reached
this. It is the same shape as the lesson that recurs: a shape an analysis does not know is a shape it
does not check.

## 5. Gates

- **Emission.** The 40 removed entries (ten sources × four targets) and `filter-go`'s four new ones
  are the only changes. Every other emitted file, outcome and refusal is byte-identical. The proof
  counts are 1,997 of 2,042 operations and 358 of 376 loops; the +1 of each is `filter-go`. The
  removed examples contributed nothing, because they were refused before any counting.
- **The rest.** The compiler, IR (251 of 251) and differential steps pass, and `go vet ./...` is clean.
  Compile time is 1.04–1.06×, within noise.
