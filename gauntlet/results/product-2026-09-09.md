## 1. The type is the term's spelling

```lisp
(sig f ((sp (array (array (int 0 65535) (int 0 65535))))) int …)

(def sbeg (fn (sp w) ((sp w) 0)))
(def send (fn (sp w) ((sp w) 1)))
```

`(array V)` names one index set — `Fin n` for an `n` nobody has stated — so it is
homogeneous and its length is dynamic. `(array A B)` names `Fin 2` exactly, so
the family may vary. **Arity disambiguates, and it is not a trick**: one argument
or many is precisely the static/dynamic distinction tables.md §5.3 says forces
homogeneity, written in the type.

Canonically `prod(A, B)`, and it is **delimited** where every other canonical
type is space-separated — because a component may itself contain spaces
(`int 0 255` does), and `MapTypes` gets away with splitting on the first space
only because a map's key is always one token.

## 2. Flattening is currying, and that is the whole pass

products.md §6 derives the representation from one isomorphism:

```
    Π_{(i,j) ∈ I×J} V  ≅  Π_{i∈I} Π_{j∈J} V
```

Right to left is an array of k-tuples; left to right is a flat table indexed by
`k·i + j`. The pass is that isomorphism in four positions:

```
((t i) j)              ->  (t (+ (* k i) j))          projection
(set b i (array v…))   ->  k nested stores            construction
(set (b i) j v)        ->  (set b (+ (* k i) j) v)    field update
(len t)                ->  (/ (len t) k)              elements, not slots
(build n f)            ->  (build (* k n) f)          capacity in slots
```

**The field update is set applied to a PROJECTION**, the exact dual of read
applied to one — one surface, both directions. Without it a program that changes
one field has to rewrite the whole element, and rewriting a field you did not
change is how a swap becomes a copy (effects.md §7c).

**Why the field index must be static is not a restriction we impose.** tables.md
§5.3: *a dynamic index forces homogeneity and forces existence, and it is the
same condition doing both.* Read backwards it **defines** the product.

### 2.1 Why the flat representation, and why that is not a choice

products.md §6 says which of the three isomorphic forms is emitted is a TARGET
decision, and §8 says not to pick one by argument. This picks the flat one for a
reason that is neither: **it is what `tree.oro`, `freq.oro` and `kara/core.oro`
already write by hand**, so adopting the type cannot cost speed on any host. The
array-of-structs and struct-of-arrays forms are a target declaration and a
benchmark, in that order, and they are not in this build.

## 3. THE ARITY TRAVELS WITH THE BUFFER, and that is where the work was

The rewrite is small. Knowing *which* tables are products is not, and the reason
is ADR 0018's threading:

- a `build`'s binder is almost always handed straight to the `loop` that fills
  it, so the stores are to the **loop's** variable, not the binder;
- a helper returning a table becomes `(let (build …) (fn (sp) …))` once reduction
  has inlined it, so the arity has to cross a `let`;
- and detection reads the arity off the stores, so it has to follow the same
  aliasing the rewrite does — in the other direction.

Each of those was found by a program failing to flatten, not by design. The
first version knew the arity for exactly one term and lost it immediately, which
is every program anyone would write.

## 4. THREE FACTS THE REFINEMENT LAYER DID NOT HAVE

`((sp w) 1)` becomes `(sp (+ (* 2 w) 1))` guarded by `w < (len sp)/2`. Proving
that index in range needed three things, and the test fails if **any one** is
removed:

**A quotient is an ATOM.** A division was outside the linear fragment
*entirely* — not opaque, absent — so `asLinear` refused it and a guard mentioning
one bounded nothing at all. `w < (len sp)/2` is a perfectly linear fact about an
unknown; what is nonlinear is the relation between that unknown and the length.

**`k·(x/k) ≤ x` for a non-negative x and a positive literal k.** A **declared
sound axiom, never a search** — decidability-map.md's rule for the nonlinear
fragment, and the same shape as the existing `x ≤ x*x`: the operation is outside
the fragment and it entails something inside it. Restricting x to a LENGTH is
what makes `x ≥ 0` free rather than assumed.

It is seeded **once at the root**, and that is not tidiness: a quotient in a
loop's *guard* never reaches the walk, because `loopLike` turns a guard into a
fact directly. An axiom added where the term is met is an axiom the one program
that needs it never sees.

**One Fourier–Motzkin elimination step.** For `a ≤ 0` and `b ≤ 0` sharing a
variable with opposite signs, `|b_v|·a + |a_v|·b ≤ 0` no longer mentions it.
Here `2·(w < q) + 1·(2q ≤ len)` gives `2w + 2 ≤ len`. Neither one fact scaled —
the existing single Farkas multiplier — nor two facts summed can reach it,
because the combination needs a **different multiplier on each**. This is the
principled form of the rule json-tree-bench added for a stride, arriving at the
same shape from the other side.

**All three are provability only: 70 of 70 emitted files were byte-identical**
after they landed, before any program was rewritten.

## 5. `freq.oro` rewritten, and the honest measurement

products.md §11 item 1: *rewrite either table as an array of records and count
again. If neither number falls, §5's argument is wrong.*

Both of `freq.oro`'s strided tables — the span table (start, end) and the
distinct table (word, count) — are now arrays of pairs.

| | before | after |
|---|---:|---:|
| strided index expressions | 16 | **2** |
| `cli` clamp sites | 25 | **22** |
| `cl`, `pat` | 2, 7 | 2, 7 |
| code lines | 158 | 155 |
| integer operations bounded | 951 of 951 | **872 of 872** |
| **emitted Go, lines** | **2,105** | **1,895** |

**The two surviving strides are the merge sort's `(* 2 w)` width doubling**,
which was never a record. Every stride that encoded a product is gone.

**And the clamp answer is more precise than the question.** Five `(cli (* 2 nd) …)`
disappeared and two `(cli nd …)` replaced them: **the clamps the product removes
are INDEX clamps, on a slot the program computed; the clamps that survive are
VALUE clamps, on what a table read returns.** Those are frozen-2026-08-28's
stratum 0 and have nothing to do with products — a word index and an occurrence
count are both values read out of a table, and no type makes them bounded.

**The emitted code is 10% smaller**, and the diff says why: the compiler clamps
the *element* index and generates the stride from it, where the program had to
clamp the *strided* index. Clamping once and multiplying is shorter than
multiplying and clamping.

**Correctness is unchanged**: byte-identical to `sort | uniq -c | sort -rn` on
eight real files, plus the empty file, a file with no letters, a missing file,
no argument, and `a`, `a a`, `a a a`, `the The the`.

## 6. Four targets

The differential case `product` builds twelve pairs, writes each with
`(array a b)`, reads fields with `((t i) j)` and returns a position-weighted
checksum: **1079 1001 845 on go, js, java and windows**, computed by hand before
the program was run. Verified to fail against two bugs — the projections swapped,
and the fields stored in the other order.

**There is no clamp in that program**, which is the strongest thing it says:
every index is a loop variable the guard already bounds, and the stride the
compiler generates from it is proven from that same guard.

One target detail is recorded in the case rather than worked around silently: the
checksum carries a `+ 14` bias because `win/fmt.print-int` prints a blank line
for a negative number and is within its rights — refinements.md §6b names that
exact gap. Without the bias windows built, ran, exited 0 and printed nothing.

## 8. What this leaves

**The heterogeneous product has a type and no representation.**
`(array int string)` parses, canonicalises and type-checks; `prodTable` declines
it, so it is refused where it tries to exist rather than flattened into a slot
that cannot hold both. That is products.md §8's layout machinery, and it is what
the Win32 `GUID` — 174 names, the single largest in that survey's *struct by
value* bucket — actually needs.

**AoS against SoA is untouched and still owes a measurement.** §2.1.

**A product may not be a scalar value.** It is an element type; a parameter or a
lone result of product type is not in this build, and `values` remains the
negative product at a function boundary.

**And one pre-existing limitation surfaced.** A clamped value used twice is
let-bound by call-by-need, and the refinement layer loses the clamp's bounds
across that binding — so `(let (clamp r) (fn (i) … (t i) …))` cannot discharge
what `(t (clamp r))` can. It is not caused by products and it is not fixed here;
it was found by writing the differential case, and the case is written without
the clamp because the guard is enough.
