# const T* as the call's ref(x), the mode `in` withdrawn (ADR 0130)

2026-11-18. hamza, on ADR 0129's `rc ∈ windef.RECT in`: "why do we have in? what did the language
fail to express for us to add it", then "go ahead with ref(x)".

## 1. The answer

Nothing. `rc` passed by address and `pt` passed by value both mean a record value passed (ADR 0084
P2). They differ in how C receives the argument, which is representation, and a set has none
(ADR 0049). `in` was a mode no program can observe:
- `linear` and `inout` change what the program sees, a uniqueness it keeps or a value written back;
- `in` changes only the machine code.

ADR 0118 already states how a C argument is formed, as a linear term over the parameters in the
host clause, and `&x` of a fresh copy is one more such term.

## 2. What was built

- **`ref(x)`**, a C argument term:
  - read by the target reader (`core/jreadtarget.go`);
  - resolved as x's one occurrence (`emit.resolveCArgs`, `CRef`);
  - refused where x's set has no C layout;
  - printed as the copy's address (`ir/llvm`'s `cCall`).
- **The by-value decision moved after the terms resolve** (`cPrototypes`): `Prim.ByValue` is every
  struct parameter not under `ref`. A struct parameter's set is its bare record set in the unfold.
- **`in` withdrawn**: from `core/jparse.go`, `jreadtarget.go`, `TypeName`, `emit/alias.go`, j.md
  §1.4 and §2.4, and the inventory. `ref`'s inventory row now holds both its senses, a boxed
  representation and this argument; 180 words, 147 specified, as before ADR 0129.
- **The declarations**:
  - `RegisterClassA(wc ∈ WNDCLASSA)` with `call "RegisterClassA"(ref(wc))`;
  - `PtInRect(rc ∈ windef.RECT, pt ∈ windef.POINT)` with `call "PtInRect"(ref(rc), pt)`.

## 3. Measured

`PtInRect`'s four points answer `1 0 0 1` on windows and windows32, and the emitted calls are
unchanged: `(ptr, i64)` on x86_64 and `(ptr, ptr byval([8 x i8]) align 4)` on i686.
`RegisterClassA` registers and finds its class on both (`TestACStringFieldIsLent`). The prototype
check passes with `ref(wc)` read as the copy's address.

## 4. The test

`TestAStructIsPassedByValue` gains `emit.PlantRefByValue`: the rectangle under `ref(rc)` passed by
value instead, its sixteen bytes on i686's stack where `PtInRect` reads an address. The program must
then fail to build or to run.

## Paid and bought

- **Compiler lines**: `emit/target.go` +35 (`CRef`, its check, the by-value decision, a plant);
  `core/jreadtarget.go` +10; `ir/llvm` +3. Removed: `in`'s 40 lines in `core` and `emit`.
- **Test lines**: +30 (`ref`'s fault and a runner that may fail).
- **Emitted text changed**: none. Every program is byte-identical, 481 emitted and 215 refused, and the
  full check passed every step.
- **Language**: one contextual word fewer in a header, `in`. One argument term more in a host
  clause, `ref(x)`, a second sense of an existing word.
