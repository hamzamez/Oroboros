# release-2026-11-09: a table released at its death on the LLVM layer

6b′ step 3, R1a (hamza, 2026-11-09: "I agree to the recommendations. add the steps to the plan. and
do the first one"). ADR 0096, ir.md W11, llvm.md §4. Before this, nothing on the LLVM layer freed
memory: every table any windows program made stayed until the process ended.

## The algebra

**A frozen table's view is counted fractions.** ADR 0084 gave a frozen buffer the persistent
permission, linear logic's !A, which may be dropped. That leaves `free`'s full permission never in
hand. Counted fractions instead (Boyland 2003; Bornat et al. 2005): freezing splits the permission
into one fraction per reference, each reference's death returns its fraction, and at the last death
`free`'s precondition holds. Where the references are SSA names the count is static, and the last
death is the point after the last use (integers-research Proposition 3).

**Ownership** is the greatest fixed point of three rules (`ir/release.go`):
- a table is a **birth** (a `build`, `tabulate` or array literal with its storage), or a loop
  parameter or a join's result whose every incoming value is owned and moved in;
- it is **moved** at most once (a loop's `init`, a `continue`, a `break`, a `yield`, a `the`), nothing
  uses it after the move, and no loop lies between its definition and the move;
- everything else **borrows** it: `len`, an index, a call that returns no table. Any other use
  escapes.

A π on a table is a renaming with a fact, so its name is the same reference as its source.

**Placement.** An owned table is released on each path where it is not moved, after its last use
there. A branch the table is live into gets a release in each arm; an arm that moves it gets none.

**release ∘ region = id.** `release` is an operation of the IR, `release(storage(t), len t, w)`.
`storage : Table → Region` is the new operation `storage`, the inverse projection of ADR 0092's
`store`. ι substitutes `lang.release`, b = n·w + 8, which calls Σ_OS's new header `release(p, b)`.
windows defines that by the rule `region` chose by: `VirtualFree(p, 0, MEM_RELEASE)` from 64 KiB,
`HeapFree` below. n·w + 8 is proven from the new fact `len(a) <= 2^47 − 9`, x64's user space being
2⁴⁷ bytes, on the model of the JVM's `arraylength` bound.

## What was built

- **The pass** `ir.Release`, after the first `Storage` and before ι (`ir/pipeline.go`).
- **The check**, W11 (`ir.CheckReleases`), run right after the pass and re-deriving each release's
  ownership: owned, moved nowhere on its path, used by nothing after, inside no loop it is defined
  outside of, released once on every path.
- **The operation** `storage` (`ir/ir.go`, typing, the verifier's arity, the LLVM printer: a no-op
  `getelementptr`).
- **The target**:
  - kernel32's `VirtualFree` and `HeapFree` as prototypes;
  - Σ_OS's fourth header `release` and windows' definition of it;
  - `lang.release`, with `realize release = lang.release`;
  - `fact max_len` on windows.

## Witnesses

- **`TestATableIsReleasedAtItsDeath`**: a table carried round a loop, a fresh table made from it each
  iteration, and two tables joined at an `if`, at least four releases, every one accepted by W11. A
  table made before the loop and moved inside it on one iteration is not owned, so it is a leak, not a
  refusal.
- **`TestAReleaseW11RefusesIsAFault`**, three planted faults in the pass, each refused by W11:
  - a release after the first use, not the last;
  - a release on a path that moved the table;
  - a move admitted inside a loop the table is defined outside of.
- **M1** (integers-research §7), best of three runs on windows:

  | iterations | peak before | peak after | time before | time after |
  |---|---|---|---|---|
  | 10⁶ limb additions | 278 MB | 3.5 MB | 179 ms | 123 ms (0.69×) |
  | 10⁷ | 2,747 MB | 3.5 MB | 1,672 ms | 972 ms (0.58×) |

  Peak memory is now flat and the output identical. The time fell too. The likely reading, not
  separately measured: the heap now hands back blocks already committed and in cache, where every
  addition used to touch fresh pages.

## What failed first

- **W5 refused a table flowing into `VirtualFree`'s `ptr`**, rightly. Relaxing "a table is a pointer"
  would let any program hand its table to a C function as a raw region, which the views forbid. What
  was missing was the storage algebra's projection, `storage`, an operation of the IR and not a host's.
- **The witness could not fail at first.** Its program used each table once per region, so the
  first-use fault changed nothing, and it moved nothing inside a loop. Each fault was then given a
  program that exercises it. Two tries failed on the language itself before that: a rule as a loop's
  initial value is not materialized (the lowering gap of llvm-render-2026-11-07), and β shared two
  `len(t)` reads into one.
- **A rule stronger than the algebra.** The pass first refused ownership to a table moved into a
  target that was not owned, such as a function's escaping result. On the path where it is moved, the
  target takes the reference, and the pass releases nothing there. On every other path its reference
  is the only one. So the rule only made those paths leak (`fact-limbs` released nothing). W11 never
  had it. It was removed.

## What was measured

- **The corpus, statically**, counting the emitted windows files' allocation and release sites (each
  is two calls, the two allocators):
  - **the check's counts**: unchanged, 5,120 of 5,174 operations and 522 of 546 loops;
  - **what is still not released**, each for its reason:
    - a table a function returns (`kara/workspace`, `smooth-go`), which escapes to the caller;
    - the crash's newline (`expect`, `nulfree`, `utf8-widths`), made by a term on a path that never
      returns.
  - Strings from the helpers (`string_of`, `++`, `ascii`) are not tables the pass knows, so they still
    leak: R1e.
- **Emission**: 14 windows programs change, each by its releases. Every release is outside the
  loops that made its table hot. A release's instance also prints its header's membership tests as
  values nothing reads, as `allocate`'s instance does (a pre-existing shape of term instances); under
  `clang -O2` none remains. The gauntlet is byte-identical, and compile time is 1.00×.
- **The windows sieve**, the one gauntlet program on windows, built at the baseline in a worktree and
  with releases, 15 alternating runs each: the same output (1798400), a median of 32.90 ms against
  33.14 ms, 1.007×, inside the noise floor. Its two releases follow the loop.

## Not done here

- **R1b–R1e**: same-size reuse, frame slots for tables of static length, the data stack, strings and
  containment.
- **A table a host makes** (none on windows yet), and **a table inside a table**, both not owned.
