# The remainder: one law in three encodings becomes four facts, and the interval layer induces its transfer

2026-09-15. [spec/theories.md §7.5](../../docs/spec/theories.md),
[facts.md §3](../../docs/facts.md). The second slice after [langfacts-2026-09-15](langfacts-2026-09-15.md).

## 1. The law, and where it was written

Truncating division gives `a = b·q + r`, with `|r| < |b|` and `r` taking the dividend's sign
(integers.md §4, measured agreeing on four hosts). facts.md §3.1 located that law three times in Go,
one for each consumer:

| | encoding | consumer |
|---|---|---|
| F6 | `remI`, `|a % b| ≤ min(|a|, |b| − 1)` | the interval analysis |
| F7 | `storedRange`'s literal divisor | element narrowing |
| F8 | the `big%-small` transfer | the bignum reports |

It is now four F-B facts in `emit/lang-facts.oro`, on the one trigger `(% a b)`. `|·|` is not linear,
so each bound is split into sign cases: two clauses bound the remainder by the divisor, and two by the
dividend.

```lisp
(fact rem-divisor-pos ((a int) (b int)) (when (<= 1 b))  (and (<= (- 1 b) (% a b)) (<= (% a b) (- b 1))))
(fact rem-divisor-neg ((a int) (b int)) (when (<= b -1)) (and (<= (+ b 1) (% a b)) (<= (% a b) (- -1 b))))
(fact rem-dividend-nonneg ((a int) (b int)) (when (<= 0 a)) (and (<= 0 (% a b)) (<= (% a b) a)))
(fact rem-dividend-nonpos ((a int) (b int)) (when (<= a 0)) (and (<= a (% a b)) (<= (% a b) 0)))
```

`remI`, `storedRange` and `big%-small` all call one induced transfer over those facts.

## 2. Theorem T is not enough, and the repair is exact

facts.md's Theorem T applies a fact where its guard holds on **all** of the box `γ(X̄)`. A divisor in
`[−7, 7]` satisfies neither `1 ≤ b` nor `b ≤ −1`. So a meet of facts alone gives `⊤`, where the
hand-written rule gives `|a % b| ≤ 6`. The induced transfer would prove less than the Go, which is
exactly theories.md §7.10's refutation condition.

**The repair is case splitting, and it is exact rather than a heuristic.**
- A single-variable guard `c·x + k ≤ 0` is a half-line, so it cuts `x`'s interval at one point: at
  `⌊−k/c⌋` for `c > 0`, and at `⌈k/|c|⌉ − 1` for `c < 0`.
- Cutting every argument at every guard's point partitions the box into cells, on each of which
  every guard is decided.
- Then

  ```
  ⟦%⟧#(X̄)  =  ⊔_{cells C}  ⊓_{facts whose guards hold on C}  [lo s#(C), hi t#(C)]
  ```

- **Soundness.** Each meet is Theorem T on its cell, and the cells cover the box.
- **The divisor's cell `{0}` contributes nothing**, because `%` is undefined there. That is the domain
  condition of `lang`'s division, a semantic law (facts.md class S) and not a fact. When every cell is
  undefined, the answer is `⊥`, the exact abstraction of no value.

## 3. Two bugs, both caught by the precision test before anything else ran

`TestTheInducedRemainderIsNeverLessPrecise` compares the induced rule against the old `remI`, kept in
the test file, on 50,000 random interval pairs. It failed twice.

1. **`(−∞, −1] % [−70000, −1]` came out `[−69999, 69999]` against `[−69999, 0]`.** The guard `a ≤ 0`
   was evaluated through `mulI(exact(1), X)`. Interval multiplication gives up on an unbounded factor,
   which is right for two unknowns and wrong for a constant: `x ↦ c·x` is monotone. `scaleI` now
   scales a half-line to a half-line.
2. **`[−70000, −1000] % [0, 0]` came out `⊤` against `[0, 0]`.** Every cell was undefined, and the
   transfer did not distinguish "no value" from "no clause". It returns `⊥` for the first.

**Admission condition 4 was also wrong in the first slice.** It asked `asLinear` to recognise the
trigger, which happens to work for `/` by a literal and does not for `%`. It now substitutes an atom
for the trigger, which is what *"linear once the trigger is read as an atom"* says.

## 4. Witnesses

- **Soundness** — `TestDivisionAndRemainderContain`, 20,000 random interval pairs each sampled
  concretely, passes on the induced `remI`.
- **Never less precise** — 50,000 pairs, the induced result inside the hand-written one. **And strictly
  tighter where a bounded dividend spans zero**: `[−5, 7] % 10` is `[−5, 7]`, where
  `min(|a|, |b|−1)` said `[−7, 7]`.
- **The evidence can fail** — weaken `rem-divisor-pos` by one, `(- b 2)`, and random sampling finds a
  remainder outside the claim.

## 5. Cost

- **Code**: `interval.go` 1,958 → 1,931, `target.go` 2,324 → 2,322, `fact.go` 263 → 491. That is
  **+199**: the induced transfer, the cell splitting and its arithmetic, which every later interval fact
  reuses. The linear layer is unchanged, because `asLinear` does not read `%` as an atom, so a
  remainder instance there asserts nothing.
- **`go run ./cmd/check`, every step, passes**: emission 194 of 194 files byte-identical and no
  compiler note changed, proof counts identical (2,307 of 2,413 integer operations, 345 of 382 loops),
  differential on four targets, tooling. The strictly tighter cases decide nothing in this corpus,
  which is the honest scope: this is a consolidation with one gain in precision, not a new proof.

## 6. Then the mask, and the three that are not facts

**F9 is two facts.** In two's complement `&` only clears bits. So a non-negative operand, whose sign
bit is clear, gives `0 ≤ a&b ≤` that operand, whatever the other operand is:

```lisp
(fact and-left  ((a int) (b int)) (when (<= 0 a)) (and (<= 0 (& a b)) (<= (& a b) a)))
(fact and-right ((a int) (b int)) (when (<= 0 b)) (and (<= 0 (& a b)) (<= (& a b) b)))
```

`andI` is now the induced transfer over them. It passes the same three witnesses as the remainder:
- **Soundness**: the existing mask containment test passes.
- **Precision**: on 50,000 random pairs it is inside the hand-written `andI`, and strictly tighter where
  one operand is non-negative and the other spans zero. `[0,255] & [−7,7]` is `[0,255]`, where the old
  rule answered `⊤`, because the non-negative clause holds on every cell of the split.
- **Evidence**: weakening `and-right` by one is caught.

**Moving the others is what showed three entries are not facts at all.**

| entry | why it is not a fact |
|---|---|
| F5, `|a/b| ≤ |a| / min|b|` | As a fact it is `b·q ≤ a`: a product of two extension terms, failing covering and linearity together. Over a box whose divisor excludes 0 it *is* Moore's interval quotient, the operator's best abstraction, in the class §7.5 keeps for `+`, `−` and `·`. Its sign cases are corollaries of that quotient. |
| F10, `x >> k = ⌊x/2ᵏ⌋` | It equates two extension terms and needs `2ᵏ` as a compile-time function of `k`: **F-C**, reserved beside `isqrt`. |
| F12, `0·x = 0` for unbounded `x` | Interval multiplication's convention for `0 · ±∞`: the operator's own abstraction, not a law a declaration could add. |

So facts.md's class F — twelve entries — is now either declaration or reclassification, each with its
reason. The one left is F3/F4, the square, which waits on a compile-time `isqrt`.

**THE ONE EMITTED CHANGE IS A CORRECT NARROWING, AND THE FIRST EXPLANATION OF IT WAS WRONG.** Two
files changed, both `render.oro` on windows (the example and its differential case). A limb table's
store `x & 16777215` went from `mov qword ptr` to `mov byte ptr`.

**Seen cold, that looks like 24-bit limbs truncated into a byte**, and the first hypothesis was that
the induced transfer answered `⊥` for a `⊥` operand, which a byte fits. The probe showed it did:
`andI(⊥, 16777215)` was `⊥`. It was fixed so a `⊥` operand reads as `⊤`, with a test. **And the
emitted hashes did not move**, so `⊥` was not the cause. The fix stays, for a different and true
reason: the hand-written transfers never answered `⊥`, and no consumer has been measured accepting
one.

**The real cause is the precision gain itself, and that part is measured.** With HEAD's `interval.go`
put back, so the hand-written `andI` and nothing else changed, the windows emission is
**byte-identical to the baseline**. So the induced `andI` alone moves it, and
`TestTheInducedMaskIsNeverLessPrecise` proves that rule is never wider than the old one.

The old `andI` checked for a constant mask first and answered `[0, 16777215]` without looking at `x`.
The induced transfer also meets `and-left`, so a bounded non-negative `x` bounds the result. **The
likely source, inferred and not measured**: `fact`'s signature bounds `n` to `[0, 40]`, so a multiplier
widened into limbs has limbs of at most 40.

**Checked at run time**: the windows differential case prints 25! and 30! correctly from the byte
table. **No slower**:
no benchmark covers the windows limb path, and wintables-2026-08-25 measured one-byte elements at
0.88× of hand-written assembly on this host. Accepted.

**Cost**: `interval.go` 1,931 → 1,915.

- **`go run ./cmd/check -accept`, every step, passes**: 192 of 194 emitted files byte-identical, the two
  being this narrowing; proof counts identical (2,307 of 2,413 integer operations, 345 of 382 loops);
  differential on four targets, including the windows case that runs the byte table; tooling.
