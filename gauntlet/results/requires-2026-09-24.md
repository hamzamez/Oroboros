# What enforcing a definition's parameter ranges at its calls would refuse

2026-09-24. A measurement, taken before anything is enforced. hamza chose option A — a declared range
(and `where`) on a definition's parameter is an obligation at every call it is inlined into — and
asked for the count first.

## 1. The question

A non-exported definition is inlined before anything is analysed, so a declared parameter range has no
call site left to be checked at. refinements.md §6b decided that for `where`: dropped, because the
body's own obligations land on the caller's values, which is stronger for **safety**. What it does not
protect is **meaning**: a total body computes something else outside its declared domain, silently.

```lisp
(sig digits18 ((g (int 0 999999999999999999))) string)
(digits18 1000000000000000005)          ; compiles, prints 000000000000000005
```

## 2. How it was measured, and why it changed nothing

`cmd/gen -report-requires` (`cmd/gen/requires.go`):
- For every direct call of a definition with a ranged parameter, the reducer wraps the argument in a
  mark, `(#req "def" "param" "type" a)`, whose value is `a` (`core.Env.Requires`).
- A mark whose argument reduces to a literal is decided by the reducer and dropped.
- The rest reach the residual, where the interval analysis decides them
  (`emit.MeasureRequires`) and they are erased before anything else runs.

Ranged parameters are integers, and the only reduction rule that inspects an integer argument's shape
is `duplicable`, which looks through the mark. So the claim is that the marks change no reduction
decision. **It was checked over the whole corpus: 551 compiles — every source under `examples/`,
`lib/` and the stdlib acceptance programs on four targets, and every differential case as the harness
renders it — each compiled with and without the flag. Not one emitted byte differs.**

What it does not see:
- a definition passed higher-order rather than called by name;
- a range with an infinite endpoint, `(int 0 +inf)`;
- `where` clauses. There is one on a non-exported definition in the corpus, `count-primes` in
  `examples/table/sieve-win.oro`, and its one call passes the literal 200000, which is in range.

## 4. The design point it surfaced

A range above the target's word is enforced **at its bit length** (bigrepr-2026-09-03 §3a):
`(int 0 (pow 2 200))` admits every value under 2²⁰¹. So `fact`'s declared result guarantees
`x < 2²⁰¹`, and `render` declares the same type for `x`. Checked exactly, as `x ≤ 2²⁰⁰`, the
obligation would not follow from the guarantee, although the two positions carry the same type.

**The coherent rule is that a type denotes one set wherever it appears.** Above the word, that set is
the one enforcement admits, so an obligation on a range above the word is checked at bit length. Then
`render`'s 21 obligations follow from `fact`'s result, once an ascription is read as the fact it
enforces.

## 5. What it means for option A

Of 346 obligations across the corpus:
- **314** are discharged by what exists;
- **4** are discharged once enforcement also asks the refinement layer;
- **21** are discharged by reading an ascription as a fact, checked at bit length;
- **7**, one line of one program, are refused. The refusal is correct: the exported `run` really did
  not guarantee `fact`'s domain.

No program in the corpus passes a literal outside a declared range. The criterion set before
measuring was "a handful, each with a declaration that is actually wrong". The answer is one program
and one missing declaration.
