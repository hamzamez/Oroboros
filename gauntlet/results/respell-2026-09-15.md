# The respelling: `variant`, and one `tuple` for products and several results

2026-09-15. [spec/data.md §10](../../docs/spec/data.md), after the loader's target half
([loader-2026-09-15](loader-2026-09-15.md)).

## 1. What changed, and what did not

| old | new |
|---|---|
| `(sum S …)` | `(variant S …)` |
| term `(values a b)` | `(tuple a b)` |
| product stored in a table, `(set t i (array a b))` | `(set t i (tuple a b))` |
| product type `(array A B)` | `(tuple A B)` |
| several results `(sig f … (A B))`, in programs and target files | `(sig f … (tuple A B))` |

The old spellings are refused naming the new one. **`(array …)` now means one thing, a table.**
data.md §6's reason: `(array int)` could not say whether it was a table of ints or a product of one,
and a product type in a result position was read as several results. Arity carried a meaning a name
should carry.

**Why one word is right for both products and several results.** They are the same object, a function
on `Fin n` (data.md §1), and the spec already said where each position lowers it (§3.3): consumed in
one reduction it disappears; as a function's result it becomes the host's multiple return; as a
table's element it becomes the flat stride. Two words for one object is the collision data.md §6
removes.

## 2. The one decision, and the test that made it

data.md §3.4 left one implementation question open: is `(tuple e…)` the Church term
`(fn (#k) (#k e…))` or a table literal? The acceptance test was to decide.

**The Church term**, because it is what `values` already read as. So:
- destructuring is β, with nothing added to the reducer;
- all four backends' several-results path, which matches that term, is untouched;
- the product pass recognises a stored tuple with the same `multiValue` matcher. It no longer looks
  for an `(array …)` literal, which could not be told apart from a table of two.

**What that required, and it is one inversion.** The reader is context-free, so `(tuple A B)` written
as a type also arrives as `(fn (#k) (#k A B))`. A type is built from a term in exactly one place,
`TypeName`, which now reads that term back as the tuple type. `#k` is not an identifier a program can
write, so no other term has that shape. The `sig` reader then needed two small changes, because it had
dispatched on term kind: a tuple type is a function term, not a list.

**A buffer may be a tuple component; it may not be inside an array's element.** Several results may
hand a buffer back (`hex.Decode` returns `(tuple (buffer (int 0 255)) int error)`), and ADR 0020's
rule 6 is about elements. So the rule moved from the product type to the `array` constructor
(`prodHoldsBuffer`), and is tested there.

## 3. Two bugs on the way, both caught by existing checks

**The translator rewrote a user's function.** `cmd/respell` renamed every list headed by `sum`, and
eight files define and call their own `sum`, a fold (`(def dot (fn (a b) (sum (zip …))))`). A
`variant` declaration always has a name in second position, never a term, so all eight were found by
that shape and restored. **The core tests caught it** (`TestSameTermTwoNormalForms` refused
`(variant (zip …))`).

**A store the search missed.** Product stores are terms, so they were rewritten by hand. The search
for them matched `(array x y)` only when the first component was a bare name, and missed
`freq.oro:277`'s `(array (pat ord nw k) 1)`. **The emission check caught it**: freq was refused on all
three hosts, its flattened product accesses went **71 → 57**, and the refusal named an unflattened
`((dt2 s17) 1)`. A search for every `set` of an `(array …)` literal then found no other.

## 4. Cost

- **Emission: 194 of 194 emitted files byte-identical**, proof counts identical (2,307 of 2,413
  integer operations, 345 of 382 loops), no refusal text changed. Nothing accepted, because nothing
  changed.
- **Code**: `core/read.go` 1,300 → 1,309 code lines, `emit/target.go` 2,313 → 2,299 (`resultList`
  deleted), `emit/product.go` 415 → 419; **4,028 → 4,027 across the three**.
- **Translated**: 25 files mechanically, then 12 sites by hand where a Go test built the text by
  concatenation or a product was stored.
- **`go run ./cmd/check`, every step, passes**: vet, compiler, emission (byte-identical), the
  differential suite on four targets, and tooling (the surveys twice, the acceptance programs, the hand
  declarations against the host).

## 5. Not built

- Projection of a literal tuple by a literal index, `((tuple a b) 0)`. It is one reduction clause and no
  program writes it.
- Refusing a heterogeneous `(array a b)` literal. Whether the components' types differ is a question for
  the checker, not the reader.
- Records, symbols and `with` (data.md §2, §4); types, companions and `const` in modules
  (theories.md §3).
