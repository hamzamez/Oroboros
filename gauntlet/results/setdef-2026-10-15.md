# setdef-2026-10-15 — a program's own set is refused where it is named

Found by du-2026-10-14 (surface-design.md §6.3, "One hole du found"). A program that names its own
set, `(def Byte (int 0 255)) (sig f ((x Byte)) …)`, was accepted at the definition and at the `sig`,
and the checker then read `Byte` as an opaque type:
- `(+ x 1)` was refused, "x is Byte, but int is required here", a message about the use, not the
  cause;
- `(sig f ((x (array Byte))) int)` compiled, and Go was printed with `[]/*Byte?*/`, which does not
  build.

A program's own sets come with types-as-values step 2 (spec/typevalues.md §1, §10), so until then the
definition has no set to denote.

## What changed

**The rule** (typevalues.md §1): a type in a program's `sig` that names one of the program's
definitions, in its own module or through an import (`s.Byte`), is refused at that `sig`, naming the
definition and the section. It is checked in `Load` (`core/reduce.go`, beside the rule for a variant
in a parameter), over every word of every parameter and result type, resolved by the same `scope`
that resolves a variant type.

**The witness**, `TestAProgramsOwnSetIsRefusedAtItsSig` (`emit/typevalues_test.go`): five programs
(a parameter, a result, an array element, a set over a constant endpoint, an imported definition)
refused at loading, and a constant used as a value still accepted. With the check removed, all five
load.

**Cost.** `cmd/check -skip tooling` byte-identical (560 runs, 2058 of 2103, 352 of 371); the
acceptance programs pass. No corpus program named a definition as a set.

## Not fixed

**Any unknown name in a program's `sig` is still an opaque type.** `(sig f ((x (array Nonesuch))) int)`
with no `Nonesuch` anywhere compiles and prints `[]/*Nonesuch?*/` on Go. The sound rule is that a name
in a claim must denote a set (a language set, one the target declares, a variant, a static
parameter), and a program's `sig` is never resolved against the target's sets today
(`core/reduce.go` copies it unresolved; `emit/target.go`'s `ty` prints the placeholder). That needs
the target's types at load time, so it is its own step.
