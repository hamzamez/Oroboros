# setname-2026-10-23: a set's name denotes a set

ADR 0073, the 10-21 plan's item 7 (found in setdef-2026-10-15, "Not fixed").

## 1. What it is

A header's set is a term of the set algebra, and ⟦·⟧ is defined on it by structural recursion, a
homomorphism into sets. It is total exactly when every atom is bound in Γ_T: the language's sets (`?`,
`?int`, the ranges, the formers `Array`, `buffer`, `cell`, `Map`, products) and the sets target T
declares, the base sets among them. So well-formedness is a scope check, the set-level twin of a term's
"is not bound". An unbound name has no denotation, and a claim about it says nothing.

Measured before, on Go:

| header | before | after |
|---|---|---|
| `export fn f(x ∈ Array(Nonesuch)) (Int)` | `func GenF(v0 []/*Nonesuch?*/) int`, does not build | refused: "parameter x names Nonesuch, which is no set" |
| `export fn g(x ∈ Nonesuch) (Int) { x + 1 }` | refused at `+`, "x is Nonesuch, but Int is required here" | refused at the header |
| `export fn h(x ∈ Int) (Nonesuch) { x }` | "x is Int, but Nonesuch is required here" | refused at the header |
| `fn k(x ∈ Nonesuch) (Int) { 0 }`, never called | compiled | refused |
| `export fn keep(r ∈ strings.Replacer) (strings.Replacer)` | `func GenKeep(v0 /*strings.Replacer?*/) /*strings.Replacer?*/` | `func GenKeep(v0 *strings.Replacer) *strings.Replacer` |

The last row was not in the plan. Measuring which names must stay legal found it: a host set written
through its import alias was never resolved, so an export printed a placeholder. It is the same defect
from the other side, a name that does denote a set, left unresolved. Resolving the alias at load (ρ_m,
as for a term) fixes it.

## 3. The vocabulary, measured first

Every set word in every corpus program's headers, loaded on each of the four targets: `Any`, `Int`, `F64`,
`String`, the ranges (`-inf` and `+inf` ends included), `Array`, `buffer`, `Map`, `go.bytestring`,
`go/strings.Replacer`, `map-string-int` (Go), `map-string-long` and `double-array` (Java), and
`vec-f64`. `vec-f64` is declared only on `blas`. Its two programs, `examples/dot.oro` and
`lib/num/vec.oro`, are refused on the four targets already, for an unbound term name in the body, and
keep that refusal. A target's type named on another target (a Java program on Go) is in the same case.

## 4. The corpus

`cmd/check`, every step including tooling: pass. Emission, outcomes and refusal text are
**byte-identical**, and compile time is 1.00× the baseline. Every header in the corpus names a set, and
no existing refusal changed its text, because each program that names another target's set also names
that target's functions in its body, which is refused first.

## 5. Planted faults

`TestASetsNameDenotesASet` (`emit/setname_test.go`): eight headers refused, seven legal ones accepted
(the base sets, ranges above the word, the formers, a buffer, a host set through its alias, a product, a
variant result), the alias's resolution read off the loaded header, and a target's type on its own
target and on another. Each fault was planted in a copy and restored byte for byte:

| fault | caught by |
|---|---|
| parameters not checked | never called, a map's value, misspelled |
| aliases not resolved | a host type refused; the header still `strings.Replacer` |
| a map not taken apart | a map's value |
| a product not taken apart | a table's product (added when the first fault passed: a tuple result is split into its components before the check, so no product reached it) |
| variants not in Γ_T, bare or applied | **nothing**: no variant reaches a header by then, so both branches were dead and are removed |

## 6. Not built

- The program's own sets, `set Byte = 0..255` named in a header: step 2 of typevalues.md §10.
- A set name in a target's own declarations: target files are read by the target loader, which this
  step does not touch, and whether it refuses an undeclared one is not measured here.
