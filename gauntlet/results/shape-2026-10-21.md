# `bufio`'s Reader, program first: `shape`, and C met

2026-10-21. The 10-20 plan's item 3 (assessment-2026-10-20 §5): *"`bufio`'s `Reader`, program first:
a program that reads delimited records. It will meet C, a borrow a later call ends (`Peek`,
`ReadSlice`), the first wall; research it when it is met."* `examples/lines/shape.oro`,
`bufio.Reader` with `NewReader` and `ReadString`, a test against a reference written from the
definition, a fix to J's reader, and [borrow-research.md](../../docs/borrow-research.md).

> **THE PROGRAM IS ITS DEFINITION**: on 13 inputs at the factorization's edges, and on records at
> and around the Reader's 4,096-byte buffer, its output is what a reference written from
> `bytes.Split` prints. Its 5 operations are proven. On 260 MB it runs at parity with the same
> algorithm written by hand: 1.01×.
>
> **C WAS MET AS A COST, NOT AS A WALL.** `ReadString` copies each record, and `shape` holds one at a
> time. The hand-written program a Go programmer writes, with `ReadSlice` and `bytes.Count`, takes
> **0.74×** the time and **0 garbage collections against 78**.
>
> **A NAIVE `ReadSlice` MISCOMPILES A CORRECT PROGRAM.** Declared as an ordinary table, it compiles.
> A program that copies the record before the next read prints the overwritten bytes, because
> call-by-need moved the pure copy past the read. So C needs a side condition in the reducer as well
> as a check. borrow-research.md derives both, and has six decisions for hamza; nothing of C is
> built.

## 1. The algebra

B = [0, 255], d = LF. The words ending at their first d form a prefix code C_d = (B ∖ {d})*·d, so
the input factors uniquely as x = c₁ … c_k u, with cᵢ ∈ C_d and u ∈ (B ∖ {d})* (Berstel, Perrin and
Reutenauer, *Codes and Automata*, ch. 2).

- **The records** are each cᵢ without its d, then u when u ≠ ε. A final LF ends a record and begins
  none, and the factorization is lossless.
- **`ReadString(d)` returns exactly the factors**, then u with the error that ended the input. Go's
  law, *"ReadString returns err != nil if and only if the returned data does not end in delim"*, is
  the factorization's own characterization. The buffer is invisible: a factor longer than it is
  reassembled from full buffers.
- **Fields.** fields(r) = |r|_s + 1, where |r|_s is the letter count of SEP in r, a monoid
  homomorphism (B*, ·, ε) → (ℕ, +, 0). It is `strings.Count(w, SEP)` on the factor w, since
  SEP ≠ LF.
- **The report** is a left fold over the records: their number, the first record's fields, the
  records whose count differs (with the first one named), and the longest.
- **Counts are on ℕ_C**, C = 2⁶² − 1, with x ⊕ 1 = min(x + 1, C), as `du` counts sizes. Nothing in a
  Go string's type bounds its length below the word (`len ≤ 2⁶³ − 1`, tables.md §2.3.1), so
  |r|_s + 1 is not provably inside it.

`targets/go/bufio.oro`'s header now states the Reader's algebra: the state is the unread suffix, the
factorization is over C_d, `ReadString` is lossless and blind to the buffer, and `ReadSlice` is the
same factorization refined by the buffer, its pieces lent.

## 2. The program and its declarations

`examples/lines/shape.oro` is 58 lines of J, plus a 40-line header comment. It needs:
- `bufio.NewReader`;
- `Reader.ReadString`;
- `strings.Count` and `strings.IndexByte`;
- `errors.Is` and `io.EOF`, to tell the end of the input from a failure;
- `fmt`.

New in `bufio.oro`:
- `set Reader = host "*bufio.Reader"`;
- `NewReader`. Its comment records that it is **not fresh in general**: `NewReaderSize` returns its
  argument when that argument is already a large enough `*bufio.Reader`;
- `Reader.ReadString(delim) (bytestring × result.result((), error))`, a partial success (ADR 0044).

Each is checked against the host. The Reader is checked as its own module so that planted mistakes
reach it: a string delimiter and an integer result, both caught. `NewReader` returning a Writer is
caught in the package's entry.

What writing it by hand found:
- **J's `!=` was a name nothing binds.** The reader passed `a != b` on as an application of `!=`, and
  no program can bind that name; the corpus never used it. It now reads as `!(a == b)`, the negation
  of the language's equality, erased as `!` is (ADR 0017). `TestNotEqualIsTheNegationOfEquality`
  pins it. This is the plan's item 4: what J's reader misses, counted.
- **The language's `==` is integer equality** (strings.md), so "SEP is not LF" is written
  `strings.IndexByte(sep, 10) < 0`.
- **Relevance refused both unused `Fprintln` errors** on standard error. They are `ignore`d, with the
  reason given in `lines`.

Proofs: 5 of 5 operations, 0 of 1 loop. The loop runs once per factor of the input, which nothing in
the program bounds. The program is Go only, as `lines` is: on JavaScript, Java and Windows it is
refused at `` `go/errors`.Is ``.

## 4. C, measured

### 4.1 The cost

The input is a 260 MB TSV file of 2.5 million records: 8 fields of varying width, every 1,000th
record with 7, a record of 100,000 bytes in the middle, and the last unterminated. All three programs
print the same output. Each was run 9 times, serially and interleaved, with no compiler or benchmark
process running; the times are medians.

| program | median | GC cycles |
|---|---:|---:|
| `shape`, emitted | 308 ms | 78 |
| hand-written Go, `ReadString` and `strings.Count` | 304 ms | 77 |
| hand-written Go, `ReadSlice` and `bytes.Count` | 227 ms | 0 |

The hand-written lent form's loop. The counts are homomorphisms, so a factor's pieces add:

```go
for {
    w, err := in.ReadSlice('\n')
    c += bytes.Count(w, sep)
    size += len(w)
    any = any || len(w) > 0
    if errors.Is(err, bufio.ErrBufferFull) {
        continue
    }
    … // the record ends: the fold's step, as in shape
}
```

Every read of `w` precedes the next impure call: `bytes.Count` and `len` are pure, and `errors.Is`
comes after them. So this program satisfies E0, borrow-research.md §5.

### 4.2 The hazard

`ReadSlice` was declared in a scratch layer (a fragment beside the program) as
`(Array(0..255) × result.result((), error))`. The input is 4,000 `A`s, LF, 200 `B`s, LF.

```
// A: held across the next read
(first, r1) = rd.ReadSlice(in, 10)
(second, r2) = rd.ReadSlice(in, 10)
fmt.Println(go.string_of_bytes(first), go.string_of_bytes(second), drop(r1) + drop(r2))

// B: copied BEFORE the next read
(first, r1) = rd.ReadSlice(in, 10)
a = go.string_of_bytes(first)
(second, r2) = rd.ReadSlice(in, 10)
fmt.Println(a, go.string_of_bytes(second), drop(r1) + drop(r2))
```

Both print a first record that begins `BBB` and holds 3,799 `A`s and 200 `B`s. B's emitted Go has
`string(v3)` after the second `ReadSlice`: β moved the pure copy past the read. With two short
records, both programs print correctly, because both records arrive in one fill. A test that does
not cross the buffer cannot see either fault.

## 5. Not built

- **All of C.** The mode `lent`; which writes end the epoch (E0, E1, E2); the reducer's side
  condition, effects.md §7c generalized; (L0) on the IR; `shape` in its lent form with `bytes.Count`.
  These are borrow-research.md's six decisions.
- `Peek`, `ReadLine`, `Scanner.Bytes`, `Writer.AvailableBuffer`, and the Reader's L-class methods:
  `ReadByte`, `ReadRune`, `Discard`, `Buffered`, `Size`, `Reset` and others. No program calls them.
- Quoted CSV (`encoding/csv`), and a `cut` that writes fields out. The latter would be E1's trigger.
