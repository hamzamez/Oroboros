# The signed sum as one recurrence, and the written prefix on a terminator tree (R3a)

Date: 2026-11-09. R3's first step in the plan: R2's storage finding
([signlimbs-2026-11-09](signlimbs-2026-11-09.md)), 10⁷ signed additions at 8.5× the unsigned loop,
fixed and measured on R2's loop before the variable-length magnitudes.

## The finding, restated

Each signed iteration made four heap tables and freed four, because each allocation sat inside a
branch of a statement-level `if`:
- `sof`'s `case v >= 0`;
- `sadd`'s case on the signs.

R1b's tokens reach only an allocation at the top level of a terminal arm.

## The derivation: a conditional commutes with a table's construction

A table is a function on [0, n), and a build is its construction from an element function. So,
pointwise,

    if c then build(f) else build(g)  =  build(λi. if c then f(i) else g(i)).

Where the branches differ only in data, the case moves inside the element, and there is one
allocation, at the top level, where R1b's tokens already reach. **No pass changes.** The alternative,
a token threaded through a branch, is the same linearity law on a coproduct, used once in every arm.
It is not built, since no allocation now needs it.

For the group completion's sum this gives **one recurrence for x ± y** (`addsub`, `emit/bignum.oro`):

    t = x + σ·y + c,   σ ∈ {+1, −1},   x, y = a, b or b, a (sw),   |x| ≥ |y| when σ = −1,

with t ∈ [−2²⁴, 2²⁵), digit t mod 2²⁴, and carry ⌊t / 2²⁴⌋ ∈ {−1, 0, 1}. The sign is written at entry n,
and is 0 when every digit is 0. That zero test is an OR-fold carried in the same loop, `nz`, so the
normal form needs no copy: `with_sign ∘ add` and `with_sign ∘ sub` are fused (deforestation, Wadler
1988). Applied to the library:
- **`sadd`, `ssub`**: the sign case chooses `sw` and σ, data, and calls `addsub` once;
- **`sof`**: the case on v's sign moved into each digit's expression, so it is one build;
- **`smul_small`**: `mul_small`'s recurrence with the sign at entry n, so no copy.

**`smul` and `sdiv_small` keep the copy.** Both allocations are at the top level, so both take tokens.
`mul` accumulates into its table rather than writing a prefix. `div_small`'s counter descends from
the top, and the sign cannot be written before the quotient's zero test is known.

## The written-prefix theorem, on a terminator tree

The new builds write the sign entry from a second continuing arm (`i == n -> { o[i] := … }`). ADR
0097's theorem took a single continuing region, so these builds kept their zero fill. **The
induction step holds on each path**: if every leaf of the continuing side's terminator tree
continues (or is unreachable), and on the path to it the buffer is written at the counter, not read,
and the counter stepped by one, then [0, i) is written at each iteration's start, as before
(`ir/fill.go`, `pathWritesAt`). A path that breaks is refused, since a second exit could leave before
[0, n) is written.

The exit test `i ≥ n + 1` computes n + 1 a second time. **Count equality is by congruence**: in SSA a
pure operation is a function, so `add` of the same counts is the same count (congruence closure,
Nelson and Oppen 1980, on `add`, `sub` and `mul`).

## Witnesses

**`TestTheWrittenPrefixTheorem`** gains three cases:
- proven: two continuing arms, each writing at the counter, the sign entry's shape;
- refused: two continuing arms, one not writing;
- refused: a second exit before the table is full.

The planted fault, `PlantFillDead`, is unchanged, and `TestAZeroFillIsKeptWhereItIsRead` still sees
its wrong sum. `big-sign`, `big-signed-ops` and the R2 witness agree on four targets.

## What was measured

10⁷ additions of 10²¹ on windows, best of five, two rounds:

| loop | R2 (signlimbs) | fused | fused, and the theorem on a tree |
|---|---|---|---|
| unsigned, V_9 | 138.7 / 144.1 ms | 145.5 / 148.0 | 138.0 / 139.8 |
| signed, equal signs | 1,219.0 / 1,219.9 | 287.8 / 296.0 | **214.4 / 217.6** |
| signed, mixed signs | 1,298.1 / 1,306.4 | 348.4 / 356.4 | **291.6 / 294.0** |

The signed loop is 0.18× R2's, and **1.55× the unsigned one**. Each iteration now makes three tables,
the same as the unsigned loop: the constant 10²¹ is 10¹⁵ · 10⁶, built each time because nothing
hoists it ("deliberately not next"). After `ir.Reuse`, every allocation in the body takes a token.

What remains is computation:
- one more entry;
- the operands selected per digit (`sw`);
- the `nz` flag;
- when the signs differ, a magnitude comparison and the subtraction's two-sided carry: the mixed loop
  is 1.36× the equal-sign one.

This is not argued away. It is the cost of sign-magnitude over two's complement for this loop, and
ADR 0098's "Why not" names the measurement that would justify the second mechanism.

**The check**: the emission changed only for `big-sign` and `big-signed-ops` on windows. No other
program's build is newly proven born full. The counts went from 5,943 of 5,997 operations and 866 of 890
loops to 5,656 of 5,710 and 638 of 662, since the fused library has less code; the unproven 54 and 24 are
unchanged. The two cases compile in 0.64× and 0.62× the time.

## What failed first

- **Two checks ran at once**: one from before a pause was still running, and both shared `.check/`.
  Both were stopped and the check was run alone.
- **The theorem missed the new builds**, which keep their zero fill (`reuse`, not `reuse-raw`, in the
  dumped IR): the continuing side was a tree, and the counts were two copies of n + 1. Both are fixed
  above, each by the same proof read more carefully.

## What was not built

- **A token through a branch**: R2's first proposal, now not needed by any allocation in the
  library. It waits for a program whose branches allocate different tables.
- **`sdiv_small` fused**, which needs the quotient's zero test before its first write: |a| ≥ k, a
  comparison by a word. It is a copy at the top level, which takes tokens.
- **Hoisting a constant out of a loop**, still deliberately not next.
