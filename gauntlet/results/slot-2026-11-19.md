# A window procedure's state: the captured cell is its slot (ADR 0133 steps 3 and 4)

2026-11-19. ADR 0133 items 4–6 (hamza's 1.1 B, 1.2 one state per process, 1.3 option 3, 1.4b (i),
1.4c the cell's own `var` scope as the extent).

## 1. The derivation

Theorem T (callbacks-research §3.3): under Theorem N's nesting, a program whose step threads S, lending
S to every host call that may dispatch, has the meaning of the C program whose S is one global, read
and written in place. The theorem names both sides. The threaded side needs every dispatching call
found and the state passed in and out of it. The global side needs nothing found: a read after any
host call sees what an activation inside it wrote. With option 3, no classification, every host call
is lent the state, and a state lent to every call is the global. So the global is built, and lending
is the identity.

## 2. What was built

- **The loader's slot pass** (`core/slot.go`, before the state translation). A cell of a `var` scope
  that a λ at a record's field captures becomes a slot: every read of it in the scope a load
  `(#sget N)`, every write a store `(#sset N v)`, and the cell at a cell parameter its reference
  `(#sref N)`. The λ so captures no cell, is closed, and step 1 lifts it. The record's builder
  form, `((fn (#rc…) (#rec …)) e…)`, is read as a record.
- **A definition's cell parameter** (step 4, 1.4b (i)): in `fn step(s ∈ cell(S), …)` a read of s is
  `(#deref-p s)` and a write `(#setref s v)`. β substitutes the reference, which the reducer reads as
  the slot's load and store. The slot's set is the cell parameter's S.
- **The reducer** expands a load into the record of its leaves' loads and a store into each leaf's
  store, claimed in the leaf's set (ADR 0048's claim). Loads and stores are effects in program order.
  A slot's reference is a value, and a duplicable one. A λ at a callback's field is marked
  `(#cbfn λ)` and read as a value, since the host applies it and the program never does. So it is
  substituted where its record is used once, rather than let-bound as an argument whose body runs.
- **The leaves** (`emit.RegisterSlotLeaf`): each a static global of the triple,
  `@"N~k" = internal global i64 0`, its load and store primitives impure. They are registered from
  the loader's slots and, by `ir.RegisterProgram`, from an IR file's calls, so a program reprints
  from its text (ADR 0038).

## 3. Measured

`TestAWindowProcedureHasAState`, on windows and windows32, prints `0 2 2`:
- WM_USER + 1 counts a click and answers 0;
- WM_USER re-enters the procedure by sending WM_USER + 1 to itself, which counts again, and answers
  what the inner activation left, 2;
- `main` reads 2.

`examples/native/wndproc-win.oro` posts three clicks and a quit, runs the message loop, and prints
`3 3` (the quit's code and the state main reads) on both.

## 4. What failed first

- **The λ at the field arrived as a name.** Its body is impure, so the record's curried binder
  let-bound it as an argument whose body runs, and the `#ref` boundary saw `#0.6`. The `#cbfn` mark
  fixed it.
- **The reference was let-bound** for the same reason, used several times and not duplicable, so
  the step's `s` was never the slot.
- **A store was dropped as pure**: an unknown head was read as a value, and `s.clicks := …`, whose
  value is discarded, vanished.
- **The unit was spelled `(tuple)`**, a name the IR does not lower. The core's unit is a Church
  tuple.
- **`${v}` in a synthesized template**: the reader writes positional holes, `%1`.

## 5. What is refused, and what it costs

- **A read knows only S.** Two reads are two loads, and nothing proves them equal: `m == 1025 &&
  s.clicks < 1000 -> { s.clicks := s.clicks + 1 }` is refused, the second read unbounded below. The
  program reads once, `c = s.clicks`, and guards and writes through c. It is option 3's cost, named
  in sketches §1.3, here even with no host call between the reads.
- **A captured cell passed to no cell parameter** is refused: nothing states its set.
- **An ordinary cell at a cell parameter**, one no λ at a field captures, is refused, not built:
  by reference it needs the cell's address or a threaded pair, and no program asks.
- **One slot per captured cell**: a scope entered again while its λ is running would share it. One
  state per UI process (1.2) makes that the decided meaning.

## 6. The tests

`TestAWindowProcedureHasAState`. Its fault, `core.PlantSlotUnshared`, gives the λ a slot of its own
apart from the scope's, the stale state Theorem T excludes, and main then reads 0. Its refusals: a
captured cell passed to no step, and a field read twice.

  every write a store, which LLVM keeps across a host call (the trampoline may run). Unmeasured
