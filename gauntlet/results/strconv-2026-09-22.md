# strconv and encoding/binary, declared by hand

2026-09-22. Commit `5148421`. `targets/go/strconv.oro`, `targets/go/encoding/binary.oro`,
`gauntlet/stdlib/acceptance/{strconv,encoding-binary}.oro`. These are the two packages CLAUDE.md
named next, and both hit the integer window first, which is what
[ADR 0026](../../docs/decisions/0026-an-int-is-an-integer.md) and
[word-2026-09-22](word-2026-09-22.md) removed. Each is *supported* in ADR 0022's sense:
- **declared by hand**, from Go 1.27's source;
- **checked against the host** by the survey's generated declarations, with four planted
  mistakes each, all caught;
- **exercised by a program** whose expected output is the real package's, run from
  `tooling_test.go`.

## 1. strconv: the algebra

```
N_b ⊂ A*       the numerals in base b, 2 ≤ b ≤ 36: optional '-', digits over [0-9a-z][:b], no leading zero
F_b : ℤ → N_b  FormatInt, an INJECTION (positional notation is unique)
P_b : A* ⇀ ℤ   ParseInt, a PARTIAL LEFT INVERSE: P_b ∘ F_b = id on the word
               F_b ∘ P_b ≠ id — P_b accepts '+', uppercase, '_' and 0x… with base 0 — but it is
               IDEMPOTENT: a projection onto N_b
```

P_b's domain is the words whose value lies in the word. Past it, P_b returns the nearest bound
with `ErrRange`: it **saturates, never wraps**. The acceptance program shows this at both ends,
`9223372036854775807` and `-9223372036854775808`, each with its error.

**The claim the decision was for.** `ParseUint`'s result is U = [0, 2⁶⁴−1], held as a
`uint64`. The program parses 2⁶⁴−1−i back, divides it by 10¹² and sums its digits, all in a
machine word. Under ADR 0012 this value could be printed and not computed with. Under the
survey's old map it was declared `int`, so declared narrower than Go returns, and the emitter
believed it (what-an-int-is.md §3.3).

**Preconditions, read off the source:**

| function | Go 1.27 does | declared |
|---|---|---|
| `FormatInt`, `FormatUint`, `AppendInt`, `AppendUint` | `formatBits` panics outside 2 ≤ base ≤ 36 | `(where (and (<= 2 base) (<= base 36)))` |
| `FormatFloat`, `AppendFloat` | panics unless bitSize ∈ {32, 64} | bitSize = 64. The disjunction is outside the linear fragment; narrowing a parameter is sound (contravariance), and the language's only float is a float64 |
| `ParseInt`, `ParseUint`, `ParseFloat` | a bad base or bitSize is an error value, not a panic | nothing |

**Narrower than the host, and justified:** `UnquoteChar`'s rune is in [0, MaxRune], where the
host type says int32. A plain character is decoded UTF-8 (`RuneError` at worst). `\x` and
octal give at most 255, and octal past it is an error. `\u` and `\U` are checked with
`utf8.ValidRune`, and an error returns 0.

**Not said, and named:** `ParseInt(s, b, bitSize)` lies in [−2^(bitSize−1), 2^(bitSize−1)−1].
That range depends on an argument's *value*, which `ensures`' linear fragment cannot state.
The declaration gives the widest, bitSize = 64, which contains every other.

## 2. What the declaration needed from the compiler

- **Host integers as the host's.** `int64` is the word and `uint64` is U: honest *results*,
  where the window lied.
- **A `u64` argument converted at a host call.** `(sc.FormatUint 18446744073709551615 10)`
  reaches Go as `strconv.FormatUint(uint64(18446)·10¹⁵ + …, 10)`: the literal's Horner spine,
  computed in U.
- **A multi-result continuation's `u64` bound as one.** `((sc.ParseUint …) (fn (y e) …))`
  gives `y` its interval and its representation.

## 3. The survey, made honest at results

The generator spelled `int64`, `uint64` and `uint` as the language's `int`. Its own comment
called that sound, because an operation on such a value is refused at the call site. That is
correct for parameters and wrong for results, where a declaration must accept everything the
host returns. Now `int64` is the word, `uint64`/`uint` are U, and every non-`int` integer
argument is converted in the template.

| | before | after |
|---|---:|---:|
| declarable | 4,331 (87.8%) | 4,331 (87.8%) |
| usable | 2,978 (60.4%) | 2,978 (60.4%) |
| constants declarable | 509 | **514** |
| primitives emitted | 5,282 | 5,287 |

The five constants are `math.MaxInt64`, `math.MinInt64`, `math.MaxUint64` and `hash/crc64`'s
two polynomials. They were "outside the portable window"; now the word or U holds them. It
needed one loader change: a `const` value past int64 arrives as a Horner spine and is read at
full precision, as a range endpoint already was.

The headline figures do not move, because "usable" is syntactic. What moved is what a usable
declaration *says* at 206 result positions (what-an-int-is.md §3.2). That is not in these
numbers; it is in what a program can now do with the value.

## 4. encoding/binary: the algebra (the varint half)

```
C : U → B*    LEB128: base 128, least significant group first, the high bit of every byte but the last set
              PREFIX-FREE — no codeword is a prefix of another — with |C(x)| = max(1, ⌈bitlen(x)/7⌉) ≤ 10,
              and Kraft's inequality holds
Uvarint       C⁻¹ on the first codeword of a buffer
z : word → U  zig-zag, z(x) = 2x for x ≥ 0 and −2x − 1 otherwise: a BIJECTION onto U (Protocol Buffers)
Varint        z⁻¹ ∘ Uvarint;   PutVarint = PutUvarint ∘ z
```

The acceptance program checks C⁻¹ ∘ C = id at every length boundary: 1, 1, 2, 2, 3, 9, 10 and
10 bytes for 0, 127, 128, 16383, 16384, 2⁶³−1, 2⁶³ and 2⁶⁴−1. It checks zig-zag at both ends of
the word, and that two appended codewords parse the first alone. It reads from an
`io.ByteReader`, a `*strings.Reader` from the generated `strings` file, through a subsumption
edge the survey checked. And it decodes 2⁶⁴−1 and computes y/2 = 2⁶³−1, y mod 1000 = 615 and
y/4 + n natively.

**Not said, and named:**
- **|C(x)| depends on x's value, nonlinearly.** So `PutUvarint`'s exact requirement,
  len buf ≥ |C(x)|, is outside the fragment. It is stated as len buf ≥ 10, which is stronger
  than needed and so sound.
- **`Uvarint`'s count is a three-way sum encoded in a sign:** n > 0 bytes read, n = 0 the
  buffer ended first, n < 0 an overflow after −n bytes. Read off the source, n ∈ [−11, 10],
  and the program shows −10 (a tenth byte above 1) and −11 (an eleventh byte). Its honest type
  is a variant: `(variant (read n) (short) (overflow n))`. It is declared as the integer range
  it is, and the variant is the wall this package names for later.
- **The `ByteOrder` half** (`BigEndian.Uint64` and the rest) hangs off unexported types reached
  through package variables, which the survey cannot declare. The reflective half (`Read`,
  `Write`, `Size`) takes `any`.

## 5. Found on the way

- **A repeated `(import …)` on a template silently replaced the first.** This is the class of
  bug a repeated `where` was fixed for. It is refused now; `ReadVarint`'s wrapper names its
  reader as an interface literal instead of importing `io`.
- **The tooling checker compared an unrealized `f64` in a generated fragment against the hand
  file's `float64`.** A fragment's language types are realized by the whole target now.
  strconv was the first hand-declared package with a float.
- **`io.ByteReader`**, and its one method `ReadByte`, joined `io.oro`, the type's owner.
- **A constant name inside a `where`** (`MaxVarintLen64`) is not unfolded by the refinement
  layer, only as a range endpoint, so the literal 10 is written there.

## 6. Where Go's standard library stands

Supported by hand now:
- `unicode/utf8` and `encoding/hex`;
- `io`'s interfaces (`Reader`, `Writer`, `Closer`, `WriteCloser`, `ByteReader`);
- **`strconv`**;
- **`encoding/binary`'s varints**.

The next packages are for the standing goal to choose. The walls named here are the dependent
range, the sum in a sign, and the `ByteOrder` values.
