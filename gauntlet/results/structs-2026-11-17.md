# A host struct is its layout: ADR 0128, step 2a

2026-11-17. ADR 0128's build order, step 2: the host struct (items 8–11), program first. hamza:
"do both" (the product's remaining positions, and this). Its first half: a struct of scalars and
nested structs, as a cell the host writes.

**A Win32 struct is declared by its C definition, its layout is the fold of Theorem L, and clang
agrees on both triples.** `GetClientRect` fills a RECT and `GetLocalTime` a SYSTEMTIME, each
a struct's cell. A program reads them by label, `rc.right - rc.left`, on both Windows triples:

```
0 0 1920 1080 2026 11 17
```

## 1. What was built

**Respelled 2026-11-18** (hamza: "go ahead"): the first build had a set former `struct { … }` whose
type carried the C order, so two orders of one record were two types, which is no set (ADR 0049).
The layout is now a representation, `repr RECT c(…)`, beside the record set (§1a).

| the cell | `core/outcell.go`, `ir/lower.go` | the cell declaration carries the C name and the record; `(#ref "NAME" leaves…)`, `(#deref r j)` in canonical order; `cell-ref NAME` and `cell-get r j` in the IR, printed and read back |

### 1a. Why a representation and not a set former

A record set has no order, and a C layout is an order and a packing over it. That is a
representation, which ADR 0083 says a host boundary states and nothing chooses. Integers are the same
shape: `set DWORD = 0..2^32-1` is a set, and its C type follows from it, because over C's integer
types the set determines the type. Over structs it does not, since one record has many field orders.
So the layout is stated, as targets already state `repr … word` and `repr scalar 32`, and no word
enters the language. Theorem F's determined fields (step 2b) then belong to the `repr` line alone,
outside the record, which is exactly the program's view.

## 2. Measured

- **The layouts**: 5 structs on each triple, each clang's. The fault that ignores packing
  (`PlantNaturalLayout`) is caught on FORMATRANGE's alignment, 8 against clang's 4 on x86_64.
- **The program** (`cmd/build/struct_test.go`), on windows and windows32: the desktop at 0, 0 with a
  positive size, and the local date a date. The fault that reads the leaves from a fresh region
  (`PlantStructUnread`) answers a desktop 0 wide.
- **The access's alignment** (`ir/llvm/structcell_test.go`) is min(A, o & −o) on the measured
  layouts' cases: FORMATRANGE's pointer at 8 is 4, PRINTDLGA's at 34 under pack(1) is 1. The
  natural-alignment fault (`PlantLeafAlignNatural`) claims 8.
- **The emitted LLVM** for i686: RECT `alloca [16 x i8], align 4`, its four `load i32 … align 4`;
  SYSTEMTIME `alloca [16 x i8], align 2`, its `load i16 … align 2`.

## 3. What failed first

- **The first spelling, `struct { … }`, made order part of a type** (§1a): replaced by a record and
  a `repr`. Respelled, the declaration's cell was unfolded to its bare record and lost its layout,
  "cell(record{…}) is no C type": a cell's element that names a C layout keeps its name, at the
  prims' unfolding and at an out-cell's.
- **A struct's field types named sets relative to its module** (`minwindef.WORD`). The layout test
  unfolded them with no module and found no C type: they are unfolded in their module, and
  `mapTypeNames` now descends into a record's and a struct's fields.
- **The data model's names are not aliases**: `basetsd.UINT_PTR` is not in the target's alias table.
  A pointer's size is the triple's ISA word (`DigitBits`), which is the data model's pointer width
  on both triples.
- **The IR's text could not write a struct's type**, which has braces, colons and semicolons; it is
  written as a string and read back as one.

## 4. Not built (step 2b, ADR 0128 items 12–13)

- **A field the declaration determines** (Theorem F): `lStructSize`, a buffer's length, a reserved
  zero.
- **A pointer field into the program's memory** (Theorem P′): a C string, a buffer, a nested record
  by pointer.
- **A packing the data model states** (commdlg's pack(1) on ILP32, item 9).
- **A struct passed by value**, and a struct in a struct cell's `_In_` position (a value encoded
  before the call); the cell takes it, `(#ref "S" leaves…)`, and no declaration asks yet.
