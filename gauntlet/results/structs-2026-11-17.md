# A host struct is its layout: ADR 0128, steps 2a and 2b

2026-11-17. ADR 0128's build order, step 2: the host struct (items 8–11), program first. hamza:
"do both" (the product's remaining positions, and this). Its first half: a struct of scalars and
nested structs, as a cell the host writes.

**A Win32 struct is declared by its C definition, its layout is the fold of Theorem L, and clang
agrees on both triples.** `GetClientRect` fills a RECT and `GetLocalTime` a SYSTEMTIME, each
a struct's cell. A program reads them by label, `rc.right - rc.left`, on both Windows triples:

```
0 0 1920 1080 2026 11 17
```

## 1. What was built

**Respelled 2026-11-18** (hamza: "go ahead"): the first build had a set former `struct { … }` whose
type carried the C order, so two orders of one record were two types, which is no set (ADR 0049).
The layout is now a representation, `repr RECT c(…)`, beside the record set (§1a).

| piece | where | what it is |
|---|---|---|
| the set | `targets/win32`, a `record { … }` | the language's record, structural; the C type's name its typedef |
| its layout | `repr NAME c(l…) [pack(p)]`, `core/jreadtarget.go` `cLayout`, `emit.Target.Layouts` | the record's labels in C order and the packing, kept by the qualified name |
| the fold | `emit/layout.go` | L_{M,p}: fields in C order, each at ⌈off⌉ at min(a, p), A the max, N rounded to A; a pointer the triple's word; a field of a C type with a layout laid out as it |
| the cell | `core/outcell.go`, `ir/lower.go` | the cell declaration carries the C name and the record; `(#ref "NAME" leaves…)`, `(#deref r j)` in canonical order; `cell-ref NAME` and `cell-get r j` in the IR, printed and read back |
| the name kept | `emit/alias.go` | a cell's element that is a C type with a layout is not unfolded to its record |
| the printer | `ir/llvm/structcell.go` | `alloca [N x i8], align A`, zero filled; each leaf at `getelementptr i8 … o`, its C type, aligned min(A, o & −o) |
| the check | `emit/layout_test.go` | every declared layout's size, alignment and offsets as `_Static_assert`s against the SDK, clang on both triples |
| the declarations | `targets/win32` | `windef`'s RECT and POINT; `minwinbase` (new) SYSTEMTIME; `richedit` (new) CHARRANGE and FORMATRANGE, pack(4); `sysinfoapi` (new) GetLocalTime; `winuser`'s GetClientRect and GetDesktopWindow |

### 1a. Why a representation and not a set former

A record set has no order, and a C layout is an order and a packing over it. That is a
representation, which ADR 0083 says a host boundary states and nothing chooses. Integers are the same
shape: `set DWORD = 0..2^32-1` is a set, and its C type follows from it, because over C's integer
types the set determines the type. Over structs it does not, since one record has many field orders.
So the layout is stated, as targets already state `repr … word` and `repr scalar 32`, and no word
enters the language. Theorem F's determined fields (step 2b) then belong to the `repr` line alone,
outside the record, which is exactly the program's view.

## 2. Measured

- **The layouts**: 5 structs on each triple, each clang's. The fault that ignores packing

- **The program** (`cmd/build/struct_test.go`), on windows and windows32: the desktop at 0, 0 with a
  positive size, and the local date a date. The fault that reads the leaves from a fresh region
  (`PlantStructUnread`) answers a desktop 0 wide.
- **The access's alignment** (`ir/llvm/structcell_test.go`) is min(A, o & −o) on the measured
  layouts' cases: FORMATRANGE's pointer at 8 is 4, PRINTDLGA's at 34 under pack(1) is 1. The
  natural-alignment fault (`PlantLeafAlignNatural`) claims 8.
- **The emitted LLVM** for i686: RECT `alloca [16 x i8], align 4`, its four `load i32 … align 4`;
  SYSTEMTIME `alloca [16 x i8], align 2`, its `load i16 … align 2`.

## 3. What failed first

- **The first spelling, `struct { … }`, made order part of a type** (§1a): replaced by a record and
  a `repr`. Respelled, the declaration's cell was unfolded to its bare record and lost its layout,
  "cell(record{…}) is no C type": a cell's element that names a C layout keeps its name, at the
  prims' unfolding and at an out-cell's.
- **A struct's field types named sets relative to its module** (`minwindef.WORD`). The layout test
  unfolded them with no module and found no C type: they are unfolded in their module, and
  `mapTypeNames` now descends into a record's and a struct's fields.
- **The data model's names are not aliases**: `basetsd.UINT_PTR` is not in the target's alias table.
  A pointer's size is the triple's ISA word (`DigitBits`), which is the data model's pointer width
  on both triples.
- **The IR's text could not write a struct's type**, which has braces, colons and semicolons; it is
  written as a string and read back as one.

## 4. Step 2b, 2026-11-18: determined fields, the model's packing, `_In_` structs, C strings

hamza: "go ahead with step 2b". Three programs that run without a person, each with the host as the
witness of what it checks:

| program | what it exercises | answers, windows and windows32 |
|---|---|---|
| `GlobalMemoryStatusEx` | `dwLength ∈ DWORD = size`, written into a fresh cell before the host reads it | 1, a load in 0..100, the physical memory in MB |
| `PrintDlgA`, `PD_RETURNDEFAULT` | `lStructSize = size`, eight fields `= 0`, `pack(ILP32 : 1)`: 66 bytes on i686, 120 on x86_64 | 1 and error 0 (a default printer), or `PDERR_NODEFAULTPRN`; never `CDERR_STRUCTSIZE` |
| `RegisterClassA`, `UnregisterClassA` | an `_In_` struct, `wc ∈ WNDCLASSA`; a C string field, `lpszClassName`; `where nulfree(wc.lpszClassName)` | 1 1: registered, and found by its name |

Each rule has its fault, and each fault fails its case:
- `PlantNoDeterminedSize`: dwLength left 0, and GlobalMemoryStatusEx answers 0.
- `PlantNaturalLayout` on i686: PRINTDLGA laid out naturally is 68 bytes, and PrintDlgA answers
  `CDERR_STRUCTSIZE`. The clang check fails on it as well.
- `PlantCStringHeader`: the string passed with its length first, so the class is registered under
  another name and UnregisterClassA cannot find it.
- `PlantWhereProjectionUnread`: the `where`'s `wc.lpszClassName` read as a name, so the obligation is
  undecided and the program refused.

A class name that may hold a NUL, `string_of(d.wMonth % 128)`, is refused naming `nulfree`.

**What was built.**
- **Determined fields** (Theorem F): `l ∈ S = size | 0 | len(m)` on the `repr` line, outside the
  record. `= size` is written by the printer after the zero fill.
- **The data model's packing**: `pack(ILP32 : 1)`, the model read off the pointer's size.
- **`_In_` structs**: a parameter whose set is a C type with a layout is `const T*`. The reducer writes
  its argument's leaves into `(#ref "T" …)` (`Env.InStructs`), and nothing is read back.
- **C-string fields**: laid out as a pointer, written as s + 8. A host `where`'s `p.l` is the
  parameter's projection (`core.ProjectBound`), and ν is decided on the leaf it reads
  (`refiner.projected`).
- **A pointer's zero**: null.

**What failed first.**
- **Determined fields' sets named through another module.** `LPARAM` is minwindef's
  `basetsd.LONG_PTR`, which `UnfoldType` resolved from the struct's module, where it is unbound: the
  layout resolves each definition in its own module (`resolveSet`), as `unfoldAliases` does. Earlier,
  `basetsd.UINT_PTR` seemed absent from the alias table; its key is spelled `UINT-PTR`.
- **`zero(commdlg.PRINTDLGA)`**: a target's set, which the scope check read as an unbound name and the
  reducer could not unfold. `zero`'s argument is a set, and a target's environment unfolds it
  (`Env.UnfoldSet`).
- **An `_In_` struct read as a cell parameter**: cell parameters are found after the unfolding that
  makes a C struct `cell T`. The unfolding marks the parameters it made (`Prim.InStructs`), and
  they are skipped.
- **A cell declared after an out-call, a wrong refusal for scalar cells too.**
  `(sz, ok) = GetFileSizeEx(h, out …)` then `var hi := 0` and `GetFileSize(h, hi)` was refused,
  "#s2 is neither". The calls pass translated the scope pass's call a second time, and the two
  passes' fresh names, each counted from 1, then captured an argument: `GetFileSize(#s1, #s1)`.
  A call already translated is left alone, as `calls` already did (`PlantCellCallTwice`), and the
  calls pass names past the scopes' (`PlantCellNamesClash`). Both faults are caught by
  `TestACellAfterAnOutCallIsACell`.
