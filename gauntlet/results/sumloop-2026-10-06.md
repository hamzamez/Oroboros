# A loop yields a sum, a success arm is a tail, substitution shifts, and η for products

2026-10-06. [expect-2026-10-06](expect-2026-10-06.md) §6 named a wall for errors.md §12's step 5: a
loop over a fallible step, "read, `try`, go round", was refused twice. hamza: *"if the algebra leads to
your recommendation, do it."* It did, and closing it took four changes. The third is a soundness bug in
the reducer's substitution, found by the first program written under the second. The fourth, η for
products, is the law the first made necessary.

## 1. A constructor is the tuple it was always said to be

```lisp
(loop ((i 0) (acc 0))
  (>= i 10)       (result.ok acc)
  (= (% i 2) 1)   (result.err i)
  else            (again (+ i 1) (+ acc i)))
```

was refused: *a tuple pattern of 2 names takes apart a `build` or a `loop`, so every exit must give 2
values*. The residual's exits were `(fn (#x) (#x 0 acc))` and `(fn (#x) (#x 1 i))`. Those are
two-component tuples in every respect except the binder's spelling, and `tupleArity` recognises a
tuple by its binder, `#k`. sums.md §1 says a sum is represented as the product (tag, payload), and the
generator's own comment called a nullary constructor "the constant `(values i 0)`". **One term had two
spellings**, and passes keyed on one spelling did not see the other.

A constructor is now `(fn (#k) (#k tag payload))`, exactly what `(tuple tag payload)` reads as
(`core/read.go`, `Sum.Defs`). Nothing else changed: the loop yields the sum as two results through the
tuple-out-of-a-loop machinery ADR 0031 built. Every existing emitted file is byte-identical. One
refusal message changed: it prints the residual of `lib/result.oro` compiled standalone, and its
constructors now print `#k`.

## 2. `again` in a success arm (ADR 0041)

`(try (s x) e body)` binds the payload and runs `body` once, now: a binding's tail, as a host call's
continuation is (ADR 0027). Its other arms leave the loop, `try`'s with the failure as the loop's
value and `expect`'s into 0, so the clause list is still every back edge. The reader accepts `again`
as `body`, or anywhere a clause body may hold one, and refuses it in the value, the pattern and the
reason (`checkClauseBody`, `isMonadForm`). After reduction the arm is an arm of an `if`, which every
walker of a clause chain walks, so nothing below the reader learns that `try` exists.

Checked where the tag is not known at compile time. A scrutinee with an effect, read in the loop's
condition, reduces through the commuting conversion: its argument is a λ, which is a value. The
program prints `0 1 -2` on Go, JavaScript and Java. A sum cannot be a parameter of an export yet, so
that source of an unknown tag does not exist. A sum bound once and read twice is refused (§5).

## 3. The substitution was unsound for a value holding an index

The differential case for §1 and §2 panicked the refinement layer: *index out of range [0] with
length 0*, in `Term.Op`, on a term that was a bound index. The residual held

```
(fn (#k) (#k 0 (+ #3.1 (/ #c 2))))
```

`#3.1` is the loop's `acc`, referenced from one binder deeper than its index counts. The recount
(sumofsums-2026-10-06) substitutes a pure value that ends up used once with `subst`, and `subst` was a
**named** substitution. It opened each λ it passed and inserted the value unshifted. Reduction works on
closed bodies, so a value normalised there refers to enclosing binders by index, and under k more
binders each such index must count k more. `openWith`, β's own substitution, shifts. `subst` did not,
so it was sound only for a value with no index in it. Every caller before the recount happened to hand
it one.

**The fix is the substitution the representation calls for.** Locally nameless needs no opening and no
freshening for a free name: inside a closed body every name is free, because a binder's own parameters
are indices, so capture is unrepresentable. `subst` now walks the closed term and shifts the value by
the depth it lands at (`core/reduce.go`, `substAt`). It replaces the opening, freshening one for every
caller: the recount, `markWhere`'s instantiated conditions, and `Rename`/`Rename2`. Its own comment had
said *"The stronger version belongs with the IR format"*. It is 30 lines shorter.

Every emitted file is byte-identical under it, and every test passes. That evidence fits the diagnosis:
the old substitution differed from this one only on a value holding an index, which only the recount
produced.

## 4. The case, and a wrong expectation

`gauntlet/differential/cases/try-loop.oro`: `run n` sums half(2i) for i < n, then `try`s half(n + 1).
All four targets agreed from the first run, on `-1 1 -3 5 -5 41 -11`. My `; expect:` said 4 and 46 at
n = 3 and n = 9. The sum is n(n−1)/2 + (n+1)/2 for odd n, so 5 and 41: the expectation was wrong and the
compiler right. That is the case for `; expect:` and agreement both, since either alone can be wrong.

## 5. η for products, built: a binding of a product is taken apart

A sum, or any tuple, bound by a `let` and read twice was refused:

```lisp
(let r (if c (result.ok i) (result.err i))
  (seq (case r …) (try (result.ok x) r (again …))))
```

It reduced to `(let S (fn (r) … (r k₁) … (r k₂)))`: an eliminator applied to a variable, which no
commuting conversion reaches. The refusal was the tuple-pattern message, which names exits and not the
cause. Making a constructor a tuple then broke R1's test the other way round. `(build b 4 (some (set b 0
n)))` was no longer refused as "a variant out of a scope", and the residual
`(let SCOPE (fn (o) … (o k)))` was read by the refiner as an indexing. Both are the same missing law.

**η for products**: for any r of a product type, r = (π₁ r, …, πₙ r). So a binding whose value has
every tail an n-tuple is taken apart where it stands (`core/reduce.go`, β's residual `let`):

```
(let V (fn (r) B))  ⟶  (V (fn (c₁ … cₙ) B[r := (tuple c₁ … cₙ)]))
```

That is ADR 0031's tuple pattern, a join point over a scope or a loop, and each `(r k)` in B is a
β-redex. `Env.tupleTails` decides the condition. It walks a value's tails through `if`, a residual
`let`, a host call's continuation, a scope, a where-mark and a loop's exits, where `again` is no tail.
It answers no on any other shape, so a form it misses leaves the binding as it was: imprecise, never
unsound. Effects are untouched: V is evaluated once, where it was bound, before B.

What it closed:
- **a sum read twice** builds and prints `100 101 -2 -2` on Go, JavaScript and Java;
- **a variant out of a scope is ADR 0031's product.** Its payload buffer is a component, frozen by the
  tuple-component law, and `(case o (some t) (+ (t 0) (len t)) none 0)` gives 7 on all three. R1 is now
  what it says, a buffer *inside* another value: an array's element, a closure, a rule. Two constructors
  whose payload slot would be a buffer in one arm and an integer in the other are refused by the type
  checker, as two branches of different types;
- **a core test that pinned the stuck shape.** `TestTheRecountDoesNotMoveAnImpureValue` asserted the
  impure payload stayed let-bound with the sum unreduced, and its comment called that a limitation. The
  residual is now `(if (go.> 5 n) n (if (go.> (go.roll) n) 1000 2000))`. The call still runs once, at the
  point the program wrote it, as the condition choosing the constructor. The test pins that.

Every existing emitted file is byte-identical with η on.

## 6. Witnesses and planted faults

| rule | witness | planted fault, and what caught it |
|---|---|---|
| a constructor is the tuple | `TestSumGeneratesConstructors` pins `(fn (#p) (fn (#k) (#k 0 #p)))`; `cases/try-loop.oro` | `#x` restored: the case is refused, *a tuple pattern of 2 names* |
| `again` in a success arm | `TestAgainMaySitInASuccessArmOnly`: two accepted, three refused | the rule off: both accepted forms refused |
| substitution shifts | `TestSubstShiftsAnIndexUnderABinder`: under a binder, at the top, and a free name under a λ hinted the same | the shift removed: the unit test fails and the case's build panics |
| η for products | `TestEtaForProductsNeedsEveryTailATupleOfOneArity`: three taken apart, four left bound; the recount test's residual; the variant-out-of-a-scope test | arities joined unchecked; an unknown shape accepted; the rule off: each fails a test |

The tests that asserted a constructor's **absence** by `#x` (`map_test`, `sum_test`, `try_test`) would
have passed vacuously after the respelling. They now look for `#k`, and every one still passes, so no
output they read holds a tuple.

## 7. Cost

- **Emission:** byte-identical except the one refusal message (§1) and the new case's four outputs.
- **Balance:** about +200 lines of compiler and tests, and −30 in `subst`. No change in `examples/`: the
  case is in `gauntlet/`.
