2026-09-10. `gauntlet/stdlib/jdk/Dump.java`, `gauntlet/stdlib/jvm.go`,
`gauntlet/stdlib/jsdump.mjs`, `gauntlet/stdlib/js.go`, and two acceptance
programs. Two of four targets had never been priced, which
gomethods-2026-09-09 and struct-literals.md both named as owed.

## 1. The JVM: the runtime is the manifest

Go ships `api/go1*.txt` and the Windows SDK ships headers. The JDK ships neither
and needs neither: `jrt:/` enumerates every class in every module and reflection
reads its signature, so `Dump.java` is not a description of the JDK that could
drift from it — **it is the JDK, asked**. That is the coercion result's rule
arriving on a second host: the host is the oracle.

**48,966 lines: 4,508 public types and 38,042 callable members** across 223
exported packages — 7.7× Go's surface.

### 1.1 Four decisions, stated before the number

**OUR `int` IS JAVA'S `long`**, so Java's `int` is a RANGE, `(int -2147483648
2147483647)`, and ADR 0003's ladder renders it back. `targets/java/java.oro` says
why: declaring our `int` as Java's would be a silent miscompilation, because
Java's wraps at 2³¹, inside the range our literals already cover.

**A BOXED TYPE IS ITS PRIMITIVE.** `java.lang.Long` where a `long` is wanted and
back is javac's own conversion (JLS 5.1.7, 5.1.8), inserted exactly as Go inserts
an interface coercion. The hazard is named rather than hidden: **unboxing a null
throws**, and a Java programmer has that hazard too.

**A TYPE VARIABLE IS NOT A TYPE**, and this is the JVM's defining refusal — not a
version of Go's, because Go's standard library is barely generic and Java's is
generic to the bone. **7.6% of the surface refused outright**, and 3,026 names (8.0%)
mention one. Decomposed rather than quoted: **1,872** are a member of a generic
CLASS, where instantiating the class at a ground
type would substitute the variable — one declaration per (class, argument), which
`targets/java/util.oro` calls *"the same limitation squared"* and is why it
declares `Map<String,Long>` and nothing else. **1,154 are a variable in the
member's own signature with a non-generic owner, and nothing can substitute
those: they are the honest refusal.**

**AND A PARAMETERISED TYPE IS SPELLABLE AT A GROUND INSTANTIATION.**
`java.util.List<java.lang.String>` gets a name the way `*os.File` does — we never
APPLY a type constructor, we NAME the applied thing. That is a correction the Go
survey owes itself: it refuses `iter.Seq[[]uint8]` as a `generic instantiation`
on an argument that does not survive here.

### 1.2 A functional interface is an ordinary object

On Go a `func(…)` value is refused in both directions. **On the JVM a callback is
an OBJECT with one method**, so holding one costs nothing and calling one is an
ordinary method call; only MANUFACTURING one is callbacks.md tier 3 — which the
obtainable fixed point decides already, with no special case. 286 of them.

That is worth recording as a difference between hosts rather than a fact about
callbacks: **the same refusal costs different amounts depending on how the host
spells the thing refused.**

### 1.3 The number, and the way it could have flattered

**81.4% declarable, 60.9% usable** — and two corrections were made before it was
written down, both deflating.

**`java.lang.Object` is REFUSED**, matching Go's `interface{}`. A value with no
operations, and treating it as `any` would make the fixed point vacuous since a
large part of the JDK returns one. 1,891 names, 5.0%.

**A TYPE NO MODULE EXPORTS IS NOT SPELLABLE**, however public the method that
mentions it. A signature can name a `jdk.internal.*` or `sun.*` class from a
package exported to nobody, and the first version let those through: **958 names,
2.5%, and it took declarable from 84.3% to 81.4% and usable from 61.6% to 59.8%.**
Checked against the manifest's own type lines rather than a list of prefixes,
because the module graph is the fact and a prefix is a guess.

## 2. The coercion, on a host that declares its own relation

`java.util.StringJoiner` takes a `CharSequence` and we hold a `string`.

coercion-2026-09-09 built exactly this and had to work for it: Go's relation is
STRUCTURAL, the api manifest lists the exported API, so an interface sealed by an
unexported method looked satisfied by everything and **182 of 1,651 candidates
were false** until `go build` named them.

**The JVM writes its relation down.** `getSuperclass` and `getInterfaces` are the
answer, so the dumper reads 3,333 declarations and the survey emits **10,095
edges over 3,225 subtypes** with nothing to guess and nothing for a host filter to
catch. (Corrected 2026-09-11 from *5,186*, which nothing reproduces, and from
*"direct edges only"*: `closeSub` closes the relation before emission, so the
edges are the transitive closure — harmless, since `closeImplements` closes it
again at load and a closed relation is a fixed point of closing.)

**`(implements string java-lang-CharSequence java-lang-Comparable …)`** is the
edge that pays, and it needed one thing the Go generator never had to think
about: **a range is not a name**. `java.lang.Byte` spells `(int -128 127)`, a
type EXPRESSION, which cannot be the subject of an edge — and nothing is lost,
because `ValueType` normalises a range to `int` and `int` carries the edges.

## 3. The two format problems Go could not have shown

**OVERLOADING.** `tg.Prims` is keyed by NAME ALONE, so `nextInt()` and
`nextInt(int)` are one entry. overloading.md §3 already records this as *"a
target-file wart: `Println`, `Println2`, `Println3` exist because `tg.Prims` is
keyed by name alone"* — with ONE live instance. **Java has 4,948**, 16.0% of the
emitted surface (corrected 2026-09-11 from 5,446 and 17.6%, which the committed
tool does not print), and the existing precedent is the answer: the first spelling
keeps the name, each later one takes a numeral, deterministic because the list is
sorted by (owner, kind, name, parameter list) first.

**AND A CLASS IS THE MODULE, NOT A PACKAGE.** The first version put static
methods in the package module and `java.lang.Math.atan2` collided with
`java.lang.StrictMath.atan2` — two classes, one package, one name. Every member
lives in `java/<pkg>/<Class>` now, which is what `targets/java/lang.oro` already
does by hand: `(use java/Math)` then `(Math.abs x)`, reading exactly as Java
reads. A CONSTRUCTOR stays in the package module under its class's own name, so
`(ju.StringJoiner ", ")` reads as the type being built.

**30,940 primitives emitted, and 30,940 + 19 = 30,959 declarable** — the residue
being voids with no argument, which have nothing to be. *A name counted
declarable and never emitted is a claim*, and the arithmetic closes.

## 4. JavaScript: the headline is that there is no headline

`jsdump.mjs` walks `globalThis` and 53 `node:` modules: **3,913 members, 2,340 of
them callable**, 1,106 of those instance members reached through `.prototype.`.

**DECLARABLE IS 100% AND IT MEASURES NOTHING.** `targets/js` declares every type
`any` — deliberately, and target-native.md says why — so any host function can be
given `(prim f ((a0 any) (a1 any)) any expr "f(%s, %s)")` because `any` demands
nothing. Reporting that as a capability would be the fifth time a survey's first
number described the measurer, and the largest.

**USABLE HAS NO DOMAIN.** The other two surveys compute it as a least fixed point
over the types a program can obtain. Here there is one type and every value has
it, so the fixed point is total and says nothing. **That is the same fact that
made ADR 0019's bounded-by-default VACUOUS on JavaScript** (bigrep-2026-09-02):
the analysis counted zero integer operations because a language operator
inherited `any` from the host, and a check with nothing to prove reports success.

### 4.1 So the survey measures the SHAPE, and the shape is misreported

A JavaScript declaration needs a name, a call form and an ARITY. The first two
are answerable. The third is the finding.

```
Array.prototype.map      reports 1      takes 2
Array.prototype.push     reports 1      variadic
Math.max                 reports 2      variadic
Math.min                 reports 2      variadic
String.prototype.concat  reports 1      variadic
console.log              reports 0      variadic
```

`Function.length` counts the parameters before the first default or rest, and a
NATIVE function's parameters are not introspectable at all. **604 of 2,326
nameable callable members report arity ZERO (26.0%)**, which for a native function means
either that it takes nothing or that nothing can be known.

> **The host does not merely decline to tell us the types — it misreports the
> shape**, which is the one thing we needed from it. A declaration must name an
> arity and nothing on this host can check it, which is `Println`/`Println2`/
> `Println3` arriving as the only honest form: one declaration per arity a
> program actually uses.

**The comparison that makes this worth writing.** win32-2026-09-06 found the host
with no type system pricing BETTER than Go, because *"on x86-64 every handle,
pointer and integer is ONE REGISTER, so there is nothing to be opaque about"*.
JavaScript is that observation taken to its limit and inverted: **everything is
one dynamic value, so nothing is opaque AND nothing is checked.** Opacity is a
property of the pair; so is checkability.

### 4.2 The one refusal that is ours

**10 callable members have a key the host accepts and our READER does not** —
`RegExp.$1`, `RegExp.$&`. `core/read.go` allows letters, digits, `_` and the
symbol characters `-+*/<>=!?_%&|^~`, and deliberately not `$`, because a target
file renaming a host operation would be *"teaching the reader's limitations rather
than the host's"*. Nine names, named as ours rather than counted as the host's.

**And three things the dumper had to stop describing**, each of which put this
machine into the manifest rather than the host: `node:module._pathCache` is keyed
by ABSOLUTE PATH, `process.config` is how this Node was built,
`process.moduleLoadList` is what this run loaded. Plus `http.METHODS`, an ARRAY
whose 35 elements became 35 members named `0`, `1`, `2` — data in the numerator.
*A manifest that embeds where it was run is not a description of the host.*

## 5. The correction to the Go survey, which is why doing both was worth it

Go's `obtainableFrom` considered only `s.kind == "func"` with no receiver. A type
returned by a METHOD was therefore not obtainable — and `(*os.File).Stat` gives an
`fs.FileInfo` from a file we can open.

On the JVM this is impossible to miss: `new` and a method are the two idioms, and
`list.iterator()` is how a large part of the JDK is reached. On Go the constructor
idiom is a package function, so the omission looked like the whole story.

| | before | after |
|---|---:|---:|
| obtainable host types | 289 | **568** |
| **usable** | 50.0% | **60.4%** |
| method usable | 42.6% | **53.9%** |
| cannot build the argument | 45.1% of declarable | **31.1%** |

**Struct literals are worth +268 against yesterday's +229** on the corrected base,
and struct-literals.md's projection of 55.2% is now bracketed on both sides: the
seeding it used was too generous and the fixed point it seeded was too strict.

> Seventh correction to a number this survey has published, and the second in two
> days that the survey found rather than the next question finding it. **Four
> deflated and three inflated.** The rule holds: when a measurement of what a
> language can do is written by the same hands as the language, the first number
> describes the measurer.

## 6. Acceptance, because a percentage that does not build is a claim

**`gauntlet/stdlib/acceptance/jvm-object.oro`** — every declaration generated:

```lisp
(SJ.toString (SJ.add (SJ.add (SJ.add (ju.StringJoiner ", ") "a") "b") "c"))
(Random.nextInt2 (ju.Random2 42) 100)
```

prints `a, b, c` and **30**, which is what `new java.util.Random(42).nextInt(100)`
prints in Java — a value the JVM specifies, so it is checkable against the host
rather than against ourselves. The emitted Java:

```java
final var v1 = ((((((new java.util.StringJoiner(", "))).add("a")).add("b")).add("c")).toString());
final var v2 = (((new java.util.Random(42))).nextInt(100));
```

**No conversion syntax at all** for the `string` → `CharSequence` coercion, exactly
as on Go.

**`gauntlet/stdlib/acceptance/js-shape.oro`** prints **7**, **ABC**, and a single
dot — and the dot is the point. `path.join.length` is 0, so the generated
declaration is `(prim join (none) any expr "path.join()")`: **legal, buildable,
runnable, and unable to be passed a path.** The finding exhibited rather than
asserted.

## 7. One compiler bug, and generating a whole runtime is what ran the path

```
ReferenceError: path is not defined
```

**A single-result JavaScript prim dropped its `(import …)`.** `emitMultiPrim`
collected it and the ordinary prim path did not, so the emitted call named a
binding nothing creates — with no diagnostic from us.

Latent since the JS import mechanism landed yesterday, because **every prim that
had ever carried an import on this host was fallible and therefore
multi-result**: `fs.readFileSync` is a `try`/`catch` template, and `lib/io/js.oro`
reaches `process`, which is a global. *A path nothing runs is a path nothing
checks*, sixth time — and what ran it was declaring the entire Node runtime.

One line, at the site where the prim is looked up. Pinned by a test using the
simplest shape that has the bug — one result, one import, no continuation —
verified to fail against it.

## 9. What it leaves

**The JVM's residue is a type variable, and half of it is answerable.** 1,872 of
the 3,026 are members of a generic class, where instantiating at a ground type
would substitute — one declaration per (class, argument), which is combinatorial
and which `targets/java/util.oro` already refused by hand. Whether that trade is
worth making is a measurement nobody has taken.

**JavaScript's residue is that there is nothing to measure**, and the useful
question is a different one: what would a SECOND source of types buy? TypeScript's
`lib.*.d.ts` is the obvious candidate and is not on this machine. Until then, a
JavaScript declaration is a claim with no oracle — which is exactly what the other
three hosts do not have to say.

**And the four numbers now sit beside each other for the first time.** Go 60.4%,
JVM 60.9%, Win32 34.8%, JavaScript unmeasurable. The two big managed ecosystems
landing half a point apart, from completely different refusals — Go's are
interfaces and struct literals, the JVM's are type variables and `Object` — is
either a coincidence or the parasite model's ceiling, and one more host would
tell us which.
