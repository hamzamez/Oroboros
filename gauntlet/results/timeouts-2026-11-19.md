# timeouts — a time limit on every program a build test runs, 2026-11-19

Assessment-2026-11-18 §5 item 4 (§3.4 item 3): a stalled child cost the whole compiler step, up
to its 40-minute `go test` timeout, where it should cost one test.

## What was built

`cmd/build/program_test.go`: `program(name, args…)`. It is `exec.CommandContext` under a
2-minute limit, with `WaitDelay` of 5 s so a grandchild holding the pipes cannot keep `Wait` from
returning. Every program the package's tests run now goes through it: the 32 sites of
`exec.Command(exe…)`, `(art…)`, `(a…)`, `("node", …)` and `("java", …)`, in 17 test files and the
shared helpers `buildAndRun`, `runOn` and `runOnMayFail`. `go` and `clang`, the build and not the
program, do not.

`TestAProgramThatStallsIsKilled`: the test binary, asked to sleep 3 s under a 300 ms limit, is
killed and reports an error. The fault `PlantNoProgramLimit` runs it with no limit, and it then
sleeps its 3 s and succeeds.

## Not built

`ir/java` and `ir/js`'s printer tests run one small program each through `exec.Command` (java,
node). They are printer tests on fixed inputs, not build tests. A limit there is owed, at the same
cost, if one of them is ever seen to stall.
