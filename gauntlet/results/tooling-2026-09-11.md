## 1. What is tested, and what it needs

`go test ./gauntlet/stdlib/` runs every survey **twice from the manifest up** — `Dump.java` and
`jsdump.mjs` included, so the dumpers are held to the same property — and shares the two runs among
four tests:

**`TestSurveysAreFunctionsOfTheirInput`** — the two manifests, the two reports (with the output
directory masked) and every emitted file, byte for byte.

**`TestEveryDeclarableNameIsEmitted`** — *a name counted declarable and never emitted is a claim*
(win32-2026-09-08), as arithmetic. It needs no pinned number, so it survives a toolchain upgrade:

| host | emitted must equal |
|---|---|
| Go | declarable − voids with no argument + generated constructors: 4,331 − 20 + 462 = **4,773** |
| Win32 | declarable: **9,427** |
| JVM | declarable − voids with no argument: 30,959 − 19 = **30,940** |
| JavaScript | declarable: **2,326** |

and the report's count of emitted primitives must be the count of `(prim` lines in the files, since
the files are what a program loads.

**`TestPublishedCountsAreTheCounts`** — every figure a result document or CLAUDE.md quotes, as a line
the report must contain, with the document named beside it. **Pinned to the host version it was
measured on** — go1.27.0, Windows SDK 10.0.26100.0, JDK 17.0.12, Node v26.7.0 — because a manifest is
the host's own account of itself, and a new toolchain is a new manifest. **A mismatch FAILS rather than
skipping**: the message says to re-measure, re-pin and correct every document that quotes the number,
which is the step that has been skipped before. A test that quietly stops running after an upgrade is a
witness that cannot fail.

**`TestAcceptanceProgramsRun`** — the nine programs in `acceptance/`, built from THIS run's generated
declarations and run, each checked against what the host prints: `2`, `1`, `1 79`, `0 24 87`, `64`,
the size of `go.mod`, `8 4`, `a, b, c 30`, `7 ABC .`. Three of those answers are the host's rather than
ours — `ERROR_FILE_NOT_FOUND`, `new Random(42).nextInt(100)`, the byte count of a file — and two exist
because an earlier witness could not fail.

A host whose toolchain is absent is **skipped by name** — `java`, `node`, the Windows SDK, and the
windows target off Windows — and nothing is skipped for any other reason.

## 2. The reports were not a function of their input

```
first:  "  IUnknown                            17"
second: "  bool                                17"
```

Go's list of interfaces most asked for, Win32's unresolved typedefs and its SAL categories, and the
refusal and gap tables in all three of `survey.go`, `win32.go` and `jvm.go` were each built by ranging
over a map and sorting by count. **A count alone is a partial order**, and `sort.Slice` is not stable,
so every tie came out in whatever order the map produced. It is structlit-2026-09-10's finding one
level up: *sorting was necessary and not sufficient; what matters is a TOTAL order* — and that result
checked the emitted files and not the report the numbers are read from.

No count moved — the numbers were right and their order was not — so no published figure changes. But
a report that differs between runs is one where a diff cannot tell a change in the host from noise,
which is the only way anyone would notice the next correction.

## 3. Two JVM figures nothing produces

| published | the committed tool, same manifest | what the number is |
|---|---:|---|
| 5,446 overloads, 17.6% | **4,948, 16.0%** | prims renamed with a numeral |
| 5,186 edges | 4,626 | `implements` lines, one per subject per package file |
| — | **10,095** | distinct (subtype, supertype) pairs emitted |
| — | 3,225 | distinct subtypes |
| — | 8,542 | direct supertype declarations in the dump (6,935 distinct) |

**The overload count is almost certainly stale rather than wrong when written**: surveys-2026-09-10 §3
records that the first version put static members in the PACKAGE module and collided
`Math.atan2` with `StrictMath.atan2`, and moving every member into its class's module removes exactly
that kind of collision. The number was not re-taken after the move. **The edge count has no candidate
source at all.** It is not the lines, the pairs, the subjects or the dump's declarations, and the tool
had only ever printed the line count under the word *edges*.

**And the document said *"direct edges only"* while the code emits the closure** — `closeSub` runs
before emission and its own comment says so. Emitting the closure is harmless, because the loader
closes the relation anyway and a closed relation is a fixed point of closing; the claim about it was
wrong. The report now prints **pairs and subjects**, and says the edges are the closure.

Both are pinned now. That is the second unsourced figure in two days — assessment-2026-09-11 named
*"675 enums"*, repeated three times and measured by nobody — and the first one a test found.

## 4. A recipe nothing ran

`os-methods.oro`'s recipe in `acceptance/README.md` put the generated file at `<project>/go/os.oro`.
The source's own directory is also the LIBRARY search path, so `(use go/os)` finds that file as a
module and reads it with the wrong grammar — *"go/os: target go: expected (prim …)"*. The same README
explains exactly this trap two sections later, for `io-reader`, which is why that recipe uses `tg/go/`.
The recipe beside it was written before the trap was understood and never run again. Fixed to the
`tg/` layout; it prints 64. *A path nothing runs is a path nothing checks*, seventh time.

## 6. What it leaves

**Pinning is not measuring.** A pinned count says the number has not moved; it cannot say the number
was right. Every figure this tooling published that turned out wrong was wrong in its METHOD — seeding
a fixed point, collapsing qualified names, counting lines as edges — and a pin would have frozen each of
them. The test that is worth more is the arithmetic one, because it checks the tool against ITSELF: two
counts computed different ways must agree.

**The acceptance programs cover nine names of 47,000.** *(Ten as of structval-2026-09-12, and that
round is what the sentence was about: 585 generated Win32 declarations had a parameter typed as an
integer where the host wants an address, and no acceptance program touched one.)* They are the only semantic check any generated
declaration has, and they were chosen by hand. assessment-2026-09-11 §4's risk 1 stands — *a template is
checked only when some program happens to call it* — and the Go edges remain the one class every member
of which the host has accepted. Doing the same for templates means compiling every generated
declaration, which is a larger thing than this and is named rather than started.

**Next is item 3**: one application on two hosts through generated declarations, which now has a test
harness to live in.
