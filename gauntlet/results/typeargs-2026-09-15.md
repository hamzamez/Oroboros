# Type arguments on variant types: a declaration is a constructor, an instance a substitution

2026-09-15. [spec/data.md §5.5.3–§5.5.4](../../docs/spec/data.md).

## 1. The algebra

- **A declaration is a type constructor.** `(variant (result T E) (ok T) (err E))` declares
  `F : Type² → Type`, with `F(A, B) = Σ_c P_c[A/T, B/E]`.
- **An instance is the substitution** `σ = [A⃗/T⃗]` applied to every payload. A payload is a type
  name, so a parameter can occur only as a whole payload, and substituting on a flat payload is the
  whole homomorphism (`Sum.instantiate`).
- **An instance is identified applicatively**, by its declaration and its arguments. Its canonical
  spelling is `F(A₁, …, Aₙ)`, and its key is `a.result(int, string)`. The spelling is delimited,
  because an argument may contain spaces (`int 0 255`) or be applied itself (`option(int)`). So
  `Applied` splits arguments only at parenthesis depth zero.
- **Arguments are never inferred.** Inside a program reduction erases every variant, so a
  parameterised variant reduces exactly as an unparameterised one does, with nothing left behind. At a
  boundary the signature writes them, which is the only place they are needed. No unification is
  involved.
- **At a boundary an instance is its tag and its substituted payload**, `k = 1`: the representation
  every sum already has. So nothing new reaches a backend.

`option` is now `(option T)`, with `(some T)` and `none`. `(sig find ((n int)) (option int))` loads as
two results, `int int`. Before, its payload was `any` and no signature could name its argument.

## 2. Well-formedness, each rule the consequence of one stated elsewhere

| refused | because |
|---|---|
| a repeated parameter, or one named like the type | parameters are distinct names in the constructor's own scope |
| an applied parameter, `(variant (r (F int)) …)` | higher-kinded; no demand, and where module systems become research |
| a phantom parameter | an instance is identified by its arguments; one that no payload uses distinguishes nothing a program has shown |
| a payload naming its own type, `(variant tree leaf (node tree))` | μ, which the well-founded order of declarations refuses (theories.md §1.3) |
| `(sig f … result)` for a parameterised `result` | *"write (result T E) with its arguments"* |
| `(result int)` against two parameters | *"takes 2 type arguments, not 1"* |
| `(nothing int)` where `nothing` is no variant type | *"not a parameterised variant type in scope; several results are (tuple A B …)"* |
| an applied type as a parameter | a variant crosses a boundary as a result today |
| `(result int string)`: two distinct payloads | one slot per distinct payload type (§5.5.5), named a **compiler limitation**, not a rule |

The recursive-type refusal is new for unparameterised declarations too. Before it, a sum whose payload
named itself was accepted and simply had no meaning.

## 3. The grammar was ambiguous, and the first build proved it

The first version put the applied production in `TypeName`, which is where every other compound type
is spelled. Core passed. **Fourteen emit tests failed**, on refinement facts that no longer named their
parameters.

The reason is a grammar fact rather than a bug in one site. A parameter is `TYPE | (NAME TYPE)`, and
`(i int)` is both a named parameter and the constructor `i` applied to `int`. A context-free reader
cannot choose between them, and `TypeName` is what parameter lists call. So `((v (array f64)) (i int))`
lost `i`, and every `where` keyed by it had nothing to attach to.

**The resolution is by position.** The applied production is admitted only where a named parameter
cannot stand:
- a signature's result;
- the type of a named parameter;
- inside a type argument.

It lives in `TypeTerm`, which extends `TypeName`, and `TypeName` keeps exactly the language it had. The
spelling test carries the witness: `TypeName` of `(p string)` must stay `""`.

## 4. Witnesses

- The declaration refusals, the boundary errors, and `k > 1` named as a limitation.
- `(option int)` and `(result string)` at a boundary are `int int` and `int string`. **This fails
  against an `instantiate` that does not substitute**, giving `int T`.
- A parameterised variant reduces to nothing inside a program.

## 5. Cost

- **Code**: `core/read.go` 1,309 → 1,394, `core/sum.go` 192 → 206, `core/reduce.go` 1,277 → 1,315,
  **+137**. Most of it is the refusals, each with a message saying why and what to write.
- **`go run ./cmd/check`, every step, passes**: emission 194 of 194 files byte-identical, proof counts
  identical (2,307 of 2,413 integer operations, 345 of 382 loops), differential on four targets, and
  tooling. No corpus program declares a parameterised variant or names `option` at a boundary, so
  nothing emitted could move.

## 6. Not built

- `k > 1`: Theorem R's `(tuple tag S₁ … Sₖ)`, which needs each backend's several-results convention at
  a width chosen by the declaration.
- An applied variant type as a parameter, and a payload that is itself applied, `(ok (option T))`.
