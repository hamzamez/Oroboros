# u128 — num/u128 in the language's own operations: two walls, one built, 2026-11-19

Decided-list item 5. hamza, 2026-11-19: "if we want to make work on every platform we rewrite it
in the language". `lib/num/u128.oro` is written over Go's `math/bits` and `strconv`, so its two
differential cases skip the other targets.

## The rewrite: ι's image in ℤ

V = [0, 2¹²⁸) and ι(h, l) = h·2⁶⁴ + l, a bijection U × U → V, the abstraction function. An
operation on V is ℤ's on ι's image, read back by ι⁻¹(v) = (v / 2⁶⁴, v % 2⁶⁴), Euclid's division
by the base:

    add(a, b)  = (t / 2⁶⁴, t % 2⁶⁴, s / 2¹²⁸)   where s = ι(a) + ι(b), t = s % 2¹²⁸
    mulw(a, w) = (t / 2⁶⁴, t % 2⁶⁴, [p ≥ 2¹²⁸])  where p = ι(a)·w,    t = p % 2¹²⁸
    divw(a, y) = (q / 2⁶⁴, q % 2⁶⁴, ι(a) % y)    where q = ι(a) / y
    decimal    repeated division by 10¹⁸, every digit by `string_of(48 + d)`

Each law (add's ι(s) + c·2¹²⁸ = ι(a) + ι(b), and the others) holds by Euclid's theorem, so the
module has no carry chain to get wrong. Every intermediate is claimed, `s ∈ 0..2^129-2` and so
on, which is a program's consent to the rung above the word (ADR 0079). Without the claims the
intermediates stay in the word, and under `-checked` they trap: Java's `multiplyExact`,
windows' `llvm.trap`. A target chooses the claimed values' representation (a host bignum, limbs).
The rewritten text is `examples/u128/inz.oro`, pinned by the emission baseline as refused, so it
shows where the walls stand.

## What failed first

1. **`x % 2^128` owed 2¹²⁸ ≠ 0, and nothing decided it, on every target.** The goal is a closed
   disequality, in J's spelling `(if (= d 0) false true)`. Its constant is past int64, so the
   word's evaluation does not fold it and the linear fragment cannot read it.
   `closedIntComparison` decided <, ≤, >, ≥ and = of closed integer terms exactly in ℤ, but not ≠.
   **Built**: it reads a ≠ b in both spellings (a host's `ne` and D's negated `=`) and decides it
   by `math/big`. `TestAClosedDisequalityIsDecidedInZ` checks three cases: 2¹²⁸ ≠ 0 in each
   spelling, true, and 2¹²⁸ − 2¹²⁸ ≠ 0, false, so a false goal is refused, not passed. The fault
   `PlantClosedDisequalityUndecided` leaves the goal to the fragment, and it is undecided.
2. **A value in the unsigned word does not widen into the rung above.** add's digits are in
   [0, 2⁶⁴), held in the unsigned word. `ir/big.go`'s `widen` realizes only `big-of`, the inclusion
   S₆₄ ↪ ℤ of the signed word, and it refuses on all four targets: *an operand is
   [0, 18446744073709551615], which is not inside target go's signed word … and only a value in the
   signed word widens into arbitrary precision*. The inclusion U₆₄ ↪ ℤ is a homomorphism like
   `big-of`, so the language already states it, but no target realizes it:
   - Go: `new(big.Int).SetUint64(x)`;
   - the JVM: an unsigned `long` into `BigInteger`;
   - JavaScript: its unsigned word is a pair of digits (ADR 0083), whose comparison is not built
     either (*a comparison of a value held in the unsigned word as a pair is not built*);
   - windows: the limb library's digits, from the word's.

   **Not built, set aside**: four realizations and the selection's rule, a day's work across four
   hosts. It is owed to this program, and it is the next step of item 5.
3. **Under `-checked`, Go printed a constant above int64 into an `int`.** Before the claims, the
   program compiled to Go source that does not compile: `cannot use (18446 * 1000000000000000)
   (untyped int constant 18446000000000000000) as int value`. Lemma C (checked-2026-11-18) says
   every operation under `-checked` is proven, trapped, or closed on the word. A constant above the
   word reached the printer as none of those. No wrong answer came of it: Go refused the text, Java
   and windows trapped, and JavaScript refused. **Owed**: a constant above the word, unclaimed,
   refused under `-checked` as an operation is.
