# A scalar cell at a host's cell of a range, and the unit eliminated

2026-11-18. hamza: "Go ahead", item 1 of the order set after mapvalue-2026-11-18: a scalar `var`
cell passed to a host's cell. structs-2026-11-17 met it on the way: the cell is `cell(Int)`, and a
Win32 cell parameter wants its C type's set.

## 1. What it is

`WriteFile`'s last parameter is a `cell(DWORD)`, 0..2^32-1: the bytes written, which the host
writes. By ADR 0048 the host gets a reference to a fresh copy, reads it and writes it, so a cell
parameter is the pair (the value in, the value out). A program's cell of set S at a host's cell of
set T fits iff:
- **in:** its value at the call is in T, an obligation on that value;
- **out:** T ⊆ S, so whatever the host writes is a value of the program's cell.

A cell's type is invariant only when both directions are asked of the type alone. Here the first
is a claim, decided as any is. The second holds for every `var` cell, whose S is ℤ (a cell has no
narrower claim to write).

## 2. What failed first

1. **The checker**: *#s5 is cell(Int), but cell(0..2^32-1) is required here*. Built: the state
   translation (`core/outcell.go`) passes a scalar cell at a cell parameter of a range T as
   `(#ref "T" (#req "#claim" "w" T w))`, the reference to a fresh copy of its value claimed in T,
   written as a struct's cell names its layout. The target hands the loader each scalar cell
   parameter's set (`CellDecl.Sets`, in the `cells` form); the checker types the reference
   `cell(T)`; lowering declares it `cell(T)`.
   - A first version wrapped the value in `(the T v)`. A word's ascription is erased before
     lowering, so the IR saw `cell(Int)` and the read-back value's interval was unbounded, and
     `print_int(w)` was refused.
   - A rule letting two cells of word sorts agree was tried, and removed once the reference carried
     its set: it was not needed.
2. **In a loop**, the cell is a loop variable, its value joining 0 and what the host wrote, so the
   IR's intervals prove the claim. They had decided nothing: *the residual does not lower: an
   application whose operator is an application*. The interval route lowers windows' `main` as
   `(loop …)` applied to `(fn () ExitProcess(0))`, and lowering had no rule for it.
   - By the algebra it is **the unit destructured**: the loop's value is `()`, and
     `(() (fn () b)) = b`. 1 is terminal, so whatever holds the unit binds nothing (`ir/lower.go`,
     the tuple eliminator's n = 0).
   - A first version reused the n-ary rule, and the unit lowered as one value, *a producer of 1
     values bound to 0 names*.

   The same refusal was mapvalue-2026-11-18's map literal read at a run-time key on windows, which
   predated that step. It is fixed by this rule.

## 3. Measured

On windows and windows32 (programs of my own, in `cmd/build/varcell_test.go`):

| program | answer |
|---|---|
| `var w := 0`, `WriteFile(…, b, 0, 3, w)`, then `w` | writes `hi`, prints `1 3` |
| the call in a loop, i = 1 … 4 bytes from offset 4 − i | `1 2 3 4`, interleaved with `! i! hi! hi!` |
| `var w := 0 - 1` at the same call | refused, *the claim w ∈ 0..2^32-1 is false: its value is -1* |
| a literal of tuples read at a run-time key in `main` | `0 6 0 0 30 0`, refused before |

## 4. The test

**`TestAScalarCellIsTheHostsCell`**, both triples, two faults:
- `core.PlantCellSetUnclaimed` keeps the typed reference and drops the claim, and the cell of −1
  must then build: the claim is what refuses it.
- `ir.PlantUnitUneliminated` refuses the unit's elimination, and both the loop (its claim left to
  the refinement layer) and the literal must then be refused.

## 5. Not built

- **A cell with a narrower claim than T** (`out` direction, T ⊄ S): a `var` cell has no claim, so no
  program meets it. When one does, T ⊆ S is the obligation, decided on the two sets.
- **Go, JavaScript and the JVM**: their cell parameters are of a host type (`go.Value`, `int`) and
  no range, so no `Sets` entry and nothing changes there.
